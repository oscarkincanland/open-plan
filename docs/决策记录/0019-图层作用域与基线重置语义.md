# 0019 图层作用域与基线重置语义

- 状态：已采纳
- 记录日期：2026-10-30
- 决策者：项目负责人（按 GIS PRD 推荐方案执行，用户 2026-10-30 未提出异议）
- 基线：v0.13.3
- 关联：[GIS 模块 PRD](../plans/2026-10-30-001-GIS模块PRD.md#GI-06)、[QGIS 化改造计划](../plans/2026-10-30-002-GIS模块QGIS化改造进度计划.md#35-重置与基线机制)、`server/map.mjs`

## 1. 背景

当前地图项目把“正式图层”（落盘 `layers/*.geojson` + 瓦片 + `config.layers`）与“临时图层”（分析/绘制/等时圈/AI 结果，只在画布内）混在一起管理。临时层没有清单，删除图层直接移除数据与瓦片，误操作无法恢复；也没有“回到项目初始状态”的能力。

## 2. 问题

如何定义图层作用域、临时层契约，以及“一键重置”的行为边界，既能让 AI 结果可追踪、可转正，又能让误操作可回退且不丢数据？

## 3. 备选方案

### 方案 A：维持隐式临时层，重置只清画布

- 做法：继续按图层 id 前缀识别临时层，新增“清空画布”按钮。
- 优点：改动最小。
- 代价：临时层无来源/要素数/转正入口；重置无法恢复顺序/显隐/样式；删除仍不可恢复。

### 方案 B：显式作用域 + 基线快照 + 回收站

- 做法：
  - 图层分三类：底图 / 正式图层 / 临时图层；
  - 临时层前端注册表 `{id, project, kind, title, source, featureCount, visible, createdAt, persistable}`；
  - 项目创建时写 `map.baseline.json`（顺序/分组/显隐/透明度/样式）；
  - 重置分三级：重置图层树 / 清空临时层 / 恢复基线；
  - 删除与恢复基线移除的图层统一进 `maps/{project}/.trash/{timestamp}/`。
- 优点：AI 结果可追踪可转正；误操作可回退；重置语义清晰。
- 代价：需要 config v2、注册表、回收站与迁移脚本，改动面较大。

### 方案 C：完整 QGIS 工程文件 + 撤销栈

- 做法：引入工程文件格式与操作级 undo/redo。
- 优点：最接近桌面 GIS。
- 代价：工程文件格式、撤销栈、并发控制复杂，超出本轮范围。

## 4. 决策

选择 **方案 B**。适用边界：

- 临时层只存在于当前会话，不写 `map.config.json`，刷新即消失；
- “恢复基线”允许移除基线后新增的正式层，但必须移入 `.trash` 且输入项目名确认；
- 不做操作级 undo/redo（用基线快照 + 回收站覆盖主要回退场景）。

## 5. 理由

- 现有代码已能通过 id 前缀识别临时层，注册表是在现有渲染入口上补元数据，不需要重写渲染。
- 基线快照复用现有 `config/style` 结构，落地成本低于完整工程文件。
- 回收站保证“重置/删除”不造成不可逆数据丢失，符合本地优先与可回滚原则。
- 操作级 undo 对地图写操作价值有限，且会显著增加状态管理复杂度。

## 6. 影响

### 正面

- 临时层可定位、可转正、可一键清空；图层树三段式信息架构清晰。
- 重置三级语义明确，误操作可恢复。
- AI 画布结果天然落在临时层，确认后才进入正式层。

### 负面 / 代价

- `map.config.json` 升级 v2，需要迁移与兼容测试。
- 回收站会占用工作区磁盘，需要在文档中说明清理方式。
- 临时层注册表必须覆盖所有渲染入口，遗漏会导致清单与画布不一致（需回归断言）。

## 7. 验证

- `test:map-project`：旧 config 自动升级；基线写入与读取；原子写。
- `test:map-reset`：三级重置结果与基线一致；移除图层进入 `.trash`；无临时层时禁用。
- `test:map-temp`：画布临时层 id 与注册表一致；转正后进入正式层。
- `test:map-layers` / `test:gis-e2e` 回归通过。

## 8. 回滚

- 功能层：`schemaVersion` 保持向前兼容，旧代码可读取未迁移字段；迁移脚本可重入。
- 数据层：`.trash` 保留被移除文件，可手工恢复。
- 若需整体回退，恢复 `map.config.json` / `style.json` 最近备份即可；不删除 `layers/` 原始文件。

## 9. 复审触发

- 需要操作级撤销/重做；
- 临时层需要跨会话持久化；
- 回收站体积影响工作区备份；
- 需要多人协同或工程文件交换格式。
