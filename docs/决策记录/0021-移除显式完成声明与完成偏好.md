# 0021 移除显式完成声明（complete_task）与完成偏好

- 状态：已采纳
- 记录日期：2026-11-03
- 决策者：项目负责人
- 基线：v0.13.22 之后（develop @ `1f1dcb2e`）
- 关联：[AGENTS.md](../../AGENTS.md) §4/§5/§7、[REQUIREMENTS.md](../../REQUIREMENTS.md) R9、[DESIGN.md](../../DESIGN.md) §7、[实施计划 007](../plans/2026-11-02-007-输入栏与预览工作区收敛计划.md)、[变更日志](../../变更日志.md)

## 1. 背景

2026-10-28（v0.13.3）引入 `complete_task` 工具：要求模型在收尾时显式声明 `success/partial/blocked/failed`，目的是把"回答完了"与"任务真正完成"区分开；2026-11-02（v0.13.20）改为默认关闭、设置面板可开，并补了「收尾强制完成声明」提醒回合（模型跑过工具但没声明时追加一个只做声明的短回合）。

2026-11-03 用户在界面验收时提出：**不要用 complete_task 结尾，用原生的来结尾**。

## 2. 问题

1. **协议冗余**：完成状态已经能从 Run 终态、产物验收与待办收口推导出来；再让模型写一遍，等于同一事实两处维护，且两处可能不一致（模型说 success、产物验收失败）。
2. **多一个模型回合**：开启「显式完成声明」时，每轮有工具调用的任务会多跑一个收尾回合（首字延迟与成本都受影响）。
3. **维护面大**：工具定义、白名单、工具元数据、提示词、预算放行、轮次预算提醒、运行偏好文件、偏好接口、设置项、事件类型、前端渲染分支、两份专属测试与一条 CI 步骤——为一件事付出十余处联动成本。
4. **默认关闭时的隐性成本**：默认关闭已经让绝大多数轮次走「按终态推断」，显式分支长期处于"存在但少用"状态，却仍在提示词与测试里占据注意力。

## 3. 备选方案

### 方案 A：维持现状（默认关闭、可开）

- 优点：保留显式声明这一选项，用户想用时可用。
- 代价：维护面不减；提示词/工具/元数据/事件仍要随其他改动同步检查；两套完成语义并存，前端要区分 `explicit` 与 `inferred`。

### 方案 B：彻底删除（选择）

- 做法：删除工具、白名单、元数据、提示词、收尾提醒回合、运行偏好文件与接口、设置项、专属测试与 CI 步骤；完成状态一律按 Run 终态推断；事件类型保留为历史回放用。
- 优点：完成语义只有一个来源（Run 终态 + 产物验收 + 待办收口），不再有模型自述与客观结果打架；少一个模型回合；维护面从十余处降到一处（`server/运行轨迹.mjs`）。
- 代价：失去"模型显式声明部分完成/受阻"的表达位——但该信息本就可以写进最终答复，且待办未完成与产物验收失败已能自动降级为 `partial`。

### 方案 C：保留工具但改名/改语义（例如改为 `finish_note`）

- 优点：历史会话与提示词兼容性更好。
- 代价：本质仍是方案 A 的维护面，只是换了个名字；不解决"同一事实两处维护"。

### 方案 D：改为「让模型在最终答复里按固定格式写结论」，服务端解析

- 优点：不需要工具，模型写结论即可。
- 代价：解析自然语言格式不稳，容易把用户的结论卡解析错；与"如实呈现、不做假结构"的既有原则冲突。

## 4. 决策

选择方案 B：**彻底移除显式完成声明，回到原生收尾。**

落点：

1. **服务端**：删除 `complete_task` 工具定义与注册、白名单项、工具元数据、提示词里的收尾要求、收尾强制完成声明回合；`server/运行偏好.mjs` 与 `GET/PATCH /api/runtime-preferences` 一并删除（该偏好是本模块唯一用途）。
2. **完成语义**：`resolveRunCompletion` 只走 `inferCompletion`，`source` 恒为 `inferred`；摘要优先取模型最终答复（清洗为一行、最长 400 字），避免会话列表与任务中心退化成「未检测到文件变更」这类通用文案。
3. **事件**：`task_completed` 与 `completion_nudge` 在注册表标 `legacy: true`，不再发射；历史会话回放仍能渲染（事件发射点守护测试跳过 legacy 条目）。
4. **前端**：删除设置项与偏好 API 调用；产物面板空态、任务中心注释等文案改为「模型最终答复」口径；`complete_task` 的历史事件渲染分支保留。
5. **测试**：删除两份专属测试与一条 CI 步骤；`任务结论事件流测试` 改为断言「工具不再暴露、提示词不再要求、收尾不再有第二个模型回合、摘要取自终稿」。

## 5. 影响

- 正面：少一次模型回合；完成语义单一来源；维护面显著收敛；提示词不再出现"要求调用一个可能不存在的工具"的风险。
- 代价：`partial/blocked` 的表达依赖模型在最终答复里写清楚，以及待办/验收的自动降级；若模型答复不完整，界面只能反映 Run 终态，不会替模型补写结论。
- 兼容性：历史会话的 `task_completed` 事件仍可回放；`.oaw/preferences.json` 里的旧字段被忽略，无需迁移。

## 6. 不做

- 不改 Run 终态语义、产物验收降级规则与待办收口逻辑。
- 不改 Pi 内核与提示词注入链路的其他部分。
- 不新增「让模型按固定格式写结论」的解析逻辑。

## 7. 回滚

删除集中在工具层与偏好层，回滚需要一并恢复 `server/运行偏好.mjs`、偏好接口与设置项。建议作为一个独立提交实施，便于整体 revert。
