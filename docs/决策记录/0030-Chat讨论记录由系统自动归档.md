# 0030 Chat 讨论记录由系统自动归档

- 状态：已采纳
- 日期：2026-11-08
- 关联：[REQUIREMENTS.md](../../REQUIREMENTS.md) R3（结论形成）、[AGENTS.md](../../AGENTS.md) §5、[会话流前端规范](../规范/会话流前端规范.md) §5、`server/讨论记录.mjs`、`server/执行句柄.mjs`

## 背景

用户希望 **Chat 模式也能留下可复用的讨论记录**（"每次研究论证都形成一个 MD 文件"），但两条既有约束直接冲突：

1. **AGENTS §5 / PRD 模式表**：Chat 只读，不得写文件、不得调用 bash/Office CLI；
2. **能力边界**：若给 Chat 开写工具，等于放开整条写入面（含审批、写入锁、路径安全），远超"留个记录"的需求。

同时用户明确：结论文档**不在对话内渲染正文**，只在工作区留下文件。

## 决策

**Chat 的讨论记录由服务端在每轮收尾时自动归档，模型全程不获得任何写工具。**

- 触发：Run 以 `completed` 收尾且 `task.mode === "chat"`（取消/失败不归档）。
- 落点：当前工作区 `回报/讨论-<会话标题>.md`，**一份会话一个文件、按轮追加**（避免每轮一个新文件）。
- 内容：该轮终稿正文 + 一行提问摘要（不抓思考与工具流水）。
- 失败处理：best-effort，异常只记诊断（`chat_discussion_archive_failed`），**不影响 Run 终态**。
- 目录与 Work 的结论文档共用 `回报/`，便于用户集中查找。

实现：`server/讨论记录.mjs`（纯函数 + 文件追加），在 `server/执行句柄.mjs` 收尾分支调用。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 给 Chat 注入 `write` 工具，让模型自己写 | 打穿只读边界；模型可写任意工作区文件，与审批/写入锁策略冲突 |
| 把讨论记录写进 `.oaw/`（运行时目录） | 用户需要"可复用文档"，`.oaw` 是运行时产物、不可提交、不便查找 |
| 每轮一个独立 md 文件 | 一次讨论会产生大量碎片文件，工作区迅速变脏 |
| 在对话内渲染该文档正文 | 用户明确要求不渲染；且与"终稿已是全文"重复 |

## 后果

- **正面**：Chat 仍保持只读（模型无写工具），但每次讨论都留痕、可检索、可后续引用。
- **代价**：归档内容与对话终稿重复（同一段文字两份）；`回报/` 目录会随讨论增长，需要用户定期清理（后续可考虑"按会话归档/一键清理"）。
- **边界**：只归档 Chat；Work 的研究型结论文档仍由模型用写工具产出（见 PRD R3），Review 报告沿用既有产物通道。
