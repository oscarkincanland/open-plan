# 0027 技能依赖采用工作区隔离安装与声明式预检

- 状态：已采纳
- 记录日期：2026-11-08
- 决策者：用户
- 基线：v0.13.24（`develop @ 7ef77f76`）
- 关联：计划 [2026-11-08-001-人机协作中枢与技能写作链路完整修改计划](../plans/2026-11-08-001-人机协作中枢与技能写作链路完整修改计划.md) §2.1/§9/§13、`REQUIREMENTS.md` R6、`AGENTS.md` §4.3/§5、[技能依赖与工作区安装规范](../规范/技能依赖与工作区安装规范.md)、[0004](0004-优化开关统一且默认关闭.md)、[0005](0005-本地文件与JSONL作为默认持久化.md)

## 1. 背景

审查（2026-11-07）显示：14 个会话出现 72 条安装类命令；17 个含安装的 Run 合计 1352s，其中单 Run `run_dea3fb50` 的 1471s 里 1015s（69%）在装依赖；120s 后台化坏 payload 出现 8 次/5 个 Run；技能包默认假设 POSIX + Python 3.10 + 可联网，而产品运行在 Windows 单机、可能没有 Python。依赖是技能的隐性契约，模型只能现场"装环境"。

## 2. 问题

技能需要什么运行时、缺哪些包、能不能在当前平台跑，产品在读取技能前完全不可知；模型只能执行 `pip/npm/git clone` 等命令现场尝试，导致长等待、不可审计、可能污染系统环境，且失败后无法解释原因。若不治理，技能"存在但跑不了"会持续消耗 Run 时长与用户信任。

## 3. 备选方案

### 方案 A：系统级 pip/npm 安装（放弃）

- 做法：允许模型直接在系统 Python/全局 npm 安装技能依赖。
- 优点：命令简单、技能作者熟悉。
- 代价/放弃原因：污染系统环境、需要管理员权限、不可回滚、不可审计；与"本地优先、可回滚"冲突。

### 方案 B：模型自动安装到工作区（放弃）

- 做法：Agent 自行执行带 `--target` 的安装命令，无需用户确认。
- 优点：用户零操作。
- 代价/放弃原因：扩大 Agent 工具白名单与安全面；网络与供应链不可控；违背"未获确认不得安装"的原则。

### 方案 C：技能自带安装脚本、由 Agent 执行（放弃）

- 做法：技能目录内提供 `install.py`/`install.sh`，运行时执行。
- 优点：技能自包含。
- 代价/放弃原因：等价于任意命令执行；跨平台差异大；无法统一校验与清理。

### 方案 D：声明式 `requires` + 只读预检 + 用户点击触发的工作区隔离安装（采纳）

- 做法：SKILL.md frontmatter 声明依赖；服务端只读探测给出 `ready/degraded/blocked`；安装只由 UI 触发、二次确认后写入 `<workspace>/.oaw/skill-deps/<skill>/`；Agent 永远不得自行安装。
- 优点：依赖可声明、可预检、可审计、可回滚；不污染系统；失败有人话原因与替代方案。
- 代价/风险：新增设置、规范、后台 job 与磁盘占用；Windows/POSIX 解释器路径差异需要专门处理。

## 4. 决策

选择**方案 D**：

1. 技能在 SKILL.md frontmatter 用 `requires` 声明 `runtime/python/npm/exec/network/platform`；解析失败不阻塞技能读取，状态按 `degraded` 处理。
2. 读取/调用技能前做**只读预检**（`where/which`、`.venv` 解释器、`python -c "import x"`、`node -e "require.resolve"`），不联网、不安装；`skills_read` 结果附 `<skill_requires status=...>`，`/api/skills` 增加 `requires/depsStatus` additive 字段。
3. 未声明 `requires` 的技能按 `blocked` 处理；状态为 `blocked` 时必须给替代方案（`editorial_pipeline`、officecli、内置能力），**不得自动安装**。
4. 安装只能由用户在技能广场/设置中点击触发：`POST /api/skills/:name/deps/install {confirm:true}`；二次确认展示目标目录、包清单、来源与"不写系统目录"承诺。
5. 安装目录固定为 `<workspace>/.oaw/skill-deps/<skill>/`：Python 用 `python -m venv` + `pip install --no-input`；npm 用 `npm install --prefix <dir> --ignore-scripts`；写完 `manifest.json`（技能名/版本/来源/sha256/时间/解释器路径/包列表）与 `requirements.lock`（`pip freeze`）。
6. 安装复用后台 job：进度、超时（120s 超时转后台并返回 `jobId`）、可取消；同一技能同一时刻只允许一个安装 job，安装期间状态为 `installing`。
7. Agent 不得执行 `pip/pip3/uv/conda/npm/pnpm/yarn/apt/brew/winget/choco/git clone` 等安装命令；尝试即返回结构化错误并提示"请用户到技能广场安装"；不新增任何 Agent 可调用的安装工具。
8. 默认不配置镜像；用户可在设置填写镜像源；不在代码硬编码第三方镜像。卸载=设置中"清理依赖"（需确认，删目录 + manifest 记录，不删用户文档）。
9. 运行时开关 `OAW_SKILL_DEPS` 控制预检/安装链路，关闭时恢复"只读、不预检、不安装"；默认值与翻转时点按计划 §15 由用户确认。

## 5. 理由

- 先把"需要什么"变成声明，再把"有没有"变成预检，最后才谈安装；三者分离使失败可定位到具体一环。
- 安装限定在工作区内，天然可回滚（删目录）、可审计（manifest + lock）、不污染系统，符合本地优先与数据边界。
- 用户点击触发而非模型自动安装，保持安全面不扩大，也避免 Run 内长时间空等。
- 与既有后台 job 机制、运行开关机制一致，不引入新架构。

## 6. 影响

### 正面

- 技能可用性在读取前置可见，模型可提前改道，安装类耗时占 Run 比例目标从 69% 降到 ≤10%。
- 未确认安装命令目标为 0；依赖来源、版本、时间可追溯。
- 失败有稳定错误码与替代方案，不再靠模型反复重试。

### 负面 / 代价

- 新增声明字段、预检、安装 job、设置页与规范，维护面增加。
- 工作区会新增 `.oaw/skill-deps/` 目录与磁盘占用；需要清理入口。
- 平台差异（Windows `Scripts/python.exe` vs POSIX `bin/python`）与网络失败仍需兜底。

### 迁移与回滚

- 迁移：无强制迁移；未声明 `requires` 的既有技能按 `blocked` 展示，用户可按需补声明。
- 回滚：`OAW_SKILL_DEPS=0` 关闭预检/安装，技能回到只读状态；删除 `.oaw/skill-deps/` 即清除已装依赖。
- 兼容：`/api/skills` 只增字段；旧技能读取路径不变。

## 7. 实施约束

- 所有安装路径必须校验在 `<workspace>/.oaw/skill-deps/` 内，拒绝路径穿越。
- 不接受任意命令；只允许受控的 venv/pip/npm 调用；`--ignore-scripts` 必须开启。
- 安装过程不写系统 Python、全局 npm、用户 home 与项目目录。
- 安装失败必须给出稳定错误码（`SKILL_DEP_*`）与人话提示，不静默重试。
- 事件 `skill_preflight/skill_read/skill_dep_install/skill_exec_allowed|blocked` 必须登记；审计不得包含密钥或用户文档内容。

## 8. 验证与验收

- 新增 `scripts/技能发现与依赖测试.mjs`（`test:skill-discovery`）与 `scripts/技能依赖与安装测试.mjs`（`test:skill-deps`）；扩展 `test:skill-injection`、`test:office-exec-gate`。
- 验收口径见计划 §20：A-12～A-19（依赖声明、只读预检、禁止自动装、工作区安装、安装 job、闸门分流、别名、技能回归）。
- 指标：未确认自动安装命令 = 0；安装类耗时占最重 Run ≤10%。

## 9. 复审触发条件

- 出现任一未经用户确认的安装命令被执行。
- 供应链或依赖来源事件；或需要引入系统级共享运行时才能满足主流技能。
- 工作区 `.oaw/skill-deps/` 体积成为用户负担，或跨平台探测误报率持续偏高。
