# 0037 Pi 内核版本升级采用精确锁定与行为基线显式化

- 状态：已采纳
- 记录日期：2026-11-10
- 决策者：用户（“开启内核全量升级。做好依赖更新和版本管理”）
- 基线：v0.13.25（`develop @ 1769a23c`）
- 关联：[计划 2026-11-10-005](../plans/2026-11-10-005-Pi%20SDK升级与功能适配计划.md)、[实施记录](../plans/2026-11-10-005-实施记录.md)、`AGENTS.md` §1/§5.1、`docs/规范/架构规范.md`、[ADR 0036](0036-新功能与修改实行文档先行确认闸门.md)

## 1. 背景

`@earendil-works/pi-coding-agent` 从 1.1.0 升级到 1.5.1（2026-11-09 npm `latest`）。只读对比结论：导出符号 0 删除（298→299），`dist/core/sdk.d.ts` 完全一致；但 1.2–1.5 存在行为变更，其中 1.5.1 把 `cacheWarming` 默认值从 `"streaming"` 改为 `"idle"`（Run 之间也保活 30 分钟），1.5.0 把工具参数校验从 TypeBox 切换到 pi-schema，并且供应商/模型目录已从 1.1.0 时代（41 家/1142 模型）变为 42 家/1208 模型。

## 2. 备选方案

### 方案 A：保持 1.1.0（放弃）

- 优点：零风险。
- 代价：错过 1.2–1.5 的稳定性/安全/模型修复；供应商目录继续过期；长期欠账扩大。

### 方案 B：浮动升级（`^1.1.0` / `latest`）（放弃）

- 优点：自动跟进。
- 缺点：内核升级影响所有会话/工具链；浮动版本无法复现构建、回退困难；违反项目“依赖可复现”原则。

### 方案 C（采纳）：精确锁定 1.5.1 + 行为基线显式化 + 快照重建 + 分阶段回退

- `package.json` 与 lockfile 精确锁定 `1.5.1`，不使用范围。
- 升级同时显式固定与 1.1.0 一致的行为基线：`cacheWarming: RUNTIME_FLAGS.cacheWarming ? "idle" : "streaming"`（默认仍是 streaming），避免静默继承 1.5.1 的 `idle` 默认。
- `PI_PACKAGE_VERSION` 改为读取实际安装包版本，避免文档/接口版本分叉。
- 用 1.5.1 重新提取 `server/Pi内置供应商.json`（42 家/1208 模型），并同步更新目录测试的确定性断言。
- 提交前跑 `npm run verify`、`test:pi-*`、`test:provider-catalog`、`test:pi-iteration`；升级前备份 `.oaw/规聚/` 与 `.规聚会话/`，保留 pin 回 1.1.0 的回退路径。

## 3. 影响

- 正向：内核与模型目录更新；工具校验统一到 pi-schema；会话/压缩/思考档位的多个修复生效；版本展示可追溯。
- 契约：依赖版本锁定、供应商快照内容、`/api/status.piPackageVersion` 值变化；不改变公开 API/事件/工具白名单。
- 行为：`cacheWarming` 默认显式保持 streaming（不新增跨 Run 保活）；1.2 的会话起步 busy 语义、1.5 的 pi-schema 错误文案属于模型可见的细微变化。
- 回退：`package.json` 回 1.1.0 + `npm install`（或还原升级前提交）并重启；若新版本已写新格式会话，需先停服还原 P0 备份。

## 4. 验收

- `npm run verify` exit 0；`test:pi-connectivity`、`test:pi-config`、`test:pi-config-api`、`test:provider-catalog`、`test:pi-iteration` 全通过。
- `/api/status.piPackageVersion === "1.5.1"`；`Pi内置供应商.json` 为 42 家/1208 模型且 `generatedAt` 更新。
- 工具参数校验、会话恢复、网络代理注入、压缩行为在真实 Run 中无回归（真实 Run 与桌面安装包由后续验收补齐）。
