# 0032 专家团队按需触发采用建议与显式入口

- 状态：已采纳
- 记录日期：2026-11-09
- 决策者：用户
- 基线：v0.13.24（`develop @ 8a7361e9`）
- 关联：[计划 2026-11-09-001](../plans/2026-11-09-001-专家团队按需触发与可观测性修改计划.md)、[ADR-0023](0023-专家团队采用TeamLite边界.md)、[计划 014](../plans/2026-11-04-014-AgentTeams与subagent能力适配计划.md)、`REQUIREMENTS.md` R2、`DESIGN.md` §7、`server/团队建议.mjs`、`server/团队指标.mjs`

## 1. 背景

Team Lite 上线后，专家团队只有“模式白名单 + 一段系统提示词 + 模型自觉”。实测 555 个 Run 仅 8 次创建团队（约 1.4%），其中 7 次是用户明确点名或测试，1 次是用户追问“为什么没用团队”。能力在、但自主触发率极低；同时缺少“建议但未采用”的观测，无法判断是提示词问题还是任务判断问题。

## 2. 问题

- 提示词只有一句模糊的“多角色才用”，没有“团队 vs 子代理 vs 单干”的决策表；
- 能力计划里 `team=available`，没有“本轮建议”信号；
- 没有用户显式入口（`/team`），想用只能靠自然语言；
- 团队创建无来源记录（user/suggested/model），无法运营；
- 无“先有任务再组队”的护栏，可能为组队而组队。

## 3. 备选方案

### 方案 A：服务端按关键词强制创建团队（放弃）

- 做法：命中多材料/审阅关键词时代码直接 `createTeamService` 并注入“必须用团队”。
- 优点：触发率 100%。
- 代价/放弃原因：把“要不要多角色”的决策从模型拿走，简单/边界任务会被过度拆队，成本与延迟不可控；违背 Team Lite 的“专家小组”定位；回退需要改代码。

### 方案 B：只改提示词，加决策表（部分采纳）

- 做法：把“单干/子代理/团队”写成规则。
- 优点：改动最小、无契约变更。
- 代价：仍无“建议”信号、无显式入口、无观测；模型仍可能沉默跳过。

### 方案 C（采纳）：决策表 + 建议器 + `/team` 入口 + 护栏 + 观测

- 做法：提示词决策表；`planTaskCapabilities` 对复杂任务输出 `team.status="suggested"`（≥2 信号，含原因/minTasks）；`/team` 置 `teamIntent="required"`；`team_spawn` 前无任务则阻断；`team_started.trigger` 与新事件 `team_suggested`/`team_spawn_blocked`；`.oaw/team-metrics.json` 计数。
- 优点：保留模型决策权；合适任务会被“提醒”；用户想用有确定入口；失败可观测；全部开关可回退。

## 4. 决策

采纳方案 C，并确认（用户 2026-11-09）：

1. 建议阈值：正向信号命中 **≥2** 才建议；
2. 命令名：`/team`；required 模式允许用 `run_subagent` 做并行只读准备，但团队必须 ≥2 个可认领任务，不得用子代理替代团队；
3. 护栏：非 required 模式下仅当任务数为 **0** 时阻断 `team_spawn`；
4. 默认值：`teamSuggest`、`teamGuard`、`teamRequiredEntry` 默认**打开**（用户已按 AGENTS §4.3 确认；`OAW_TEAM_*=0` 可回退）；
5. “建议未采纳”只在 Run 收尾给一句可操作提示，不进入过程流；
6. 指标持久化到 `.oaw/team-metrics.json`（运行时 JSON，可删除重建，不引入数据库）。

## 5. 影响

- 正向：复杂任务更容易获得多角色协作；用户有确定入口；团队来源可追溯；可计算建议采纳率与空团队率。
- 负向/风险：建议误报可能增加成本（阈值、负向清单与护栏缓解）；`team_spawn` 前后顺序变化（须先建任务）；提示词变长（仅 Work/Review，≤8 行）。
- 契约：新增可选 task 字段 `teamIntent`、能力计划 `team` 的 `required|suggested` 与 `reasons/minTasks/signals`、事件 `team_suggested`/`team_spawn_blocked`、`team_started.trigger`；`/api/metrics/summary.teams`。全部只增不改，旧回放兼容。
- 边界：Team Lite 的 3 人/20 任务/不嵌套/不跨 Run 不变；Chat 仍无团队工具。

## 6. 验证

- `test:team-trigger`（建议器正/负例、阈值、接线、护栏、事件、前端命令、指标）；
- `test:team`、`test:team-panel`、`test:capability-contract`、`test:event-registry`、`test:event-payload`、`test:event-emission`；
- `npm run verify`；
- 真实验收：`/team` 必建队、复杂任务出现建议并可采纳、单步任务不误报、护栏阻断并记事件。

## 7. 复审与回退

- 开启后观察 1 周 `team_suggested`→`team_started` 采纳率、空团队率与简单任务误组队率，再调阈值/文案；
- 回退：设 `OAW_TEAM_SUGGEST=0`（不注入建议）、`OAW_TEAM_GUARD=0`（不阻断）、`OAW_TEAM_REQUIRED_ENTRY=0`（禁用 /team）；指标文件可直接删除。
