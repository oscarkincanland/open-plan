# 0013 GIS 交付能力默认开启

- 状态：已采纳
- 记录日期：2026-10-30
- 决策者：用户（2026-10-30 明确确认“GIS 开关默认体验”）
- 基线：v0.13.3
- 关联：[GIS 模块 PRD](../plans/2026-10-30-001-GIS模块PRD.md#GI-16)、[QGIS 化改造计划](../plans/2026-10-30-002-GIS模块QGIS化改造进度计划.md#T4.3)、`server/运行开关.mjs`

## 1. 背景

GIS 交付层（G7 批量导出、G8 分析报告、G9 项目打包、G5 模板、G10 书签）在 2026-10-16 落地时，按“优化项默认关、基线等价”的约定全部挂在 `OAW_MAP_*` 环境变量后，默认关闭。实际运行 `/api/status` 显示 `mapReport/mapExport/mapPack/mapTemplates/mapBookmarks` 均为 `false`，界面入口不可见，用户体感“GIS 功能缺失”。

## 2. 问题

GIS 交付能力是否继续默认关闭？若继续关闭，用户每次都要手工设置环境变量，功能等于不可发现；若默认开启，则与既有“优化项默认关”约定冲突，需要明确回退方式与测试基线。

## 3. 备选方案

### 方案 A：保持默认关，仅在设置页提供开关

- 做法：继续 `readFlag`（默认 false），设置页提供开关，开启后写配置。
- 优点：完全符合 ADR 0004“默认关闭、基线等价”。
- 代价：首次使用者看不到报告/批量导出/打包/模板/书签，功能发现成本高；设置页开关本身也要新增存储与下发。

### 方案 B：默认开启，环境变量显式关闭

- 做法：五个 GIS 交付开关默认 `true`；新增 `readFlagDefault(name, true)`，仅当环境变量为 `0/false/off` 时关闭；`/api/status` 下发实际值；设置页提供开关说明。
- 优点：默认即可体验；保留一键回退；与用户 2026-10-30 决策一致。
- 代价：改变历史默认基线，需要同步更新“默认关”测试与文档；离线/资源紧张环境下批量导出入口会默认出现。

### 方案 C：按项目默认开启

- 做法：在项目配置中记录各能力开关，项目级默认开启。
- 优点：粒度更细。
- 代价：配置面扩大、跨项目行为不一致，超出本轮范围。

## 4. 决策

选择 **方案 B**：GIS 交付能力默认开启。

适用边界：仅 `mapReport`、`mapExport`、`mapPack`、`mapTemplates`、`mapBookmarks` 五项；`dataAdapters`、`amapMcpBridge` 等涉及外部数据/网络桥接的开关仍保持默认关闭。

## 5. 理由

- 用户明确要求“GIS 开关默认体验”，默认开启是唯一能让功能可发现的方式。
- `OAW_MAP_*=0` 提供与 ADR 0004 等价的一键回退，且无需改代码。
- 交付能力均为只读或产物写入工作区，失败不破坏项目，默认开启的风险可控。
- 外部数据适配与 MCP 桥涉及网络与凭据，继续默认关闭，避免安全面扩大。

## 6. 影响

### 正面

- 首次安装即可从界面进入报告、批量导出、打包、模板、书签。
- 开关状态经 `/api/status` 下发，前端按实际值显隐入口。

### 负面 / 代价

- 既有“默认关”断言需更新为“默认开 + 显式关”两组基线。
- 批量导出默认可见，低配机器可能触发较重的浏览器导出任务，需要在入口处提示资源占用。

## 7. 验证

- `test:map-report` / `test:map-export` / `test:map-pack` / `test:map-template` 增加“默认开”与“`OAW_MAP_*=0` 关闭”两组断言。
- `test:gis-e2e` 在无环境变量时 `/api/status` 五项为 `true`。
- `npm run verify` 通过。

## 8. 回滚

设置 `OAW_MAP_REPORT=0 OAW_MAP_EXPORT=0 OAW_MAP_PACK=0 OAW_MAP_TEMPLATES=0 OAW_MAP_BOOKMARKS=0` 后重启服务，即回到默认关基线；代码层保留 `readFlagDefault` 的单点实现，可整体回退。

## 9. 复审触发

- 批量导出在默认开启后造成明显卡顿或资源占用投诉；
- 需要按项目或按用户控制能力可见性；
- 新增更多 GIS 交付能力需要统一默认策略。
