# 0016 会话流折叠过程而不折叠答案，字号收敛为三档

- 状态：已采纳
- 记录日期：2026-11-01
- 决策者：项目负责人
- 基线：v0.13.3（main @ be113d38）
- 关联：[AGENTS.md](../../AGENTS.md) §3/§4.3、[会话流前端规范](../规范/会话流前端规范.md) v2.0、[DESIGN.md](../../DESIGN.md) §7、[003 折叠与字号计划](../plans/2026-11-01-003-会话流整轮折叠与字号收敛计划.md)、[001 改版落地文档](../plans/2026-10-31-001-会话流改版落地文档.md)

## 1. 背景

2026-10-31 的会话流改版（`08d4679d`..`be113d38`）为了去掉过重的「运行框」，把一轮 Run 改成**无外框、时间流直铺**，并在规范 §2/§11 明文禁止「整轮折叠头」「时长徽标」「运行框」。这条规则解决的是“运行框太占地方”。

改版落地后出现两个新问题：

1. **过程铺满屏**。一轮 12 步的 Run 会把思考、工具、阶段结论全部展开，一屏里出现 3–4 个同权重的 14px/600 粗体块（实测单个会话出现 13 个「阶段结论」cap）。用户要读的答案被埋在中段。
2. **字号阶梯变成噪声**。实测同一会话流出现 9 种字号（10 / 10.166 / 11 / 11.5 / 11.96 / 12 / 12.5 / 13 / 14）与 22 种「字号 × 字重 × 颜色」组合。相邻差 0.5px 甚至 0.04px，视觉上不构成层级，只构成抖动。更严重的是**信息权重倒挂**：真正的内容（详细展开）是 12.5px、`--dim`、对比度 4.42:1（低于 WCAG AA 4.5:1），而「最终结果如下」这类元信息句是 14px/600 近白。

## 2. 问题

如何让「一轮 Run 结束后只留必要信息」，同时不重新引入被 001 阶段否定的「运行框」，并让阅读层级重新可用？

## 3. 备选方案

### 方案 A：维持无折叠，只调字号与间距

- 优点：不动结构，不回退既有决定，改动最小。
- 代价：过程仍然铺满屏，答案仍在折叠体之外被十余行工具记录冲淡；只解决“看得清”，不解决“找不到”。

### 方案 B：照搬旧 RunFold，整轮（含答案）折叠成一行

- 优点：最干净，一屏可容纳很多轮。
- 代价：这是工作台，答案是交付物。每读一轮都要点一次展开；且与 001 阶段否定的“折叠头”形态完全重合，等于回退。

### 方案 C：折叠过程、答案常显（选择）

- 做法：时间流、系统提示聚合收进一行折叠头（「已完成 · 用时 9 分 8 秒 · 12 步」）；**结论正文、产物卡、未决 ask/审批、需行动提示留在折叠体外常显**。同时把字号收敛为 12 / 14 / 16 三档，正文回到 14px + 默认正文色。
- 优点：一屏从“过程 + 答案”变成“折叠头 + 答案”，答案回到视觉中心；保留了 001 阶段的核心成果（无运行框、无外边框、时间流本身不变）。
- 代价：多一个可交互状态（展开/收起）与对应的无障碍处理（`aria-expanded`、焦点归还、折叠态移出焦点序列）。

### 方案 D：折叠过程 + 仅显示结论首行

- 优点：更紧凑。
- 代价：需要判断“哪一行是结论”，而模型输出没有稳定结构；容易把表格或列表截断。不做。

## 4. 决策

选择 **方案 C**。

1. **折叠对象是过程，不是答案。** 折叠体只装时间流与系统提示聚合；结论正文、产物卡、未决交互、需行动提示常显。
2. **失败与取消同样默认折叠。** 状态由折叠头（状态点 + 文案）表达，可执行的动作由折叠体外的「需行动提示」承载，不要求用户先展开才能看到该做什么。
3. **展开态不持久化。** 组件内状态，切会话/刷新回到默认折叠，与规范 §8「历史回放不重播」一致，也避免把界面状态写进 `oai_ui_state`。
4. **字号收敛为三档：12 / 14 / 16。** 正文 14px/400/`--text`；分节标题 16px/600；元信息 12px/`--muted`；代码 12px。字重只有 400 / 600。禁止 em 相对字号（`1.1em` 会随宿主字号滚出 13.75px 这类非整数档）。
5. **正文不再使用 `--dim`。** `--dim` 只承载 12px 次要信息，并提升到 ≥4.5:1。

本决策**推翻** [会话流前端规范 1.1](../规范/会话流前端规范.md) §2「没有运行框、不出现折叠头」与 §11「禁止新增整轮折叠头」。规范同步升到 2.0，被推翻的条文以本 ADR 为准。

## 5. 理由

- 与 001 阶段不冲突：001 否定的对象是「运行框 + 外边框 + 折叠头」三件套组成的**容器**；本决策只保留一个**无外框的一行按钮**，时间流本身的形态、缩进、行级展开全部不变。
- 与用户的实际浏览路径一致：读一轮 Run 时先看“答了什么”，需要时才追问“怎么做的”。
- 字号收敛是可量化验收的：会话流可见文本的字号集合必须 ⊆ {12px, 14px, 16px}，可以写成测试断言。

## 6. 影响

### 正面

- 完成后首屏高度显著下降，答案重新成为视觉主体。
- 字号档位从 9 档降到 3 档，相邻档位差 ≥2px，层级可读。
- 正文对比度从 4.42:1 提到 ≈17:1，达到 AA。
- 折叠头把“用时 / 步数 / 终态”合并成一个可点击信息点，去掉原先分散在 cap、`.tl-elapsed`、状态点三处的重复表达。

### 负面

- 新增一个交互状态与无障碍负担（`aria-expanded`、`aria-controls`、折叠态 `visibility: hidden`、收起时焦点归还）。
- 用户若要逐条看过程需手动展开一次；对“必须盯着工具执行”的场景体验略降（可用运行中不折叠缓解：运行中仍直铺）。

### 不做

- 不折叠结论与产物。
- 不做“结论超过 N 行自动截断”（保留为后续可选项，复用现有 `answerClamped`）。
- 不改 SSR/事件协议/后端归约。
- 不新增动画、渐变或硬编码色值。

## 7. 落地与回滚

- 落地：[会话流前端规范](../规范/会话流前端规范.md) v2.0、`client/src/components/chat-flow/RunFoldBar.jsx`、`ChatPanel.jsx` timelinePath 分支、`SummaryBlock.jsx` 瘦身、`styles.css` 字号段；测试见 [003 计划](../plans/2026-11-01-003-会话流整轮折叠与字号收敛计划.md) §4。
- 回滚：折叠与字号分两个提交，回退闭合接入（`ChatPanel.jsx`）即回到直铺形态，不影响字号收敛；反之亦然。
- 若折叠范围需要改为“连结论一起折”，把 `RunFoldBar` 的 `scope` 由 `process` 改为 `run` 即可，不改变其余实现。
