# 0013 提交门禁与未验证改动不提交

- 状态：已采纳
- 记录日期：2026-11-01
- 决策者：项目负责人
- 基线：v0.13.3（main @ be113d38）
- 关联：[AGENTS.md](../../AGENTS.md) §7.1/§8、[变更日志](../../变更日志.md)、[会话流收敛计划](../plans/2026-11-01-002-会话流收敛与提交门禁落地计划.md)

## 1. 背景

2026-10-31 的三份计划（会话流改版、会话流精修、Office 写作防线）落地后，仓库进入一种混合状态：

- 已提交的历史（`d81a3077`、`96cf853a`、`0b809dc2` 等）功能完整、测试可复现；
- 工作区同时存在一批**未提交**的会话流改版（删除 `RunFold.jsx`、新增无框时间流、修改 DESIGN 与新规范），没有计划任务号、没有实施记录，并且打红了 `test:motion` 与 `test:chat-flow`；
- 另有 `tmp-*`、`.tmp-l3-result.json`、地图临时图层、未跟踪的实验目录等运行时/实验产物与源码混在一起。

在这种状态下，“哪些改动算完成、哪些可以进仓库”没有可执行的判据，容易出现“先提交再修”的半成品提交。

## 2. 问题

如何保证进入 `develop` / `main` 的每个提交都对应**功能明确且验证通过**的改动，而不是把探索过程、临时文件或未验证代码带进历史？

## 3. 备选方案

### 方案 A：维持现状，依赖评审人自觉

- 优点：零成本，不改变现有工作流。
- 代价：无法阻止半成品进入集成分支；本次工作区状态已经证明“自觉”不足。

### 方案 B：提交前置清单 + 工作区/`wip/*` 隔离（选择）

- 做法：在 `AGENTS.md` 写死提交门禁（功能明确、验证通过、失败可区分、范围单一、禁入内容零容忍、文档同步、禁止先提交后验证）；未验证改动只能留在工作区或 `wip/*` 分支。
- 优点：不改工具链、不增加依赖，立即可执行；提交历史可回滚、可审计。
- 代价：每次提交需要逐文件暂存并先跑测试，操作成本略增。

### 方案 C：提交钩子/CI 强制拦截

- 优点：最硬，能机械阻止不合规提交。
- 代价：本地钩子可被绕过；当前 CI 37 项中仍有 6 项红（含基线失败），在基线未清理前加硬门禁会持续误报。可作为后续增强，不作为本次决策。

## 4. 决策

选择方案 B：**只有功能明确且验证通过的改动才允许提交；未验证改动不得提交。**

落点为 `AGENTS.md` §7.1 的 7 条硬性门禁：

1. 功能明确（R 编号 / 缺陷 / 计划任务号，边界与不做清单清楚）；
2. 验证通过（受影响 `test:*` + `npm run verify`，新功能有测试、修复有回归）；
3. 失败可区分（列出无关的既有失败并证明未新增）；
4. 范围单一（禁止 `git add -A` / `git add .`，逐文件审核）；
5. 禁入内容零容忍（运行时产物、临时文件、用户数据、密钥、未纳入计划的实验资产）；
6. 文档同步（行为变化同步 PRD/DESIGN/规范/计划/变更日志；纯文档提交也要过链接与口径检查）；
7. 禁止“先提交后验证”。

未验证的工作只能留在工作区或独立 `wip/*` 分支，不得进入 `develop` / `main`。

## 5. 理由

- 与 `AGENTS.md` §4.2「未运行验证就声称已完成/已通过」的禁止项一致，只是把“禁止声称”推进到“禁止提交”。
- 不改变构建、测试与发布工具链，不引入新的运行时开关或依赖，符合 0012 之后“默认路径可靠、可一键回退”的原则。
- 本次工作区的问题正是“代码、文档、临时产物混在一起”，逐文件暂存是最小、最直接的约束。

## 6. 影响

### 正面

- 提交历史中的每个条目都能对应到需求/缺陷与测试证据，回滚粒度清晰。
- 临时文件、调试脚本与未验证实验不会再进入仓库。
- 文档与代码的同步关系可追踪。

### 负面

- 提交前必须跑目标测试与 `npm run verify`，提交耗时增加。
- 未验证的 WIP 需要额外管理工作区或 `wip/*` 分支，不能再用“临时提交”保存进度。

### 不做

- 本次不新增 Git 钩子或 CI 强制门禁；待 37 项 CI 基线清理后，再评估是否把门禁机械化。

## 7. 落地与回滚

- 落地：`AGENTS.md` 版本 2.1、§7.1、§8 DoD 新增加勾选项；`变更日志.md` 记一条 `docs`。
- 回滚：撤回 `AGENTS.md` §7.1 与版本号即可，不影响代码、测试与运行时行为。
