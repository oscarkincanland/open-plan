# 0024 桌面端采用「壳优先 + 一份源码 + 平台适配层」

- 状态：已采纳
- 记录日期：2026-11-06
- 决策者：用户（2026-11-06 明确：文件树「一份源码 + 适配层」、LibreDWG 随包、版本继续 0.13.x）
- 基线：v0.13.24（develop @ `3d58759c`，未发布）
- 关联：[023 桌面端完整修改计划](../plans/2026-11-06-023-桌面端完整修改计划（0.13.x）.md)、[021 桌面端开发方案](../plans/2026-11-06-021-桌面端开发方案（v0.13.24基线）.md)、[022 工程结构与冲突治理](../plans/2026-11-06-022-桌面端工程结构、安装包收敛与双形态冲突治理.md)、ADR 0002（单仓单服务）、ADR 0020（默认在 develop 开发）

## 1. 背景

仓库已有一个**完整的 Electron 桌面端**实现留在 `github.com/sungatetop/open-plan`（`fork/main`）：`electron/` 344 文件、IPC `op:*` 直调、NSIS 安装包、89 个 vitest。本项目在 2026-10-19 与之分叉，此后主线独立演进。

2026-11-02 曾选定「路线 1：把 `electron/` 搬回主线，桌面端成为主形态、web 降级」，状态为「待启动」。

到 2026-11-06，事实已变化：

| 指标 | 2026-11-02 | 2026-11-06 |
|---|---|---|
| develop 独有功能 | 177 提交（v0.13.3） | **257 提交（v0.13.24）** |
| fork/main vs develop 合并冲突 | 1081 文件 | **406 个冲突文件** |
| 主线测试 | 161 个 `.mjs` | **192 个 `.mjs`** |

fork 的形态要求把 `server/*.mjs` 全部 TS 化重写进主进程、前端 API 层换成 IPC 客户端、测试体系换 runner。在主线已长到 v0.13.24 的情况下，这条路的成本与返工面显著高于收益。

## 2. 问题

在不放弃 web 形态、不重写 192 个测试与 110 个服务端模块的前提下，如何交付可安装的桌面端，并让后续功能迭代不被双形态拖垮？

## 3. 备选方案

### 方案 A：壳优先 + 一份源码 + 平台适配层（采纳）

- 做法：Electron 主进程 `import` 现有 `server/index.mjs`（随机端口 + API token），`BrowserWindow` 加载 `client/dist`；差异集中在 `desktop/`（壳）与 `client/src/平台/`、`server/平台/`（适配层）。
- 优点：1–2 周可用；192 个测试与全部治理继续有效；web 形态无损；改动集中在低冲突目录。
- 缺点：主进程与后端同进程（需把重任务移出主线程）；端口/token 需处理；不是「纯 IPC」形态。

### 方案 B：搬迁 fork 的 `electron/`（原路线 1）

- 做法：`electron/` 整体迁入，桌面端成主形态，IPC 直调，web 降级为可选本地服务。
- 优点：无端口、启动快、已有 R0–R6 完成度。
- 缺点：406 冲突；257 提交功能要重搬；测试双 runner；与 ADR 0002 正面冲突，须废止。

### 方案 C：Tauri

- 优点：体积最小。
- 缺点：与「Node 后端进程内直调」不兼容（要么 Rust 重写，要么退回 sidecar = 自己起 Node 服务）；officecli/CAD 子进程与地图静态资源管理复杂。

## 4. 决策

**采纳方案 A**，并明确三条边界：

1. **文件树**：`client/`、`server/` 保持唯一事实源；新增 `desktop/`（壳，约 20 文件）与两个 `平台/` 适配目录；业务代码零行新增。
2. **平台差异**：只允许出现在适配层，业务代码只问「能力有没有」，不问「是不是桌面」；`client/`、`server/` 禁止 `import "electron"`（`scripts/平台边界检查.mjs` 门禁）。
3. **随包二进制**：LibreDWG 随包（覆盖 DWG 读取）；ODA 不随包，DWG 原格式写回继续走「另存 `-修改.dxf`」降级。

**版本**：继续 0.13.x 补丁线，桌面端首发 `v0.13.25`；不启用 v0.14.0（与 `版本管理计划.md` 现行表述一致）。

**浏览器模块**：桌面端采用 Electron `WebContentsView` + `webContents.debugger`（页面原生渲染，删除 screencast/SSE/base64 帧流），web 端保留现有实现，开关 `OAW_BROWSER_DRIVER=system|embedded`。

## 5. 后果

- **正面**：可回滚（`OAW_DESKTOP=0` 回 web）；测试体系不动；桌面端后续迭代集中在 `desktop/`。
- **负面**：主进程承载后端，重任务（知识库索引、Office 渲染）需移出主线程；打包体积 150–190MB；`webContents.debugger` 与 DevTools 互斥需约定。
- **需要后续跟进**：M3 代码签名与升级通道；`docs/多用户隔离与桌面端路线梳理.md` 中「推荐 Tauri」的结论需标注失效；ADR 0002 在方案 A 下**不冲突**（仍是单仓单服务），无需废止。
