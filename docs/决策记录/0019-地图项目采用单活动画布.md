# 0014 地图项目采用单活动画布

- 状态：已采纳
- 记录日期：2026-10-30
- 决策者：用户（2026-10-30 明确确认“单活动画布”）
- 基线：v0.13.3
- 关联：[GIS 模块 PRD](../plans/2026-10-30-001-GIS模块PRD.md#GI-10)、[QGIS 化改造计划](../plans/2026-10-30-002-GIS模块QGIS化改造进度计划.md)、`client/src/components/MapPanel.jsx`

## 1. 背景

GIS 模块目前一个 `MapPanel` 实例对应一个活动地图项目，项目切换通过重载 `style.json` 完成。用户提出“新开一个画布让 Agent 开始做图”的诉求，需要明确：是支持多个画布标签页并存，还是每次新建/切换项目只保留一个活动画布。

## 2. 问题

同一时刻是否允许多个地图画布并存？若不明确，前端状态（临时层、选中态、地图实例、Agent 上下文）会出现多实例共享问题，AI 结果可能写入错误项目。

## 3. 备选方案

### 方案 A：多画布标签页

- 做法：在同一地图模块内维护多个 MapLibre 实例或标签页，每个标签绑定一个项目。
- 优点：可并排对比多个项目。
- 代价：需要多实例生命周期、标签切换状态恢复、临时层按标签隔离、内存与 WebGL 上下文翻倍；与现有单实例 MapPanel 结构冲突大。

### 方案 B：单活动画布（切换项目即切换画布）

- 做法：始终只有一个活动项目与一个 MapLibre 实例；“新建画布”创建空白项目并切换过去，旧项目保存后关闭。
- 优点：延续现有结构；临时层、选中态、Agent 上下文天然单实例；实现与测试成本最低。
- 代价：不能同时并排查看两个项目；需要在切换时清理临时层并提示未保存内容。

### 方案 C：独立窗口

- 做法：每个项目开独立浏览器窗口。
- 优点：真正并行。
- 代价：需要窗口管理、跨窗口会话同步，超出本地优先工作台范围。

## 4. 决策

选择 **方案 B：单活动画布**。

“新开画布”= 新建（空白/复制/模板）项目并切换为当前活动项目，而不是新增并行画布；切换项目时清理本会话临时层与选中态，未保存绘制结果先提示转正。

## 5. 理由

- 与现有 `MapPanel` 单实例、`task.mapProject` 单项目上下文一致，避免多实例状态同步缺陷。
- 临时层与 AI 结果按项目隔离，切换即清理，不会串项目。
- 当前用户场景是“做一个项目的图”，不是“多项目并排对比”；后者可在后续单独立项。
- 地图实例、瓦片缓存、WebGL 上下文均按单实例设计，多标签会显著增加内存与回归面。

## 6. 影响

### 正面

- 临时层、选中态、Agent 上下文只有一份，行为可预测。
- 新建画布流程简单：创建项目 → 切换 → 绑定会话 → 起步提示。

### 负面 / 代价

- 不支持多项目并排；用户需要对比时只能切换。
- 切换前必须处理未保存绘制结果，增加一次确认交互。

## 7. 验证

- `test:map-ai-canvas`：新建空白画布后仅一个活动项目；切换项目后旧项目临时层不出现。
- `test:map-temp`：切项目自动清理临时层并提示未保存内容。
- 手工走查：新建画布 → Agent 出图 → 切回旧项目 → 再切回新项目，图层与视图正确恢复。

## 8. 回滚

本决策不引入新的运行时开关；如需多画布，必须新建 ADR 并评估 MapPanel 多实例改造，不能在本决策内静默扩展。

## 9. 复审触发

- 用户提出多项目并排对比/卷帘对比需求；
- 地图对比分析成为高频场景；
- MapPanel 拆分为可复用画布组件后，多实例成本显著下降。
