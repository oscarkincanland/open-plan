# 开发规范补遗 · 本轮新增的坑与约定

> 只记「下一轮还会踩」的坑。通用规范见 AGENTS.md 与 docs/2026-10-20-项目文件管理与测试验收规则.md。

## 坑 1：DXF 的 LAYER 记录是连续的，收口必须发生在「下一条开始前」

DXF 的 `0/LAYER` 记录之间**没有显式结束标记**（不像 ENDTAB）。逐对遍历时若在「遇到新 LAYER」分支里直接 `rec = []`，会把上一条未推送的记录覆盖丢弃——只有一条图层时永远发现不了，两条以上就丢首条。正确写法：新记录分支先 `pushLayer(rec)` 再清空；ENDSEC 兜底再收一次。
**推广**：任何「连续同类型记录」的流式解析，状态重置前必须先收口上一条。

## 坑 2：块（BLOCK）内实体不能计入顶层实体统计

块定义里的实体（如树池圆）会被实体遍历器顺带解析。若计数器放在共用收集函数里，块内实体会让顶层统计虚高、 CadViewer 图层数对不上。约定：收集函数带独立的 `counts` 参数，仅顶层 ENTITIES 节传入；块内实体只进 `blocks[].entities`。

## 坑 3：Node ESM 模块缓存使同进程无法验证 flag 关闭场景

`运行开关.mjs` 在模块加载时一次性解析 env 并冻结快照。测试里先以 `OAW_CAD_AGENT=1` import 过 task.mjs 后，即使改回 env、换 query 参数重新 import task.mjs，其依赖的 运行开关.mjs 仍是**缓存的旧实例**（query 只 bust 直接导入的模块，不传递到依赖树）。
**约定**：验证 flag 关闭基线用**子进程**（`execFile(process.execPath, ["--input-type=module","-e",script], { env: 不带 flag })`），不要在同一进程内反复 import。

## 坑 4：中文 AutoCAD 出的 DXF 多为 GBK 编码

utf8 直读会出现 U+FFFD 替换符。约定：CAD 文本入口统一走 `decodeDxfText`（utf8 优先、检测到替换符回退 GBK、二进制 DXF 哨兵头显式拒绝）；任何新增 CAD 读写路径不得直接 `fs.readFileSync(path, "utf8")`。

## 坑 5：脚本化代码改写严禁 String.replace(new 含 `$\`` / `$&` / `$'`)

用 `str.replace(old, new)` 做代码重构脚本时，若 `new` 里含 JS 模板串结尾 `` $` ``、`$&`、`$'` 等，会被当作**替换特殊模式**：`` $` `` 会把"匹配位置之前的全部内容"塞进结果（本轮实测把 workspace.mjs/context.mjs 打成语法残废，且无报错静默产出）。
**约定**：任何程序化文本替换一律用 `str.split(old).join(new)`（纯字面替换），并在替换后跑 `node --check` + 断言校验锚点存在。

## 约定 5：CAD 落盘必须走统一写入通道

cad_edit 的执行器只做纯变换（`prepareCadEdit` 返回 content 不写盘），落盘由 agent 层 `requireToolApproval` + `writeWorkspaceFile` 完成——与 review_copy 同构，保证 run 备份/写入清单/审批事件不旁路。后续任何 CAD 写入类工具照此模式。

## 约定 6：CAD 新能力一律过双开关

`cadPreview`（预览/文件树）与 `cadAgent`（读取/修改）独立门控；新增 CAD 相关路由/工具/白名单改动必须默认关且由 `scripts/CAD解析测试.mjs` 的基线反例断言覆盖（flag 关=与基线逐字一致）。

## 坑 6：LibreDWG 的 `dxf2dwg` 会丢实体，只能用于读取

`dwg2dxf`（读 DWG）对真实 AutoCAD 文件可用；反向 `dxf2dwg` 对缺少 `TABLE/ENDTAB` 包裹的 DXF 会打印 `ERROR` 但**退出码仍为 0**，产出的 DWG 图层在、实体全丢（实测块参照还缺 `BLOCK_CONTROL`）。因此：
- 读取入口（`detectConverter`）允许 ODA / LibreDWG，优先 ODA（兼容性），回退 LibreDWG。
- 写回入口（`resolveOdaConverter`）只认 ODA；LibreDWG 不参与 DWG 写回，否则会静默产出空图纸且无报错。

## 坑 7：ODA File Converter 必须整套目录分发，且可免管理员解包

ODA 依赖同目录 DLL 与 `platforms/`（Qt 插件）等 50+ 文件，单独拷 exe 启动即失败。无管理员权限时可用 MSI 管理安装解包：
`msiexec /a <ODAFileConverter.msi> /qn TARGETDIR=<目标目录>`（实测 exit=0 且可直接运行，批量转换 22KB DWG 约 1.1s）。
**约定**：便携包统一放 `bin/oda`（已被 `.gitignore` 的 `bin/` 忽略，不入库）；探测只认该目录下的 `ODAFileConverter.exe`。

## 坑 8：ODA 按 DXF 声明的版本/代码页解码，不是一律 UTF-8

ODA 读 DXF 时依据 `$ACADVER` / `$DWGCODEPAGE`：AC1032（2018）按 UTF-8，中文可正常往返；而缺少 `$ACADVER` 的手工 UTF-8 DXF 会被按本地代码页（GBK）解释成乱码（`金义东线` → `閲戜箟涓滅嚎`）。
**约定**：涉及 ODA 回转的自动化测试用 ASCII 片段（如 `K12+300`）断言写回生效，中文往返只在 `$ACADVER ≥ AC1021` 的样例上验证；旧版 DXF 的中文写回暂不承诺。
