# 开发规范补遗 · 本轮新增的坑与约定

> 只记「下一轮还会踩」的坑。通用规范见 AGENT.MD 与 docs/2026-10-20-项目文件管理与测试验收规则.md。

## 坑 1：DXF 的 LAYER 记录是连续的，收口必须发生在「下一条开始前」

DXF 的 `0/LAYER` 记录之间**没有显式结束标记**（不像 ENDTAB）。逐对遍历时若在「遇到新 LAYER」分支里直接 `rec = []`，会把上一条未推送的记录覆盖丢弃——只有一条图层时永远发现不了，两条以上就丢首条。正确写法：新记录分支先 `pushLayer(rec)` 再清空；ENDSEC 兜底再收一次。
**推广**：任何「连续同类型记录」的流式解析，状态重置前必须先收口上一条。

## 坑 2：块（BLOCK）内实体不能计入顶层实体统计

块定义里的实体（如树池圆）会被实体遍历器顺带解析。若计数器放在共用收集函数里，块内实体会让顶层统计虚高、 CadViewer 图层数对不上。约定：收集函数带独立的 `counts` 参数，仅顶层 ENTITIES 节传入；块内实体只进 `blocks[].entities`。

## 坑 3：Node ESM 模块缓存使同进程无法验证 flag 关闭场景

`运行开关.mjs` 在模块加载时一次性解析 env 并冻结快照。测试里先以 `OAW_CAD_AGENT=1` import 过 task.mjs 后，即使改回 env、换 query 参数重新 import task.mjs，其依赖的 运行开关.mjs 仍是**缓存的旧实例**（query 只 bust 直接导入的模块，不传递到依赖树）。
**约定**：验证 flag 关闭基线用**子进程**（`execFile(process.execPath, ["--input-type=module","-e",script], { env: 不带 flag })`），不要在同一进程内反复 import。

## 坑 4：中文 AutoCAD 出的 DXF 多为 GBK 编码

utf8 直读会出现 U+FFFD 替换符。约定：CAD 文本入口统一走 `decodeDxfText`（utf8 优先、检测到替换符回退 GBK、二进制 DXF 哨兵头显式拒绝）；任何新增 CAD 读写路径不得直接 `fs.readFileSync(path, "utf8")`。

## 约定 5：CAD 落盘必须走统一写入通道

cad_edit 的执行器只做纯变换（`prepareCadEdit` 返回 content 不写盘），落盘由 agent 层 `requireToolApproval` + `writeWorkspaceFile` 完成——与 review_copy 同构，保证 run 备份/写入清单/审批事件不旁路。后续任何 CAD 写入类工具照此模式。

## 约定 6：CAD 新能力一律过双开关

`cadPreview`（预览/文件树）与 `cadAgent`（读取/修改）独立门控；新增 CAD 相关路由/工具/白名单改动必须默认关且由 `scripts/CAD解析测试.mjs` 的基线反例断言覆盖（flag 关=与基线逐字一致）。
