# 决策记录 · CAD 预览与 Agent 读写

> 只记录「定了的事」，不记录讨论过程。编号分配后不复用。

## D-01 DWG 支持方式：外部转换工具（非 npm 依赖）+ 自动降级

- **背景**：DWG 是闭源二进制格式，纯 JS 无法解析；项目硬约束「零新增 npm 依赖」。
- **决策**：DXF 用纯 JS 解析（主链路，无任何外部依赖）；DWG 经外部转换工具（ODA File Converter 优先 / LibreDWG dwg2dxf / `OAW_DWG_CONVERTER` 环境变量显式指定）转 DXF 后复用 DXF 链路；未装转换器时**自动降级**——预览/读取返回安装指引、修改另存 `-修改.dxf`，不阻塞 DXF。
- **后果**：DWG 完整体验依赖用户机器装转换器（本机未装）；好处是仓库零污染、DXF 永远可用。
- **日期**：2026-10-21（用户裁决豁免「外部工具非 npm 依赖」）
- **补充（2026-11-02，DWG 启用）**：改为「项目内置便携包优先」——`bin/oda`（ODA File Converter，读取优先、兼容性最好）与 `bin/libredwg`（LibreDWG `dwg2dxf`，读取回退）；两者均在 `.gitignore` 的 `bin/` 下、不入库，放入即生效。DWG 写回改用独立的 `resolveOdaConverter()`：LibreDWG 的 `dxf2dwg` 对块表兼容性差、会丢实体，故只用于读取，不用于写回。

## D-02 修改实现方式：组码对级最小手术，不重建 DXF

- **背景**：从解析对象重新序列化 DXF 会丢失未理解的结构（自定义节、扩展数据、未知实体细节），风险高。
- **决策**：`CAD修改.mjs` 在组码对序列上做记录级替换/删除/追加，未理解的记录原样保留；修改为纯函数（`prepareCadEdit` 返回内容不落盘），落盘统一走 `writeWorkspaceFile`（run 备份/写入清单/审批事件与 review_copy 同构）。
- **后果**：修改兼容性最大化；代价是无法修改未建模的实体属性（白名单限定 5 种操作）。
- **日期**：2026-10-21

## D-03 白名单操作边界（v1）

- **决策**：cad_edit 仅支持 replace_text / rename_layer / move_entities / delete_layer_entities / add_entity(LINE/CIRCLE/TEXT)；move/delete 仅作用于顶层实体（块内实体影响所有实例，属危险操作，不开放）；块定义级修改、标注样式、SPLINE 等后续迭代。
- **日期**：2026-10-21

## D-04 预览不做 ACI 颜色映射（v1 取舍）

- **决策**：实体统一用主题描边色（`--oaw-cad-ink`，暗/亮双值），图层区分靠显隐面板；ACI 256 色表映射列入下一步候选。
- **理由**：颜色表是大静态数据且与主题系统有冲突面；v1 先保证几何正确性。
- **日期**：2026-10-21

## D-05 cad_dwg 能力计划不做同步探测

- **决策**：`planTaskCapabilities` 保持同步函数，cad_dwg 条目恒 `planned`，实际可用性以 cad_read/cad_edit 执行时返回为准；不在计划期 spawn 转换器探测（避免每轮任务额外子进程）。
- **日期**：2026-10-21

## D-06 测试形态：永久守护测试替代「临时- 脚本」

- **背景**：原计划解析单测用 `临时-` 前缀（当次会话删）；但用户要求「有反例逻辑的地方，同步写测试」。
- **决策**：采用项目既有守护测试形态（同 `预览懒加载测试.mjs`），永久保留 `scripts/CAD解析测试.mjs` 并注册 `npm run test:cad`；后续回归与重构依赖它。
- **日期**：2026-10-21
