# 功能验证测试规范

> 状态：生效　版本：1.1　基线：v0.11.55　更新：2026-10-26
> 依据：[AGENTS.md](../../AGENTS.md)、[架构规范](架构规范.md)。目标：每项改动都有可复现的证据，而不是“看起来没问题”。

## 1. 原则

- **先能失败，再谈通过**：新增测试必须在修复前能复现问题，修复后通过。
- **默认确定性**：不依赖真实模型、外网、用户文件、系统时间；必须依赖时单独标 `:live`。
- **断言行为，不断言实现**：优先测输入输出、契约、状态迁移；源码接线断言只用于无法运行时验证的接线事实。
- **隔离与可清理**：临时目录、临时端口、临时工作区；结束后清理，不污染真实工作区。
- **证据可复现**：交付时给出命令、环境、结果；未运行的测试如实说明。

## 2. 测试分层

| 层 | 内容 | 入口 | 是否进 CI |
|---|---|---|---|
| L0 基础门禁 | server 语法、前端构建、API 冒烟 | `npm run verify` | 是（构建 + 冒烟） |
| L1 源码/契约 | 纯函数、事件 schema、能力计划、工具白名单、路由接线 | `scripts/*测试.mjs`、`npm run test:<名>` | 关键子集 |
| L2 接口/端到端 | 启动真实服务（临时端口），走 HTTP/SSE，临时工作区 | `scripts/*测试.mjs` | 关键子集 |
| L3 真实集成 | 真实模型、真实浏览器、高德/外网、用户样本 | `test:*:live` 或手动 | 否 |
| L4 人工验收 | 双主题、窄屏、动效、无障碍、文档渲染 | 验收清单 + 截图 | 否 |
| L5 性能/预算 | 首字延迟、流预算、运行预算、地图性能 | `test:first-token-latency`、`test:perf-budget` 等 | 按需 |

`npm run verify` 当前包含：

1. `node --check` 检查 `server/` 全部 `.mjs`；
2. `npm run build` 构建前端；
3. 在临时端口启动服务，跑工作区写入、能力路由、模式边界、事件 Store、主要 API 冒烟。

## 3. 何时必须写测试

| 改动 | 最低测试要求 |
|---|---|
| 新功能 | 至少 1 条行为测试 + 能力/接线测试；涉及 UI 时补人工验收清单 |
| 缺陷修复 | 1 条能复现原缺陷的回归测试（先红后绿） |
| 事件新增/修改 | `test:event-registry` + `test:event-payload` 或对应 schema 测试 |
| 工具白名单/模式边界 | `test:capability-contract`、`test:domain-guard` 或 `verify` 中的模式断言 |
| API 新增/变更 | 接口冒烟 + 错误结构 + 权限/路径校验 |
| 工作区/产物/回滚 | `test:workspace-isolation`、`test:artifacts`、`test:run-budget` 等相关项 |
| 地图能力 | 对应 `test:map-*`；只读/写入边界与临时层必须覆盖 |
| 纯文档改动 | 不强制单测；必须检查链接、命名、与代码一致性 |
| 重构 | 既有测试全通过；行为不变要有对照证据 |

不确定该写哪条时，先找同目录最近的测试脚本作为模板。

## 4. 脚本命名与注册

- 文件：`scripts/<中文功能名>测试.mjs`，必要时加 `回归`、`契约`、`场景`。
- npm 别名：`test:<英文-kebab>`，在根 `package.json` 的 `scripts` 中注册。
- 真实集成：文件与别名都带 `:live` 语义，如 `test:map-chat:live`，默认不进 CI。
- 测试名与脚本名、npm 别名三者要能互相对应，避免“别名存在但文件找不到”。
- 新测试脚本必须能在仓库根目录直接运行：`node scripts/<名>.mjs`。

## 5. 脚本结构

```js
#!/usr/bin/env node
/**
 * <功能>测试
 * 覆盖：<行为 1> / <行为 2> / <边界>
 * 用法：node scripts/<功能>测试.mjs
 * 退出码：0 通过，1 有失败
 */
import assert from "node:assert/strict";

let failed = 0;
function test(name, fn) {
  try {
    fn();
    console.log(`  ✓ ${name}`);
  } catch (error) {
    failed = 1;
    console.error(`  ✗ ${name}: ${error.message}`);
  }
}

test("正常输入返回预期结果", () => {
  assert.equal(检查坐标范围([{ 经度: 120, 纬度: 30 }]).ok, true);
});

test("越界输入被阻断并给出事件类型", () => {
  const result = 检查坐标范围([{ 经度: 140, 纬度: 30 }]);
  assert.equal(result.ok, false);
  assert.equal(result.事件类型, "geo_out_of_range");
});

process.exitCode = failed ? 1 : 0;
```

异步脚本：

```js
async function main() {
  // 启动临时服务、跑接口、清理
}

main()
  .catch((error) => {
    failed = 1;
    console.error(`  ✗ 测试执行异常: ${error.stack || error.message}`);
  })
  .finally(() => {
    process.exitCode = failed ? 1 : 0;
  });
```

要求：

- 使用 `node:assert/strict`；不用自定义“差不多相等”。
- 每个 `test` 只验证一个行为；失败信息包含期望与实际。
- 默认聚合所有失败后统一退出，不因第一条失败中断后续覆盖。
- 临时资源在 `finally` 清理；服务进程必须 `kill`/`close`。
- 输出使用 `✓` / `✗`，便于 `CI运行测试.mjs` 提取失败注解。
- 不在测试中写真实用户工作区、真实配置目录或真实密钥。

## 6. 确定性与隔离

- 临时目录用 `fs.mkdtempSync`/`mkdtemp`；测试结束删除。
- 服务端口用临时端口或固定测试端口（如 `3199`），启动前确认可绑定。
- 时间相关逻辑注入固定时间或放宽为范围断言；禁止 `sleep` 猜时序。
- 事件/文件顺序不敏感；需要顺序时显式排序后断言。
- 网络默认禁用；沙箱禁止回环时，冒烟测试应显式跳过并说明，而不是伪造通过。
- 真实模型调用默认禁止；需要时放 `:live`，并由人工触发。
- 测试之间不共享可变全局状态；必须共享时在每个用例前重置。

## 7. 断言质量

- 契约测试断言**结构与不变量**：必填字段、类型、枚举、版本、事件登记、白名单一致性。
- 行为测试断言**用户可观察结果**：返回值、文件变化、事件序列、HTTP 状态、产物状态。
- 边界测试至少覆盖：空值、最小/最大值、越界、重复、并发、取消、超时。
- 安全测试覆盖：路径穿越、密钥脱敏、审批拒绝、外部输入不可信。
- 源码接线断言只在“运行时难以触发”时使用，并注明原因；不得用它代替真实行为验证。
- 断言失败信息要能直接定位：

```js
assert.equal(result.ok, false, `越界坐标应被阻断，实际：${JSON.stringify(result)}`);
```

## 8. CI 门禁

- CI 入口：`.github/workflows/ci.yml`，push `main` 与 PR 触发。
- 包装器：`node scripts/CI运行测试.mjs <测试脚本名>`，失败时把 `✗` 行转成 GitHub 注解。
- 当前 23 步关键回归，**一步失败即停**：执行轨迹、事件注册表、任务结论、成果可信度、动效、主任务流、对话流、AVA 状态可信、AVA 队列、AVA 草稿、AVA 历史分页、AVA 消息版本、AVA 长期目标、AVA 链接页签、长连接、地图五套、工作区隔离、供应商目录、Review 修复。
- 新增 CI 步骤的条件：属于高频回归或不可回滚契约；能在无外网/无真实模型下稳定运行；单步时长可控。
- 不允许通过 `--no-verify`、跳过测试、放宽断言来让 CI 变绿。
- 本地提交前至少跑：目标测试 + `npm run verify`；触及关键链路时跑 CI 同款列表。

## 9. 真实集成（`:live`）与人工验收

`:live` 测试需要真实模型、浏览器、外网或凭据，必须：

- 在脚本头注释写明前置条件、环境变量、可能副作用；
- 默认不进入 CI，不阻塞普通提交；
- 结果记录环境、模型、时间、样本；不提交密钥与用户数据；
- 失败时区分“产品缺陷”与“环境不可用”，不得混为一谈。

人工验收至少覆盖：

- [ ] 暗/亮主题、窄屏、键盘可达、动效降级；
- [ ] 文档打开/预览/批注定位/保存后刷新；
- [ ] 对话流：思考、工具卡片、产物卡片、终态颜色、取消/恢复；压缩中禁发、停止后保留队列回执、发送/停止三态；
- [ ] 地图：图层显隐、属性表、临时层提示、保存/清理；
- [ ] 工作区切换、会话切换、长连接重连不卡死；
- [ ] 错误提示可理解，且不泄露内部路径/密钥。

## 10. 验收与证据格式

功能完成时，交付总结必须包含：

```markdown
### 验证
- 命令：`npm run test:event-registry`
- 结果：通过（12/12）
- 命令：`npm run verify`
- 结果：通过（语法 / 构建 / 冒烟）
- 人工验收：暗/亮主题、窄屏已检查（截图/说明）
- 未验证：真实模型调用（需凭据，未运行）
```

要求：

- 写清命令与结果，不只写“测试通过”。
- 失败但已修复的，写“修复前失败断言 + 修复后结果”。
- 未运行的项目必须列出原因与风险，不得省略。
- 性能数字必须给环境与样本，不得只给单次结果。
- 截图/日志放 `docs/audits/` 或本地 `.oaw/`，不提交用户数据。

## 11. 缺陷修复协议

1. **复现**：给出最小输入、命令、实际结果、期望结果。
2. **定位**：写清根因（文件/函数/条件），不要只写“已修复”。
3. **回归测试**：新增或强化能复现的测试；修复前确认它失败。
4. **修复**：最小改动，不夹带重构。
5. **验证**：目标测试 + `npm run verify` + 受影响关键链路。
6. **记录**：`变更日志.md` 的 Fixed，说明根因与回归测试名。

## 13. 反模式（禁止）

- 没有失败路径的“全绿测试”（只断言函数存在/字符串包含）。
- 测试直接读真实用户工作区、真实 `.oaw` 或真实配置。
- 用 `sleep` 等待异步完成；用随机数据导致不可复现。
- 在默认测试里调用真实模型/外网/付费接口。
- 一条测试覆盖十个行为，失败后无法定位。
- 为了让旧断言通过而修改期望值，而不确认产品行为是否正确。
- 只跑构建不跑契约测试，就宣称“功能已验证”。
- 测试失败时跳过或标记 flaky 而不定位根因。
