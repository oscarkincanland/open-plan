## 2. 同一份信息的多通道矩阵

> 读法：一行 = 一份信息，一格 = 哪条通道在渲染它。**只要同一行出现 ≥2 个 ✓，改渲染就必须同时处理这些通道**，否则会出现"改了但没变"或"新老界面同屏"。

| 信息 | C1 | C2 | C3 | C4 | C5 | C6 | C7 |
|---|---|---|---|---|---|---|---|
| 思考正文 | ✓ | ✓ | ✓ | — | — | — | ✓ |
| 工具调用（名称/参数/结果） | ✓ | ✓ | ✓ | ✓ | — | — | ✓ |
| 阶段小结 | ✓ | ✓（折叠内） | ✓（折叠内） | — | — | — | ✓ |
| 最终答复 | — | ✓（折叠外） | — | — | ✓ | — | ✓ |
| 未决 ask / 审批 | ✓（折叠外） | ✓（折叠外） | ✓ | ✓ | — | — | ✓ |
| 运行结论 / 用量摘要 | — | 折叠头 | 折叠头 | — | ✓ | ✓ | — |
| 系统提示聚合（压缩/文件变更） | — | ✓（折叠内） | ✓ | ✓ | — | — | ✓ |

## 3. 删除/收敛顺序（建议）

1. **C4 旧执行流**：v3 下已关闭；下一步从基线路径也删掉，并把 `messageExecutionFlow` 的计算一并移除（它只在 C4 里用）。
2. **C5 结论卡**：v3 下已关闭且终稿已由 C2 承担；基线路径待产品确认后删。
3. **C6 `RunSummary`**：只在历史 `system` 消息与 Review 轮出现，等历史数据迁移后收敛。
4. **C3 基线折叠**：等 v3 开关**默认打开**并观察一个版本后删除，届时 `transcriptV3` 开关本身也一并移除。

> 目标终态：**C1 + C2（Work/Chat 运行轮）+ C7（无 runId 的纯问答/Review）**，即从 7 条收敛到 3 条。

## 4. 变更本表的规矩

- 新增/删除任一通道，必须同时更新本表与《会话流前端规范》§2；
- 新增通道若与既有通道覆盖信息重叠，必须在表 §2 矩阵里显式写出重叠项，并在计划里说明收敛计划；
- 改动任一通道的渲染分支后，必须跑 `npm run test:ui-smoke`（打开有消息会话的运行时冒烟），见《运行时验收与门禁规范》。
