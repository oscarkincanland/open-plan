# 代码规范

> 状态：生效　版本：1.1　基线：v0.11.55　更新：2026-10-26
> 依据：[AGENTS.md](../../AGENTS.md)、[架构规范](架构规范.md)。本文约束新增与修改代码；既有代码不强制批量整改。

## 1. 原则

- **简单优先**：用最小代码解决问题，不做投机性抽象。
- **最小侵入**：只改必须改的；匹配所在文件的既有风格。
- **可验证**：优先写纯函数、显式输入输出、可被脚本直接导入。
- **单一事实来源**：同一规则只写一处，其余引用。
- **不做顺手重构**：格式化、重命名、目录搬迁必须独立成提交并经确认。

## 2. 文件与目录命名

- 新增文件必须中文命名；代码文件按语言惯例保留扩展名（`.mjs` / `.jsx` / `.css`）。
- 目录名优先中文，如 `server/工作流/`、`client/src/components/`。
- 既有英文文件（`index.mjs`、`agent.mjs`、`api.js`、`ChatPanel.jsx`）保持原名，不因规范而重命名。
- 测试脚本：`scripts/<中文功能名>测试.mjs`；npm 别名可用英文 kebab-case。
- 一个文件只承担一个主要职责；组件文件名用 PascalCase 中文，如 `工作产物面板.jsx`。
- 禁止 `utils.mjs`、`helpers.mjs`、`common.mjs` 这类无边界模块；需要共享时按领域拆。

## 3. 模块与导入

- 使用 ESM：`import` / `export`；Node 内置模块带 `node:` 前缀（`node:fs`、`node:path`）。
- 服务端模块使用**具名导出**；React 组件使用默认导出。
- 导入顺序：Node 内置 → 第三方 → 项目模块；组间空一行。
- 禁止在模块顶层执行有副作用的业务逻辑（启动、写盘、网络）；副作用只放在入口或显式 `init`。
- 避免循环依赖；需要互相调用时，把共享契约下沉或由 `index.mjs` 注入。
- 不在 L2 模块中 import `server/index.mjs`；不在前端 import `server/`。
- Pi SDK 直接 import 仅限架构规范 §3 列出的三个文件。

```js
import fs from "node:fs";
import path from "node:path";
import express from "express";
import { 检查坐标范围 } from "./工作流校验.mjs";
```

## 4. 格式

仓库未配置 ESLint/Prettier，以“与所在文件一致”为准：

- 缩进 2 空格；不使用 Tab。
- 字符串优先双引号；模板字符串用于插值。
- 语句结尾加分号。
- 对象/数组多行时保留尾逗号（与现有文件一致）。
- 单行建议 ≤ 120 字符；长表达式换行并按逻辑分组。
- 不提交纯格式化 diff；不因个人偏好重排既有代码。

## 5. 注释与文档

- 注释用中文，解释“为什么”而不是“做了什么”。
- 导出函数/复杂契约用 JSDoc 标注参数、返回、错误码；内部简单函数不必强行加注释。
- 文件头注释用于说明模块职责、契约来源、关键约束，不写个人署名与日期流水账。
- 不保留被注释掉的旧代码；历史交给 Git。
- `TODO` 必须写清触发条件或关联计划，如 `// TODO(计划 2026-10-18-001)：...`。
- 注释中引用规范时写清章节，如 `// 依据 AGENTS.md §6 坐标硬约束`。

## 6. 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 文件/目录 | 中文 + 连字符，代码扩展名按语言 | `写入协调.mjs`、`工作产物面板.jsx` |
| React 组件 | PascalCase，可用中文 | `工作产物面板`、`MapViewer` |
| 函数/变量 | camelCase；领域概念可用中文 | `检查坐标范围`、`runId`、`pendingApprovals` |
| 常量 | UPPER_SNAKE_CASE | `MAX_BLOB_BYTES`、`TASK_MODES` |
| 事件类型 | snake_case 英文 | `run_finished`、`tool_approval_request` |
| API 路由 | 英文小写 + 连字符 | `/api/agent/runtime` |
| 布尔值 | `is/has/can/should` 前缀 | `isAbortLikeError`、`hasWriteAccess` |
| 回调 | `onXxx` / `handleXxx` | `onClose`、`handleSubmit` |

- 中文标识符用于领域语义；技术概念、第三方 API、事件字段保持英文，避免半中半英的拼接名。
- 不用拼音缩写（`gg`、`tj`）；不用无意义编号（`data2`、`temp`）。
- 同一概念全仓库同名：Run 不叫 Task，产物不叫文件，工作区不叫目录。

## 7. 错误处理与日志

- 可预期失败返回结构化结果（`{ ok:false, code, message, details }`）或抛带 `code` 的 `Error`；不要返回 `null` 表示多种错误。
- HTTP 层统一映射：参数错误 400、未找到 404、冲突 409、超限 413/429、服务器错误 500；错误体至少含 `error`。
- 在系统边界（HTTP、文件、外部命令、模型）做校验与归一化；内部调用信任契约，不重复防御。
- 捕获后不得静默吞掉；要么恢复、要么记录并上抛。清理逻辑放 `finally`。
- 日志用中文短句 + 关键字段；禁止输出密钥、Token、完整文档内容、用户隐私。
- 外部命令错误要保留退出码与 stderr 摘要，但需截断与脱敏。
- 用户可见错误给“下一步”，不要只抛堆栈。

```js
try {
  await 写入工作区文件(target, content);
} catch (error) {
  throw Object.assign(new Error("工作区写入失败"), { code: "workspace_write_failed", cause: error });
}
```

## 8. 异步、IO 与并发

- 使用 `async/await`；禁止浮空 Promise（未 `await`、未 `catch`、未显式后台托管）。
- 所有外部调用设置超时或 `AbortSignal`；长任务必须有取消/收尾路径。
- 并发必须有上限；批量文件/模型/网络操作使用队列或信号量，禁止无界 `Promise.all`。
- 关键状态写入使用 `server/持久化工具.mjs` 的原子写；工作区写入使用 `server/写入协调.mjs` 的锁。
- 热路径避免同步 IO；启动/一次性脚本可以用同步 API。
- 不用 `setTimeout` 猜时序；等待条件用事件、轮询上限或显式状态机。
- 定时器/监听器/SSE 必须在卸载或结束时清理。

## 9. Node / Express / API

- 路由只做：解析参数 → 校验 → 调领域函数 → 映射响应/错误；不写业务细节。
- 所有文件路径必须经 `server/workspace.mjs` 解析与校验；禁止字符串拼接绕过工作区边界。
- 请求体限制大小；上传校验扩展名/MIME/大小；文件名使用 `safeName`。
- 不在响应中回显密钥、内部绝对路径、完整环境变量；诊断接口必须脱敏。
- 长连接（SSE）统一经 `server/流连接.mjs`，包含配额、去重、退避与关闭；不要在路由里裸写 `res.write`。
- 新增 API 必须同步 `client/src/api.js`；无客户端消费的内部接口要在注释中说明。
- 对外契约变更先加版本/兼容层，再迁移消费方；不得直接改字段含义。

## 10. 事件与 Run

- 任何新事件类型必须先登记 `server/事件注册表.mjs`，声明 `lifecycle`、`persist`、`schema`。
- `persist: true` 必须同时 `lifecycle: true`；高频事件（token、进度）默认不落盘。
- 事件 payload 使用稳定字段名；可空字段不要放进 schema 的 `required`。
- 事件发送统一走既有 emit/append 通道；禁止在业务模块直接写事件文件。
- Run 的完成语义以服务端终态为准；不得用前端文案替代 `run_finished`。
- 新增/修改事件必须跑 `test:event-registry` 与 `test:event-payload`（或对应契约测试）。

## 11. React / 前端

- 函数组件 + Hooks；不使用 class 组件。
- Hooks 必须在组件顶层、早退 `return` 之前；禁止条件调用 Hooks。
- `useEffect` 依赖完整；订阅、定时器、EventSource、ResizeObserver 必须在 cleanup 释放。
- 列表 `key` 使用稳定业务 ID，不用数组下标。
- 重型库/面板用 `React.lazy` + `Suspense`；新增大依赖需说明体积影响。
- 组件内禁止直接 `fetch`；统一 `api.js`。SSE 统一 `长连接预算.js`。
- 事件到 UI 的转换放纯投影模块；组件只消费视图模型。
- 样式用 CSS 变量/设计令牌；不写死颜色、圆角、阴影、间距。
- 图标用 `Icon.jsx`；按钮/输入/弹窗遵循 `DESIGN.md` 的组件交互规范。
- 错误提示用 `Feedback.jsx`；关键操作需确认与可撤销/可回滚。
- 无障碍：可键盘操作、焦点可见、`aria-*` 正确、窄屏有降级。
- 不在渲染期做重计算/大对象复制；用 `useMemo` 前先确认确有性能问题。

## 12. CSS / 设计令牌

- 颜色、字体、间距、圆角、阴影、动效时长必须来自 `DESIGN.md` 定义的三层令牌。
- 新增颜色先加到基础色阶，再映射语义令牌，最后组件变量；禁止在组件里新增十六进制色值。
- 暗/亮主题都必须验证；不得只改一个主题。
- 选择器优先组件级类名，避免深层后代选择器与全局标签选择器。
- 动效遵循 `data-reduce-motion`；持续动画必须进白名单，不能无限新增。
- 新增样式尽量追加，不覆盖既有选择器；确需覆盖时写清作用域。

## 13. 安全

- 禁止 `eval`、`new Function`、动态 `require` 执行外部输入。
- 执行命令使用 `spawn`/`execFile` + 参数数组；禁止把用户输入拼进 shell 字符串。
- 防路径穿越：解析后确认仍在允许根目录内；外部根目录必须显式登记。
- 渲染 HTML/Markdown 时按既有清洗链路；外部网页内容视为不可信。
- 审批策略是最后一道闸门：不得在工具实现里绕过 `审批策略.mjs`。
- 新增日志/诊断字段前先判断是否含敏感信息；默认不输出。
- 测试与文档中也不放真实密钥；用明显占位符。

## 14. 领域数据

- 坐标范围、记录数校验、产物根目录等硬约束以 `AGENTS.md` §6 与 `server/工作流校验.mjs` 为准。
- 导入数据先校验结构、坐标系、记录数，再进入分析；失败要给出可定位原因。
- 演示数据在文件名、接口字段、UI 文案中都要标注，禁止冒充真实数据。
- 地图写入区分临时层/正式层；删除/覆盖正式图层必须经审批。
- 统计口径、单位、时间范围必须显式写在结果中。

## 15. 变更纪律与审查清单

提交前自检：

- [ ] 改动是否只覆盖本次需求？有没有顺手重构/格式化？
- [ ] 新文件是否中文命名？是否放在正确的层？
- [ ] 是否新增了第二份事实来源（白名单、事件清单、开关、路径）？
- [ ] 错误路径、取消路径、空数据路径是否处理？
- [ ] 是否写入工作区而非项目目录？是否加锁/原子写？
- [ ] 是否泄露密钥、用户数据、绝对路径？
- [ ] 事件是否登记？schema 是否通过？
- [ ] 是否补了测试与 `变更日志.md`？
- [ ] 是否运行了目标测试与 `npm run verify`？

代码审查优先看：契约一致性、错误与取消路径、并发写入、权限边界、可回滚性、测试是否真的能失败。
