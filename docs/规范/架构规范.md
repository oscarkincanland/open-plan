# 架构规范

> 状态：生效　版本：1.1　基线：v0.11.55　更新：2026-10-26
> 依据：[AGENTS.md](../../AGENTS.md)、[产品需求文档](../../REQUIREMENTS.md)、[设计规范](../../DESIGN.md)、[决策记录](../决策记录/决策记录索引.md)。本文约束“代码放在哪里、依赖指向哪里、契约由谁定义”。

## 1. 架构总则

项目采用**模块化单体（modular monolith）+ 本地优先**：

- 一个仓库、一个 Express 服务、一个 React SPA、一个 Pi 内核进程内实例。
- 单机默认部署，服务只监听 `127.0.0.1`；不引入微服务、消息队列、数据库。
- 自研的是控制平面（Run / 事件 / 产物 / 工作区 / 权限 / 知识库 / 地图 / Office），Pi 只是内核。
- 任何改变上述形态的提案必须先写决策记录，再动代码。

架构目标按优先级排序：

1. **可解释**：每一步有事件、有产物、有错误码，用户能看到发生了什么。
2. **可回滚**：运行时开关默认关，产物可暂存/回滚，变更可降级。
3. **可测试**：契约与纯函数可被脚本直接导入断言。
4. **单一事实来源**：事件、任务、工具白名单、开关、工作区路径各自只有一个定义处。

## 2. 分层与职责

```text
L4 工作台 UI        client/src/（React SPA）
        │  HTTP / SSE（只经 client/src/api.js）
L3 接口与传输       server/index.mjs（路由组合根）、事件协议、事件存储、流连接
        │
L2 领域服务         server/*.mjs（Office / 地图 / 知识库 / Run / 工作流 / 产物 / 记忆…）
        │
L1 内核适配         server/agent.mjs、Pi运行时管理.mjs、项目信任.mjs、pi-extensions/
        │
L0 智能体内核       @earendil-works/pi-coding-agent（node_modules，不改）
        │
L5 数据与工作区     office-workspace/、.oaw/、.sessions/、用户配置目录
```

| 层 | 目录/文件 | 职责 | 允许依赖 |
|---|---|---|---|
| L4 | `client/src/` | 界面、交互、展示投影、SSE 消费 | 只经 HTTP/SSE；不得 import `server/` |
| L3 | `server/index.mjs`、`事件协议.mjs`、`事件存储.mjs`、`流连接.mjs` | 路由注册、依赖装配、SSE 广播、事件持久化 | L2、L1 |
| L2 | `server/` 其余领域模块 | 业务规则、文件/数据操作、工作流、审批、产物 | L1、L0 的类型（仅经 L1） |
| L1 | `agent.mjs`、`Pi运行时管理.mjs`、`项目信任.mjs`、`pi-extensions/` | Pi 会话、模型运行时、事件转译、扩展 | L0 |
| L5 | 工作区与运行时目录 | 用户文档、地图项目、Run/事件日志 | 不反向依赖代码 |

## 3. 依赖规则

1. **只能向下依赖**：L4 → L3 → L2 → L1 → L0；禁止反向 import。
2. **`server/index.mjs` 是组合根**：只做路由注册、参数校验、依赖注入和 HTTP 错误映射；业务逻辑必须落在 L2 模块。
3. **`server/agent.mjs` 是内核适配层**：负责 Pi 会话与事件转译；不得继续堆叠知识库/地图/Office 等领域规则。
4. **领域模块之间不互相 import `index.mjs`**；需要跨域协作时，由 `index.mjs` 注入依赖，或通过事件/纯函数接口。
5. **Pi SDK 直接 import 仅限** `server/agent.mjs`、`server/Pi运行时管理.mjs`、`server/项目信任.mjs`；新增导入点必须在 PR 说明理由并更新本节。
6. **前端纯投影模块**（`运行展示投影.js`、`事件展示.js`、`对象聚合.js`、`运行轨迹.js`）不得访问 DOM、不得发请求、不得读全局状态；输入事件，输出视图模型。
7. **脚本可以 import `server/` 模块做测试**；`server/` 不得 import `scripts/`。
8. **禁止循环依赖**。出现双向依赖时，把共享契约下沉到独立模块，或改为 `index.mjs` 注入（参考 `绑定执行依赖`）。
9. **运行时优化开关统一从 `server/运行开关.mjs` 读取**；业务模块禁止自行解析 `OAW_*` 特性开关。存储目录、端口、超时上限等基础设施参数允许在对应模块解析（如 `runs.mjs`、`事件存储.mjs`、`workspace.mjs`、`Pi配置管理.mjs`），但不得用于功能分支。
10. **模块体量**：新增 L2 模块建议 ≤ 600 行，新增组件建议 ≤ 600 行，单函数建议 ≤ 80 行；超过时按职责拆分。既有超大文件只减不增（见 §9）。

## 4. 运行时主链路

```text
浏览器
  │ POST /api/agent/prompt（文本、引用、附件、模式）
  ▼
TaskEnvelope / 能力计划（server/task.mjs）
  │ 模式 → 工具白名单 → 能力声明 → 输出边界
  ▼
准入与审批（审批策略 / 项目信任 / 写入协调）
  │
  ▼
Pi 会话（server/agent.mjs）
  │ Pi 原生事件
  ▼
事件转译与规范化（server/事件规范化.mjs）
  │ 统一信封：protocolVersion / eventId / sequence / runId / type / payload
  ▼
事件注册表（server/事件注册表.mjs）——登记 lifecycle / persist / schema
  │
  ├─ 当前会话 SSE（server/流连接.mjs）
  └─ 根级事件存储（server/事件存储.mjs，.oaw/events/事件流.jsonl）
  ▼
前端消费（client/src/长连接预算.js → 运行展示投影.js → ChatPanel）
  │
  ▼
Run 记录与产物（server/runs.mjs、写入协调、产物验证、成果管理）
  │ 暂存 → 校验 → 发布 → 验收/回滚
  ▼
工作区（office-workspace/）与 .oaw/runs/
```

各阶段的所有权：

| 阶段 | 唯一负责人 | 不允许 |
|---|---|---|
| 任务语义/模式 | `server/task.mjs` | 前端或 agent 自行推断模式边界 |
| 工具白名单 | `server/task.mjs`（`run_subagent` 由会话按 `hasSubagent` 动态注入） | 在 agent.mjs 里另写一份静态白名单 |
| 事件类型/落盘语义 | `server/事件注册表.mjs` | 在业务模块里硬编码事件清单 |
| 事件信封/版本 | `server/事件协议.mjs` | 私自扩展 SSE 字段 |
| Run 生命周期 | `server/runs.mjs` + `server/执行句柄.mjs` | 用前端“完成”文案代替终态 |
| 写入与锁 | `server/写入协调.mjs` | 绕过锁直接写已发布路径 |
| 产物验收 | `server/产物验证.mjs` + `server/成果管理.mjs` | 未校验就标记成功 |
| 运行时开关 | `server/运行开关.mjs` | 业务模块直读 `process.env` |
| 工作区解析 | `server/workspace.mjs` | 拼接字符串绕过路径校验 |

## 5. 契约清单

| 契约 | 定义位置 | 变更要求 |
|---|---|---|
| 产品需求基线 | `REQUIREMENTS.md`（PRD） | 需求编号/范围/验收变化需同步测试与追踪矩阵 |
| 界面与体验基线 | `DESIGN.md` | 视觉/交互/令牌变化需同步设计测试与回滚说明 |
| 任务信封 / 能力计划 | `server/task.mjs` | 新增字段要向后兼容；模式/工具变化必须改测试 |
| 事件注册表 | `server/事件注册表.mjs` | 新事件必须登记；`persist` 必须同时 `lifecycle`；带 schema |
| 事件信封 / SSE 协议 | `server/事件协议.mjs` | 破坏性变更需升 `PROTOCOL_VERSION` + ADR |
| 事件存储 / 回放 | `server/事件存储.mjs` | 归档/游标语义变化要有回放测试 |
| Run 生命周期 | `server/runs.mjs`、`server/执行句柄.mjs` | 终态集合、取消/恢复语义变化需 ADR + 回归 |
| 写入 / 产物 | `server/写入协调.mjs`、`server/产物验证.mjs`、`server/成果管理.mjs` | 路径、锁、回滚语义变化需 ADR |
| 审批策略 | `server/审批策略.mjs` | 自动批准范围变化必须写安全说明与测试 |
| 运行时开关 | `server/运行开关.mjs` | 默认关；基线等价；快照经 `/api/status` 下发 |
| 工作区 | `server/workspace.mjs` | 外部路径、隐藏工作区、信任位变化需测试 |
| 工作流 | `server/工作流注册表.mjs`、`server/工作流校验.mjs`、`server/工作流/` | 依赖/领域硬约束变化必须补契约测试 |
| 记忆 | `server/记忆管理.mjs`、`server/记忆准入.mjs` | 准入规则变化需 ADR + 测试 |
| 模型配置 | `server/Pi配置管理.mjs`、`server/供应商目录.mjs` | 不得回显密钥；一键导入需能力/登录方式校验 |

契约变更的最小动作：更新定义处 → 更新消费方 → 更新测试 → 更新规范/ADR → 在 `变更日志.md` 说明兼容性。

## 6. 前端架构

- `client/src/App.jsx` 是总编排：会话、工作区、模式切换、三栏布局、懒加载入口；不要把所有业务状态塞进 App。
- `ChatPanel.jsx` 负责对话交互；事件到视图的转换优先落在纯投影模块，不在 JSX 里重复解析事件。
- 重型模块必须懒加载：文档预览、地图、知识库、模板库、设置、命令面板等已有 `React.lazy`，新增重库沿用。
- HTTP 统一经 `client/src/api.js`；组件内禁止直接 `fetch`，便于统一错误、Token、超时与埋点。
- SSE 统一经 `client/src/长连接预算.js` 获取连接；禁止组件各自建 EventSource。
- 状态归属：服务端事实（会话、Run、事件、模型）以服务端为准；仅界面偏好（主题、面板宽度、展开状态）用 `persist-ui.js`/localStorage。
- 样式：全局 `styles.css` + CSS 变量；设计令牌与组件交互规范以 `DESIGN.md` 为准。新增颜色/间距先加令牌，禁止散落魔法值。
- 图标统一 `Icon.jsx`；不使用 emoji 充当功能图标。
- 反馈统一 `Feedback.jsx`（`notifyError`/确认框）；关键路径不得用原生 `alert`。
- 组件必须可被错误边界兜底；渲染异常不得白屏。
- 无障碍：键盘可达、焦点可见、窄屏降级；动效遵循 `data-reduce-motion` 与动效档位。
- 图标/文案/交互组件改动，必须检查暗/亮双主题与窄屏。

## 7. 数据与存储

| 数据 | 位置 | 是否入库 | 规则 |
|---|---|---|---|
| 用户文档/生成产物 | `office-workspace/` | 否（`.gitignore`） | 只能经工作区解析与写入协调落盘 |
| 地图项目 | `office-workspace/maps/` | 是（`maps/` 例外） | 瓦片等生成物不入库；演示数据必须标注 |
| Run 记录/事件流/锁 | `.oaw/` | 否 | 只用于审计、恢复、回滚；不提交 |
| 会话 | `.sessions/`、`.规聚会话/` | 否 | 含用户内容，禁止提交 |
| 前端构建 | `client/dist/` | 否 | `npm run build` 生成 |
| 配置/密钥 | 用户配置目录或 `.oaw/` | 否 | 响应/日志必须脱敏 |

写入规则：

- 所有落盘使用 `server/持久化工具.mjs` 的原子写（临时文件 + rename）；禁止直接 `fs.writeFileSync` 写关键状态。
- 同一工作区的写操作必须经 `server/写入协调.mjs` 的写锁；批量工具调用不得并发绕过。
- 事件流按体量归档，单文件不得无限增长；回放游标与归档索引必须一起维护。
- Run 快照有文件数/字节上限；触顶必须标记 `truncated`，不得把“没扫到”报告成“没有变更”。

| 要加什么 | 落点 | 必做 |
|---|---|---|
| 新 Agent 工具 | L2 领域模块实现 + `task.mjs` 白名单 | 能力计划、审批策略、事件登记、工具契约测试 |

| 文件 | 约行数 | 约束 |

## 10. 反模式（禁止）

- 在 `index.mjs` 或 `agent.mjs` 里新增一段“顺手就能跑”的业务逻辑。
- 前端组件直接解析原始 SSE 事件，绕过 `运行展示投影.js`。
- 新增第二份事件清单、工具白名单、模式判断或开关读取。
- 用 `process.env` 直接控制业务分支，绕过 `运行开关.mjs`。
- 组件直接 `fetch`、直接建 `EventSource`、直接写 localStorage 存服务端事实。
- 未加锁直接写工作区，或先发布产物再校验。
- 为了让测试通过而放宽断言/跳过真实错误。
- 为单个页面引入全局状态库、UI 框架或新构建工具。
- 在业务提交里夹带内核升级、目录重命名、全量格式化。

## 11. 必须写决策记录的架构变更

- 更换/新增智能体内核，或修改 Pi SDK。
- 拆分/合并服务、引入微服务、数据库、消息队列、桌面壳。
- 破坏性修改 API/SSE 协议、事件语义、Run 终态、审批模型。
- 新增默认开启的运行时开关，或改变默认工具白名单。
- 改变工作区根、产物发布/回滚模型、长期记忆准入规则。
- 新增跨层依赖（L2 → L4、L1 → L3 等）或打破 §3 的依赖方向。
