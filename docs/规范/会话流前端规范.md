## 1. 目的与范围

本规范约束「一轮 Run」在对话流里的呈现：结构、折叠、层级、字号、颜色、结语来源、历史恢复一致性与动效。

不做的事：

- 不改 SSE 事件协议、Run 存储结构与后端归约（见 `docs/规范/架构规范.md`）；
- 不改 AskBlock / ApprovalBlock 的表单与审批语义；
- 不为「好看」新增动画、渐变、阴影或硬编码色值；
- 纯问答消息（无 `runId`）与 Review 轮次仍走原有渲染路径，不在本规范内。

## 2. 一轮 Run 的结构

按真实输出顺序自上而下：

```
[运行中]  时间流直铺（思考 / 阶段小结 / 工具 / 子代理 / 系统提醒）
[结束后]  折叠头一行 ── 点击展开 ──▶ 时间流
[ask / 审批]                          未决时在折叠体外常驻
本轮总结（结论正文）                   无标签、无框，常显
本轮产物                              产物卡，常显
需行动提示                            仅 blocked / partial / failed / cancelled，常显
```

规则：

- **折叠的是过程，不是答案**（[ADR 0014](../决策记录/0014-会话流折叠过程而不折叠答案与字号收敛.md)）：时间流与系统提示聚合进入折叠体；**结论正文、产物卡、未决 ask/审批、需行动提示一律不折叠**。
- **没有「运行框」**：不出现外边框、背景块、包裹式折叠容器。折叠头只是一行 28px 的按钮。
- **运行中不折叠**：`isTaskLive`（运行 / 排队 / 等待 / 恢复中 / 收尾）时直铺时间流，让用户看到实时进度；结束后默认折叠。
- **失败与取消也默认折叠**：终态由折叠头（状态点 + 文案）表达，可执行动作由折叠体外的「需行动提示」承载。
- 时间流左侧有一条 1px 竖线（`.tl-list`），条目之间 2px 间距，标题行 4px/8px 内边距。
- 运行中的条目靠状态点脉冲表达，不额外加一条总状态横幅。
- 交互条目（`ask` / 审批）未决时始终可见且在折叠体外；已回答 / 已过期 / 已决后被折进事件流，不再常驻（见 §6）。
- 总结与产物卡只在运行结束后出现；运行中只显示时间流。

### 2.1 折叠头规格

| 终态 | 文案 | 状态点 |
|---|---|---|
| `completed` | `已完成 · 用时 9 分 8 秒 · 12 步` | `--success` |
| `blocked` / `partial` | `完成（有风险）· 用时 3 分 · 8 步` | `--warning` |
| `failed` | `失败 · 用时 2 分 4 秒 · 5 步` | `--error` |
| `cancelled` | `已取消 · 用时 40 秒 · 3 步` | `--muted` |

- 步数取 `runTimeline.length`；无时间流时不显示步数，不写「0 步」。
- chevron 用 `<Icon name="chevronRight">` 旋转 90°，**禁止使用 `▸ / ▾ / ↗` 字符**（`scripts/界面一致性守护测试.mjs` 会拦）。
- 展开态**不持久化**：组件内状态，切会话与刷新回到默认折叠。
- 折叠体过渡用 `grid-template-rows: 0fr → 1fr`，时长取 `--dur-base`、缓动 `--ease-out`。
- 折叠态必须 `visibility: hidden`（延迟到过渡结束）：`0fr` 只是视觉收起，内部按钮仍会被 Tab 到。
- 收起时若焦点在折叠体内，必须交回折叠头。

## 3. 字体族

- 全站统一 `OPPO Sans 4.0`（`client/src/assets/fonts/oppo-sans/`，100–700 可变字体，按 `unicode-range` 分片加载），回退 `Segoe UI Variable Text → Segoe UI → system-ui → Microsoft YaHei UI → PingFang SC`。许可证与署名见同目录 `LICENSE` / `NOTICE.md`。
- 会话流内**只用一个字体族**，不用衬线体、不用等宽体做正文（命令、路径、代码块由 `.markdown-body code/pre` 单独处理）。
- 字重只用 400 / 600 两档。OPPO Sans 的 600 是真实字重，不触发浏览器合成加粗；禁止在会话流内使用 700/800。

## 4. 字号与颜色层级

全表只有 **三个字号**：12 / 14 / 16。

| 层级 | 类名 | 字号 | 字重 | 颜色 |
|---|---|---|---|---|
| 正文（结论 / 详细展开 / 文本块 / 时间流动作与对象 / 思考正文） | `.sum-body .markdown-body`、`.flow-markdown`、`.tl-verb`、`.tl-obj`、`.tl-thinking-text` | **14px** | 400 | `--text`（对象摘要用 `--dim`） |
| 正文分节标题 h1 / h2 | `.markdown-body h1`、`.markdown-body h2` | **16px** | 600 | `--text` |
| 正文分节标题 h3–h6 | `.markdown-body h3`..`h6` | **14px** | 600 | `--text` |
| 元信息（折叠头 / 耗时 / 状态） | `.run-fold-head`、`.tl-time`、`.tb-cap` | **12px** | 400 | `--muted` |
| 代码（行内 / 代码块） | `.markdown-body code`、`.markdown-body pre code` | **12px** | 400 | `--text`（底色 `--panel2-bg`） |

约束：

- 字号只允许出现在本表内；新增层级必须先更新本表再改样式。会话流可见文本的字号集合必须 ⊆ {12px, 14px, 16px}。
- **禁止 em / 百分比相对字号**：`h2 { font-size: 1.1em }` 会随宿主字号滚出 13.75px 这类非整数档，是 1.x 出现 9 种字号的直接原因。
- 结论是「一轮的答案」，用**默认正文色 + 正常字重**排版；不得使用强调色、渐变、描边或整段 600 加粗。
- 绿色主色只用于图标、交互与状态点，不用于结论文字，也不用于行内代码。
- 所有颜色取语义令牌（`--text` / `--dim` / `--muted` / `--accent` / `--success` / `--warning` / `--error`），禁止新增硬编码 hex（`test:design-tokens` 会拦截）。
- `--dim` 只承载 12px 次要信息，且对比度必须 ≥ 4.5:1；正文不得使用 `--dim`。

## 5. 结语来源（重要）

一轮的结语按以下优先级取用，**不得反过来**：

1. **模型自己的终稿**（`authoritativeFinalText`，即 `assistant_final` / Run `finalText`）——唯一默认来源；
2. `complete_task.summary` —— 仅在终稿不可用（缺失，或未能在时间流里匹配到对应文本块）时兜底；
3. 两者都没有 → 不渲染总结块，不编造结语。

展示方式（`splitCompletionSummary`）：

- 无标题结构：首段 → 结论；其余段落 → 详细展开。
- 有 `## 结论` 分节：该节首段 → 结论，并从详细展开中移除，避免重复。
- 有 `## 做了什么 / 完成工作 / 工作内容`：该分节丢弃，不再单独成行（2.0 起不渲染「做了什么」行）。
- 终稿已被结论块消费时，时间流里对应的文本块必须隐藏（`finalTextBlockIndex`），同一段文字不得出现两次。
- 渲染时结论与详细展开**合并为一篇连续 Markdown**，不加分节标签、不加 cap。

## 6. 交互条目（ask / 审批）

- 未决（`!answer && !expired` / `!resolved && !decision`）→ 作为 `TimelineRow locked` 常驻，**位于折叠体之外**，头部写「等待你回答 / 等待审批」。
- 已决 / 已过期 → 不常驻，折叠为时间流里的一行事件（保留问题与选择结果，可展开回看）。
- 禁止出现「已回答但仍显示答题卡」的状态。

## 7. 历史恢复一致性

切换会话后，**同一轮必须回到同一形态**（折叠头 + 总结 + 产物），不得退回旧渲染。

- 历史消息保持 JSONL 原顺序，**不按 `createdAt` 全局排序**（缺时间戳的消息会被推到最前，导致结构乱）。
- Run 总结卡用 `mergeRunSummaries()` 按收尾时间锚点插入：
  - 有 `finishedAt` → 插到最后一条不晚于它的消息之后；
  - 未结束 → 插到下一轮 `startedAt` 之前；最后一轮（仍在运行）追加到末尾。
- 总结卡必须排在本轮消息**之后**，`associateRunMessages` 才能向前扫描到本轮 assistant 消息并写入 `runId`；`runId` 缺失即 `timelinePath=false`，会整轮回退旧渲染。
- 折叠展开态不持久化：切回历史会话一律回到默认折叠。
- 回归用例：`scripts/会话流时间线测试.mjs` 的「历史恢复合并」段（运行中 Run 必须保留 `runId`、总结卡不得孤立、消息顺序不得被重排）。

## 8. 动效

- 只允许 `transform` / `opacity` / `grid-template-rows` 过渡；时长取 `--dur-fast/base/slow`，缓动 `--ease-out`。
- 折叠头不得新增无限动画；状态点只用静态语义色。
- 运行中入场动画只作用于 `.tl-list.is-live > *`；历史回放不重播。
- 打字机：正文与「展开后的思考」逐字输出，折叠态思考用既有跑马灯做滚动预览（`.tl-think-preview`）。
- 全部动效纳入统一闸门：`data-reduce-motion="1"` 或 `data-motion-level="off"` 时立即落定，信息不丢（`scripts/动效治理测试.mjs`）。
- 折叠规则必须写在统一动效闸门**之前**，由闸门负责压平。

## 9. 宽度与对齐

- 会话流各块（折叠头 / 时间流 / 总结 / 产物卡 / 行动提示 / 用户气泡）共用 `--msg-content-max`（`min(100%, 720px)`），右缘对齐。
- 不允许单个块自行设置宽度；需要更窄时用内边距，不改列宽。

## 11. 禁止项

- 新增「运行框」：外边框、背景块、包裹式折叠容器。
- 把结论正文、产物卡、未决交互一起折进折叠体。
- 用彩色 / 渐变 / 700 字重 / 整段加粗强调结论。
- 在会话流里引入第四种字号、em 相对字号或第二套字体族。
- 在折叠头使用 `▸ / ▾ / ↗` 字符箭头，或新增无限动画。
- 把 `complete_task.summary` 当默认结语，或把两段相同文字各渲染一次。
- 按时间戳全局排序历史消息，或让总结卡排到本轮消息之前。
