## 2. 全局完成定义（每个功能都要过一遍）

功能算「完成」必须**同时**满足以下 10 条：

- [ ] **验收标准逐条通过**，并在本文件标记状态与日期
- [ ] **有对应测试**；确实只能手测的，写明手测步骤并记录证据
- [ ] **主路径**：正常输入 → 得到预期结果
- [ ] **反例 1**：空输入 / 非法格式
- [ ] **反例 2**：无权限 / 越权模式 / 未登录
- [ ] **反例 3**：重复提交 / 大数据量 / 网络失败（至少覆盖一个）
- [ ] **三态齐全**：空状态、加载状态、错误状态都有明确反馈
- [ ] **数据落库正确**：刷新页面/重启服务后结果一致
- [ ] **边界值**：0 条、1 条、很多条都走过
- [ ] **原有功能没被弄坏**：跑第 3 节回归清单

补充硬性条件（来自项目治理规则）：

- [ ] L4 `npm run verify` 绿；改动面对照表定向回归全绿
- [ ] 新能力默认关（或经批准默认开）；关=旧行为逐路径一致
- [ ] 提交只含本工作流文件；无 `临时-` 文件；无调试残留
- [ ] `变更日志.md` 已登记；影响架构/决策的已更新 01/06
- [ ] 可回滚：feature flag 或独立提交保证整体可退
- [ ] 服务端改动已重启 3002 并做过接口冒烟

**以上任一条不满足，结论只能是「未完成」。**

## 3. 回归清单（每次发布前必跑，10 条）

> 没有完整测试覆盖时的安全网。固定顺序，照着点一遍。

1. 服务能启动（`npm run dev`），`/api/status` 正常，控制台无红色报错。
2. 首页/主界面能打开，三栏布局正常，无白屏。
3. 打开一份 docx：分页、中文、表格线正常；关闭再打开仍正常。
4. 打开一份 xlsx：日期/合并/列宽正确，首行首列不空。
5. 发送一条普通对话：流式输出、工具卡片、结论卡正常；发送后引用条清空。
6. 跑一次 Work 写文件任务：产物运行中可见，结束后落在工作区；可回滚。
7. 刷新页面：历史会话与产物仍在；断线事件能补齐。
8. 切换 Chat/Work：地图只读/可写边界正确；越权操作有提示。
9. 切换暗/亮主题：刷新后保持；无对比度异常。
10. 服务日志无异常堆栈；`.oaw/` 与运行日志未进入 `git status`。

- [ ] **CAD（flag 开）**：DXF 预览不白屏；未装 DWG 转换器时有安装指引

## 5. 测试用例标准

### 5.1 用例格式（手测/自动都用）

```
用例 ID：TC-xxx
对应验收项：T-xx
前置条件：<数据/模式/开关状态>
步骤：
  1. …
  2. …
预期：<可观察结果，含具体数值/文案>
实际：<验收时填写>
证据：<命令输出 / 截图路径 / 事件 runId>
结论：通过 / 失败 / 阻塞
```

### 5.2 编写规则

- 每个 P0 需求至少一条端到端用例，覆盖「主路径 + 1 个反例」。
- 测试名用中文描述行为：`应当拒绝超过 5MB 的上传`。
- 自动化用例必须可重复执行，不依赖真实网络/真实浏览器；live 用例单独命名。
- 断言的是**用户可观察行为**，不是实现细节。
- 修 bug 必须先有能复现的用例（红），修复后必须变绿。
- **禁止**为过测试改断言、加 skip、弱化覆盖；确需改，提交信息说明理由。
