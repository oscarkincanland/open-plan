## 3. 通用编码规则

- **简单优先**：最小代码解决问题，不做投机性抽象；不为"将来可能"设计。
- **最小侵入**：只改必须改的；匹配现有风格；不顺手重构、不顺手格式化无关文件。
- **目标驱动**：任务转成可验证目标，循环到验证通过；不以"基本可用"收尾。
- **一次只做一件事**：本轮目标以外的改动一律拒绝；确需连带修改，先拆步骤报批。
- **不新增依赖**：见 D-004；确需新增先写理由/替代方案，经产品负责人批准并更新 06。
- **不改数据模型/公共接口签名/目录结构**：确需改，先更新 [01-架构文档](01-架构文档.md) 并通过评审。
- **不确定的 API 行为先验证**：写最小脚本或查文档，禁止凭记忆编 API。
- **文件上限**：单文件超过 500 行视为待拆分（`agent.mjs`/`index.mjs`/`ChatPanel.jsx` 为已知债，不得继续无节制膨胀）；新增文件超过 300 行先拆分。
- **注释用中文**，只解释"为什么"，不复述代码；改动过的代码才补注释。

## 5. 服务端规范

- 统一 ESM（`import`/`export`），文件后缀 `.mjs`；不引入 TypeScript 编译链。
- 所有业务逻辑在 L2 模块；`index.mjs` 只做路由、admission、参数校验与响应。
- **禁止业务模块直读 `process.env`**：一律走 `运行开关.mjs`（`RUNTIME_FLAGS` / `readFlagWithDefault`）。
- **事件先登记再发**：`事件注册表.mjs` 未登记的类型不得 emit；`persist` 标记决定是否落盘。
- **工具注册三处对齐**：`customTools` / `tools` / `setActiveTools`；能力计划 `planTaskCapabilities` 声明的能力必须与模式白名单一致（防"声明了却调不到"）。
- **写盘统一通道**：`writeWorkspaceFile` / 写入协调；不得绕开写入清单直接 `fs.writeFile` 写用户工作区。
- **受控外部进程**：只允许 officecli、服务监督、浏览器 CDP、DWG 转换器；不得开放任意 shell 给 Chat/Office/Review。
- **超时必备**：网络请求、外部进程、HITL 等待、流静默都要有超时与可读错误。
- **并发保护**：同一文件写入走写入锁；同一会话 prompt 走串行队列；子代理并发上限 2。
- **纯逻辑可测**：编排、投影、判定类逻辑抽成纯函数（不 import Pi SDK），便于单测。

## 6. 错误处理与异常标准

### 6.1 用户可见错误

- 必须说人话：**发生了什么 + 怎么办**。禁止把堆栈、英文报错原文直接抛给用户。
- 文件占用/权限错误统一经 `文件权限错误.mjs` 归一化（`OFFICE_DOCUMENT_LOCKED` / `WORKSPACE_PERMISSION_DENIED`），给出可操作建议。
- UI 必须有错误态（见 03 文档），不能只弹全局 toast。

### 6.2 API 响应

- 保持现有约定：错误返回 `{ error: "<code>", message?: "<人话>" }`；需要时带 `requestId`。
- 成功响应保持 `{ ok: true, ... }` 或现有字段结构；**不得为统一格式而批量改历史接口**。
- 用常量/枚举表达错误码，不写魔法字符串。

### 6.3 catch 规则

- 每个 `catch` 必须做三件事之一：**处理、上报、以明确信息重抛**。禁止空 catch、禁止 `catch {}` 吞掉关键错误。
- 允许"尽力而为"的空 catch（如可选缓存解析）时，必须写注释说明为什么安全。
- 不得用 catch 掩盖降级失败；降级要有日志或事件痕迹。

### 6.4 失败与降级

- 外部依赖失败必须有降级路径（见 01 文档第 6 节）；降级时明确告知用户当前能力边界。
- 审批超时 = 拒绝；ask_user 超时发 `ask_expired`；流静默超时触发重连/结束，不得永久悬挂。
- 取消中的 Run 不复活；中断后残余消息走排空语义。

## 7. 日志规范

| 类别 | 规则 |
|---|---|
| 服务端控制台 | `[模块名] 事件描述`，带 runId/threadId 等定位信息；一个事件一行 |
| 级别 | `console.error` 仅用于真实失败；`console.warn` 用于降级；`console.log` 用于生命周期；禁止用 log 当调试残留提交 |
| 敏感信息 | 禁止输出密钥、token、Cookie、完整用户文件内容、个人信息 |
| 大对象 | 截断（≤800 字符），必要时只打计数与类型 |
| 用户可见日志 | 不暴露内部路径与堆栈；错误信息按 6.1 处理 |
| 审计 | 以事件流为准（`.oaw/events/`、`.oaw/runs/`），不靠控制台日志做审计 |
| 日志文件 | 只允许 `运行日志/` 与服务监督产物；**禁止在根目录新建 `*.log`** |
| 提交前 | 清理调试 `console.log`；保留的必须有明确用途 |

## 8. 安全规范

- 服务只监听 `127.0.0.1`；如需局域网访问必须先重审凭证与口令强度。
- 所有凭证只走环境变量或本地设置；`.env` 必须在 `.gitignore`；提供 `.env.example` 说明字段。
- 不信任前端传来的路径、ID、角色；路径必须做工作区边界校验（防目录穿越）。
- 写操作默认需要审批；`always` 规则可撤销；`deny` 优先于自动批准。
- 浏览器导航：拒绝 `file://`，域名白名单；下载与截图走受控目录。
- 地图/文档服务不得暴露任意本地文件读取；`sendFile` 类接口显式设置 `dotfiles: "allow"` 前必须有文件名校验。
- 日志、错误响应、事件负载都不得包含密钥或完整敏感内容。
- 视频类文件/目录、`.oaw/`、用户上传数据一律不入库。

## 9. 性能规范

- 首字延迟必须可观测（`首字延迟.mjs` / `test:first-token-latency`）；改动主链路后记录分段数据。
- 前端流式渲染用 rAF 节流；长列表/长文按需渲染；工具卡聚合不得阻塞输入。
- 大文件预览必须截断或懒加载（Excel 5000 行×120 列×30 表上限；sheet 懒加载开关）。
- 缓存必须有失效策略与容量上限（docx LRU 3×25MB；工作簿 LRU 6 本，mtime 失效）。
- SSE：有界队列、背压、心跳、配额；不得无限缓冲。
- 禁止在渲染路径做同步重计算；投影结果可缓存但必须随事件版本失效。
- 任何性能优化都必须挂 flag（默认关）或有基线对比数据，不得"感觉更快"。

### 10.3 测试纪律

1. **修 bug 先写能复现的测试**，确认红，再修，修完必绿。
2. 测试名用中文描述行为，例如 `应当拒绝超过 5MB 的上传`。
3. **禁止**为过测试改断言、加 skip、弱化覆盖；确需改断言，提交信息写明理由。
4. 新能力必须带至少一项定向回归，否则不满足 DoD。
5. 只测纯逻辑的脚本不得依赖真实网络/真实浏览器；live 用例单独命名（`--live`）。
6. 服务端改动后**重启 3002 服务**再做功能验证，避免前后端版本不一致导致 404。
7. 测试失败先定位根因，再重跑；禁止无脑重试掩盖不稳定。

## 11. Git、分支与提交

> 本章为摘要；**分支、提交、评审、合并、打标、发布、冲突、仓库权限的权威定义见 [07-GIT工作流](07-GIT工作流.md)**。两者冲突时以 07 为准。

### 11.1 分支模型（与仓库现状一致）

```
main                 ← 保护分支，永远保持"能跑、能部署"，只接受评审通过的合并
develop              ← 可选集成分支；仅 ≥2 人并行时启用，默认不建
feature/<语义>        ← 新功能，如 feature/v0.11.56-execution-handle
fix/<语义>            ← 缺陷修复
chore/<语义>          ← 构建/依赖/仓库卫生
docs/<语义>           ← 纯文档变更
hotfix/<语义>         ← 验收基线阻断缺陷，需产品负责人批准
```

- 小改动（文案、样式微调）可直接在 `develop`；动结构/数据/主链路必须开分支。
- **不自行切换或创建分支**，除非产品负责人明确要求。
- 合并前：`npm run verify` + 对应定向测试 + 代码审计通过。
- 合并后立即删除已合并分支；不保留"备用分支"。

### 11.2 提交规则

- 格式：`类型(范围): 描述`；类型 ∈ `feat / fix / refactor / docs / test / chore / perf`。
- 描述写"为什么 + 做了什么"，不写 `update` / `修改` / `提交`，一行以内。
- **一次提交 = 一条工作流**；提交前逐文件核对 diff 归属。
- 必须用 **pathspec 提交**：`git commit -m "…" -- <文件列表>`；**禁止 `git add -A` / `git add .`**。
- 多工作流共享文件（`styles.css`、`ChatPanel.jsx`、`App.jsx`、`.gitignore`、`server/index.mjs`）提交前必须检查暂存/未暂存 diff；混有其他工作流时跳过或拆分。
- 提交前必须：L4 `npm run verify` 绿 + 改动面对照表定向回归绿 + 无 `临时-` 文件 + 无调试残留 + `变更日志.md` 已登记。
- 一个能跑的状态就提交；禁止攒一整天。

### 11.3 版本与标签

- 语义化小版本在当前稳定基线递增（`v0.11.x`）。
- 正式版本 tag 用附注类型：`git tag -a v0.11.55 -m "验收基线：…"`。
- 版本号、`package.json`、`变更日志.md`、README 版本矩阵必须同步。

### 11.4 AI 的 Git 边界

| 操作 | 权限 |
|---|---|
| `status` / `diff` / `log` / `show` | 随时可用 |
| `add` / `commit` | 先跑测试、展示文件清单，**经产品负责人确认** |
| `reset --hard` / `checkout -- .` / `clean -fd` | 必须说明会丢什么，等确认 |
| `rebase` / `merge` / 删除分支或标签 | 必须说明后果，等确认 |
| `push --force` / `commit --amend` 已推送提交 / 改写历史 | **绝对禁止** |

> 推送 = 备份；每天至少推一次（网络可用时）。网络不可达时记录在 05 的阻塞项，不得强行重试掩盖。

### 11.5 仓库卫生

- 行尾与二进制类型由 `.gitattributes` 统一：`*.bat` 用 CRLF，`*.sh` 用 LF，图片/Office/压缩包标记 `binary`；大二进制沿用现有 LFS 规则。**不得在无说明的情况下改动该文件**（会让全仓库显示被修改）。
- 不提交：`.oaw/runs/`、视频/音频大文件、`临时-` 脚本、调试日志、`node_modules`、`dist`、个人工作区数据。
- 提交前用 `git status` 逐项核对；既不把无关文件带进去，也不把本工作流文件落下。

## 12. 文档维护规范

1. **单一事实源**：需求在 00，验收在 04，决策在 06，进度在 05。别处只引用文件名，禁止复制内容。
2. **AI 起草，人拍板**：文档由智能体改写，产品负责人只负责删和确认；不写"本轮工作总结"，只改"变了的事实"。
3. **长度上限**：`AGENT.MD` ≤240 行；`05-当前进度` ≤1 屏；`00-需求` 只保留当前与下两个迭代。
4. **过期立刻处理**：被替代的条目标 `已废弃（替代者：xxx）`；做完的移到归档。**过期的文档比没有文档更危险。**
5. **不建这些**：开发日记、会议纪要、调研长文、README 副本、自动生成文档的手抄版、第二份"规则说明"。
6. **编号是引用契约**：`R/F/P/D/T` 编号一旦分配不复用；下线保留一行说明。
7. **代码与文档冲突**：以代码实际行为为准，然后改文档；不确定就报告，不要猜着补。
8. **每轮收尾**：更新 05；有新决策写 06；有新坑写本文件 §14；有验收变化写 04。

## 13. 标准工作流

### 13.0 角色与分工（角色细节的权威位置）

> `AGENT.MD` 只规定授权边界；**角色职责、输入输出与协作流程以本节为准**。

| 角色 | 类型 | 输入 | 输出 | 权限边界 |
|---|---|---|---|---|
| 产品负责人（用户） | 人工 | 需求、反馈 | 决策、批准、验收签字 | 唯一批准需求变更、默认开 flag、新增依赖、合并/发布、推翻决策 |
| 主控智能体 Leader | 工作流 | 用户请求 + `05`/`00`/`06` | 方案、代码、验证证据、`05`/`06` 更新 | 本轮范围内读写；Git 只读；提交须确认；不得代签验收 |
| 资料探索 scout | 运行时 | 子任务描述 | 带路径的证据要点 | 只读；60s |
| 方案拆解 planner | 运行时 | 目标 + 约束 | ≤5 步可执行方案 | 只读；60s；不写代码 |
| 审阅 reviewer | 运行时 | 待审内容 | 问题清单（附证据） | 只读；120s |
| 执行 worker | 运行时 | 已批准子任务 | 交付说明 + 产物 | 仅 Work 模式可写；写操作需审批；180s |
| 独立核验 verifier | 运行时 | 子任务 + 执行结论 | 检查清单 + `判定：pass/revise/fail` | 只读；120s；回环 ≤1 轮 |
| 代码审计 code-auditor | 工作流 | 改动 diff + 项目规则 | 阻断/建议/提示三级问题 | 只读，不改代码 |
| 运维 Ops | 工作流 | 运行状态 | 检查结论 + 操作记录 | 只运行运维脚本；不改业务代码 |

- **角色降级**：请求 `worker` 但父会话不可写（Chat/Office/Review）→ 降级 `scout`；未知角色 → `scout`。
- **协作硬规则**：只有 Leader 对用户说话；子代理不直接提问、不互相通信，一律经 Leader 汇总；结论必须带证据；越权请求拒绝并说明依据；角色冲突由 Leader 列证据交用户裁决。
- **运行时真实性**：只有 scout/planner/reviewer/worker/verifier 五个角色可由 `run_subagent` 派发（`server/子代理编排器.mjs`）；其余是工作流角色，禁止虚构运行时角色。

### 13.2 排查与修复

1. **先定位，不改代码**：现象 / 期望 / 实际 / 复现步骤 / 频率 / 环境 / 原始日志。
2. 输出 2 个最可能根因 + 验证方法 + 涉及文件行 + 修复影响面。
3. 修复：先写复现测试（红）→ 改代码（绿）→ 跑全部相关测试。
4. 第 3 次仍未解决：停止修改，列出改动，换思路或回滚到上一个可跑提交。
5. 修完把根因写成"现象 → 正确做法"，补进 §14。

### 13.3 代码审查（每个逻辑改动后）

- 审查范围：本次 diff，不审未改动代码。
- 必查：逻辑错误、边界、并发、权限、错误处理、测试缺口、规范冲突。
- 输出分级：**阻断 / 建议 / 提示**；阻断项未清零不得提交。

## 14. AI 常犯错误清单（持续追加）

> 每条写"现象 → 正确做法"。这是本文档最有价值的一节。

1. **顺手改无关文件** → 一次只改本轮目标；越界即回滚。
2. **页面里直接拼请求/写文件** → 走数据层 / `writeWorkspaceFile` 通道。
3. **颜色/间距写魔法数字** → 用 03 文档的令牌。
4. **给已有接口加参数时改顺序** → 只允许在末尾追加可选参数。
5. **未登记事件类型直接 emit** → 先登记 `事件注册表.mjs`，否则 `test:pi-iteration` 失败。
6. **业务模块直读 `process.env`** → 走 `运行开关.mjs`。
7. **只改 `customTools` 漏改 `tools`/`setActiveTools`** → 工具注册三处对齐。
8. **能力计划声明了但模式白名单没有** → 声明与 `toolPolicyForMode` 双向对齐。
9. **图层写进 `style.json` 但没进 `config.layers`** → 图层面板不可见；必须注册。
10. **用 1-based 行列键喂 0-based 表格** → Excel 整体偏移一格；统一 0-based。
11. **路径拼接不去空值** → `currentFile` 为空时 `join` 产生尾随空格，扩展名正则失配，officecli 路由误降级；先 `filter(Boolean)`。
12. **发送后不清引用状态** → 引用条残留；普通/排队/注入三条路径都要清。
13. **引用徽章区间差一位** → 整条不渲染；`referenceTokenRanges` 必须包含完整 `@` 与文件名。
14. **手动删了引用文本但引用状态还在** → 来自文本的引用必须随编辑同步增删。
15. **任务结束才展示产物** → 开 `stagedVisible`；结束后 `autoTab`。
16. **只判断 `status === "partial"` 就提示未完成** → 还要校验 `incomplete/blockers` 非空。
17. **React hooks 放在 `if (!open) return null` 之后** → 白屏；hooks 必须在顶层。
18. **并发 prompt 直接调用** → `entry.busy=false` 但 Pi 仍 `isStreaming`，抛 "already processing"；走 steer/重试。
19. **创作产物不写工作区** → `snapshotWorkspace` 检测不到；必须写 `office-workspace/`。
20. **officecli 冷启动阻塞 admission** → 生成类任务走原生直写，CLI 仅兜底/编辑类 preferred。
21. **为过测试改断言/加 skip** → 禁止；测试失败就是失败。
22. **提交信息写"更新/修改"** → 三个月后无法回滚定位；写清做了什么。
23. **用 `git add -A` 提交** → 混入其他工作流与用户数据；只允许 pathspec。
24. **把 `.oaw/`、视频、日志提交进仓库** → 立即停止并清理。
25. **文档写"视情况"** → 等于没有规则；写具体路径/阈值/命令。
