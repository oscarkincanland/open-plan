## 一、产品定位

**Open Plan（规聚）**：面向**交通规划工程师**的本地化 AI 办公工作台。

- 形态：Web 工作台（Express 单服务 + React SPA），浏览器/桌面端访问 `127.0.0.1:3002`
- 内核：Pi Agent SDK（进程内调用，不改内核）+ officecli（Office 文档受控操作）
- 场景：公文与规划文档的撰写、审查、修订；交通数据（OD/路网/客流）分析与地图可视化；汇报材料生成
- 部署：本地单机优先，工作区即本地文件系统（`office-workspace/`），数据不出本机

## 三、用户与四种工作模式

四种模式由 `server/task.mjs` 的 `toolPolicyForMode` 统一约束工具白名单与能力边界：

| 模式 | 定位 | 能力边界 |
|------|------|---------|
| **Chat** | 检索问答 | 只读：知识库/Skills/工作区资料/地图只读四件套，不落盘 |
| **Office** | 文档处理 | officecli 精准编辑，不开放通用脚本写入 |
| **Agent（Work）** | 全能执行 | 完整工具链：分析、写盘、地图写入、浏览器、编辑流水线 |
| **Review** | 规范审查 | 本地材料+规范库 → 报告+副本；`ask_user` 确认后才写回原文 |

## 四、设计目标（工程与体验原则）

1. **简单优先、最小侵入**：最小代码解决问题，不顺手重构；只改必须改的（`AGENT.MD`）。
2. **事件即事实**：所有 Agent 行为统一为事件（`事件注册表.mjs` 登记 → JSONL 落盘 → 断线回放），前端只是事件投影。
3. **基线冻结 + flag 门控**：新能力一律挂 `OAW_*` 开关（`运行开关.mjs` 统一管道），默认关=基线零变化；**用户明确批准的能力才允许默认开**（2026-10-19 起例：askAutoResume、stagedVisible、autoTab）。
4. **零新增 npm 依赖**：优化优先复用已有依赖（xlsx/docx/typebox 等），全部基于 Pi SDK 原生导出能力。
5. **人工在环（HITL）**：关键决策交还用户——`ask_user` 提问（60 分钟窗口 + 迟到回答自动续跑 + 克制提问纪律）；写操作审批（allow/always/deny 三值，超时视为拒绝）。
6. **产物可信**：创作产物必须写入工作区并纳入写入清单；generated 产物回读验证后才可声明 success；预览带文件身份（identity/revision）防跨工作区串内容。
7. **中文优先**：中文界面、新增文件中文命名（代码文件按语言惯例）。
8. **暗/亮双主题**：CSS 变量驱动，禁写死色值（`DESIGN.md` 三层令牌）。
9. **性能预算**：首字延迟分段可观测；大文件预览截断/懒加载；SSE 背压与心跳可配。

## 五、体验基线（已交付的关键体验决策）

- **ask_user 交互**：等待窗口 60 分钟（`OAW_ASK_TIMEOUT_MS` 可调）；迟到回答自动续跑（忙=排队接力，空闲=新 Run）；提问纪律=整轮默认 1 次、至多 2 次，禁止"需要我继续吗"式请示。
- **结论可信**：同轮多次 `complete_task` 按"状态变化最新优先、同状态信息量优先"合并，寒暄式结论覆盖不掉实质总结；最后一条正文必须是"已交付什么 + 停在哪 + 可选下一步"。
- **产物及时可见**：暂存产物运行中即可见（stagedVisible 默认开）；任务结束自动切「工作产物」页签（autoTab 默认开，手动切页签 10 秒内不打扰）。
- **引用输入**：@引用在输入框内渲染为行内徽章，整块编辑（Backspace 一次删整块、块内打字先整块选中）；发送后引用条自动清空。
- **任务编排**：子代理角色表（scout/worker/verifier…）+ 确定性编排（代码编排而非模型自治）；revise 回环 ≤1 轮。

## 六、明确不做（不做清单）

源自对标报告 §6.2，全程遵守：

- 不做 Qoder 皮肤引擎（多 Flavor × Swatch）；只对齐视觉语言
- 不把对话流改为手写 SSE 解析（保留原生 EventSource）
- 不修改 Pi 内核；不引入官方不存在的 subagent / plan mode 能力假设
- 不新增独立应用/独立前端工程/独立后端服务
- 不追求复刻 Qoder 界面
- 运行记录（`.oaw/runs/`）不提交 Git
