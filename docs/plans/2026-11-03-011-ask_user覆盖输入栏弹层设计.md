# ask_user 覆盖输入栏弹层设计

> 状态：设计稿，**未修改任何代码**
> 日期：2026-11-03
> 基线：`develop` @ `acda06cd`
> 适用范围：`client/src/components/ChatPanel.jsx`、`client/src/styles.css`
> 关联：[DESIGN.md](../../DESIGN.md) §6.4、[会话流前端规范](../规范/会话流前端规范.md)
> 后续：用户已拍板「超时自动消失、不影响后续工作」，超时/跳过策略见 [013 计划](2026-11-03-013-无上限预算与异步工作流收敛计划.md) §2。

## 0. 结论先行

把「待回答」从**消息流里的内联卡片 + 输入栏上方的重复操作条**，改成**覆盖输入栏的一张弹层**：

- 弹层出现时，输入框暂时隐藏/被覆盖，用户只看到问题和作答控件；
- 提交成功后弹层收起，输入框回来并获得焦点；
- 历史里不保留一张可交互的大卡片，只留一行「✓ 已回答 · 问题摘要 → 回答摘要」，点开可看全文；
- 不改变服务端 `ask_user` 契约、30 分钟超时、单槽位限制和事件流。

## 1. 现状与问题

### 1.1 同一件事有三处入口

| 位置 | 代码 | 问题 |
|---|---|---|
| 消息流内联卡片 | `ChatPanel.jsx:6705` `AskBlock` | 问题可能被折叠进历史、被后续消息顶走；用户要往上找 |
| 输入栏上方操作条 | `ChatPanel.jsx:6611` `PendingActionBar` | 与卡片功能重复；字段型提问只提示「去上方填写」 |
| 执行过程状态 | `pendingAsk` + `pendingApproval` | 只做定位，不承载作答 |

### 1.2 回答后卡片仍占一大块

`AskBlock` 在 `block.answer` 后仍渲染完整卡片（标题、问题、回答），历史会话里每个提问都留下一个“已处理但很大”的块，削弱阅读流。

### 1.3 目标

- **一个入口**：待回答时只出现一个弹层；
- **回答即消失**：提交成功 → 弹层收起 → 输入框回来；
- **不丢上下文**：历史保留一行可展开的回执；
- **不打断阅读**：弹层只覆盖输入栏区域，不遮住上方对话；
- **可稍后处理**：允许收起成一个小胶囊，继续看历史，再点开回答。

## 2. 目标交互

### 2.1 桌面（≥721px）

弹层与输入框同宽、同左缘，覆盖在 `.chat-compose` 的位置；上方消息流保持可见。

```
┌──────────────────────────── 对话区 ────────────────────────────┐
│  … 消息流 / 执行过程 …                                          │
│                                                                │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │ 💬 需要你确认        规划结构 · 剩余 4:32        ⌄ 稍后   │  │
│  │                                                          │  │
│  │  这份文档的篇幅和受众是？                                │  │
│  │                                                          │  │
│  │  ┌────────────┐  ┌────────────┐  ┌────────────┐          │  │
│  │  │ 1–3 页     │  │ 5–10 页    │  │ 10–20 页   │          │  │
│  │  └────────────┘  └────────────┘  └────────────┘          │  │
│  │                                                          │  │
│  │  ┌────────────────────────────────────────────────────┐  │  │
│  │  │ 补充说明（可选）                                   │  │  │
│  │  └────────────────────────────────────────────────────┘  │  │
│  │                                          [ 提交回答 ]     │  │
│  └──────────────────────────────────────────────────────────┘  │
│                                                                │
│  （输入框被弹层覆盖，不占位、不可聚焦）                         │
└────────────────────────────────────────────────────────────────┘
```

### 2.2 窄屏（≤720px）

- 左右各 8px，最大高度 `70vh`，内部滚动，底部按钮 sticky；
- 头部只保留图标 +「需要你确认」+ 倒计时；「稍后」变成图标按钮；
- 选项从横排改为整行按钮（每行 44px 点击区）。

### 2.3 回答之后

- 弹层 160–180ms 向下淡出，输入框 160ms 淡入并获得焦点；
- 消息流对应位置插入一行回执：

```
✓ 已回答 · 篇幅：5–10 页 · 受众：局领导        [展开]
```

- 点「展开」才显示完整问题与回答；默认只占一行，不打断阅读。

### 2.4 「稍后」

- 点击后弹层收起，输入栏上方出现 28px 高的小胶囊：

```
[ 💬 待回答 · 1 ]        ← 点击重新打开弹层
```

- 胶囊不遮挡输入框；用户仍可先发别的话（服务端会拒绝新的 ask，但普通消息可排队）。
- 30 分钟倒计时继续走；超时后胶囊变成 `已超时`，点击只显示说明，不能再提交。

## 3. 组件与状态

### 3.1 组件拆分

| 组件 | 职责 |
|---|---|
| `AskComposerSheet`（新） | 覆盖输入栏的弹层；头部、倒计时、问题、作答、错误、提交、稍后 |
| `AskForm`（从 `AskBlock` 抽出） | 纯表单：options / text / select / radio / checkbox / file 字段与校验 |
| `AskReceipt`（新） | 历史一行回执；展开显示完整 Q/A；已超时/已取消同款降级 |
| `PendingActionBar` | **只保留审批分支**；删除 ask 分支（不再有第二套作答入口） |
| `AskBlock` | 保留为历史/回放兼容组件，但改用 `AskReceipt` 形态；不再渲染大卡片 |

### 3.2 状态机

```
idle
  └─ ask_user 事件到达 → pending（弹层打开，焦点进入）
        ├─ 提交中 → submitting（按钮 loading，控件禁用）
        │     ├─ 成功 → closing（160ms）→ idle + 回执
        │     └─ 失败 → pending + 行内错误（可重试）
        ├─ 点击「稍后」→ collapsed（小胶囊；倒计时继续）
        │     └─ 点击胶囊 → pending
        ├─ 30 分钟到点 → expired（弹层/胶囊显示已超时；不可提交）
        └─ 用户中断本轮 → cancelled（同 expired，文案不同）
```

### 3.3 数据来源不变

- `pendingAsk` 已由 `ChatPanel.jsx:4268-4276` 从消息块派生，含 `id / question / options / fields / expiresAt / messageId / owner`；
- 提交仍走 `POST /api/agent/answer { client, thread, answer }`；
- 成功仍调用 `handleMessageAskAnswered(messageId, blockId, answer)`；
- 超时仍由 `useEffect` 定时 `markAskExpired`；
- 不新增事件、不修改服务端。

## 4. 视觉规范

| 项 | 规范 |
|---|---|
| 宽度 | 与 `.chat-compose` 同宽（`--msg-content-max`），左缘与输入框一致 |
| 位置 | 覆盖输入栏位置；`position: absolute; bottom: 18px; left/right: 16px`（相对对话区容器） |
| 背景 | `--panel-bg`，96% 不透明 + 8px 背景模糊（可选）；上方对话仍可见 |
| 边框 | `1px solid color-mix(in srgb, var(--accent) 38%, var(--border))` |
| 圆角 | `var(--radius-lg)`（8px）；窄屏 12px |
| 阴影 | `0 16px 40px color-mix(in srgb, var(--pure-black) 28%, transparent)` |
| 标题 | 12px/600 `--text`；左侧 20px 图标（comment，accent） |
| 倒计时 | 11px `--muted`，`tabular-nums`；最后 60 秒变 `--warning` |
| 问题 | 14px/1.6 `--text`，最多 4 行后内部滚动 |
| 选项 | 28px 高（窄屏 44px），无外框；选中 `--accent-soft` + accent 文字 |
| 输入 | 与设置面板一致（`--panel2-bg` + border，focus accent） |
| 主按钮 | `btn primary`，右对齐；提交中显示「提交中…」并禁用 |

| 动效 | 进入：opacity 0→1 + translateY(8px)→0，`var(--dur-base)` `var(--ease-out)`；退出反向 160ms；`prefers-reduced-motion` 直接切换 |
| 禁止 | 不新增无限动画；不改变输入栏 28px 工具条规范 |

## 5. 交互细节

### 5.1 焦点与键盘

- 打开时焦点进入第一个可作答控件（有 options → 第一个选项；有 fields → 第一个字段；否则文本框）；
- 焦点圈定在弹层内（Tab/Shift+Tab 循环），`aria-modal="false"`（因为不遮全屏，但焦点仍锁定）；
- `Esc` = 稍后（收起，不丢问题）；
- 单行输入 `Enter` 提交；`Shift+Enter` 换行；
- 多字段表单 `Ctrl/Cmd+Enter` 提交；
- 提交成功/超时后焦点回到输入框。

### 5.2 倒计时与超时

- 头部显示 `剩余 4:32`，每秒更新；最后 60 秒变琥珀；
- 到点自动切 `expired`，弹层收成一行「该问题已超时，Agent 已按假设继续」；
- 超时后不保留可提交控件，避免 404。

### 5.3 归属与多来源

- 子代理发起的提问显示 `来自：子 Agent · 资料探索`（复用现有 `交互归属文案`）；
- 审批与提问同时存在时：提问弹层优先；审批仍走输入栏上方的 `PendingActionBar`（只保留审批）。
- 同一会话同时只有一个待回答问题（服务端单槽位），不做队列 UI。

### 5.4 历史与回放

- 已回答：一行回执，展开可见完整 Q/A；
- 已超时/已取消：一行灰字说明；
- 回放时不重新弹层，只显示回执；只有“当前未决”的提问才打开弹层。

### 5.5 预览文件

- `previewFile` 存在时，头部右侧显示「打开预览」按钮，点击调用现有 `onOpenFile`；
- 不因为打开预览而收起弹层；用户回答后仍按原逻辑关闭。

## 6. 技术落点（未来实施）

1. **抽取表单**：把 `AskBlock` 中 `fields` 渲染与 `submitForm` 校验抽成 `AskForm`，行为不变。
2. **新增弹层**：在 `ChatPanel` 的输入区容器内渲染 `<AskComposerSheet ask={pendingAsk} …/>`；用 `pendingAsk` 控制显隐，不需要新全局状态。
3. **移除重复入口**：`PendingActionBar` 删除 `ask` 分支与 `onLocateAsk`；只保留审批。
4. **历史回执**：`AskBlock` 改为 `AskReceipt` 形态；`answered/expired/cancelled` 都收成一行。
5. **样式**：新增 `.ask-sheet*` 与 `.ask-receipt*`；旧 `.ask-block` 仅作回放兼容，逐步删除。
6. **DESIGN 同步**：实施时更新 DESIGN §6.4「审批卡与 ask_user 卡」与 §7「消息流」——待回答不再作为折叠体外常驻卡片，而是输入栏弹层；已回答变一行回执。
7. **测试**：
   - 源码契约：弹层存在、`PendingActionBar` 无 ask 分支、回执类名、倒计时、Esc/快捷键；
   - 浏览器：提问时弹层覆盖输入栏、回答后消失且输入框聚焦、历史一行回执、稍后胶囊、超时态、窄屏 44px；
   - 无障碍：焦点圈定、aria、reduced-motion。

## 7. 风险与非目标

- **不改变服务端契约**：30 分钟超时、单槽位、回答提交接口都不动；
- **不新增“跳过问题”**：跳过会让 Run 一直等在 `ask_user`；只提供“稍后”；
- **不把审批改成弹层**：审批涉及高风险写操作，保留现有独立入口；
- **不做全屏遮罩**：用户需要边看对话边回答，遮罩会破坏上下文；
- **历史回执不能完全删除**：否则回放时看不到本轮问过什么，审计和继续对话都会丢信息。

## 8. 验收口径

- 待回答时，输入框不可见/不可聚焦，弹层占据同一位置；
- 提交成功后 200ms 内弹层消失、输入框恢复焦点；
- 消息流只多出一行回执，不再出现完整问答大卡片；
- 点「稍后」后弹层收起，胶囊可重新打开，倒计时不重置；
- 30 分钟到点后弹层/胶囊变为已超时，提交入口消失；
- 窄屏无横向滚动，按钮不小于 44px；
- 键盘可完成：打开 → 选择/输入 → 提交 → 焦点回到输入框。
