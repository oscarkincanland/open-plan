## 0. 结论先行

1. **测试目标不是“跑绿”，而是回答三个问题：** 新能力是否可用？是否可审计？关掉开关是否与基线逐字一致？
2. **分五层执行：** L0 基础门禁、L1 契约/单元、L2 接口/集成、L3 真实集成（可选）、L4 人工验收、L5 性能/预算。默认不依赖真实模型与外网。
3. **用例总量约 51 条新增用例 + 现有回归矩阵。** 其中治理/计量 12 条、记忆/上下文 10 条、扩展/编排 10 条、P2 5 条、边界/回滚 8 条、性能 6 条。
4. **每个 WP 必须有“开关关=基线”的反向用例；** 没有反向用例的 WP 不算完成。
5. **五个门禁 G0–G4，逐门禁出证据。** 证据包括测试输出、事件流片段、usage JSONL 样本、延迟样本、人工验收记录；运行产物不入库。
6. **对照验收单独成表：** H-01..H-17 逐项给出“自动/人工/不适用”的结论与证据，避免“功能做了但说不清对没对上”。
7. **最大测试盲区是真实模型行为。** 提示词段落、记忆召回选择、Hook 拒绝后的模型反应，必须有小样本人工验收；不能只看字符串断言。

## 1. 测试范围与分层

### 1.1 范围

| 范围 | 覆盖 |
|---|---|
| 新增能力 | H1-1..H1-4、H2-1..H2-4、H3-1..H3-4、H4-1..H4-5 |
| 受影响存量 | 工具白名单/审批、事件注册表/事件流、Run 生命周期、子代理、记忆治理、上下文、产物、首字延迟 |
| 不覆盖 | Pi SDK 内部实现、前端视觉重做、地图业务正确性、Office 排版质量（由各自测试线覆盖） |
| 对照验收 | ZCode H-01..H-17 的能力对照结论 |

### 1.2 分层（对齐《功能验证测试规范》）

| 层 | 内容 | 手段 | 是否进 CI | 通过标准 |
|---|---|---|---|---|
| **L0 基础门禁** | 语法、构建、服务冒烟、事件注册表 | `npm run verify`、`test:event-registry` | 是 | 全绿 |
| **L1 契约/单元** | 元数据、ruleId、usage schema、段落预算、Hook 配置、错误 envelope | 纯 Node 脚本，无网络/模型 | 关键子集 | 断言全绿 |
| **L2 接口/集成** | 临时服务 + 临时工作区；工具调用、审批、结果外置、usage API、记忆召回回退、Hook 拒绝 | HTTP/SSE/本地文件 | 关键子集 | 行为与事件一致 |
| **L3 真实集成** | 真实模型、真实记忆目录、真实工具输出 | `:live` 或手动 | 否 | 小样本通过 |
| **L4 人工验收** | 审批 UX、提示词质量、Hook 可解释性、产物可读性 | 验收清单 + 截图/记录 | 否 | 签字 |
| **L5 性能/预算** | 首字延迟、事件量、usage 文件增长、2MB 输出、Hook 超时 | 采样 + 基线对比 | 按需 | 不超阈值 |

### 1.3 测试原则

1. **先能失败：** 新测试在实现前应能复现“缺元数据/无 ruleId/结果被截断/记忆不可召回”等问题。
2. **默认确定性：** 不依赖真实模型、外网、用户文件、系统时间；必须依赖时标 `:live`。
3. **断言行为：** 优先断言输入输出、事件、文件、决策对象；源码接线断言只用于无法运行时验证的接线事实。
4. **隔离与清理：** 临时工作区、临时端口、临时目录；结束后清理，不污染真实工作区。
5. **反向用例：** 每个开关都必须有“关=基线”的对照；没有反向用例不算完成。

## 7. 人工验收清单（L4）

### 7.1 三个代表性任务

| 任务 | 模式 | 检查点 |

- [ ] ask 卡片显示工具、输入摘要、ruleId（或可解释来源）。

- [ ] 拒绝后模型收到可执行的原因，不反复重试。
- [ ] 超时后不悬挂，界面有明确状态。

### 7.3 Hook 可解释性

- [ ] Hook 拒绝时用户能看到“哪条 Hook、什么原因”。
- [ ] 超时不阻塞主流程，日志有记录。
- [ ] 修改 Hook 声明后需要重新授信，界面有提示。

- [ ] 产物面板只显示用户产物，不显示工具结果外置文件。
- [ ] 关闭开关后，界面不出现只属于新能力的空状态/错误提示。

## 10. 回滚与故障演练

| 演练 | 步骤 | 通过标准 |
|---|---|---|
| 开关回滚 | 全开 → 全关 → 重跑关键 Run | 无新事件/新文件；行为与基线一致 |
| 数据残留 | 关闭后检查 usage/tool-results/hook 目录 | 不再增长；旧文件不被读取 |
| Hook 故障 | 配置错误命令/超时/非法 JSON | 主流程继续；有明确错误；无孤儿进程 |
| usage 写失败 | 只读目录/磁盘满模拟 | 主 Run 不受影响；有告警；不丢主终态 |
| 记忆召回失败 | 模型不支持 schema/返回非法 JSON | 回退全量摘要；主流程继续 |
| 抽取失败 | 子会话超时/无结果 | 不产生候选；事件记录；主 Run 已完成 |
| 事件未登记 | 故意发未登记事件 | `test:event-registry`/`test:event-payload` 失败 |

## 11. 性能与容量基线

> 阈值在 G0 用基线样本校准；以下是初始建议，不是承诺。

| 指标 | 基线采集 | 目标 | 采集方式 |
|---|---|---|---|
| 首字延迟 P50/P95 | G0 跑 20 次空/短任务 | P50 ≤ ×1.05，P95 ≤ ×1.10 | `test:first-token-latency` + 样本 |
| 单 Run 事件数 | G0 跑 3 类任务 | 新增 ≤ +30 条/普通 Run | 事件流统计 |
| usage 文件 | 同上 | ≤8KB/典型 Run | 文件字节数 |
| 2MB 工具输出 | 构造 | 预览 ≤30KB；内存增量 ≤50MB | 进程内存采样 |
| 记忆召回注入 | 10 条夹具 | ≤60KB；额外 ≤3s（不含模型） | 日志/计时 |
| Hook 超时 | 构造 10s Hook | ≤配置 + 500ms；无孤儿 | 进程检查 |

## 12. 风险与未验证项

| 风险/盲区 | 影响 | 处理 |
|---|---|---|
| 真实模型行为不可完全确定性 | 提示词/召回/抽取质量只能小样本验收 | L3/L4 单独执行；不纳入 CI；记录样本与结论 |
| Pi 并行工具能力未确认 | H1-1 的并发字段无法验证 | G0 探针；未确认则只做审计字段 |
| 子代理 usage 取不到 | H1-4/H3-2 的“用量可见”降级 | 记录 `unknown`；在报告中写明 |
| Hook 安全 | 新执行面可能被滥用 | 默认关、白名单、超时、信任三态、专项演练 |
| 事件量膨胀 | 性能与存储 | 采样、persist=false、单 Run 上限 |
| 测试脚本本身有缺陷 | 假绿/假红 | 先红后绿；关键用例人工复核 |
| 工作区/端口污染 | 影响用户使用 | 临时目录/临时端口；结束后清理 |

**明确未验证：**
- 未运行任何真实模型小样本（本轮只写计划）。
- 未验证 Pi 内核并行/子代理 usage/compaction 细节。
- 未验证前端展示与视觉；L4 在实施后执行。
