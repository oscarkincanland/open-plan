## 1. 结论先行

`github.com/sungatetop/open-plan` **不是参考示例，是已经做好的 Electron 桌面端**。路线 1 的本质不是"从零做桌面端"，而是**把已存在的桌面端成果搬回主线，并把主线领先的功能补进桌面端**。

因此本计划的核心命题是：**两条线在 2026-10-19 分叉后各自演进了 5 个月，谁都不可能整线吞掉另一条**。必须按功能切片做双向搬运。

## 3. 关键判断

### 3.1 "拉取桌面端的依赖"这个说法需要修正

桌面端不是一个可插拔的依赖包，而是一次**架构重写**：

- HTTP + SSE → IPC `op:*` 通道（前端 `api/client-api.ts` 与 `api/ipc-client.ts` 两套实现）
- `server/*.mjs` → `electron/src/main/backend/**/*.ts`（**TS 化，函数签名与错误处理都要重写**）
- `client/*.jsx` → `electron/src/renderer/**/*.tsx`
- 根包 `express` 删除；`electron/package.json` 通过 `"open-plan": "file:.."` 反向依赖根包拿 `@earendil-works/pi-coding-agent`

所以"依赖好拉、代码难搬"：依赖是一次 `npm install` 的事，**移植是逐模块重写**。

### 3.2 与 ADR 0002 的冲突（必须处理）

ADR 0002「保持单仓、单 Express 服务、React SPA 的模块化单体」被桌面端路线**推翻**。路线 1 一旦启动，必须新建 ADR 废弃或改写 0002，否则仓库同时存在两份互相矛盾的架构宪法。

同时 `docs/多用户隔离与桌面端路线梳理.md` §四推荐 **Tauri**，与已选定的 Electron 实现直接矛盾——Tauri 做不到"Node 后端进程内直调"（要么 Rust 重写，要么退回 sidecar，即 fork 已废弃的形态）。该文档必须改写。

### 3.3 桌面端形态下的能力删减清单

| 主线能力 | 桌面端是否需要 | 处置 |
|---|---|---|
| 跨标签页 SSE 配额（`client/src/跨标签页流配额.js`） | **不需要** | IPC 无浏览器连接槽问题，直接退役（连带 `长连接预算.js`、`跨标签页流租约.js`） |
| SSE 断线重连 / `lastEventId` | 不需要 | 退役 |
| HTTP 控制面超时（`CONTROL_TIMEOUT_MS`） | 不需要 | 退役 |
| 端口占用检测 / 单实例锁 | 降级为单实例锁 | 保留锁，退役端口逻辑 |
| `officecli` 外部二进制 | 需要 | 随安装器分发（fork 已有 `scripts/tools/install-officecli.mjs`） |

## 4. 阶段划分

每阶段都是可独立验证、可独立回滚的。**P1 完成前不移植任何主线功能**——先让桌面端能在本仓跑起来、装得上。

### P0 · 基线冻结（前置，依赖线 A）

- 把当前 `develop` 冻结为 `v0.14.0`（`main` + tag），使桌面端迁移随时可回滚。
- 前置条件：`版本管理计划.md` 中"**不启用 v0.14.0**"的表述需先修订（与用户 2026-11-02 指令冲突）。
- 交付：可回滚的已知良好基线。

### P1 · `electron/` 目录级迁入（不碰 `client/` 与 `server/`）

| 步骤 | 内容 | 完成判据 |
|---|---|---|
| P1-1 | 把 fork 的 `electron/`（344 文件）整体迁入本仓 `develop` | 目录落地，`git status` 干净 |
| P1-2 | 迁入 `electron/package.json` 依赖清单（见 §5） | `npm --prefix electron install` 通过 |
| P1-3 | 迁入 `electron/electron-builder.yml` + `electron/build/` 图标 | `npm run desktop:dist` 产出 NSIS 安装包 |
| P1-4 | 迁入 `scripts/tools/install-officecli.mjs` 并适配本仓 `scripts/` 结构 | 桌面端能定位并调用 officecli |
| P1-5 | 根 `package.json` 加 `desktop:*` 脚本聚合 | `npm run verify` 聚合桌面端 typecheck/test/smoke |
| P1-6 | 迁入 `electron/scripts/smoke.mjs` + `verify-nsis-install.mjs` | 两脚本在本仓通过 |

**P1 交付态**：仓库同时存在 web 形态（`client/` + `server/`，默认）与桌面端形态（`electron/`，可选启动）。此时桌面端功能落后主线，但**可运行、可安装、可回滚**。

### P2 · 契约对齐（唯一事实源约束）

ADR 0003 规定「事件注册表是事件流唯一事实来源」。桌面端引入后：

- `electron/src/shared/protocol/` 必须与 `server/事件注册表.mjs` **共用同一份 schema**，不得各写一份。
- `electron/src/main/backend/` 事件发射点须逐一对照 `server/事件注册表.mjs` 登记，未登记的不得发射（主线已有 `test:capability-contract` 与事件注册表校验脚本，需为桌面端补对应用例）。
- IPC `op:*` 通道名需与主线 API 语义一一对应，形成映射表（建议落在 `docs/规范/` 下，作为 IPC 契约规范）。

**P2 交付态**：桌面端事件/IPC 契约与主线一致，有校验脚本兜底。

### P3 · 主线功能移植（分批，按价值排序）

每批一个主题、一条 ADR 级别的追溯、一个可验证交付。

| 批次 | 内容 | 移植难度 | 备注 |
|---|---|---|---|
| P3-1 | Goal 六状态 + 持久化 + API + 事件 + Prompt 注入 | 中 | 会话流基础，先做 |
| P3-2 | Links 页签与角标 / 欢迎页 / Agent 继承 / `@` 提及 | 中 | 会话流交互 |
| P3-3 | 记忆准入 + 召回 + 抽取调度 | **高** | 主线是 `.mjs`，桌面端是 TS；且涉及 `Prompt 注入` 与 `agent.mjs` 核心装配 |
| P3-4 | 顶栏搜索 / TurnRail / 工作区菜单 / 音视频附件 | 中 | renderer 为主 |
| P3-5 | Office 写作层（规范层 + 写作闸门 + 四路由 + 编辑流水线） | **高** | 与 `officecli` 进程边界强耦合 |
| P3-6 | CAD 能力（若 v0.13.14 评审采纳取件） | 中 | DXF/DWG 解析 + 写回 + 预览组件 |
| P3-7 | 运行偏好 + `complete_task` 开关 | 低 | 偏好落盘语义与桌面端一致 |
| P3-8 | 跨标签页配额相关 | — | **不移植**（§3.3），直接退役 |

### P4 · 形态切换与交付

| 步骤 | 内容 |
|---|---|
| P4-1 | 桌面端成为默认入口；web 形态降级为"本地服务模式"开关（默认关），走 `server/index.mjs` 原路径 |
| P4-2 | `officecli` 等外部二进制随安装器分发并支持独立更新 |
| P4-3 | NSIS 安装包全量验证（`verify-nsis-install.mjs` 门禁） |
| P4-4 | 升级通道（Tauri updater 的等价物：electron-updater 或自建） |
| P4-5 | 桌面端与 web 形态的**功能对等验收清单**（哪一版是"准"，哪一版是"遗留"必须明确） |

### P5 · 测试体系归一（**不可跳过**）

主线 161 个 `scripts/*测试.mjs` 与桌面端 89 个 vitest 文件是**两套 runner**。必须在 P3 之前或同期决定：

- **选项 1**：把主线 `.mjs` 脚本测试逐个移植为 vitest（工作量大，但最终只有一套 runner）
- **选项 2**：保留双 runner（`.mjs` 脚本测 web 形态，vitest 测桌面端），CI 同时跑两套（维护两套）
- **选项 3**：桌面端测试只覆盖 `electron/` 内逻辑，主线脚本测试在 P4-1 后退役

**建议选项 1**，但需在 P3-1 之前先定，否则 P3 的每个批次都要同时维护两套测试。

### 5.2 根 `package.json`

- **保留** `@earendil-works/pi-coding-agent: 1.1.0`（桌面端 `electron/src/main/backend/agent/pi-runtime.ts` 直接 import）
- **删除** `express`（桌面端不监听端口）；`undici` / `typebox` / `geojson-vt` / `vt-pbf` / `xlsx` 保留（tiler 与 Office 链路用）
- `codemirror` 系 7 个依赖：fork 的 `electron/package.json` **未列**，需确认是改用别家编辑器还是遗漏——**待核**。

### 5.3 外部二进制

- `officecli`：随安装器分发，fork 已有 `scripts/tools/install-officecli.mjs`
- **ODA / LibreDWG 便携转换器**（若采纳 v0.13.14 的 CAD 取件）：DWG 预览与写回依赖，需确认分发方式与许可证

### 5.4 打包配置的坑（fork 已踩过，直接继承）

`electron/electron-builder.yml` 里三条约定必须原样保留，否则打包后运行时才炸：

1. **`asar: false`** —— `runScript` 以物理 node 子进程执行 `scripts/tools/*.mjs`，asar 内无法直接 exec
2. **`extraFiles` 白名单** —— `tiler.mjs` 的 ESM 解析树（`geojson-vt` / `vt-pbf` / `pbf` 3 与 4 双版本 / `ieee754` / `resolve-protobuf-schema` / `protocol-buffers-schema` / `@mapbox/*`）必须逐个复制；`vt-pbf` 升级时同步更新此白名单
3. **运行时目录锚点** —— `.oaw/`、`.规聚会话/`、`maps/`、`office-workspace/` 锚 `PROJECT_DIR` = 应用根目录，per-user 安装（`LocalAppData\Programs`）需可写

## 6. 风险与回滚

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| TS 化重写引入行为偏差（尤其 `agent.mjs` 装配与记忆调度） | 高 | 高 | 每批 P3 单独验；桌面端与 web 形态同场景对拍 |
| 两套 runner 的测试覆盖重叠/空洞 | 高 | 中 | P5 先行定方案，不留"两边都以为对方测了" |
| IPC 通道与 SSE 事件语义漂移 | 中 | 高 | P2 契约对齐 + 事件注册表校验脚本 |
| Vite 5→6 与 Electron 37 的构建/渲染回归 | 中 | 中 | P1-3 单独验收打包产物，不与功能移植同批 |
| `electron-builder` 外部依赖白名单腐化 | 中 | 高 | 保留 `verify-nsis-install.mjs` 作门禁 |
| 桌面端落后主线的功能债累积 | 高 | 中 | P3 批次清单按批次验收，不攒到最后 |
| `officecli` / ODA 等外部二进制分发与许可 | 中 | 中 | P4-2 明确分发与更新通道 |

**回滚**：

- P1–P3 每阶段独立提交，用户确认后逐阶段合并（按 ADR 0020，分支创建需用户确认）。
- 任一阶段失败：删除 `electron/` 目录即回到 web 形态，主线功能不受影响（这是"目录级迁入、最后才切换形态"的设计目的）。
- 形态切换（P4-1）之后回滚成本显著上升——**因此 P4 之前保持桌面端为可选形态**。
