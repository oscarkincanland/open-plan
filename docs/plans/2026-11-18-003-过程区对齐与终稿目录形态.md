> 决策（用户 2026-11-18 确认）：D1=A 对话终稿去掉目录条与复制按钮（保留编号标题）；D2=A 保留发丝线。
> 范围：会话流过程区对齐（明确缺陷）+ 终稿目录条形态（设计口径，含用户选项）。

## 1. 取证结论

### 1.1 图一：对齐（真实缺陷，需修）

折叠体内五级左缘错位（DOM 实测）：

| 元素 | left | 来源 |
|---|---|---|
| 折叠条 `.run-fold-head` | 38px | — |
| 组头 `.tl-group-head` | 47px | `.tl-list { padding-left: 8px }` |
| 组体 `.tl-group-body` | 53px | rail `margin 6px + padding 8px`（DSH 设计） |
| 思考行 `.tl-row-think` | 62px | 行内缩进 |
| 旁白/小结正文 `.textblock` | 85px | **基线遗留 `padding-left: 38px`**，v3 未覆盖 |

根因：`.tl-list .textblock { padding: 2px 8px 4px 38px }`（基线 2026-11-07 的对齐规则，锚定当时的卡片列），v3 行式化后旁白仍按旧轴缩进 → 与组头/行头错开 38px。

**修复**：v3 下折叠体内旁白正文与组头同轴——`[data-transcript-v3] .tl-list:not(.tl-list-replies) .textblock { padding-left: 0 }`（左缘回到 47px，与组头/行头一致；右/上下内边距保持）。折叠体外终稿（`.tl-list-replies`）已是 38px 轴，与折叠条对齐，不动。

### 1.2 图一：蓝框与分割线（解释 + 可选项）

- **完整蓝框**：是点击展开组头后留下的**键盘焦点描边**（`:focus-visible { outline: 2px solid var(--accent) }`，无障碍必需）。不是分割线，不做删除；可选优化为更淡/内缩（见决策点）。
- **横向发丝线**：组头/行头下的 `0.5px` 底线是 DSH 过程行设计的一部分（实测因 DPR 渲染为 1px 视觉线）。每个组头都有一条 → 满屏线密度偏高。可选减弱（见决策点）。

### 1.3 图二：终稿"像老版 md 渲染"（设计口径）

DOM 证实终稿已走新路径（正文常显在折叠体外、编号 h2、无任何 md 文件内嵌/iframe/chip）。观感"老版"的来源：**目录条（md-doc-bar）+ 复制 Markdown 与 md 文档预览（DocViewer）是同一套组件**，且目录条横排 wrap 铺了两行（14px 字号 + flex row wrap），在对话流里像"打开了文档页眉"。
