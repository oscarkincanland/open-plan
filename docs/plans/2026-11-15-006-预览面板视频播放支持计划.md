# 预览面板视频播放支持计划

> 日期：2026-11-15　基线：v0.13.25（develop）　状态：**已确认**（2026-11-15 用户确认，进入实施）
> 关联需求：REQUIREMENTS.md R1 文档办公与预览（扩展预览格式）　关联设计：DESIGN.md §8（预览头部/能力声明）
> 前置：[2026-11-15-005 创作画布视频元素支持计划](2026-11-15-005-创作画布视频元素支持计划.md) 已落地，视频素材/格式口径（mp4/webm/ogv）沿用该计划。

## 1. 背景与目标

画布已支持 `video` 元素，但预览面板打开 `.mp4/.webm/.ogv` 文件仍显示「无法内嵌预览」占位页。本计划让工作区文件预览（文件树点击、产物卡片点开、Markdown 结论里的本地视频链接）都能内嵌播放视频。

**依赖说明（回应"增加这些依赖"）**：本次**不引入任何新 npm 依赖**——浏览器原生 `<video>` 元素即可播放；文件类型图标复用已装依赖 `@tabler/icons-react` 的 `IconMovie` 字形。无需新增包、无安装动作。

## 2. 现状与证据

| 关注点 | 现状 | 位置 |
|---|---|---|
| `/api/doc/:rel` 类型分派 | 无视频分支，`.mp4` 等落入 else → `kind:"html"` → OfficeCLI 渲染二进制失败 → 「无法内嵌预览」占位页 | [server/index.mjs#L1414-L1476](../../server/index.mjs) |
| `/raw` 原始流路由 | mimeMap 无视频 MIME（回落 octet-stream）；`res.sendFile` 原生支持 Range 请求（视频 seek 无需改造） | [server/index.mjs#L1348-L1389](../../server/index.mjs) |

| 预览能力矩阵 | `PREVIEW_CAPABILITIES` 无视频条目 | [client/src/预览能力.js#L8-L72](../../client/src/预览能力.js) |

## 3. 方案设计

### 3.1 服务端（server/index.mjs）

1. `/api/doc/:rel` 分派新增 `VIDEO_EXTENSIONS = new Set(["mp4", "webm", "ogv"])`：命中返回 `kind:"video"` + `url: /api/doc/:rel/raw`（与 image 同构）。
2. `/raw` 路由 mimeMap 补 `mp4→video/mp4`、`webm→video/webm`、`ogv→video/ogg`；`res.sendFile` 自带 Range/ETag 支持，进度条拖动与 304 缓存开箱即用；安全头沿用现状（视频非脚本类型，不加 SVG 式 sandbox CSP）。

### 3.2 前端

1. 新增 [VideoViewer.jsx](../../client/src/components/VideoViewer.jsx)（与 ImageViewer 同构的最小组件）：
   - 工具条：格式徽标（MP4/WEBM/OGV）、「打开原文件」「在文件管理器中显示」；
   - 主体：`<video controls playsInline preload="metadata" src={doc.url}>`，等比自适应容器（不做缩放档位，视频与图片查看诉求不同）；
   - 状态：`canplay` → ready，`error` → failed（提示损坏或不可读），保留 `onPreviewState/onPreviewError` 契约与文件身份核对（切文件不串内容）。
2. [DocViewer.jsx](../../client/src/components/DocViewer.jsx) 增加 `doc.kind === "video"` → `<VideoViewer>` 分支。
3. [预览能力.js](../../client/src/预览能力.js)：`mp4/webm/ogv → { level: "full", label: "视频", detail: "浏览器视频播放器：进度条、音量、全屏；拖动进度条按 Range 分段加载。", editable: "只读" }`。
4. 图标链路：[产物类型.js](../../client/src/产物类型.js) `EXT_KINDS` 加 `mp4/webm/ogv → { icon: "video", label: "视频" }`，`KIND_BY_ICON` 加 `video: ["video", "video"]`；[文件类型图标.jsx](../../client/src/components/文件类型图标.jsx) `GLYPHS.video = IconMovie`；styles.css 增加 `--file-video` 颜色令牌（明暗双主题各一处，与既有 `--file-*` 同位）。
5. Markdown 结论内 `.mp4` 链接经 `LOCAL_FILE_EXTS` 自动放行，点击打开视频预览。

### 3.3 不做清单

- 不做视频转码/封面提取（无 poster 的视频由浏览器渲染首帧或黑帧，不阻塞）。
- 不做音频元素（audio）预览，另行评估。
- 不引入任何新 npm 依赖。
- 画布产物（designs/<slug>/project/**）不进产物台账的口径不变——视频预览面向文件树/产物卡/结论链接三条入口。
