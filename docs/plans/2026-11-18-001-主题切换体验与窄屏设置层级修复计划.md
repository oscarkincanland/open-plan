## 1. 背景与证据（已实测）

2026-11-17 对主题切换做了代码静态分析 + 真实浏览器实测，结论：

1. **单次点击功能正常**：侧栏切换按钮、设置面板"主题"按钮、工作台风格皮肤按钮均一次点击生效（浏览器实测 3/3 通过，`data-theme`、active 态、刷新持久均正确）。用户感知的"要选两次"来自：主题与皮肤是两个独立控件、切换为瞬间硬切无过渡、刷新闪屏。
2. **刷新闪屏（真实缺陷，违反 PRD R8「切换不闪白」的刷新场景）**：`client/index.html` 未在首帧前预置 `data-theme`/`data-skin`，`theme.jsx` 要到 React `useEffect` 才挂属性——亮色用户每次刷新先渲染暗色再跳亮色。
3. **重复亮色令牌块（令牌债务 + 文档漂移）**：`styles.css` 存在**4 处**裸 `[data-theme="light"]` 块（实施期复核修订，初判 2 处）——L120（v0.3.0 文档基线，青绿 `--accent: #2a8c82`）、L5974（0.10 壳层，绿色 `--accent: #628d28`）、L9323（无障碍复验后绿色 `--accent: #638e2d`，注释与《会话流前端规范》§10.1 亮色 4.66:1 复验值吻合）、L14227（CAD 描边 `--oaw-cad-ink` 单变量块）。同特异性按源码顺序后者覆盖前者，**当前实际生效是 L9323 绿色版**，且 DESIGN §5.3 仍记载青绿版——代码与设计文档不一致。
4. **窄屏 z-index 缺陷（浏览器实测复现）**：`@media (max-width: 768px)` 时 `.app-canvas-slot` 变为 `position: fixed; z-index: var(--z-overlay)`（260，styles.css L13821-13832），而设置浮层 `.module-view` 仅裸 `z-index: 30`（L9842）——598px 宽下画布绘制在设置浮层之上并拦截点击（elementFromPoint 返回画布，设置控件不可达）。
5. **皮肤选择语义不明**：皮肤只覆盖 `--accent`/`--success`（styles.css L7264-7271），明暗由"主题"控制；界面无任何说明，构成"两次选择"困惑的来源之一。

## 2. 目标

- 刷新首帧即正确主题，无暗→亮闪屏（R8）。
- 主题/皮肤切换获得平滑交叉淡入过渡（View Transition API），减少"硬切没点上"的感知；减少动效偏好下完全跳过。
- 消除重复亮色令牌块，令牌值收敛为当前实际生效值，DESIGN §5.3 同步真实值。
- 窄屏（≤768px）下设置模块浮层可正常点击，不被固定画布槽遮挡（R8/N5 窄屏可完成核心操作）。
- 皮肤选择行补充语义提示，缓解"主题/皮肤要选两次"的困惑。

## 3. 范围与不做清单

**做**：上面 §2 的 5 项；配套回归测试与文档同步。

**不做（明确排除，避免夹带）**：

- 不改 P1 动效现代化（`steps(48)` 扫光改平滑、全站脉冲周期收敛、霓虹/多彩跑马灯退役）——涉及《会话流前端规范》§8 与 DESIGN §11 强制条款修订，需单独走规范修订与确认，另立计划。
- 不合并主题与皮肤为单一"预设"控件（产品形态改动，需 PRD/DESIGN 修订）。
- 不改皮肤色值本身（7 套皮肤色板维持现状）。
- 不引入 motion / framer-motion 等动效库（DESIGN 不做清单：不新增 UI 框架）。
- 不动 Qoder 视觉层（`data-oaw-style`）与 glass 皮肤的局部亮色覆盖。

## 4. 实施步骤

### 4.1 index.html 首帧预置主题（FOUC 修复）

- [ ] 在现有 reduce-motion 内联脚本之后新增一段内联脚本：从 `localStorage` 读 `oaw_theme`（白名单 `dark|light`，默认 `dark`）与 `oaw_skin`（白名单 7 个皮肤 id，默认 `default`），在首帧前写 `document.documentElement.dataset.theme / dataset.skin`；全程 try/catch（隐私模式等异常回落默认暗色）。
- [ ] 加载占位 `<div id="root">` 内联样式改为 `background: var(--body-bg, #1a1a2e); color: var(--muted, #8a8fa3)`——样式表加载后自动跟随主题，加载前回落现值。
- [ ] 白名单与 `theme.jsx` 的 `THEMES`/`SKINS` 保持同源：新增同步守护测试（见 §4.5），防止两处清单漂移。

### 4.2 theme.jsx View Transition 平滑切换

- [ ] 抽出 `applyDocumentAttributes({ theme, skin })`：写 `data-theme`/`data-skin` 两个属性。
- [ ] 当 `document.startViewTransition` 存在且动效闸门未命中（复用 `界面外观.js` 的 `isMotionReduced()`：系统减少动效或外观设置"关闭动效"）时，属性写入包进 `document.startViewTransition(...)`；否则直接写（现行为）。localStorage 持久化不进过渡回调。
- [ ] 不新增循环依赖：`theme.jsx` → `界面外观.js` 为单向 import（后者不 import 前者）。
- [ ] 旧浏览器（无 `startViewTransition`）行为与现状完全一致。

### 4.3 styles.css 亮色令牌块合并

- [x] 将 **4 处**裸 `[data-theme="light"]` 块（实施期复核修订，初判 2 处）合并为一处：**以当前实际生效值为准**（重叠变量取无障碍复验后的最后生效块：`--body-bg:#f5f7f4`、`--accent:#638e2d` 等；初版 L120 独有变量如 `--panel-bg`、状态色、文件类型图标色、源码高亮色全部保留；CAD 的 `--oaw-cad-ink` 亮色值并入唯一块）。合并后全文件只允许存在一个裸 `[data-theme="light"]` 令牌块（由 `test:theme-appearance` 守护）。
- [x] 三处旧块原位留一行指向注释，不改动其他区段任何选择器。
- [x] 硬编码色值净变化只减不增（设计令牌棘轮：不新增 hex；合并可能减少，允许）。
- [ ] **用户可见结果为零变化**（合并前后计算值一致）——用浏览器实测对比切换前后取值验证（见 §6.2）。

### 4.4 窄屏设置层级 + 皮肤选择提示

- [ ] `@media (max-width: 768px)` 内为 `.module-view` 增加 `z-index: var(--z-drawer)`（270 > 画布槽 `--z-overlay` 260），仅窄屏生效，宽屏层叠行为不变。
- [ ] 实施时审计 z-index 60–120 区间且经 portal 挂到 `body` 的弹层（如 `prov-dialog-backdrop` z60）：确认它们要么是 `.module-view` 子节点（随上下文整体抬升），要么 z ≥ 270；存在例外则在该例外处单独说明与处理。
- [ ] `SettingsPanel.jsx` 皮肤行下方补一行说明文案：「工作台风格只切换强调色，明暗由上方主题控制」，样式沿用既有设置面板次要文字规格（`--muted`，不新增字号/色值）。

## 7. 风险与假设

- `startViewTransition` 全文档快照在低端机有单帧成本：已用动效闸门旁路，且切换属低频操作；Safari <18 / Firefox 旧版无该 API，回落直切（与现状一致）。
- `index.html` 内联白名单与 `theme.jsx` 存在双份事实：以同步守护测试压住；后续若嫌重复可改为构建期注入，不在本次范围。
- 亮色令牌合并以"当前生效值"为准（推荐项）：视觉零变化、只修文档漂移；若你希望恢复 DESIGN §5.3 原记载的青绿亮色主题（`--accent:#2a8c82`），请在确认时说明，改为以文档值为准（会有可见的颜色变化）。
- G1 需要本机有含消息的会话；服务不可达时 ui-smoke 退出码 2（跳过），不得当作通过写入交付说明。
