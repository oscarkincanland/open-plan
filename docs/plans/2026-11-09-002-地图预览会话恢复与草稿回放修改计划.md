## 0. 决策摘要（用户 2026-11-09 确认“地图预览改口径”）

| # | 决策 | 落地含义 |
|---|---|---|
| D1 | **点击最近会话即带出地图预览**（用户已确认） | 不再要求“画布为空”才打开；地图会话被用户显式点击时，打开并**激活**“地图预览”标签（显式导航动作，不算抢占）。激活方式见 §10 待确认。 |
| D2 | **草稿层只读回放**（用户已确认） | 预览除正式图层外，一并显示该会话/项目的 agent 草稿层（只读、虚线 + “未固化”标记），刷新/重启后可恢复；预览内不提供固化。 |
| D3 | **提供手动入口**（配套口径） | 画布 `+` 菜单增加“地图预览”入口；当前会话无地图绑定时禁用并说明。 |
| D4 | **视口一致性**（配套口径） | 恢复的 `center/zoom` 必须真正生效：地图模块不得用默认相机覆盖会话视口；最后一次视口不得因去抖丢失。 |
| D5 | **归档恢复联动**（**提议，待确认**） | 归档会话点“恢复会话”后自动选中该会话（有地图绑定则同时带出预览）。 |
| D6 | **只读边界不变**（配套口径） | 预览仍不可固化、不可写正式层、不可编辑草稿；写操作一律在地图模块（Work）内完成。 |

## 1. 背景与现状

### 1.1 现状链路（证据）

| 环节 | 现状行为 | 证据 |
|---|---|---|
| 会话 header | 持久化 `mapProject` + 视口白名单（center/zoom/bounds/regionName/updatedAt），变化 1.5s 后写 header | `App.jsx:1395-1409`、`client/src/地图/地图上下文.js:22-57` |
| 点会话恢复 | 回填 `mapContexts`；仅当“画布为空”或“已有预览标签”时 `openCanvasView("mapPreview")`，其他情况静默跳过 | `App.jsx:1782-1811` |
| 兜底自动打开 | 地图上下文就绪后，若画布为空才自动开预览 | `App.jsx:1413-1439` |
| 预览渲染 | `MiniMapPreview` 拉 `map.config.json` + `style.json`，只渲染正式层；未传 `drafts` | `MiniMapPreview.jsx:14-61` |
| 草稿层 | Agent 只写 `agent/drafts/`，不进 `layers/`、`style.json`、`tiles/`、`map.config.json`；只有 `MapPanel` 把 drafts 传给 `MapViewer` | `server/map.mjs:1675-1684`、`MapPanel.jsx:2351` |
| 预览标签身份 | `mapPreview` 为单例，且刷新不恢复（按会话跟随） | `画布状态.js:17`、`:157` |
| 地图模块视口 | `MapViewer` 初始化即 `publishViewport()`；`MapPanel` 未传 `initialView`，上报的是默认相机 | `MapViewer.jsx:630-635`、`MapPanel.jsx:2347-2358` |
| 归档恢复 | 只调 `archiveSession(id,false)` + 刷新列表，不选会话、不开预览 | `SessionSidebar.jsx:191`、`SettingsPanel.jsx:321-347` |

### 1.2 失效场景（用户可感知）

| 场景 | 现状结果 | 根因 |
|---|---|---|
| a. 空画布点地图会话 | 预览打开（仅正式层） | 正常路径 |
| b. 画布已有产物/文档标签 | **不打开，且预览内无入口** | `App.jsx:1797` 的 `!openTabs.length \|\| openTabs.some(mapPreview)` 条件 |
| c. 会话 A(项目X) → B(项目Y) | 预览同步 payload；同项目不同会话可能不重挂，视口停在旧会话 | `MiniMapPreview.jsx:55` key 只含 `project:updatedAt` |
| d. 切到无地图绑定会话 | 关闭预览（正常）；副作用是留下其他标签导致 (b) 复现 | `App.jsx:1804-1811` |
| e. 归档“恢复会话” | 不选会话、不开预览 | 恢复动作只改归档状态 |
| f. 仅草稿层（未固化） | **不显示** | 预览不读 `agent/drafts` |
| g. 视口 | 常被地图模块默认相机覆盖；1.5s 去抖可能丢最后一次；列表缓存 5s 可能回传旧视口 | 见 1.1 |
| h. 刷新后 | 画布空→自动开；有持久化标签→回到 (b) | 预览不持久化 |

### 1.3 根因归纳

1. “是否打开预览”被绑定在“画布是否为空”上，而画布通常已有标签。
2. 预览数据源只有正式层，草稿层被设计为“不回放”。
3. 视口写入链存在“默认相机 → 覆盖 header”的反向覆盖。
4. 归档恢复与会话选择是两条不连通的路径。

## 2. 目标 / 非目标 / 成功标准

### 2.1 目标

1. 点击任一最近会话：若该会话绑定地图项目，画布出现并激活“地图预览”标签，显示可见正式层 + 未固化草稿层 + 该会话上次视口。
2. 预览内可辨草稿（虚线/角标），并明确“只读，需到地图模块固化”。
3. 多会话切换时预览始终与当前会话一致，不出现项目/视口错配。
4. 归档会话恢复后可直接回到该会话并看到地图。
5. 不引入新依赖、不新增服务；预览性能在草稿数据上限内可控。

### 2.2 非目标

- 不做预览内固化、编辑、导入、下钻。
- 不承诺刷新时长 SLA（沿用“事件驱动 + 手动刷新”口径）。
- 不做跨工作区预览、不做预览视口上报回写（预览只读）。
- 不改地图模块的图层树/审批语义。

### 2.3 成功标准

- 场景 a–h 全部符合下表期望（见 §6 验收）。
- 草稿生成/更新/丢弃后，打开该会话的预览能显示/移除对应草稿（事件驱动，无时长承诺）。
- 地图模块打开时不覆盖会话 header 中保存的视口。
- 预览不可触发任何写入（无 `map_*` 写工具、无 REST 写、无固化入口）。

## 3. 产品规则变更（PRD / DESIGN 待确认文案）

> 按 `AGENTS.md` §3/§4.3：PRD 范围与 DESIGN 交互条款的修改需用户确认。以下为**待确认文案**，本计划不改正文。

### 3.1 `REQUIREMENTS.md` R10 “初始页地图预览”条目（现第 279 行）

**现文案（摘要）**：选择带地图绑定的会话时，画布自动打开“地图预览”标签；画布已有其他标签时不抢占当前视图；正式文件变更后刷新；草稿层不回放。

**建议新文案**：

> 初始页/侧栏选择带地图绑定的会话时，画布打开并激活“地图预览”标签（显式点击视为导航动作，不视为抢占），加载项目全部可见正式图层、该会话未固化草稿层（只读、虚线 + “未固化”标记）与上次视口；预览内不提供固化/编辑。画布已有其他标签时追加预览标签而非替换；无地图绑定的会话关闭预览。`+` 菜单提供“地图预览（当前会话）”手动入口。正式文件与草稿（`style.json` / `map.config.json` / `layers/` / `agent/drafts/`）变更后由事件驱动刷新（不承诺时长），手动刷新可恢复。**（若采纳 D5）** 归档会话“恢复会话”后自动选中该会话。

### 3.2 `REQUIREMENTS.md` R10 验收条目（现第 298 行）

**现文案**：初始页选择地图会话时画布打开只读“地图预览”标签并显示可见图层；重启后 `mapProject/mapView` 仍可恢复；正式文件/草稿变更后由事件驱动刷新（不承诺秒数），手动刷新可恢复；草稿层不回放为正式层。

**建议新文案**：

> 点选带地图绑定的会话即打开并激活只读“地图预览”标签；画布已有其他标签时追加而不替换；重启后 `mapProject/mapView` 仍可恢复且视口与上次一致；正式文件/草稿变更后由事件驱动刷新（不承诺秒数），手动刷新可恢复；**草稿层以只读形式回放（不进入正式层，不提供固化）**；预览内任何操作不得产生写入。

### 3.3 `DESIGN.md` §9.3 初始页地图预览条目（现第 385 行）

**现文案（摘要）**：画布为空时选择带地图绑定的会话，自动打开“地图预览”单例标签；不抢占已有画布标签；草稿层不回放。

**建议新文案**：

> 点选带地图绑定的会话时，画布打开并激活“地图预览”单例标签，内嵌只读小地图（项目名 + 可见图层数 + 草稿数 + 上次视口）；已有其他标签时追加标签并激活，不替换、不关闭用户标签。小地图隐藏导入工具条、属性弹窗与下钻，不提供固化；草稿层以虚线 + “未固化”角标只读显示。提供“继续编辑地图”入口进入地图模块（进入前切 Work）。`+` 菜单提供“地图预览（当前会话）”入口，无绑定则禁用并提示。地图正式文件与草稿变更后事件驱动刷新（不承诺时长）；手动刷新可恢复。

### 3.4 是否需要 ADR

本计划不改工具白名单、不新增依赖、不改变事件语义，**不需要新增 ADR**；若评审认为“草稿回放/抢占口径”属于产品范围级变更，可补一条 ADR（若创作画布占用 0031，则本项建议 0032），由用户决定。

## 4. 技术方案（模块级）

### 4.1 抽出纯函数：预览决策策略

新增 `client/src/地图/预览策略.js`（无 React 依赖，供 App 与 Node 测试复用）：

```js
// resolveMapPreviewAction({ session, previewTab, openTabs, userInitiated })
// → { type: "close" | "open" | "update" | "none", payload?, activate?: boolean }
```

规则表：

| 输入 | 输出 |
|---|---|
| 会话无 `mapProject` 且存在预览 | `close` |
| 会话无 `mapProject` 且无预览 | `none` |
| 有 `mapProject`、无预览、userInitiated=true | `open` + `activate: true` |
| 有 `mapProject`、无预览、事件驱动 | `open` + `activate: false` |
| 有 `mapProject`、已有预览、payload 不同 | `update`（sessionId/project/view/updatedAt 一并更新） |
| 有 `mapProject`、已有预览、payload 相同 | `none` |

要点：`payload.sessionId` 必须与当前会话一致；`updatedAt` 变化视为需要同步，用于触发 `MiniMapPreview` 重挂。

### 4.2 App 接线

| 文件 | 改动 |

| `App.jsx:1413-1439` | 兜底 effect 改为调用同一纯函数（`userInitiated: false`，只补建/同步、不激活）；删除 `if (openTabs.length > 0) return;`。 |

### 4.3 预览草稿回放

### 4.6 归档恢复联动

| 文件 | 改动 |
|---|---|

### 4.7 失败与降级

- 草稿拉取失败：预览仍显示正式层，头部提示“草稿加载失败 + 重试”，不阻塞地图。
- 草稿 geojson 单条超过 20MB / 5 万要素：由服务端既有上限拒绝；预览跳过并计数提示。
- 会话 header 缺失/损坏：回退 `none`，不报错。

## 6. 验收口径

| # | 验收 | 判定 |

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 草稿体量大（单条上限 20MB / 5 万要素） | 小地图卡顿 | 预览最多加载 20 条、按 `visible` 过滤；超大草稿跳过并提示；后续可加简化几何 |
| 点击会话即激活预览打扰用户 | 体验争议 | 只对**显式点击**激活；agent 事件/刷新不激活；可在设置中恢复“后台打开”偏好（后续） |
| 视口覆盖链未全定位 | A7 不达标 | P3 先写“默认相机覆盖”回归测试再改；以 `initialView` 传入为唯一入口 |
| 会话列表缓存 | 视口回传旧值 | 写 map-context 后显式失效缓存；测试断言缓存键被清 |
| 归档恢复跨工作区 | 选会话失败 | 先切工作区再选；失败给可理解提示 |
| 改动 PRD/DESIGN 需确认 | 阻塞 P0 | 先只落计划，确认后再改正文 |
