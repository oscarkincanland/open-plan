## 0. 结论先行

1. **本项目的 Office 写作能力是"三条腿、缺一条神经"**：OfficeCLI 负责编辑、原生引擎负责生成、`templates/traffic-material/` 负责内容骨架；缺的是把它们串起来的路由与验收神经。
2. **模板化写作是最有价值的既有资产，必须保留并升级为默认路径**：14 个交通规划模板、4,920 行，工可模板 451 行含十章结构、11 图 8 表清单、字号缩进规则、16 条常见错误。但实测"写一个工可材料"在能力计划里完全静默。
3. **`design-system.md` 不在本项目中**，ZCode 那套 80KB 设计系统只存在于 ZCode 安装目录；本项目需要的是"版式参数模块"，不是复制一套提示词。
4. **ask_user 已存在且提示词要求"必须问"**，但触发依赖模型自觉、只覆盖"撰写文字"、流水线不能问、单槽位会被并发覆盖。
5. **本次不做新文档生成器**，只做四件事：补路由、补规范参数、补模板接线、补确定性验收。合计 **28 项功能、37 个任务、约 26.3 人日**。

## 2. 目标与边界

### 2.1 目标

1. 用户说"改这份文档" → 稳定走编辑路由（先读后改，保留原格式）。
2. 用户说"写一个工可材料 / 写一份汇报" → **优先走模板路由**（匹配 14 个模板 → 按模板章节写 → 按模板规则验收）。
3. 没有模板可匹配 → 走生成路由（场景查表 → 版式参数 → 生成 → 后处理 → 规则闸门）。
4. 关键信息不足时，**在正确的时机强制问一次**，而不是问很多或什么都不问。
5. 每次产出都有确定性结论（模板覆盖率 + 规则闸门），可进 CI。

**成功判据（一句话）**：同一个"工可/报告"请求连续跑 3 次，模板必备章节覆盖率 100%、字号行距缩进页边距四组参数逐字节一致、规则闸门 0 error。

### 2.2 不做清单

| 不做 | 理由 |
|---|---|
| 引入 LibreOffice / pandoc / poppler 作为运行时依赖 | 与 OfficeCLI 能力重叠，新增系统依赖需 ADR |
| 复制 ZCode `documents/0.1.8` 整包 | 依赖链重叠，违反单一事实来源 |
| 新建 `templates/office/` 或第二套模板体系 | `templates/traffic-material/` 已有 14 个模板与完整链路 |
| 改写/替换 `templates/traffic-material/` 模板正文 | 模板承载领域知识与案例口径，本次只做识别/抽取/验收 |
| 用场景参数表替代模板 | 参数表管版式数值，模板管内容骨架，不可互换 |
| 多模态视觉验收（visual-judge） | 无该链路；改用规则闸门 + 人工 L4 |
| 并发 > 1 的 Office 执行 | `officeLimiter` 并发 1 是既定契约，优化另立计划 |
| 自动重排既有文档 | 违反"保留原格式"承诺 |
| 修改 Pi 内核或新增产品模式 | 违反 AGENTS.md §5.1 |
| 在 `.claude/skills/` 内新增第二份版式参数 | 违反单一事实来源 |

### 2.3 设计原则

1. **模板优先**：能匹配模板就走模板路由；规范层只补模板未覆盖的排版细节，不得覆盖模板。
2. **单一事实来源**：版式参数只在 `server/office规范/`；模板正文只在 `templates/traffic-material/`。
3. **规范层不进工具白名单**：P0 不新增模型可见工具，规范由现有工具内部消费。
4. **编辑不重排**：改字场景只检查与提示，不重排。
5. **澄清只问最阻塞的一项**：缺 ≥2 项才问，问一个，其余按默认值并在产物标注假设。
6. **验收分两级**：规则闸门进 CI；视觉抽检只做人工 L4。

## 3. 目标架构

### 3.1 四路由工作流

```text
用户输入（"改这份报告" / "写一个工可材料" / "写一份汇报" / "看看这份文档"）
        │
        ▼
server/task.mjs  路由判定（四路由，按优先级）
   ├─ 显式 @模板 / 文体关键词命中 ──> template = preferred      （模板路由）
   ├─ 命中既有 Office 文件 ────────> officecli = preferred      （编辑路由）
   ├─ 有生成意图且无模板/既有文件 ─> office_generate = preferred（生成路由）
   └─ 仅读取意图 ─────────────────> documentRead               （只读路由）
        │
        ├── 模板路由
        │     tpl.resolveTemplatePath → 读取模板正文
        │     → 抽取必备章节 / 必备图表 / 格式规则 / 常见错误
        │     → 按模板逐章写作（Writer）
        │     → 模板覆盖率验收
        │     → 规范层补模板未覆盖的排版细节（字号兜底、封面、页码）
        │
        ├── 编辑路由 ──> view text|outline 定位 → get 取 paraId → set/add/batch
        │                 → 规范层只输出"偏离项"，不自动重排
        │
        └── 生成路由（无模板兜底）
                          → 场景参数表 → 版式令牌
                          → 原生 docx 生成器（blocks v2）
                          → 目录/页码后处理
                          → 规则闸门（9 项）
                          → 产物验证 → 产物面板
        │
        ▼
澄清闸门（信息不足时）：缺 ≥2 项 → ask_user 问 1 个（选项来自场景表）
        │
        ▼
验收层：模板覆盖率 + officecli view issues + 人工渲染抽检（L4）
```

### 3.2 三层职责

| 层 | 负责 | 不负责 |
|---|---|---|
| 路由层（`server/task.mjs`） | 判定走哪条路、声明能力、给出 reason | 不写文件、不读模板正文 |
| 规范层（`server/office规范/`） | 版式参数、封面布局、场景表、模板结构、规则闸门 | 不生成文件、不改模板 |
| 执行层（OfficeCLI / 原生引擎 / 流水线） | 真正读写文件 | 不判断"该不该写" |

| `server/office规范/设计令牌.mjs` | 字号/行距/缩进/页边距/配色 | 生成器、流水线、验收 |
