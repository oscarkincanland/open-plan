## 0. 结论先行

| 问题 | 结论 |
|---|---|
| 设置里有没有「工具调用 45 轮强制收尾」？ | **没有这个设置项，也不是工具调用 45 轮。** 45 是**模型回合（turn）**的硬阈值；工具调用另有 80/160 的软/硬阈值。 |
| 45 轮时会不会强制收尾？ | **会进入「受限收尾」**：禁止改文件类工具，但允许只读、`todo`、`ask_user`、`memory_update`；默认 `soft` 模式**不会 abort 整个 Run**，模型仍可继续只读回合。 |
| 为什么看起来像「工具调用 45 轮」？ | 2026-11-03 14:55 的真实 Run 恰好 `turns=45`、`toolCalls=45`，两个数字相同；而工作流启动器又展示了 `45 次工具` 的预算，容易混淆。 |
| 有没有 UI 可以改？ | 没有。阈值是 `server/运行预算.mjs` 的常量，只能改代码或少数环境变量；项目/任务配置不会覆盖它。 |
| 还发现了什么？ | 三处接线缺口：① 软预算提示说「继续即增加预算」，但 `grantBudget()` **从未被调用**；② `noteEffective()` / `noteWaiting()` **从未被调用**，所以 45/90 分钟的时长预算实际上永远不会触发；③ 工具 160 次硬预算默认只发事件，真正的工具级拦截只在 `OAW_PI_TOOL_GATE=on` 时生效（默认关）。 |

## 1. 三套预算，不要混在一起

### 1.1 全局运行预算（真正生效）

`server/运行预算.mjs:16-21`：

| 维度 | 软预算 | 硬预算 | 触发后的行为 |
|---|---:|---:|---|
| 模型回合 `turns` | 25 | **45** | 25：提示阶段结论并询问是否继续；45：进入受限收尾，禁止改文件 |
| 工具调用 `toolCalls` | 80 | 160 | 80：提示收束；160：**默认只发事件**——真正的工具级拦截只在 `OAW_PI_TOOL_GATE=on` 时由 Pi 扩展执行（默认关，见 §1.3） |
| 有效执行时长 | 45 min | 90 min | **当前不会触发**（见 §4.2） |
| 连续失败 | — | 同一指纹 2 次 | 停止该操作 |
| 重复无进展 | — | 同一指纹 2 次（read 允许 5 次轮询） | 提示换方案/停止 |

### 1.2 轮次提醒（只发提示，不拦截）

`server/轮次预算.mjs:15-20` 另有一套 25/45 的提醒文案：

- 第 25 轮：`turn-budget`，要求阶段结论并 `ask_user` 询问是否继续；
- 第 45 轮：`turn-budget-hard`，要求立即收尾；
- 每 6 轮：`turn-progress` 进度小结（`OAW_TURN_PROGRESS_INTERVAL=0` 可关）。

它与 `运行预算` 的 25/45 是**两个独立机制**：前者只注入提示，后者才真正切换 `restricted` 状态。

### 1.3 工具级门禁默认没开

`server/pi-extensions/工作台把关.mjs` 才是把 `evaluateToolGate()` 的 `allow:false` 真正变成 `block:true` 的地方（`tool_call` 扩展点）。但它只在 `OAW_PI_TOOL_GATE=on` 时加载（`server/运行开关.mjs:69` 的 `readFlag` 默认 false）。

因此默认配置下：

- 45 回合的 `restricted` 是**真的**（在 write/edit/bash/officecli/editorial_pipeline 内部逐个拦截）；
- 160 次工具的硬预算**不会阻止工具执行**，只在 `tool_start` 时发 `run_budget_blocked` 事件；
- 同一操作连续失败 2 次 / 重复无进展 2 次的拦截同样依赖这个扩展，默认也不生效。

这会让「预算」在诊断里看起来存在、实际只拦住了「45 回合后的改文件」这一条。

### 1.4 工作流预算（只展示，不执行）

`server/工作流/*.mjs` 声明了 `budget: { maxTurns, maxToolCalls, maxWallMs }`，例如：

| 工作流 | maxTurns | maxToolCalls | maxWallMs |
|---|---:|---:|---:|
| 数据源接入 | 14 | **45** | 15 min |
| 可达性分析 | 14 | **45** | 15 min |
| OD 需求分析 | 12 | 40 | 15 min |
| 路网评估 | 16 | 50 | 15 min |
| 规范符合性审查 | 18 | 60 | 15 min |
| 报告编排 | 20 | 60 | 15 min |

`client/src/components/工作流启动器.jsx:138-139` 会展示「14 回合 · 45 次工具 · 15 分钟」。但仓库里**没有任何代码消费这三个字段**（只有注册表校验和前端展示），它们目前是说明性预算，不会限制 Run。

> 因此：用户看到的「45」可能来自两处——全局 45 个模型回合，或工作流卡片的「45 次工具」。真正的强制收尾只认前者。

## 2. 45 回合时到底发生了什么

`server/agent.mjs:4139-4149`：

```js
const gate = evaluateTurnGate(budget);
if (gate.level) {
  if (gate.level === "hard") enterRestrictedMode(budget);
  emitBudgetEvent(entry, emit, gate.level, gate.code, gate.reason);
  if (gate.level === "hard") stopRunByBudget(entry);
}
```

`stopRunByBudget()` 只在 `OAW_RUN_BUDGET_ENFORCE=hard` 时 abort（`server/agent.mjs:572,597`）。默认 `soft` 下：

1. `restricted = true`；
2. 发 `run_budget_blocked` 事件，执行过程显示「预算阻断：模型回合已达硬预算（45/45），进入受限收尾」；
3. `write` / `edit` / 改文件的 `bash` / 改文档的 `officecli` / `editorial_pipeline` 被 `enforceBudgetRestriction` 拦截；
4. `read` / `grep` / `find` / `ls` / `kb_*` / `context_read` / `todo` / `ask_user` / `memory_update` 仍可用；
5. 模型可以继续输出最终答复，但不能再改文件。

> 注意：受限模式目前只接入了 `write` / `edit` / 改文件的 `bash` / 改文档的 `officecli` / `editorial_pipeline`。地图写入（`map_edit` / `map_import` / `map_save_analysis`）没有调用 `enforceBudgetRestriction`，在 45 回合后仍可写地图。如果“受限收尾”要成为统一安全边界，这些入口也要接入。

### 2.1 真实事件

```
2026-11-03T14:50:37.304Z run_budget_notice  TURN_BUDGET_SOFT  turns=25 toolCalls=26
2026-11-03T14:55:20.424Z run_budget_blocked TURN_BUDGET_HARD  turns=45 toolCalls=45 restricted=true
2026-11-03T14:55:31.858Z run_budget_blocked TURN_BUDGET_HARD  turns=46 toolCalls=46 restricted=true
```

这条 Run 恰好 45 回合 / 45 次工具，是「45 次工具」误读的直接来源。

### 2.2 文案与实现不一致

硬预算文案写的是「**最多一个收尾回合**」，但实现只切换 `restricted`，没有限制「只能再跑一个回合」；事件里已经出现 `46/45` 仍在继续。它实际是「**无限只读收尾**」，不是「一个回合后硬停」。

这会造成两种体验：

- 用户以为已经强制结束，但模型还在读文件、解释、追问；
- 或者模型被禁止改文件，却还在反复读同一批文件，看起来「卡住」。

## 3. 设置里为什么找不到

| 位置 | 是否可配 |
|---|---|
| 设置面板（`SettingsPanel.jsx`） | 无运行预算项 |
| 项目设置（`项目管理.mjs`） | 无 `runBudget` / `maxTurns` 字段 |
| 任务能力计划（`planTaskCapabilities`） | 无预算字段 |
| `createRunBudget({ limits })` | 支持传入，但 `ensureRunBudget()` 调用时**没有传 limits**（`server/agent.mjs:575-585`） |
| 环境变量 | 只有 `OAW_RUN_BUDGET_ENFORCE`（soft/hard/off）与 `OAW_TURN_PROGRESS_INTERVAL`；25/45、80/160、45/90min 都是硬编码常量 |

所以「设置里面」严格来说没有这个开关；要调整只能改代码或改环境变量（且环境变量只能改执行方式，不能改阈值）。

## 4. 另外两个接线缺口

### 4.1 「继续即增加预算」没有接线

`server/轮次预算.mjs:38` 的软预算文案：

> 已完成 25 个模型回合（软预算），请给出阶段结论并询问用户是否继续；继续即显式增加预算。

但 `grantBudget()`（`server/运行预算.mjs:111-119`）在仓库里**没有任何调用点**。用户回答「继续」后，`budgetBonus` 仍是 0，45 回合硬预算照常命中。

这解释了为什么用户会觉得「明明点了继续，怎么还是被收尾」。

### 4.2 时长预算永远不会触发

`noteEffective()` 与 `noteWaiting()` 同样没有任何调用点。`budgetSnapshot().effectiveMs` 在所有真实事件里都是 `0`（见 §2.1）。因此：

- 45 分钟软时长、90 分钟硬时长**从未生效**；
- 「等待审批/用户接管不计入有效时长」的设计也**从未实现**；
- 预算诊断里的 `effectiveMs: 0` 不是「真的没花时间」，而是「根本没有累加」。

## 5. 可选方案（供拍板，本轮不实施）

| 方案 | 做法 | 优点 | 风险/成本 |
|---|---|---|---|
| A. 只修文案与接线 | ① 把「最多一个收尾回合」改成「进入只读收尾」；② 用户回答「继续」时调用 `grantBudget({turns:25,tools:40})`；③ 删除或实现时长预算 | 改动小，立刻消除误解 | 45 回合后仍只能只读；预算仍不可配置 |
| B. 项目级预算配置 | 在项目设置增加 `runBudget {turnSoft,turnHard,toolSoft,toolHard,effectiveSoftMs,effectiveHardMs}`，`ensureRunBudget` 读取项目配置 | 不同项目可调；长文档项目可放宽 | 需要 PRD/DESIGN/ADR；设置面板与项目设置都要改 |
| C. 把「回合」与「改文件」拆开 | 45 回合后只限制「改文件次数」，不限制只读/推理回合；或改成「连续无产出回合」计数 | 更贴合长文档写作 | 语义变化大，需要重新定义预算与测试 |
| D. 保持现状 | 只补文档/诊断，不改行为 | 零风险 | 用户仍会被 45 回合打断，且「继续」无效 |

**建议顺序**：先做 A（修文案 + 接 `grantBudget` + 处理时长预算），再评估 B。A 能让「继续」真正生效，也不会改变现有安全边界；B 需要用户确认是否把预算暴露到设置里。

另外，是否默认开启 `OAW_PI_TOOL_GATE` 需要单独拍板：开启后 160 次工具硬预算、连续失败/重复无进展才会真正 `block`；关闭时它们只是事件提示。考虑到「同一操作失败两次就停」对 OfficeCLI 重试循环有帮助，建议在 P0 埋点后默认开启，并保留开关回退。

## 6. 需要用户确认

1. 「继续」应该增加多少预算？建议 `turns +25`、`tools +40`（即一轮软预算的量），还是直接解除本 Run 的回合硬限？
2. 45 回合后是否允许继续只读？如果希望「一个收尾回合后硬停」，需要新增 `maxWrapUpTurns=1` 并真正 abort。
3. 时长预算（45/90 分钟）是要**实现**，还是**删除**？目前它是死代码，留着会误导诊断。
4. 工作流的 `maxToolCalls` 是**展示性说明**还是**应该真正执行**？如果要执行，需要接到运行预算里，并定义超限行为。
