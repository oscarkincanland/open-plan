## 一、背景

上一轮调研确认“结论太短”是三处提示词叠加的结果，其中 `complete_task` 工具层再压了一次：

- `completeTaskTool.description`：`summary 是给用户看的结论：纯问答一句话即可……`
- `summary` 参数：`建议 ≤800 字。纯问答用一两句……`
- 工具返回：把整段 summary 原样回显（`已记录任务完成状态：${label}。${completion.summary}`），模型会认为“结论已经说完”，最终只补一句“已完成”。

真实样本（`.oaw/runs`）：`run_2555f48c` 终稿 188 字、`run_a305cc77` 192 字；62 个 completed 里 6 个是系统推断文案“任务结束，未检测到文件变更”。

本次按用户决策**只改工具层**：Chat / Review / Work 的最终答复策略（`buildOutputPolicyLines`）与动态上下文里的“1-3 句”保持原样，作为后续独立决策。

## 二、目标

1. 删除 `complete_task` 的“一句话 / 一两句 / ≤800 字”软上限。
2. `summary` 改为“面向用户的完整结论”，要求覆盖结果、关键数据、产物、验证、未完成项或风险。
3. 明确“不重复”口径：不复述工具流水、不与进度句重复、同一事实只写一次、不另写更短的版本。
4. 工具返回改为短确认，不再回显 summary 全文。

## 三、非目标（用户决策 D1）

- **不改** `buildOutputPolicyLines` 的 Chat/Review/Work 最终答复措辞（`:62/:63`）。
- **不改** Work/Review 动态上下文里的长度策略（`:4755/:4764`）。
- **不改** 进度句的“1-3 句”（D2）。
- 不改 `status` 语义、`applyObjectiveDowngrade`、`inferCompletion`。
- 不改事件类型、SSE 契约、UI 布局。
- 不新增运行时开关。

## 四、目标契约：complete_task v2

### 4.1 字段语义

| 字段 | 语义 | 要求 |
|---|---|---|
| `status` | `success / partial / blocked / failed` | 必填，客观降级规则不变 |
| `summary` | 面向用户的**完整结论**（Markdown 可用） | 必填非空；覆盖结果、关键数据、产物、验证、未完成/风险；与最终答复一致，不另写更短版本；不设软上限（服务端 4000 字符） |
| `incomplete` | 未完成项（`partial` 必填） | 可选数组 |
| `blockers` | 阻塞原因（`blocked` 必填） | 可选数组 |
| `verification` | 如何验证 | 建议填写 |

### 4.2 去重规则（写进工具描述）

1. 不复述工具调用序列。
2. 不与进度句重复。
3. 同一事实只出现一次（产物路径只在“产物”处出现）。
4. 不另写一份更短的“一句话总结”。
5. 工具返回不再回显 summary。

### 4.3 工具返回

```text
已记录完成状态：{label}。请直接给用户最终答复。
```

### 建议文案（已按此实施）

A4：

```text
任务收尾时调用，显式声明本轮的完成状态。status 取值：success（目标已达成并验证）/ partial（部分完成，说明未完成项）/ blocked（受阻，说明阻塞原因）/ failed（失败）。summary 是给用户看的完整结论：说明做了什么、关键结果（含关键数字）、产物路径、如何验证、未完成项或风险；纯问答也要把结论与依据说清，不要只写“已完成”。与最终答复保持一致，不要另写更短的版本；不要复述工具调用流水，也不要重复进度播报。用户可见此状态，未调用时系统只能依据回合结束推断，请勿跳过。
```

A5：

```text
面向用户的完整结论，可用 Markdown。按内容需要写，不设字数上限（服务端上限 4000 字符）。建议覆盖：结果 / 关键数据 / 产物路径 / 验证方式 / 未完成项或风险；同一事实只写一次，不复述工具流水，不与进度句重复。
```
