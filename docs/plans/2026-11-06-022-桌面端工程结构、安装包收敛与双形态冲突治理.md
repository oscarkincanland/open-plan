## 零、三个问题的直接回答

| 问题 | 回答 |
|---|---|
| 是否要重新列一套文件树？ | **不要**。另起一套源码树等于把 110 个 `server/*.mjs`、192 个测试、`client/` 全部复制一份，是 fork 那条路的翻版（它正是这么做的，结果 406 冲突）。正确做法是**一份源码 + 两个宿主 + 一层平台适配**：只新增 `desktop/`（壳，约 15 个文件）与两个很小的适配层，`client/`、`server/` 保持唯一。 |
| 安装包怎么排布？ | 按 **M1 内测包 → M2 静默安装体验 → M3 签名与升级 → M4 正式分发** 四个里程碑收敛，每步有明确验收闸；先「能装能跑」，再「像软件」，最后「能升级」。 |
| 双端冲突怎么解？ | 三层：**① 代码单一事实源（差异只许出现在适配层）② 自动化门禁（禁止性 lint + 双目标构建 + 对等矩阵）③ 治理规则（谁是准、热点文件约定、发布节奏）**。核心口号：**「一份业务逻辑，两种外壳；差异做成能力探测，不做成 if (桌面)」**。 |

## 一、文件树：一份源码 + 两个宿主

### 1.1 原则（四条，违反即返工）

1. **单一事实源**：任何业务逻辑只存在一处（`server/` 或 `client/src/`），禁止出现 `desktop/backend/` 之类第二份实现。
2. **平台差异下沉**：`desktop/` 只做「壳 + 原生能力」；`client/src`、`server/` 通过**接口 + 能力探测**使用平台能力，不得直接依赖 Electron。
3. **双向可退化**：桌面端必须能在 web 形态下退化（能力探测失败 → 走原路径），web 形态必须能不带 `desktop/` 独立构建。
4. **禁止跨层 import**：`client/` 与 `server/` 不得 `import 'electron'`；`desktop/` 不得复制业务代码。

### 1.2 目标文件树

```
open-plan/
├── client/                      ← 保留：唯一前端源码（React + Vite）
│   ├── src/
│   │   ├── 平台/                ★新增（约 3 文件）：宿主能力探测与桥接入口
│   │   │   ├── 宿主.js           detectHost() / 平台能力开关（桌面|浏览器）
│   │   │   ├── 文件对话框.js      showOpen()/showDir()：浏览器走 <input>，桌面走 preload
│   │   │   └── 外部打开.js        openPath()/revealPath()：浏览器走 /api，桌面走 shell
│   │   ├── components/          ← 保留：唯一组件树（含内置浏览器面板等）
│   │   ├── 地图/                ← 保留
│   │   └── api.js               ← 保留：HTTP 客户端（桌面端仍走 127.0.0.1 + token）
│   └── package.json             ← 保留
│
├── server/                      ← 保留：唯一后端（110 个 .mjs）
│   ├── index.mjs                ← 保留：Express 入口（桌面端由主进程 import）
│   ├── 平台/                    ★新增（约 4 文件）：后端平台抽象
│   │   ├── 宿主信息.mjs           isDesktop() / userDataDir() / resourcesDir()
│   │   ├── 外部二进制.mjs         officecli / ODA / LibreDWG 的路径解析（打包 vs 开发）
│   │   ├── 系统对话框.mjs         Windows 原生对话框（现有 原生文件.mjs 收敛到这里）
│   │   └── 生命周期.mjs           ready/quit 回调（web 下为空实现）
│   └── ...（其余模块不动）
│
├── desktop/                     ★新增：唯一壳工程（不承载业务）
│   ├── package.json              electron / electron-vite / electron-builder
│   ├── electron.vite.config.mjs
│   ├── src/
│   │   ├── main.mjs              应用入口：单实例锁、窗口、import server/index.mjs
│   │   ├── 服务宿主.mjs           起停服务（随机端口 + OAW_API_TOKEN 回写）
│   │   ├── 浏览器视图.mjs         WebContentsView + debugger（浏览器模块 embedded 驱动）
│   │   ├── 原生桥.mjs             dialog / shell / 托盘 / 通知
│   │   └── preload.cjs           contextBridge 白名单 API（不暴露 ipcRenderer）
│   ├── build/                    图标、安装器侧图
│   └── electron-builder.yml      打包配置
│
├── scripts/                     ← 保留：192 个测试 + 门禁（新增 2 个平台边界脚本）
├── bin/                         ← 保留：officecli / oda / libredwg（打包时 extraFiles）
├── docs/                        ← 保留
└── package.json                 ← 保留：新增 desktop:* 聚合脚本
```

**新增代码量估计**：`desktop/` 约 15–20 文件、1200–1800 行；两个适配层约 7 文件、300–500 行。业务代码零行新增。

### 1.3 三方边界表（谁可以动什么）

| 层 | 允许依赖 | 禁止 | 判定脚本 |
|---|---|---|---|
| `client/src`（业务） | React、`client/src/平台/*`、`api.js` | **禁止** `import 'electron'`、`window.require`、`process.versions.electron` 直读 | `scripts/平台边界检查.mjs` |
| `client/src/平台` | 浏览器 API + 可选 `window.__OAW_HOST__` 能力探测 | 禁止直连 ipcRenderer（只经 preload 暴露的方法） | 同上 |
| `server`（业务） | Node 内置 + `server/平台/*` | **禁止** `import 'electron'`、写死绝对路径 | 同上 |
| `server/平台` | `process.env` / 宿主信息 | 禁止承载业务逻辑 | 代码评审 |
| `desktop` | `server/index.mjs`、`client/dist`、Electron API | **禁止** 复制 `server/*.mjs` 或 `client/src/*` 的任何实现 | 目录白名单检查 |

### 1.4 平台能力抽象清单（差异只在这里出现）

| 能力 | 浏览器形态 | 桌面形态 | 落点 |
|---|---|---|---|
| 文件选择 | `<input type=file>` / 拖拽 | `dialog.showOpenDialog` | `client/src/平台/文件对话框.js` → preload |
| 目录选择（工作区） | 服务端接口 | 同左 + 原生对话框 | `server/平台/系统对话框.mjs` |
| 打开/定位文件 | `/api/native/open` | `shell.openPath` / `showItemInFolder` | `client/src/平台/外部打开.js` |
| 内置浏览器 | 系统 Edge + CDP 帧流 | `WebContentsView` + debugger | `server/内置浏览器.mjs` 双驱动（见 021 方案 §6） |
| officecli 路径 | `bin/` 或 PATH | `process.resourcesPath/bin` | `server/平台/外部二进制.mjs` |
| 启动/退出 | 独立服务进程 | 主进程生命周期 | `server/平台/生命周期.mjs` |
| 单实例 | 不需要 | `requestSingleInstanceLock` | `desktop/src/main.mjs` |
| 更新 | 不需要 | electron-updater | `desktop/src/main.mjs` |

> 关键约束：**业务代码只问「能力有没有」，不问「是不是桌面」**。例：`if (平台.有原生文件对话框) …`，而不是 `if (isDesktop) …`。

## 二、安装包收敛计划（M1–M4）

### 2.1 收敛顺序（先说结论）

```
M1 内测包（能装能跑）  →  M2 安装体验（像软件）  →  M3 签名与升级（能更新）  →  M4 正式分发
   约 3 天                 约 1 周                   约 1 周                     持续
```

每一步的门禁是**硬性的**：M1 不过不上 M2，避免「打包问题堆到最后一起爆」。

### 2.2 产物结构与体积预算

```
GuiJu-Setup-<version>.exe (NSIS, per-user)
└── 安装后：%LOCALAPPDATA%\Programs\GuiJu\
    ├── GuiJu.exe
    ├── resources\
    │   ├── app.asar            ← desktop/ + server/ + client/dist
    │   └── bin\                ← extraFiles（不可进 asar）
    │       ├── officecli.exe            ~30–60 MB
    │       ├── oda\ODAFileConverter.exe ~40–80 MB（可选）
    │       └── libredwg\dwg2dxf.exe     ~5 MB
    └── locales\
```

| 组件 | 体积（估） | 处置 |
|---|---|---|
| Electron 运行时 | 90–120 MB | 固定 |
| `app.asar`（含 client/dist + server） | 8–15 MB | 压缩 |
| officecli | 30–60 MB | **必带**（文档引擎） |
| ODA / LibreDWG | 40–80 MB | **可选**：首版不带，首次打开 DWG 时引导下载 |
| 合计首版 | **≈ 150–200 MB** | 可接受；后续按需拆 |

### 2.3 四个里程碑与验收

| 里程碑 | 内容 | 验收闸（不过不进下一步） |
|---|---|---|
| **M1 内测包** | electron-builder 出未签名 NSIS；`app.asar` + `extraFiles bin/`；启动即起服务 | ① 全新机器双击安装可启动 ② 文档/地图/会话三条主链路可跑 ③ officecli 能定位 ④ 卸载后无残留进程 |
| **M2 安装体验** | 安装目录选择、桌面/开始菜单快捷方式、卸载保留/清理用户数据选项、首次运行引导（工作区选择） | ① 安装/升级/卸载三流程无报错 ② 用户数据目录明确 ③ 二次启动不重复安装 |
| **M3 签名与升级** | 代码签名（EV 证书或 OV + 时长）、electron-updater + 更新 manifest、灰度通道 | ① SmartScreen 不拦截 ② 从 vN 升级到 vN+1 保留数据 ③ 更新失败可回滚 |
| **M4 正式分发** | 官网/GitHub Release、checksum、崩溃上报（本地写入，不外传） | ① 下载→安装→使用→升级闭环 ② 崩溃可定位到日志 |

### 2.4 打包必踩的坑（提前写进 checklist）

| 坑 | 现象 | 对策 |
|---|---|---|
| `bin/` 进 asar | 子进程无法执行 | `asarUnpack` 或 `extraFiles`（**必须**） |
| `server/*.mjs` 用 ESM 动态 import | 打包后找不到模块 | electron-vite 需把 `server/` 作为 external/复制，而非打进 bundle |
| 相对路径 `office-workspace` | 装到 Program Files 后不可写 | 工作区默认指向 `%USERPROFILE%` 或用户选择目录 |
| `process.cwd()` 依赖 | 快捷方式启动 cwd 不同 | 全部改用 `app.getAppPath()` / `resourcesPath` |
| 杀软误报 | 未签名 exe 被拦 | 尽早签名；提供校验和 |
| 端口冲突 | 3002 被占 | 随机端口 + 端口回写渲染进程 |
| 多实例 | 两个进程写同一工作区 | 单实例锁 + 第二实例聚焦已有窗口 |

### 2.5 CI 与版本

- **CI 新步骤**（GitHub Actions，windows-latest）：`web build` → `desktop build` → `verify` → 打包 → 产物 checksum → 上传 artifact（tag 时发 Release）。
- **版本规则**：桌面端首发 **v0.14.0**（形态级变更，与 021 方案一致）；后续桌面修复走 0.14.x；web 形态与桌面同版本号发布，避免两端版本语义分裂。
- **通道**：`stable` / `beta`（beta 走更新 manifest 的 `beta` 字段）。

## 三、桌面端 × 网页端：冲突治理

### 3.1 冲突的四种类型

| 类型 | 例子 | 治理手段 |
|---|---|---|
| ① 源码冲突 | 两处实现同一功能（fork 的 `electron/backend` vs `server/`） | 单一事实源 + 目录白名单 |
| ② 运行时行为差异 | 桌面能选目录、浏览器只能用路径输入 | 能力探测 + 显式降级提示 |
| ③ 测试口径 | 192 个 `.mjs` 只测 web 形态 | 双目标构建 + 平台边界测试 + 桌面冒烟 |
| ④ 发布节奏 | 一端修了、另一端没测 | 对等验收矩阵 + 同版本号发布 |

### 3.2 机制一：代码单一事实源（防 ①）

- 只允许 `desktop/` 出现 Electron API；`client/`、`server/` 通过适配层。
- **新增门禁脚本** `scripts/平台边界检查.mjs`（约 120 行，纯静态扫描）：

```text
检查项（违反即 verify 失败）：
1. client/src/**、server/** 出现 `from "electron"` / `require("electron")`     → 失败
2. client/src/** 出现 `window.require` / `ipcRenderer`                          → 失败
3. desktop/** 出现 `server/` 以外的业务实现（白名单：服务宿主/浏览器视图/原生桥/preload）→ 失败
4. server/** 出现硬编码盘符路径（/^[A-Za-z]:\\/）                                → 失败
5. client/src/平台/** 之外的代码出现 `process.versions.electron`                → 失败
```

### 3.3 机制二：自动化门禁（防 ③）

| 门禁 | 内容 | 何时跑 |
|---|---|---|
| `npm run verify` | 现有 192 测试（web 语义不变） | 每次提交 |
| `npm run desktop:build` | 壳 + SPA 构建 | 每次提交（CI） |
| `平台边界检查` | 见上 | 每次提交 |
| `desktop:smoke` | 启动 → 打开一篇文档 → 关闭（无 UI 断言，仅存活/退出码） | CI（windows） |
| 双形态对等矩阵 | 手工清单：R1–R16 在两端各点一遍 | 每个 minor 发布前 |

### 3.4 机制三：治理规则（防 ②④）

| 规则 | 内容 |
|---|---|
| **谁是准（金标准）** | 业务逻辑以**共享层**为准；交互规范以 **DESIGN.md** 为准；平台能力以**适配层接口**为准。某端不支持 → 显式降级 + 界面提示，不得静默失败 |
| **降级必须可见** | 例：桌面端有原生目录选择，web 端显示「当前为网页模式，请输入路径」 |
| **热点文件约定** | `client/src/components/ChatPanel.jsx`、`client/src/styles.css`、`server/agent.mjs`、`server/index.mjs` 为热点：桌面端改造**不得**直接大改这些文件，优先新增适配层/开关 |
| **并行协作** | 本仓存在多会话并行：桌面端改动集中在 `desktop/` 与 `server/平台/`，与主线改动零交集 |
| **发布节奏** | 两端同版本号、同 tag；先 web 验收再打桌面包；桌面端出问题 → 用 `OAW_DESKTOP=0` 回退 web 入口 |
| **弃用清单** | 桌面端上线后，web 形态的「长连接预算/跨标签页配额/SSE 断线重连」在**桌面宿主下**跳过（代码保留，桌面不启用），不做物理删除，保证 web 仍可用 |

### 3.5 一张表看清「两端各做什么」

| 场景 | web 形态 | 桌面形态 | 差异实现位置 |
|---|---|---|---|
| 打开文档 | 服务端路径 | 同左 | 无差异 |
| 选工作区 | 输入/服务端列表 | 原生目录对话框 | `server/平台/系统对话框.mjs` |
| 内置浏览器 | 系统 Edge + 帧流 | 内嵌视图 + CDP | `server/内置浏览器.mjs` 双驱动 |
| 打开外部链接 | 新标签页 | `shell.openExternal` | `client/src/平台/外部打开.js` |
| 崩溃恢复 | 服务重启 | 主进程重启 + 会话恢复 | `server/平台/生命周期.mjs` |
| 更新 | 刷新页面 | electron-updater | `desktop/src/main.mjs` |
