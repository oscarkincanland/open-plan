> 状态：已实施（2026-11-01；代码 `d29c839a` / 字体资产 `0326ecd7`，文档本提交）
> 日期：2026-11-01
> 基线：v0.13.3（main @ be113d38）
> 关联：[AGENTS.md](../../AGENTS.md) §3 §4.3 §7、[会话流前端规范](../规范/会话流前端规范.md)、[DESIGN.md](../../DESIGN.md) §7、[001 改版落地文档](2026-10-31-001-会话流改版落地文档.md)、[002 精修计划](2026-10-31-002-会话流精修计划.md)、[收敛计划](2026-11-01-002-会话流收敛与提交门禁落地计划.md)
> 目的：把「一轮 Run 的过程」收回一行折叠头，同时把会话流的字号从九档噪声收敛为三档，让「结论」重新成为页面上最易读的内容。

## 0. 结论先行

1. **折叠的是过程，不是答案。** 参考 ZCode 分享页：9 分 8 秒的完整工作被压成一行「已工作 9 分 8 秒 ›」，而**模型终稿保持展开**，作为正文直接阅读。本计划照此实现：时间流 + 系统提示聚合收进折叠体；**结论正文、产物卡、未决 ask/审批、需行动提示留在折叠体外常显**。理由：这是工作台，答案是交付物；若连答案一起折，用户每读一轮都要先点一次。
2. **折叠头承担全部状态表达。** 「已完成 / 失败 / 已取消 / 完成（有风险）」+ 用时 + 步数，左侧状态点。失败与取消**同样默认折叠**——真正的行动信息由折叠体外的「需行动提示」和未决交互块承载，不靠展开才能看见。
3. **字号收敛为三档：12 / 14 / 16。** 现状实测出现 9 种字号、22 种「字号/字重/颜色」组合（10 / 10.166 / 11 / 11.5 / 11.96 / 12 / 12.5 / 13 / 14）。收敛后：正文 14、元信息 12、分节标题 16，字重只有 400 / 600。
4. **信息权重倒挂要扶正。** 现在最亮最大的是「最终结果如下」这类元信息句（14px/600/近白），真正的正文是 12.5px/`--dim`（实测 4.42:1，低于 AA 4.5:1）。收敛后正文回到 14px/`--text`（≈17:1），结论降为大号普通正文而不是整段加粗。
5. **规范先行。** 现行规范 §2 与 §11 明文禁止「整轮折叠头 / 时长徽标」，这条是上一轮为去掉旧形态立的。要反转必须先改规范并补 ADR `0014`，不能先改代码。

**决策点 D1（需你确认）**：折叠范围默认取 `process`（过程折叠、答案常显，ZCode 同款）。若你要的是「连结论一起折成一行」，把 `RunFoldBar` 的 `scope` 由 `"process"` 改为 `"run"` 即可，其余实现不变——本计划按 `process` 落地。

## 1. 目标与非目标

### 目标

| 编号 | 目标 | 验收口径 |
|---|---|---|
| G1 | 一轮结束的 Run 在会话流里只占「一行折叠头 + 结论正文 + 产物卡」 | 完成后首屏高度相比现状下降 ≥50% |
| G2 | 折叠头准确表达终态、用时、步数 | 5 种终态文案各 1 条用例 |
| G3 | 会话流字号只有 12 / 14 / 16 三档 | `test:chat-layout` 新增字号白名单断言 |
| G4 | 正文对比度 ≥ AA | 正文 `--text`；`--dim` 提升到 ≥4.5:1 |
| G5 | 分节标题在正文里可识别 | h2 16px/600，上边距 ≥20px |
| G6 | 未决 ask/审批不被折进折叠体 | 未决时交互块仍在折叠体外可见 |

### 非目标

- 不改 SSE 事件协议、Run 存储结构、后端归约与 `server/` 任何代码。
- 不改 `ask` / 审批的表单与语义（只改它们的容器位置）。
- 不改纯问答消息（无 `runId`）与非 `timelinePath` 的旧渲染路径（`ChatPanel.jsx:5898+`、`RunSummary` 嵌入态）。
- 不改 Review 轮次渲染。
- 不新增动画、渐变、硬编码色；不改字体族（仍为 OPPO Sans 4.0）。
- 不做「整轮含结论折叠」之外的自动摘要（不调模型生成折叠头文案）。

## 2. 设计规格

### 2.1 结构

```
.msg.assistant > .msg-main
├─ .run-fold                     ← 新增：折叠容器（状态类 ok/err/warn）
│  ├─ button.run-fold-head       ← 一行：状态点 + 「已完成 · 用时 9 分 8 秒 · 12 步」+ chevron
│  └─ .run-fold-body             ← 折叠体（0fr → 1fr）
│     ├─ .tl-list（时间流，含已决 ask/审批行）
│     └─ ExecutionFlow(embedded)（系统提示聚合）
├─ .tl-row.locked …              ← 未决 ask/审批：留在折叠体外常显（规范 §6）
├─ SummaryBlock                  ← 结论正文：常显（本次瘦身后只剩正文）
├─ ArtifactCard                  ← 本轮产物：常显
└─ .run-result-action            ← 需行动提示：常显
```

对应现有锚点：`client/src/components/ChatPanel.jsx:5854-5897`（`timelinePath` 分支），父容器 `.msg-main` 在 `:5834`（`display:flex; flex-direction:column; gap:4px`，见 `styles.css:1451-1459`）。

### 2.2 折叠状态机

| 条件 | 折叠头文案 | 状态点 | 默认开合 |
|---|---|---|---|
| `isTaskLive`（运行/排队/等待/恢复中） | 不渲染折叠头，直铺时间流（保持现状） | — | — |
| 终态 `completed`，无 `blocked/partial` | `已完成 · 用时 9 分 8 秒 · 12 步` | 绿 | 折叠 |
| `blocked` 或 `partial` | `完成（有风险）· 用时 3 分 · 8 步` | 琥珀 | 折叠 |
| `failed` | `失败 · 用时 2 分 4 秒 · 5 步` | 红 | 折叠 |
| `cancelled` | `已取消 · 用时 40 秒 · 3 步` | 灰 | 折叠 |

规则：

- **展开态不持久化**：组件内 `useState`，切会话/刷新回到默认折叠。与规范 §8「历史回放不重播」一致，也避免 localStorage 写入（`persist-ui.js` 只存工作区类信息）。
- **未决交互不受折叠影响**：`timelineInteractionItems` 中未决项渲染在折叠体之外（`ChatPanel.jsx:5865`），折叠头右侧追加「等待你回答」。
- **失败/取消也默认折叠**：错误详情在折叠体内的失败行里可展开；需要用户动作的信息由 `.run-result-action` 与未决交互块在折叠外承载。
- **步数口径**：`runTimeline.length`（含思考/文本/工具/子代理/系统提醒）。工具数可另取 `summarizeTimeline(runTimeline).toolCount`（`client/src/chat-flow-projection.js:236-246`），折叠头只显示步数，避免两个数字抢位。

### 2.3 折叠头规格

- 高度 28px，12px/400，`--muted`；hover 时 `--text`。
- chevron 用 `<Icon name="chevronRight" size={12}>` 旋转 90°——**不得使用 `▸/▾/↗` 字符**（`scripts/界面一致性守护测试.mjs:62` 会拦）。
- 状态点 7×7 圆点，复用现有 `.tl-state` 语义色（`--success` / `--error` / `--warning` / `--muted`），**不新增无限动画**（`scripts/动效治理测试.mjs:103-112` 有动画白名单）。
- 折叠体过渡：`grid-template-rows: 0fr → 1fr`，`--dur-base` + `--ease-out`，与 `TimelineRow` 的 `.tl-detail-wrap` 同型（`styles.css:10472-10473`）。
- 折叠态 `visibility: hidden`（延迟到过渡结束）——`0fr` 只是视觉隐藏，内部 `button` 仍可 Tab；`visibility:hidden` 才会移出焦点序列。

### 2.4 字号与层级（新规范 §4）

| 层级 | 类名 | 字号 | 字重 | 颜色 |
|---|---|---|---|---|
| 正文（结论 / 详细展开 / 文本块 / 时间流动作与对象 / 思考正文） | `.sum-body .markdown-body`、`.flow-markdown`、`.tl-verb`、`.tl-obj`、`.tl-thinking-text` | **14px** | 400 | `--text`（对象摘要用 `--dim`） |
| 正文分节标题 h2 | `.markdown-body h2` | **16px** | 600 | `--text` |
| 正文分节标题 h3–h6 | `.markdown-body h3..h6` | **14px** | 600 | `--text` |
| 元信息（折叠头 / cap / 耗时 / 状态 / 步骤标签） | `.run-fold-head`、`.sum-cap`、`.tl-time`、`.tb-cap` | **12px** | 400 | `--muted` |
| 代码（行内 / 代码块） | `.markdown-body code`、`pre code` | **12px** | 400 | `--text`（背景 `--panel2-bg`） |

约束：

- 全表只有三个字号；**禁止 em 相对字号**（`h2 { font-size: 1.1em }` 会随宿主 12.5px 滚成 13.75px，是当前九档噪声的来源之一，见 `styles.css:1112`）。
- 字重只用 400 / 600。结论不再整段 600。
- 绿色只用于图标、交互、状态点；**行内代码去掉 `var(--accent)`**（`styles.css:1128`），改回正文色 + 浅底。

### 2.5 间距与颜色

| 项 | 现状 | 改为 | 依据 |
|---|---|---|---|
| 正文 `p` 间距 | 4px（`styles.css:10400`） | 10px | ZCode 实测 16px，701px 列宽下 10px 更合适 |
| `h2` 间距 | `10px 0 4px`（`:10403-10404`） | `22px 0 8px` | ZCode 实测 `24px 0 16px` @14px 正文 |
| `h3` 间距 | 同上 | `16px 0 6px` | — |
| `hr` | 6px（`:10416`） | 18px | 分节感靠留白 |
| `li` | 3px（`:1109`） | 5px | ZCode 实测 6px |
| 正文行高 | 1.7 | 1.75 | ZCode 实测 1.75 |
| 正文颜色 | `--dim` #727d73（4.42:1） | `--text` #edf2ea（≈17:1） | AA |
| `--dim` | #727d73（4.42:1） | 提升到 ≥4.5:1（暗色建议 #7f8a80 ≈5.3:1） | 仍需承载 12px 次要信息 |

## 6. 风险与回滚

| 风险 | 影响 | 处置 |
|---|---|---|
| 折叠与「未决 ask/审批常驻」冲突 | 用户看不到待回答的问题 | 未决项固定在折叠体外；补 1 条用例 |
| `0fr` 折叠体内按钮仍可 Tab | 无障碍缺陷 | 折叠态 `visibility: hidden`，并在收起时归还焦点 |
| 字号改动破坏其他复用 `.markdown-body` 的页面 | 文档预览、知识库排版变化 | 只在 `.msg` / `.sum-body` 作用域内覆盖，不动 `.markdown-body` 全局基线 |
| `--dim` 提对比度触发 `test:design-tokens` 色值棘轮 | 门禁红 | 先跑该脚本再提交；只改令牌值，不新增 hex |
| 反转规范条款未留痕 | 违反 AGENTS §4.3 | P0-0 先提交 ADR，代码在 ADR 之后 |

**回滚**：每步独立提交；P0-2（接入）与 P1（视觉）分离，回滚 P0-2 即回到直铺形态，不影响字号收敛。
