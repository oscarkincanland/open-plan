## 0. 目标与原则

**目标**：让修改计划里的每一项功能（O-01～O-28）都有可执行、可复现、可 CI 化的验证证据；没有证据的功能不得标记完成。

**原则**（依据功能验证测试规范 §1）：

1. **先能失败，再谈通过**：每条新增测试在实现前必须先红。
2. **默认确定性**：不依赖真实模型、外网、用户文件、系统时间；必须依赖的放 `:live`。
3. **断言行为，不断言实现**：优先测输入输出、契约、状态迁移。
4. **隔离与可清理**：临时目录、临时端口、临时工作区；结束后清理。
5. **证据可复现**：交付时给命令、环境、结果；未运行项如实说明。

**成功判据**：`npm run verify` + 本文件全部 L1/L2 测试通过 + 人工 L4 清单勾完 + 模板覆盖率 100%。

## 1. 测试对象与范围

### 1.1 被测模块

| 模块 | 类型 | 测试重点 |

| `server/task.mjs` | 纯函数 | 触发词、四路由、能力计划、澄清闸门 |

- 真实模型写作质量的主观评价（放 L3 `:live`，人工触发）。
- OfficeCLI 二进制本身的行为（属于外部依赖，只测我们的封装）。
- 多模态视觉判定（不实现）。
- 并发 > 1 的性能（并发 1 是既定契约）。

## 3. 用例设计

### 3.1 `test:office-route`（34 例）

**触发词（14 例，O-01）**

| # | 输入 | 期望 |
|---|---|---|
| 1 | 帮我写个文档 | output=true，office 意图=true |
| 2 | 帮我写一份汇报 | output=true，office=true |
| 3 | 写一个工可材料 | template 命中 |
| 4 | 帮我写份工程可行性研究报告 | template 命中 |
| 5 | 按模板写一份汇报材料 | template 命中 |
| 6 | 起草一份交评报告 | template 命中 |
| 7 | 编制五年发展规划 | template 命中 |
| 8 | 写个方案 | output=true，template=未命中（反例） |
| 9 | 做个 PPT | template 命中 11_PPT汇报 |
| 10 | 改一下这份报告 | 编辑意图（需 currentFile） |
| 11 | 把第三段改短一点 | 编辑意图 |
| 12 | 看看这份文档 | 只读 |
| 13 | 这份材料有什么问题 | 只读/审查 |
| 14 | 帮我整理一下会议纪要 | output=true，template=未命中 |

**四路由（12 例，O-02）**

1. `@模板[04_...]` + "写" → `template`
2. `currentFile=.docx` + "改" → `edit`
3. 无文件 + "写" + 无模板 → `generate`
4. 无文件 + "看" → `read`
5. 有文件 + "写一份新的" → `generate`（新建意图优先）
6. 附件 `.xlsx` → `edit`
7. 引用 `kind=template` → `template`
8. Chat 模式 + docx 关键词 → 不产生写路由
9. Review 模式 → `read`/`review`
10. 空文本 + currentFile → `read`
11. 文本含 "officecli" → `edit`
12. 多文件引用 → 取第一个并记录 reason

**能力计划与注入（8 例，O-02/O-05）**

1. `routing.template` 与 `capabilities` 一致
2. `routing.officeFormat` 默认 `off`（开关关时）
3. 模板命中时 `capabilities` 含 `template`
4. 生成路由时 `capabilities` 含 `office_generate`
5. 编辑路由时 `officecli=preferred`
6. 提示词片段来自同一常量（两处引用）
7. 开关开/关两态的路由差异
8. reason 字段非空且可读

### 3.2 `test:office-clarify`（20 例）

**最小信息集（8 例，O-23）**

| # | 已知信息 | 期望 |
|---|---|---|
| 1 | 类型+篇幅+受众+素材+风格 全有 | 不问 |
| 2 | 缺 1 项 | 不问，用默认值并在产物标注 |
| 3 | 缺 2 项 | 问 1 个（文档类型优先） |
| 4 | 缺 5 项 | 只问 1 个，不连续追问 |
| 5 | 文档类型明确但篇幅/受众缺 | 问篇幅（第二阻塞项） |
| 6 | 用户说"你看着办" | 不问，全默认 + 标注假设 |
| 7 | 模板路由 + 模板已规定结构 | 不问结构类问题 |
| 8 | 编辑路由 + 目标段落明确 | 不问 |

**追问范围与回传（6 例，O-24/O-25）**

1. 编辑路由 + "改一下"（无段落） → 问"改哪一段"
2. 编辑路由 + 段落明确 + 改法不明 → 问"改成什么"
3. 编辑路由 + 要求"重排" → 问"是否保留原格式"
4. 流水线 Planner 前缺类型 → 返回 `needs_clarification`
5. 流水线缺项时不产出 docx
6. 父会话收到回传后调用 `ask_user`（事件序列断言）

**单槽位与超时（6 例，O-26）**

1. 并发两次 `ask_user` → 第二次明确失败，不覆盖第一次
2. 第一次正常回答 → 正常继续
3. 5 分钟超时 → 返回"按专业判断继续"文案
4. 超时后前端卡片失效（`/api/agent/answer` 返回 404 路径）
5. 取消 Run 时挂起提问 → 回填"已取消"
6. 重启后 `.oaw/pending-asks.json` 可接收回答

### 3.3 `test:office-format`（52 例）

**令牌（8 例，O-06）**
- 13 档字号递增且无重复
- 行距四档映射（1.15/1.3/1.5/固定 28pt）
- CJK 缩进 SimSun=480 / YaHei=420
- 页边距三套（A4 常规/公文/窄）
- 配色 12 套字段齐全
- 空值/未知场景 → 明确回退
- 令牌单位全部为 twips/half-point
- 与 `DESIGN.md` 无冲突

**封面（15 例，O-07/O-08）**
- 长标题 40 字不溢出（总高 ≤ 15638 twips）
- 单字孤行被拆行
- 中英混排不断词
- 空副标题
- 超长 meta（10 行）
- 10 行标题
- 7 套配方 × 三不变量（`margin=0`、行高 `exact`、`allNoBorders`）

**场景（20 例，O-09/O-10）**
- 7 场景 × 必填字段（页面/字体/结构/禁忌）= 14 例
- 默认场景 1 例
- 选择器 28 正例（抽样 5 条）+ 8 反例（"不是论文，是报告"等）

**边界（9 例）**
- 未知场景、空文本、超长文本、全英文、纯数字、模板缺失、JSON 损坏、Schema 不匹配、并发读取

### 3.4 `test:office-template`（32 例）

**匹配（14 例，O-13）**
- 14 个模板各 1 条关键词命中（工可/可研/预可/选址/交评/规划/汇报/物流园区/年度报告/五年规划/条文式/PPT/素材库/通用规范）

**结构抽取（8 例，O-14）**
- 工可 → 十章、11 图 8 表、字号缩进规则、16 条常见错误
- ✅/🔧 标记解析正确
- 无标记模板 → 降级为"仅标题结构"
- 结构快照可 diff（稳定序列化）
- 模板文件哈希不变（只读）

**映射（4 例，O-16）**
- 7 场景映射齐全
- 映射目标文件存在
- 无对应模板的场景走参数表
- 仓库中不存在 `templates/office/`

**覆盖率（6 例，O-15）**
- 完整产物 → 0 error
- 漏一章 → 报错并定位章节名
- 缺一张必备表 → 报错并定位表号
- 缺可选章节 → 仅提示
- 模板无 ✅ 标记 → 跳过覆盖率
- 产物无标题 → 明确报错

## 4. 测试数据与 fixture 策略

- **不提交二进制 fixture**：docx 一律由测试代码用 `buildDocxFromBlocks` 或 `JSZip` 现场构造到 `fs.mkdtemp`，`finally` 清理。
- **版式快照**：纯 JSON，存 `scripts/fixtures/office/`，用于"3 次一致"比对。
- **模板**：只读真实 `templates/traffic-material/`，不复制、不修改；测试前后比对文件哈希。
- **中文样本**：固定字符串常量，不用随机数据。
- **时间**：不依赖系统时间；超时测试用可注入的假计时器或缩短常量（测试专用）。

## 10. 缺陷与回归协议

1. **复现**：最小输入、命令、实际结果、期望结果。
2. **定位**：根因（文件/函数/条件），不只写"已修复"。
3. **回归**：新增或强化能复现的测试；修复前确认失败。
4. **修复**：最小改动，不夹带重构。
5. **验证**：目标测试 + `npm run verify` + 受影响关键链路。
6. **记录**：`变更日志.md` 的 Fixed，写根因与回归测试名。

**关键回归地图**

| 改动区域 | 至少运行 |
|---|---|
| 路由/触发词 | `test:office-route`、`test:capability-contract` |
| 澄清/ask_user | `test:office-clarify`、`test:chat-flow` |
| 模板/覆盖率 | `test:office-template` |
| 生成/样式层 | `test:doc-engine`、`test:office-generate` |
| 验收规则 | `test:office-qa`、`test:artifacts` |
| 事件 | `test:event-registry`、`test:event-payload`、`test:run-trace` |
| 写入/锁 | `test:write-lock`、`test:workspace-isolation` |

## 11. 未验证项与局限

| 项 | 原因 | 风险 |
|---|---|---|
| 真实模型写作质量 | 需模型凭据与人工评审，放 `:live` | 规则全绿但文风不佳 |
| WPS 与 Word 的渲染差异 | 无自动化双端渲染 | 封面/目录在某一端可能异常 |
| `view issues` 对中文排版的覆盖率 | 需先跑基线统计 | 规则闸门可能有盲区 |
| 模板覆盖率对非规整模板的解析 | 14 个模板标记格式可能不一致 | 误报；已设计降级 |
| 并发 > 1 性能 | 既定契约不做 | 多文档场景排队 |
| 大文档（>3,000,000 元素） | OfficeCLI 自身限制 | 明确报错，不静默 |
