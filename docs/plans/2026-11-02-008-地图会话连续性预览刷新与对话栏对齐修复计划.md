## 0. 结论先行

本次修复四个问题，按依赖顺序落地：

| 编号 | 问题 | 性质 | 方案 |
|---|---|---|---|
| P0 | 地图模块 agent 看起来与主会话不同 | 确定缺陷：ChatPanel 换父容器导致卸载重建、消息与 SSE 游标丢失 | 让对话面板常驻主对话槽位，地图模式用 CSS 定位到右侧 |
| P1 | 主界面预览地图不显示 agent 改动 | 设计边界 + 实现缺口 | 会话绑定地图时注入地图上下文；地图文件变更触发预览刷新 |
| P1 | 地图对话栏与页面对不齐 | 确定缺陷：地图槽位没复用主界面对齐规则 | 地图模式复用 `.center-chat-slot` 对齐规则 + 紧凑覆盖 |
| P2 | 结论文字间隔大 | 确定缺陷：字号/段距覆盖与 summary 结构叠加 | 地图模式单独收紧 Markdown 排版；主界面不动 |

**核心判断：地图模块没有第二套 agent。** 调用链仍是同一个 `sharedChatPanel`、同一个 `threadId`、同一套 `/api/agent/prompt` 与 `/api/agent/stream`。看起来“不一样”，是因为进入地图时 ChatPanel 从 `.center-chat-slot` 被搬到 `.app-chat-slot.map`，React 卸载重建，本地消息、SSE 游标、运行态全部丢失；服务端回放又把旧 Run 重建成孤立总结卡。现有代码注释本身就写着“避免切换地图时丢失消息流”，但实现没有做到。

## 2. 改造方案

### 2.1 问题一：对话面板常驻（P0）

**目标**：进入/退出地图、显示/隐藏地图对话栏，都不卸载 ChatPanel；消息、SSE 游标、运行态、队列、待办、系统提示去重键全部保持。

**推荐方案 A：常驻主对话槽位 + 地图模式 CSS 定位**

1. `client/src/App.jsx`
   - 根节点增加地图模式类：`<div className={`app ... ${activeModule === "map" ? "map-module-active" : ""}`}>`。
   - 主布局条件从 `!["knowledge","templates","map"].includes(activeModule)` 改为 `!["knowledge","templates"].includes(activeModule)`；地图模式下主布局继续挂载，ChatPanel 不再卸载。
   - 删除地图专用对话槽位 `{activeModule === "map" && mapChatVisible && <div className="app-chat-slot map">...}`。
   - `.center-chat-slot` 增加 `map-mode` 与 `map-chat-hidden` 类：
     `className={`center-chat-slot${activeModule === "map" ? " map-mode" : ""}${activeModule === "map" && !mapChatVisible ? " map-chat-hidden" : ""}`}`。
   - 地图下仍保留 `map-chat-resizer`，继续通过 `--map-chat-w` 调整宽度。
   - `sharedChatPanel` 仍传 `compact={activeModule === "map"}`，样式随类切换，不触发重挂。
2. `client/src/styles.css`
   - 新增地图模式隐藏主布局兄弟节点：
     ```css
     .app.map-module-active > .sidebar,
     .app.map-module-active > .app-canvas-slot,
     .app.map-module-active .center-content > :not(.center-chat-slot) {
       visibility: hidden;
     }
     ```
   - `.center-chat-slot.map-mode` 固定到右侧：
     ```css
     .center-chat-slot.map-mode {
       position: fixed;
       z-index: 220;
       top: 0; right: 0; bottom: 0;
       width: var(--map-chat-w);
       min-width: 300px; max-width: 620px;
       height: auto; flex: none;
       border-left: 1px solid var(--border);
       box-shadow: -10px 0 26px rgba(0, 0, 0, .2);
       background: var(--panel-bg);
       overflow: hidden;
       visibility: visible;
     }
     .center-chat-slot.map-mode.map-chat-hidden { display: none; }
     ```
   - 迁移原 `.app-chat-slot.map` 系列规则到 `.center-chat-slot.map-mode`（工具栏换行、`ct-pop` 定位、长文本断行等），删除已无引用的地图槽位规则。
   - 这样 `.center-chat-slot` 原有的 `chat-hist`/`chat-head` 隐藏、头像外置、输入区同宽规则会自动生效，再叠加 2.3 的紧凑覆盖。
3. 兼容性
   - `MapPanel` 的 `hideChat`、`chatVisible`、`.mp-shared-chat` / `.mp-chat-hidden` 逻辑不变；地图顶栏和画布仍按 `--map-chat-w` 预留右侧宽度。
   - 地图模式下主布局被 `visibility:hidden` 隐藏，`.mp`（z-index:100）覆盖画布；对话槽位 z-index:220 在右侧可见；返回主界面时移除 `map-mode`，ChatPanel 原地恢复。
   - 若键盘可访问性测试发现隐藏区域仍可聚焦，再补 `aria-hidden` 或 `inert`（只加在隐藏兄弟节点上，不包裹对话槽位）。

**回退方案 B（仅当方案 A 的 fixed 定位被祖先裁剪时启用）**：保留两个挂载点，但新增 `client/src/会话界面状态缓存.js`，在 ChatPanel 卸载时把 `messages`、`runState`、`busy`、`editMode`、队列、SSE 游标/streamId、系统提示去重键写入 `sessionStorage`（按 thread 限 80 条、剔除图片 data URL、容量上限 512KB），重挂时优先恢复；同时按 thread 持久化 `projectInstructionNotifiedRef` 与 `finishedRunIds`。该方案不改变布局，但需要覆盖“运行中重挂”的流式气泡恢复，风险高于方案 A。

**验收**：新会话主界面发 2 轮 → 进入地图 → 返回主界面，`.msg` 数量与 DOM 消息 id 不变；不出现孤立 summary 卡；不重复出现 AGENTS.md 提示；切换“显示/隐藏 Agent 对话”不丢消息。

### 2.2 问题二：预览地图实时只读镜像（P1，需确认 D1/D2）

**目标**：主界面会话一旦绑定地图项目，agent 与预览共享同一个项目；agent/用户保存地图正式文件后，预览自动刷新正式图层，仍保持只读。

1. 地图上下文注入（`client/src/App.jsx`）
   - 新增 `boundMapProject`：
     - 地图模块：`currentMapProject`（含默认 zhejiang-map）。
     - 主界面：`currentMapContext?.mapProject || ""`（只传会话真实绑定，不传默认值）。
   - ChatPanel props：
     - `mapProject={boundMapProject || null}`
     - `mapContext={boundMapProject ? currentMapContext : null}`
     - `currentDoc={current?.name}`，去掉 `地图项目:${project}` 伪文件名。
   - `task.mapProject` 随 props 进入 prompt，主界面绑定地图的会话不再回退 zhejiang-map。
   - MapPanel 自带 ChatPanel 同样改为传 `mapContext/mapProject`，避免潜在退化路径。
2. 地图项目创建/切换绑定
   - `handleFileChanged` 解析路径 `maps/<project>/...`。
   - 当前会话尚未绑定项目时，首个地图文件变更（含 `map_project_create` 发出的 `maps/<id>/map.config.json`）自动写入 `mapContexts[threadId]`，由现有 1.5s 防抖持久化到 session header。
   - 已有绑定时不自动切换项目；仅当路径属于当前项目时刷新预览，避免 agent 显式操作其他项目时误切预览。
3. 预览刷新链路
   - App 新增 `mapPreviewRevision` 状态；`handleFileChanged` 命中预览项目时自增。
   - `MiniMapPreview` 新增 `refreshToken`：
     - effect 依赖 `[project, refreshToken]`，重新拉 `/api/map/project` 的 config（更新可见图层数/底图）。
     - `MapViewer` 不再用 `view.updatedAt` 作为 key；项目不变时不重挂，保留预览相机。
   - `MapViewer` 新增 `reloadToken`：
     - 抽出 `reloadStyleNow`（fetch `style.json?ts=` → `applyStyle`，保留相机）。
     - `useEffect` 在 `loaded && reloadToken` 变化时调用；不复用 `readOnly` 轮询逻辑，避免为预览恢复 3 秒轮询。
     - `useImperativeHandle.reloadStyle` 复用同一函数。
   - `MapPanel` 新增 `onMapChanged`：保存样式/配置成功后通知 App 自增 revision，覆盖地图模块内手工改样式后返回主界面的场景。
4. 预览标签同步
   - `mapPreviewTab` 存在且 `payload.sessionId === currentSessionId` 时，项目变化只更新 payload，不激活标签、不抢当前画布。
   - 无预览标签、当前会话已绑定地图、画布为空、且不在地图模块时，自动打开 `mapPreview`（与选择会话的既有策略一致）。
   - 会话解绑地图时关闭预览标签。
5. 设计口径（需确认 D1）
   - 当前 PRD/DESIGN 写的是“只读快照”。本次改为“只读实时镜像（正式图层）”，需同步更新 `REQUIREMENTS.md` R10 验收与 `DESIGN.md` §9.3。
   - 临时分析层仍不回放（`map_action` 为 `persist:false`）；若用户要求预览显示热力图/等时圈，需另立“临时层持久化”计划。
6. 不做
   - 不把预览改成可编辑画布；人工编辑仍在 MapPanel。
   - 不在预览里显示临时分析层。

**验收**：
- 主界面打开绑定 `map-project` 的会话，发送“把这层路网改成红色”，运行记录的 `task.mapProject` 为 `map-project`，写入 `maps/map-project/style.json`。
- 预览在收到 `file_changed` 后 1 秒内发起新的 `style.json` 请求并显示新颜色。
- 临时 heatmap 仍不出现在预览，行为与文档一致。

   - 主界面字号断言 `scripts/会话流排版回归测试.mjs:54-56` 仍针对 `.sum-body .markdown-body` 14px/1.75，不受地图作用域影响。
