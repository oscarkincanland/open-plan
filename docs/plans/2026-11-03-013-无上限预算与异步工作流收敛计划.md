## 0. 你的决定 → 设计响应

| 你的决定 | 设计响应 |
|---|---|
| 预算上限设置为无上限 | 用户会话默认 `unlimited`：不再因回合/工具/时长强制收尾；保留计数与诊断，保留“同一操作连续失败”这一操作级护栏，避免死循环。 |
| ask_user 卡片超时自动消失，不影响接下来的工作 | 默认 90 秒超时（可配），到点弹层/卡片自动消失、写入一行回执，模型按假设继续；新增「跳过并继续」立即放行；超时不占输入栏、不阻塞后续消息。 |
| 简单文本操作不要经常调 OfficeCLI，批注等精细化操作才调 | 新增确定性路由：段落/文本/样式/表格/图片/查找替换/读取走原生 OOXML；批注、修订、域/目录更新、渲染、图表、严格校验等走 OfficeCLI。模型无需自己判断，工具入口不变。 |
| 某步骤卡住时放后台，后续工作继续推进 | 新增后台任务（Job）模型：超过阈值未完成的 `bash` / `officecli` / 子代理可自动转后台，返回 `BACKGROUNDED job_id`；模型继续做不依赖它的步骤，需要结果时用 `job_status` 等待；完成结果回注会话。 |

**一句话总结**：把“到点就掐断”改成“不设上限、卡住就转后台、简单活走原生、精细活才叫 CLI”。

## 1. 预算无上限

### 1.1 目标行为

- 不再出现「45 回合强制收尾」「工具 160 次停止」「90 分钟到点」；
- 不再在第 25 回合用 `ask_user` 问“是否继续”；
- 不进入 `restricted` 模式，不拦截任何写文件操作；
- 计数（回合、工具、token、耗时）继续记录，只用于诊断/展示；
- 用户仍可随时手动停止；
- 单次工具超时（如 `bash` 120s、`officecli` 120s）保留，但它只影响那一次调用，不终止整轮。

### 1.2 保留的安全护栏（不是预算）

| 护栏 | 行为 | 理由 |
|---|---|---|
| 同一操作连续失败 2 次 | 阻止**这一个操作**继续用相同参数重试，提示换方案 | 防止 `officecli`/`bash` 死循环；不影响其他工具 |
| 同一读取连续轮询 5 次且版本未变 | 提示复用已有结果 | 防止读文件空转 |
| 工具自身超时 | 该次调用失败/转后台（见 §4） | 不终止整轮 |
| 用户手动停止 | 立即中断 | 用户始终有最终控制权 |

> 关键区别：**无上限 = 没有全局回合/工具/时长上限**；不是“允许同一个失败命令无限重试”。操作级护栏保留，但它不再升级为整轮收尾。

### 1.3 代码改动点（未来实施）

| 文件 | 改动 |
|---|---|
| `server/运行预算.mjs` | `createRunBudget({ unlimited: true })`；`evaluateTurnGate` / `evaluateToolGate` 在 unlimited 下返回 `null`/`allow:true`；保留计数与 `budgetSnapshot` |
| `server/agent.mjs` | `ensureRunBudget` 读取任务/项目默认 `unlimited`；不再调用 `enterRestrictedMode` / `stopRunByBudget`；不再发 25/45 的 `run_budget_*`（改为可选诊断事件） |
| `server/轮次预算.mjs` | `turnNoticeKind` 在 unlimited 下返回 `null`；25/45 文案保留给 CI/专家模式 |
| `server/运行开关.mjs` | 新增 `runBudgetUnlimited`（默认 on）；保留 `OAW_RUN_BUDGET_ENFORCE` 作为专家回退 |
| `client/src/components/工作流启动器.jsx` | 移除「14 回合 · 45 次工具」的硬约束暗示，改为「参考耗时」或删除该行 |
| 测试 | `运行预算测试` 增加 unlimited 断言；长跑模拟不再触发 blocked；手动停止仍生效 |

### 1.4 UI 与文案

- 设置页不新增“预算”开关（默认无上限）；
- 任务中心显示「已用 N 回合 · N 次工具 · N tokens」但**不显示上限**；
- 工作流卡片不再展示 `maxToolCalls` 作为硬限制；
- 执行过程不再出现「预算阻断」；如果保留诊断，用「运行信息」弱提示。

### 1.5 验收

- 模拟 60 回合、300 次工具的 Run：不出现 `run_budget_blocked`，不进入 restricted，写文件不被拦截；
- 第 25 回合不再自动弹 ask_user；
- 同一失败命令连续两次仍被操作级拦截；
- 手动停止仍在 3 秒内生效。

## 2. ask_user 超时自动消失

### 2.1 目标行为

1. 待回答时显示覆盖输入栏的弹层（见 011 文档）；
2. 默认 **90 秒**倒计时（`OAW_ASK_TIMEOUT_MS`，最低 30 秒）；
3. 到点后：
   - 弹层/卡片自动消失；
   - 消息流只留一行「已超时 · Agent 已按假设继续」；
   - 服务端释放待回答槽位，模型继续执行；
   - 输入框立即恢复，用户可以继续发消息/排队；
4. 用户也可以点「跳过并继续」立即放行，不必等倒计时；
5. 超时或跳过后，迟到的回答不再提交（返回 404 时前端静默收卡）。

### 2.2 服务端行为

- `ASK_TIMEOUT_MS` 从 `300_000` 改为可配置，默认 `90_000`；
- `ask_user` 的 timeout 分支已经会 `resolve` 一段“请按专业判断继续”的工具结果，保留；
- 新增跳过语义：`POST /api/agent/answer` 支持 `{ skip: true }`（或 `answer: "__skip__"` 的显式协议），服务端用同样的“按专业判断继续”结果结算，不写入用户回答；
- 释放 `pendingAsks` 槽位，保证下一轮可以再提问；
- 事件 payload 增加 `status: "expired" | "skipped"`（复用 `ask_user` 事件，不新增事件类型）。

### 2.3 前端行为

- 弹层顶部倒计时：`剩余 1:30`；最后 20 秒变琥珀；
- 到点：弹层 160ms 收起 → 输入框恢复焦点 → 回执行「已超时，已按假设继续」；
- 「跳过并继续」按钮放在次按钮位，文案明确；
- 若用户正在看历史/切换会话，超时仍然生效，只是不抢焦点；
- 不再出现“已超时但还占着输入栏/还能点提交”的死卡片。

### 2.4 代码改动点

| 文件 | 改动 |
|---|---|
| `server/agent.mjs` | `ASK_TIMEOUT_MS` 可配；`ask_user` timeout 分支补 `status`；`/api/agent/answer` 支持 `skip` |
| `server/index.mjs` | `POST /api/agent/answer` 解析 `skip`，调用新的 `skipPendingAsk` |
| `client/src/components/ChatPanel.jsx` | 弹层倒计时/超时自动收起/跳过按钮；`markAskExpired` 后移除弹层 |
| `client/src/styles.css` | 倒计时警示色、收起动效 |
| 测试 | 超时自动消失、跳过立即继续、404 静默收卡、槽位释放后可再次提问 |

### 2.5 验收

- 90 秒不回答：弹层消失、输入框可用、模型继续、历史一行回执；
- 点「跳过并继续」：<1 秒内弹层消失、模型收到“按专业判断继续”；
- 超时后再次提问：可以正常弹出（槽位已释放）；
- 超时不影响正在排队的用户消息。

## 3. 简单文本走原生，精细操作走 OfficeCLI

### 3.1 路由分层

工具入口仍然是 `officecli`，模型不需要改调用方式；由 `server/office.mjs` + `server/文档引擎.mjs` 做确定性路由。

| 层级 | 操作 | 执行引擎 |
|---|---|---|
| L1 简单文本/读取 | `view text/outline/stats`、`get` 段落/run、`query` 常用选择器、`create`、`set --find --replace` | **原生** |
| L2 简单写入 | 段落增删改、run 文本/加粗/字号/颜色、标题样式、基础表格、图片插入、单元格读写、形状文本 | **原生（P1/P2 分批）** |
| L3 精细化 | 批注、回复批注、修订跟踪、页眉页脚、目录/页码域更新、交叉引用、表单域、保护 | **OfficeCLI** |
| L4 对象/渲染 | 图表、透视表、条件格式、迷你图、Morph/SmartArt/OLE/媒体、`view html/screenshot/svg/pdf`、严格 `validate` | **OfficeCLI** |

> 你提到的「批注等精细化」明确归 L3/L4，继续走 CLI；「改一段文字、改标题、插表格、插图」归 L2，走原生。

### 3.2 路由规则

```text
officecli(args)
  → 解析 command + 格式 + 子操作
  → 命中 native 能力矩阵？
      是 → 原生执行（不 spawn、不占 officeLimiter）
           失败/不支持 → 回退 CLI（保持现状）
      否 → OfficeCLI
  → 发 office_engine_selected（engine=native|cli, reason, command）
```

- `server/文档引擎.mjs` 的 `CAPABILITY_MATRIX` 扩展为“操作级”而非“命令级”；
- 新增 `needsNative(command, args, format)` 纯函数，可单测；
- 原生写仍走审批、按文件锁、暂存/回滚；
- 原生失败必须回退 CLI，不中断任务；
- 新增事件 `office_engine_selected`（需登记注册表）。

### 3.3 第一批原生能力（P1）

| 格式 | 操作 |
|---|---|
| docx | 段落读取/新增/修改/删除；run 文本与加粗/斜体/字号/颜色；标题样式；基础表格增删改；图片插入；全文替换（已存在）；页眉页脚读取（只读） |
| xlsx | 单元格/区域读写；行/列插入删除；基础样式；图片插入 |
| pptx | 形状文本读写；占位符文本；基础样式；图片插入；表格基础编辑 |

### 3.4 明确不迁移

批注、修订跟踪、目录/页码域更新、交叉引用、表单域、保护、签名、图表/透视/条件格式/迷你图、Morph/SmartArt/OLE/媒体、HTML/PNG/PDF 渲染、严格 OpenXML schema 校验。

### 3.5 验收指标

- 文本编辑类调用原生比例 ≥70%；
- 简单文本操作不再产生 OfficeCLI 进程（事件里 `engine=native`）；
- 批注/修订仍 100% 走 CLI，行为不变；
- 原生失败回退率 <5%，无文件损坏。

## 4. 卡住的步骤放后台，后续工作继续推进

### 4.1 什么算“卡住”

| 场景 | 判定 |
|---|---|
| `bash` 命令长时间无输出 | 超过 `stallAfterMs`（默认 20s）无新输出，或总时长超过 `backgroundAfterMs`（默认 30s） |
| `officecli` 调用长时间未返回 | 同上（默认 30s） |
| 子代理长时间无进展 | 超过 60s 无新事件（已有超时，可提前转后台） |
| 模型明确知道某步可并行 | 模型可主动传 `background: true`（如果工具参数允许） |

> 注意：工具自身的 120s 超时仍然保留；后台化是在超时**之前**把等待移出主流程。

### 4.2 Job 模型

新增 `server/后台任务.mjs`（纯 Node，无数据库）：

```
Job = {
  jobId, runId, threadId, kind: "bash"|"officecli"|"subagent",
  command, cwd, status: "running"|"completed"|"failed"|"cancelled"|"interrupted",
  startedAt, endedAt, exitCode, outputBytes, lastOutputAt,
  pid, logPath, resultSummary, mutating: boolean
}
```

- 元数据：`.oaw/jobs/<runId>/<jobId>.json`；
- 日志：`.oaw/jobs/<runId>/<jobId>.log`（有界，尾部保留）；
- 内存中有活跃 Job 表；服务重启时把 `running` 标为 `interrupted`，不自动重跑；
- 取消：`job_cancel` 或 Run 取消 → 杀进程树（复用现有 abort 链路）；
- 清理：完成后保留 24 小时或按数量上限清理。

> 现成入口：`run_subagent` 已有 `background: true` 参数（受 `OAW_SUBAGENT_PROFILE` 控制，默认关），P2 可以先复用它做“子代理后台化”，再把同一套 Job 事件/任务中心复用到 `bash` / `officecli`，避免重复造一套调度。

### 4.3 工具行为

以 `bash` 为例：

1. 正常执行，持续收集 stdout/stderr；
2. 超过 `backgroundAfterMs` 仍未结束：
   - 把进程继续放在后台（不杀）；
   - 工具返回：

```json
{
  "backgrounded": true,
  "jobId": "job_xxx",
  "message": "命令已转后台执行。可以继续不依赖它的步骤；需要结果时调用 job_status 等待。"
}
```

3. 模型看到 `BACKGROUNDED` 后：
   - 继续做其他独立步骤；
   - 需要该结果时调用 `job_status(jobId, wait=true, timeoutMs=...)`；
   - 或让完成事件自动回注。

4. 完成时：
   - 发 `background_job_finished`；
   - 如果 Run 还在，`session.followUp` 注入「后台任务 job_xxx 完成：exitCode/摘要」；
   - 如果 Run 已结束，只写任务中心，不再打扰模型。

### 4.4 审批与安全

| 类型 | 策略 |
|---|---|
| 只读命令（`ls/grep/cat` 等） | 可直接后台化 |
| 改文件命令（`bash` 写操作、officecli `add/set`） | **必须先完成审批**；审批通过后才能后台化；后台执行期间不能再弹审批 |
| 需要用户交互的命令 | 不后台化（如 `watch`、`open` 等长驻/交互命令直接返回可解释错误） |
| 并发 | 每个 Run 最多 N 个后台 Job（建议 3）；同一文件写操作仍按文件锁串行 |
| 取消 | Run 取消 → 取消全部 Job；用户可在任务中心单独取消 |

### 4.5 模型协议与提示词

新增工具：`job_status`、`job_cancel`（Work 模式；Chat 只读任务可用 `job_status`）。

提示词增加：

> 工具返回 `BACKGROUNDED` 时，不要原地等待；先继续不依赖该结果的步骤。需要结果时调用 `job_status` 等待或读取摘要。不要对同一操作反复重试。

### 4.6 UI

- 输入栏上方显示「后台 1 个任务 · 查看」小胶囊（不遮挡输入）；
- 任务中心新增「后台任务」区：命令摘要、已运行时长、状态、取消、查看日志；
- 完成后在会话流插入一行「✓ 后台任务完成 · 3 分 12 秒 · 查看结果」；
- 失败时一行红字 + 重试入口；不自动重跑。

### 4.7 代码改动点

| 文件 | 改动 |
|---|---|
| `server/后台任务.mjs`（新） | Job 生命周期、日志、取消、恢复标记 |
| `server/agent.mjs` | `bash`/`officecli` 接入自动后台化；`job_status`/`job_cancel` 工具；完成回注 |
| `server/task.mjs` | 白名单加入 `job_status`/`job_cancel`（Work；Chat 只读） |
| `server/事件注册表.mjs` | 新增 `tool_backgrounded`、`background_job_started/progress/finished/failed/cancelled` |
| `server/index.mjs` | `/api/jobs` 列表/详情/取消（如任务中心需要） |
| `client/src/components/任务中心.jsx` / `ChatPanel.jsx` | 后台任务区、胶囊、完成回执 |
| 测试 | 自动后台化、继续执行、`job_status` 等待、完成回注、取消、重启恢复、无孤儿进程 |

### 4.8 验收

- 一个 60 秒无输出的命令：30 秒转后台，模型继续下一步，输入栏不冻结；
- 需要结果时 `job_status` 能等到完成并拿到摘要；
- 后台写文件必须先审批；未审批不会后台化；
- Run 取消后 3 秒内 Job 进程树消失；
- 服务重启后 Job 标为 interrupted，不自动重跑；
- 任务中心能看到日志尾部，且日志不会无限增长。

## 5. 实施顺序

| 阶段 | 内容 | 依赖 | 风险 |
|---|---|---|---|
| P0 | 预算 unlimited + 25/45 提醒下线 + 文案/诊断 | 无 | 低 |
| P1 | ask 90s 超时 + 自动消失 + 跳过并继续 | 011 弹层设计 | 低 |
| P2 | 后台 Job 骨架（只读 bash/officecli + 任务中心） | 无 | 中 |
| P3 | 原生文本路由第一批（docx 段落/样式/表格/图片） | 012 调研 | 中高 |
| P4 | `job_status` 等待 + 完成回注 + 写操作后台化 | P2 | 中高 |
| P5 | xlsx/pptx 原生 + 批注仍走 CLI | P3 | 高 |

> 建议先做 P0/P1/P2：它们直接解决“45 回合收尾、ask 卡住、步骤卡住”三个最痛的点；P3 再进入文档引擎深水区。

## 6. 测试计划

- 单元：预算 unlimited、ask 超时/跳过、原生路由矩阵、Job 生命周期；
- 源码契约：前端弹层/回执/胶囊/倒计时、任务中心；
- 浏览器：ask 90 秒自动消失、跳过立即继续、后台任务胶囊、任务中心取消；
- 集成：60 秒命令自动后台 + 模型继续 + 完成回注；OfficeCLI 简单操作 `engine=native`；
- 回归：现有 `test:subagent-*`、`test:editorial-pipeline`、`test:main-flow`、`test:chat-flow`、`test:ava-*`；
- 安全：未审批写操作不得后台化；Run 取消杀进程树；重启不重跑。

## 7. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 无上限导致超长/高 token | 任务中心显示用量；用户可随时停止；保留操作级失败护栏 |
| 后台进程成为孤儿 | Job 管理器 PID 跟踪、Run 取消联动、服务退出清理、TTL |
| 后台写文件绕过审批 | 只允许“审批后”后台化；未审批直接拒绝 |
| 模型不知道何时等待 | 提示词 + `job_status(wait)`；完成自动回注 |
| 原生编辑损坏文档 | 原子写 + 备份 + 结构校验 + 失败回退 CLI |
| 超时太短导致问题没答 | 默认 90s 可配；「稍后」可保留到超时；用户可重开新一轮 |

## 8. 需要你拍板的细节

1. **ask 超时**：90 秒是否合适？还是 60 秒/2 分钟？
2. **后台阈值**：30 秒转后台是否合适？哪些工具允许自动后台（bash、officecli、子代理）？
3. **后台写操作**：是否允许“审批通过后”后台写？还是后台只允许只读？
4. **操作级失败护栏**：无上限后，同一失败命令连续 2 次仍拦截，是否保留？
5. **原生范围**：P3 第一批是否只做 docx？xlsx/pptx 是否延后？
6. **事件/工具命名**：`job_status` / `job_cancel` / `background_job_*` 是否采用？
