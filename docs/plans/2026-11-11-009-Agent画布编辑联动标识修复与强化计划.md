## 0. 结论先行

| # | 结论 | 证据 |
|---|---|---|
| 1 | **Bug 1（看不到/没动效）实测确证**：真实 agent 编辑画布期间 22 次采样（350ms 间隔 × 10.6s，覆盖 8+ 次 `canvas_write` 执行），标签呼吸点/画板发光/顶栏横幅**全程为 0**。根因是每个 `canvas_write` 执行中写文件即发 `canvas_changed`，而 App 的 `canvas_changed` 处理器立即把 `active` 置 false——标识只存活亚秒级，肉眼不可见。 | 本计划 §1.1 实测记录；`client/src/App.jsx:1344-1347` |

## 1. 取证

### 1.1 浏览器实测记录（2026-11-11，http://127.0.0.1:3002，Work 模式 + Claude Haiku 5.5）

| 步骤 | 操作 | 结果 |
|---|---|---|
| 1 | 会话发"用创作画布新建《OD联动测试》+ 两块板" | 画布成功创建（封面/出行OD示意），运行 ~10s 完成；期间未观测（脚本错误错过窗口） |
| 2 | 继续发"加第三块板《OD矩阵说明》+ 给第二块板补圆形"，设计标签保持激活 | 运行 5.9s 完成，产物落盘 4 文件（od-matrix.board.json 等）；**22 次采样全部 tabAgent=0 / boardAgent=0 / deckAgent=0 / banner=空** |
| 3 | 再发"加第五块板《期望线图层说明》"，运行中切走会话 | 运行完成前未能完成会话切换（模型执行过快）；切回后无残留（本轮 tool_end 全部送达） |
| 4 | 读 `.oaw/events/事件流.jsonl` 最近 30 条 canvas 相关事件 | 时序恒为 `tool_start → canvas_changed(写文件) → tool_end`，多次 `canvas_write` 串行；`run_finished` 收口 |

**推断**：采样间隔 350ms 仍全程扑空 ⇒ 标识存活窗口 < 350ms ⇒ 与 `canvas_changed` 置 false 的代码路径吻合（工具执行写盘发生在 `tool_start` 与 `tool_end` 之间，恰好落在活动窗口内把它杀掉）。Bug 2 在本次实测未复现（tool_end 均送达），但代码路径明确：三条清理通道全部缺失。

### 1.2 现状数据链路（004 实施）

```
ChatPanel（thread 流 /api/agent/stream）
  tool_start → onCanvasActivity({active:true, slug, boardPath})   ← slug 从 input JSON 解析
  tool_end   → onCanvasActivity({active:false, ...})
App.onCanvasActivity → setCanvasActivity(slug → {active, boardPath, action})
App 全局流 handlePayload（/api/agent/events）
  canvas_changed → setCanvasActivity(slug → {active:false, ...})   ← Bug 1 元凶
创作画布 agentBusy prop → 板发光 / 顶栏文字 / 板条呼吸点
画布标签栏 tabs 注入 agentEditing → 呼吸点
```

## 2. 范围

### 2.1 本次要做

- **F1 活动生命周期重构（同时修 Bug 1 与 Bug 2 的根）**：canvas 活动跟踪从 ChatPanel（thread 流）迁到 App 全局流 `handlePayload` 单一事实源；`canvas_changed` 不再触碰 `active`；`run_finished`/`agent_error`/`run_recovered` 按 `threadId` 权威清理；ChatPanel 上报链路移除（避免双流乱序复活）。
- **F2 显著性强化**：活动持续整轮（第一次带 slug 的 `canvas_start` 起、至 Run 终态止）；agent 开始编辑时自动打开/激活对应画布标签（带"用户 10s 内手动切换过标签则不抢"守卫）；agent 编辑板不在视口时画布自动平移跟随；标签发光、顶栏 pill 微光强化。
- **F3 动效治理修复（既有失败）**：`oaw-agent-pulse`/`oaw-agent-glow` 登记进动效统一闸门与 `动效治理测试.mjs` 清单；本轮新增动画同步登记。

### 2.2 非目标

- 不新增事件类型、不改事件注册表、不改服务端（终态围栏已存在）。
- 不做跨会话"正在编辑"的会话列表角标（活动按 slug 全局可见已足够）。
- 不改 `creativeCanvas` 等运行时开关默认值。
- 不做板条/全览的进一步迭代（004 验收反馈已闭环）。

## 3. 设计

### 3.1 F1 活动生命周期重构

**共享纯函数**：`canvasToolMeta`（ChatPanel.jsx:60-71）迁至 `client/src/画布状态.js` 导出；ChatPanel 与 App 统一引用（ChatPanel 以 `../画布状态.js` 相对路径引入）。

**App.jsx 全局流 `handlePayload` 新增**（canvas_changed/canvas_created 分支附近）：

```jsx
// canvas_* 工具活动跟踪（2026-11-11-008）：全局流单一事实源。
// thread 流随会话切换开合，tool_end 会丢；全局流常驻且信封自带 threadId，
// 服务端终态围栏（runs.mjs recordRunEvent）已拦截 Run 收尾后的迟到 tool_start。
if (event.type === "tool_start" || event.type === "tool_end") {
  const data = event.data || {};
  if (String(data.name || "").startsWith("canvas_")) {
    const meta = canvasToolMeta(data);
    if (meta.slug) {
      const active = event.type === "tool_start";
      setCanvasActivity((prev) => ({
        ...prev,
        [meta.slug]: {
          active,
          boardPath: String(meta.boardPath || (active ? "" : prev[meta.slug]?.boardPath || "")),
          action: String(meta.action || ""),
          threadId: String(event.threadId || prev[meta.slug]?.threadId || ""),
        },
      }));
    }
  }
}
// Run 终态权威收口：凡该 thread 的画布活动一律落定，不再依赖逐个 tool_end。
if (["run_finished", "agent_error", "run_recovered"].includes(event.type)) {
  const tid = String(event.threadId || "");
  if (tid) {
    setCanvasActivity((prev) => {
      let changed = false;
      const next = { ...prev };
      for (const [slug, info] of Object.entries(prev)) {
        if (info?.active && (!info.threadId || info.threadId === tid)) {
          next[slug] = { ...info, active: false };
          changed = true;
        }
      }
      return changed ? next : prev;
    });
  }
}
```

**canvas_changed 分支**：删除 `setCanvasActivity(... active:false ...)`（App.jsx:1344-1347），保留刷新批量逻辑原样。

**ChatPanel.jsx**：删除 L3269、L3328 两处 `onCanvasActivity?.(...)` 上报、`canvasToolMeta` 本地定义、`onCanvasActivity` prop 与 App.jsx:2601-2607 的回调透传。

**app 记忆**：`canvasActivity` state 注释（App.jsx:515）更新为"slug → { active, boardPath, action, threadId }（全局流驱动，Run 终态权威收口）"。

### 3.2 F2 显著性强化

**a) 自动定位标签（App.jsx，新 useEffect 订阅 canvasActivity）**：

- 选出"active 且本工作区"的 slug；当出现**新的**激活 slug（与上次记录比对，ref 存储）时：
  - 无对应 design 标签 → `openDesignCanvas(slug, slug)`（既有，App.jsx:834，自带 `setCanvasCollapsed(false)`）；
  - 有标签但非激活 → `setCanvasActiveId(该标签 id)` + `setCanvasCollapsed(false)`；
- **不抢守卫**：`Date.now() - canvasTabManualAtRef.current < 10000`（用户 10s 内手动切换过画布标签，语义同 autoTab App.jsx:2385）则跳过激活，仅静默记录，待下次 slug 变化再试；
- 活动结束（全部 active:false）不清空标签、不切换焦点。

**b) 视口自动跟随（创作画布.jsx）**：

- 新增 effect：`agent活动.active && agent编辑板` 变化时，若该板**不在当前可视板集**（复用 `画布模型.js` 的 `视野内板`，对板中心点做视口命中判断）→ `set视图(定位板视图(板列表, agent编辑板, 视口尺寸引用.current, 48))`；不改 `当前板路径`（不抢用户选中态）。
- 用户手动平移/缩放后 5s 内不跟随：新增 `最后用户操作引用`（视口 onPointerDown/onWheel 打戳）。

**c) 视觉强化（styles.css，全部用既有令牌 `--map-accent`，不新增十六进制色值）**：

- 标签：`.canvas-tab.agent-editing` 加 `box-shadow` 呼吸（复用 `oaw-agent-pulse` 时序 1.6s）；

## 6. 假设与决策

| # | 决策 | 依据 |
|---|---|---|
| 1 | 活动持续整轮而非逐工具闪烁 | 用户诉求"更显著"；整轮持续才能"看见" |
| 2 | 自动定位标签带 10s 不抢守卫 | 用户明确要"看到"；同时尊重手动焦点（沿用 autoTab 语义 App.jsx:2385） |
| 3 | 活动跟踪迁全局流并移除 ChatPanel 上报 | 双流并存有乱序复活风险；全局流常驻、带 threadId、有服务端终态围栏 |
| 4 | `run_recovered` 视为终态清理 | 服务重启后原 Run 已收口，残留即卡死 |
| 5 | 视口跟随不改用户当前选中板 | 只平移视口，不抢选中态 |
