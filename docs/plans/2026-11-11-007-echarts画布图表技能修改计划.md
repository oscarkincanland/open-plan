## 1. 取证

### 1.1 链路能力现状
- ECharts v5.3+ 支持服务端渲染：`echarts.init(null, null, { renderer: "svg", ssr: true, width, height })` + `chart.renderToSVGString()`（Node 无 DOM 可用），产出纯展示 SVG（path/text/defs/clipPath），无脚本。
- 画布 svg 元素两种形态：`markup` 内联（≤4MB，清洗后）或 `src` 引用 `designs/<slug>/project/assets/` 素材（`svgBlockElement` 按 viewBox 包装）；导出 SVG/PNG/PDF 走同一序列化，PPTX 走 addImage。
- 技能依赖：frontmatter `requires: npm: [echarts]` → 技能中心预检（未安装=blocked，给安装入口）→ 用户点击安装 → `<workspace>/.oaw/skill-deps/echarts-canvas-chart/node_modules/echarts`。

### 1.2 缺口
- 没有"一条命令把 option 变成画布上的图表元素"的技能化链路；agent 每次都要现推渲染方法，易错（中文字体、尺寸匹配、素材路径）。

## 2. 范围

### 2.1 本次要做
新增技能目录 `.claude/skills/echarts-canvas-chart/`（项目级，随仓库提交）：

```
.claude/skills/echarts-canvas-chart/
├─ SKILL.md                      # frontmatter（name/description/requires/install）+ 使用流程
├─ scripts/
│  └─ render-chart.mjs           # 渲染脚本：--option x.json --out y.svg --width --height [--depsDir]
└─ templates/                    # 精简 option 模板（交通规划常用）
   ├─ bar-compare.json           # 柱状对比
   ├─ line-trend.json            # 折线趋势（多系列）
   ├─ pie-share.json             # 占比饼/环
   ├─ bar-stack.json             # 堆叠柱
   └─ sankey-od.json             # 桑基 OD 流向
```

**SKILL.md 正文流程（agent 执行手册）**：
1. 判依赖：`skills_search/预检` 发现 echarts 未安装 → 提示用户在技能中心点安装（装到 `.oaw/skill-deps/`），未装则降级为"内置浏览器截图 PNG"兜底路径；
2. 选模板/写 option：从 `templates/` 起步改数据（数据来自用户/工作区文件），尺寸与目标画板一致（默认 1280×720）；
3. 渲染：`node <技能目录>/scripts/render-chart.mjs --option o.json --out <workspace>/designs/<slug>/project/assets/chart-<名>.svg --width 1280 --height 720 --depsDir <workspace>/.oaw/skill-deps/echarts-canvas-chart`；
4. 上板：`canvas_write` 在目标板追加 `{ type:"svg", src:"assets/chart-<名>.svg", x, y, w, h }`（w/h 与渲染尺寸一致）；
5. PPTX 说明：导出 PPT 后图表为**矢量图片**（不可在 PPT 内改数据）；需要可编辑图表对象属于方案二范围，不在本技能。

**渲染脚本要点**：
- 用 `createRequire` 从 `--depsDir` 解析 echarts（未装时输出明确中文指引退出码 2）；
- SSR：`echarts.init(null, null, { renderer:"svg", ssr:true, width, height })` → `setOption(option)` → `renderToSVGString()`；
- 字体：option 里默认 `fontFamily: "Microsoft YaHei"`（PPT/浏览器两侧中文安全）；SVG 输出固定写死 width/height；
- 安全校验：option 必须 JSON（禁函数/闭包），脚本不 eval 任何代码。

### 2.2 非目标
- 不做 `chart` 一等元素、不做交互图表、不改导出管线与 PPT 原生 addChart（方案二另立计划）；
- 不把 echarts 加进仓库 package.json；
- 不改动 baoyu-echarts 技能（两者互补：它管"option 怎么写"，本技能管"怎么落画布"）。

## 3. 设计

### 3.1 SKILL.md frontmatter（对齐 pptx/docx 技能样例）

```yaml
---
name: echarts-canvas-chart
description: >-
  把 ECharts 图表以静态矢量 SVG 插入创作画布并随 PPTX 导出：内置交通规划常用模板
  （柱状对比/趋势/占比/堆叠/OD 桑基），SSR 渲染到画布 assets 后用 canvas_write 上板。
  依赖 echarts（首次使用需在技能中心安装到工作区）。
requires:
  runtime: [{ kind: node, version: ">=18" }]
  npm: [echarts]
---
```

### 3.2 render-chart.mjs 关键逻辑

```js
// 伪代码（实现以此为准，错误 code 前缀 ECHARTS_）
const depsDir = 参数.depsDir || env.SKILL_DEPS_DIR;        // <workspace>/.oaw/skill-deps/echarts-canvas-chart
const require = createRequire(path.join(depsDir, "package.json"));
const echarts = require("echarts");                        // 缺失 → exit 2 + 安装指引
const chart = echarts.init(null, null, { renderer: "svg", ssr: true, width, height });
chart.setOption(option);                                    // option 由 JSON 文件读入，不 eval
const svg = chart.renderToSVGString();
fs.writeFileSync(out, svg);                                 // out 必须落 designs/<slug>/project/assets/（由调用方保证）
```

### 3.3 模板
5 个精简 option 模板（每个 ≤60 行，含中文 fontFamily 与示例数据），agent 按"改数据不改结构"使用；OD 桑基模板节点/流向用中文示例（丽水→各县市示意，标注演示数据）。

## 5. 验证

### 5.1 自动化
- `npm run test:skill-discovery` / `test:skill-deps` / `test:skill-injection`：新技能可被发现、frontmatter 解析正常、requires 预检输出 ready/blocked 合理；
- `node .claude/skills/echarts-canvas-chart/scripts/render-chart.mjs --option templates/bar-compare.json --out %TEMP%\t.svg --width 640 --height 400 --depsDir <已装目录>`：产出合法 SVG（含 `<svg` 与中文文本）。

### 5.2 手工端到端
1. 技能中心看到 echarts-canvas-chart，预检 blocked（未装）→ 点击安装 → ready；
2. Work 会话："在画布<slug>的板2 上加一张 2024 年各区县客运量对比柱状图（数据：…）"→ agent 用模板渲染 → canvas_write 上板 → 画布显示图表；
3. 导出 PPTX → 对应页图表为清晰矢量图；
4. 未装依赖时 agent 给出兜底（内置浏览器截图 PNG）。

### 5.3 未验证/风险
- npm 安装 echarts 需联网（用户点击触发，一次性）；
- 无头环境 SSR 中文文本用系统字体渲染，PPT 侧若缺字体会替换（模板默认微软雅黑缓解）；
- ECharts 高级类型（地图/3D）SSR 输出可能较大（≤4MB 清洗上限内可用）。
