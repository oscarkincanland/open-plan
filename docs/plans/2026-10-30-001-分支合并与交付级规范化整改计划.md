## 1. 硬约束（违反即停止）

1. **只做加法**：合并后逐项核对功能清单（§6.1），任何能力丢失视为阻断。
2. **未验证不提交**：每个 commit 必须附验证命令与结果；红灯不提交、不合并、不推送。
3. **无关文件不入库**：见 §4.1 排除清单；`open plan/`、`.trash/`、软著材料、汇报素材、`.trae/` 文档一律不入库。
4. **单一事实源**：规范只保留一套（`AGENTS.md` + `docs/规范/`），`doc/` 迁移后不并存。
5. **新能力默认关**：CAD、地图截图、活动摘要、懒加载、陈旧流停摆等全部挂 `运行开关.mjs`，关闭态 = 基线。
6. **零新增 npm 依赖**：`package.json` 依赖键零新增；Pi SDK 版本变更需单独说明与验证。
7. **不碰冻结区**：Chat/Work/Review 视觉冻结以远端 `DESIGN.md` 为准，只允许行为增强。
8. **提交纪律**：一条工作流一次提交，pathspec 提交，禁止 `git add -A` / `git add .`。

## 8. 阶段 P5 · 交付级代码整改

### 8.1 命名规范（写入 `docs/规范/代码规范.md`）

| 对象 | 规则 | 示例 |
|---|---|---|
| 新增服务端模块 | 英文 kebab-case | `provider-config.mjs`、`map-screenshot.mjs` |
| 新增 React 组件 | 英文 PascalCase | `ProviderConfigDialog.jsx` |
| 新增 hook/工具 | 英文 camelCase 文件 | `useRunEvents.js`、`fileIdentity.js` |
| 新增测试脚本 | 英文 kebab-case + `-test.mjs` | `activity-summary-test.mjs` |
| 存量中文代码文件 | **冻结不改名** | `事件注册表.mjs`、`工作产物面板.jsx` |
| 文档/数据/模板/用户产物 | 可中文 | `docs/规范/代码规范.md` |
| 标识符 | 英文；注释中文 | `normalizeWorkspaceWriteError` |

禁止：`utils.mjs`、`helpers.mjs`、`common.mjs`、`temp*`、`new*`、无边界模块；新增目录必须先有架构规范依据。

### 8.2 代码质量门禁

- 单文件 >500 行标技术债；新增 >300 行先拆分。
- 服务端具名导出；React 组件默认导出；Node 内置模块 `node:` 前缀。
- 业务模块不直读 `process.env`；统一走 `运行开关.mjs`。
- 写盘统一通道；事件先登记；工具三处对齐。
- 错误响应统一 `{ error, message?, requestId? }`；错误码可追溯。

### 8.3 测试与 CI

- 新功能至少 1 条正向 + 1 条反例；缺陷修复必须有回归测试。
- 本次新增测试接入 CI：`test:cad`、`test:preview-lazy`、`test:activity-summary`、`test:stale-stream`、供应商/地图相关。
- CI 以远程 16/18 步为基线，只增不减；新增步骤必须本地先绿。

### 8.4 版本与发布

- 合并完成后版本号 `0.13.12`；`package.json`、`变更日志.md`、README 版本矩阵、tag 四处一致。
- tag 用附注类型；不推 `main`，先推 `integrate/v0.13.11` 或 PR。
