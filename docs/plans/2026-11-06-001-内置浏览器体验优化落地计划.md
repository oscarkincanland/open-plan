## 1. 目标与不做

**目标（两条）**
1. 让浏览器面板不卡：切走即省资源、单帧更轻、渲染更快。
2. 让 Agent 用浏览器时用户看得见：在做什么、跑到第几步、读了什么、卡在哪。

**不做（本次）**
- 不引入 Playwright/Puppeteer/桌面壳/托管浏览器（平台选型 P2 另议）。
- 不改 SSE 契约语义（只新增事件、新增字段）。
- 不做二进制 WebSocket / WebRTC / 变化区域推帧（属 P1/P2，本期不做）。
- 不动 `server/task.mjs` 工具白名单与能力计划（不加新工具，只加事件）。

## 2. 任务分解

### T1 面板隐藏即停帧流【P0，根因 R2】

- **做法**：`App.jsx` 保持 `BrowserPanel` 挂载不变，传入 `visible`（= 当前激活画布标签是否是 browser）；面板内 `visible=false` 时释放长连接槽位（`slot.release()`）→ 服务端 `subscriberCount` 归 0 → 自动 `stopScreencast`（`内置浏览器.mjs:665-667` 已有该能力）。恢复可见时重新走现有订阅路径 + 首帧兜底（`captureFrame`）。
- 同时把 `browserAdaptiveStream`（现仅 `document.hidden`，`内置浏览器面板.jsx:170-181`）的暂停判定改为「页面不可见 **或** 画布标签未激活」。该 flag 从“默认关”仍保持关，但暂停逻辑与 T1 解耦，避免误开。
- **改动文件**：`client/src/App.jsx`（装配套件 ~lines 2863-2867）、`client/src/components/内置浏览器面板.jsx`（连接清理 + visible 判定）。
- **验收**：切到其他画布标签，服务端流登记数归 0、浏览器进程 screencast 停止；切回画面自动恢复且丢帧不白屏。
- **预估**：0.5 天（含手工回归）。

### T2 帧参数基线调优【P0，根因 R1/R4】

- **做法**：`server/内置浏览器.mjs:36-43` 常量调整：
  - `FRAME_QUALITY` 70 → 55（密集页帧从 ~145KB 降到 ~80-100KB，可读性损失小）
  - `FRAME_MAX_WIDTH/HEIGHT` 1600/1000 → 1280/900（面板实际显示宽度远小于该值）
  - `FRAME_BROADCAST_INTERVAL_MS` 90 → 120（等效 9fps，肉眼基本无差异）
  - 均已有 `OAW_BROWSER_FRAME_*` 环境变量覆盖路径，默认值即新基线；不加新运行时开关。
- **改动文件**：仅 `server/内置浏览器.mjs`。
- **验收**：`test:browser`；同一页面调整前后截图对比帧大小下降 ≥30%；面板观感无明显糊。
- **预估**：0.25 天。

### T3 渲染改 Blob URL【P0，根因 R3】

- **做法**：`内置浏览器面板.jsx:646-653` 的 `data:` URL 改为 `Blob` + `URL.createObjectURL`（文件内已有同类代码 `downloadBase64` `:469-478` 可参考）；新帧到达时创建新 URL、旧 URL 延迟 revoke（跨帧保留旧图避免闪白，保留最近 2 个）。
- **改动文件**：仅 `client/src/components/内置浏览器面板.jsx`。
- **验收**：长会话 objectURL 数恒定；Performance 面板长任务消失；滚动/点击无闪烁。
- **预估**：0.5 天。

### T4 复活 `agent-action` 广播【P0，根因 R8】

- **做法**：`server/内置浏览器.mjs` 在 Agent 写操作工具路径（`browserClick/browserType/browserPress/browserScroll/browserOpen`，`built-in` 已有 `broadcast` 基建 `:127`）发出 `agent-action` 事件：`{ kind, nx, ny, text, direction, key, url, at }`；前端渲染层已存在（`:122-128,657-670`），无需改前端。
- **改动文件**：仅 `server/内置浏览器.mjs`（每个工具函数 1 行广播）。
- **验收**：Agent 跑一次「搜索→点结果」，面板出现虚拟鼠标与动作气泡。
- **预估**：0.25 天。

### T5 打开/等待进度可见【P0，根因 R7】

- **做法**：`state` 增加 `phase` 字段（"navigating" | "settling" | "waiting" | ""），在 `waitForLoad`（`:1207-1238`）与 `waitForCondition`（`:1552-1569`）进入不同阶段时更新并 `emitState`；面板状态条（`:597-603`）与 busy 文案展示该阶段（如“等待内容稳定…”）。
- **改动文件**：`server/内置浏览器.mjs`（state/emitState）、`client/src/components/内置浏览器面板.jsx`（状态文案）。
- **验收**：打开慢站点时状态文案区分「加载中/稳定内容中/等待条件」；`test:browser` 回归通过。
- **预估**：0.25 天。

### T6 浏览器步骤与"读到内容"时间线【P0，可观测性主体，根因 R8/数据层】

- **事件契约**（登记进 `server/事件注册表.mjs`，遵守其 lint 约定）：
  ```
  browser_step_start (persist, lifecycle)  { runId, toolCallId, kind, url, title }
  browser_step_end   (persist, lifecycle)  { runId, toolCallId, status, durationMs, url, title, error }
  browser_read       (persist, lifecycle)  { runId, toolCallId, url, title, chars, elementCount, preview≤300字 }
  browser_progress   (不落盘, lifecycle)   { toolCallId, phase, detail, elapsedMs }
  ```
- **服务端落点**：`server/agent.mjs` 的 `browser_*` 工具路径内（附近已有 tool_execution_start/end 结构）统一包装 emit；`browser_snapshot/browser_extract` 结果里拿 `text/elements` 派生 `browser_read`。**不改 `内置浏览器.mjs`**，保持其零业务依赖。
- **前端落点**：会话流新增「浏览器活动」折叠时间线（每步一行：动物词 + 目标 + 读了 N 字 + 耗时 + 状态），数据从现有事件 SSE 消费；点开某步可看 `browser_read.preview` 与（如该步有截图）`/api/browser/shot` 缩略图。组件挂在 `ChatPanel.jsx` 工具卡链路旁，复用其状态样式。
- **改动文件**：`server/事件注册表.mjs`、`server/agent.mjs`、`client/src/components/ChatPanel.jsx`、（新样式进 `styles.css`）。
- **测试**：新增事件必须登记 + 对应测试（`scripts/事件注册表测试.mjs` 会强制）；新增 `browser_read` schema 校验测试；手工回归一轮真实浏览器会话。
- **预估**：1 天（事件+包装 0.5，前端 UI+联调 0.5）。

## 4. 测试与验证计划

1. 每个 commit 前：`npm run verify` + 受影响 `test:browser` / 事件注册表测试。
2. 手工回归清单（一次会话内完成，截图存 `docs/plans/evidence/`）：
   - 打开必应（观察 phase 文案）
   - Agent 完整跑一轮「搜索→点进一条结果→snapshot 读正文」（观察虚拟鼠标、时间线、读取字数）
   - 切换到文档/地图标签 1 分钟（确认帧流停止、CPU 下降）→ 切回（确认画面恢复）
   - 用户接管/交还各一次（确认 ownership 不受影响）
   - 多会话切换后浏览器会话恢复正常
