## 1. 缺陷现象（用户报告）

> 用户原话：“我的输入栏这里的模式切换，以及上下文的窗口这里有点问题，向上弹窗有点被折叠了看不到了。”

复现结论：输入栏工具条（`.chat-toolbar`）内所有**向上展开的浮层**被工具条的 `overflow: hidden` 整体裁掉，点击后 DOM 已展开（`aria-expanded="true"`）、但屏幕上完全看不到。已确认受影响 3 处：

| # | 浮层 | 触发器 | 用户可感知表现 |
|---|---|---|---|
| 1 | 审批模式下拉（自动批准 / 每次询问） | 工具条左侧「自动」按钮（盾牌图标） | 点击后无任何下拉可见，无法通过该入口切换审批模式（键盘仍可 Tab 到不可见项） |
| 2 | 上下文用量浮层（含「压缩上下文」入口） | 工具条右侧上下文环「3% 26k」 | 点击后无用量明细，无法看到压缩线、token 明细，也无法点「压缩上下文」 |
| 3 | 「+」添加内容菜单（图片 / 文件；地图模式另含当前地图视图） | 工具条最左侧「+」 | 点击后无菜单出现，无法添加图片/文件 |

对照：**模型选择浮层正常**——它已改为 `createPortal` 到 `body` + 视口定位（`client/src/components/ChatPanel.jsx:5907-5913`、定位函数 `:912-933`），不受工具条裁剪影响。这也说明问题只在“仍渲染在工具条内部”的三个浮层。

DESIGN §6 明确要求这三处能力：「`+` 聚合菜单（图片 / 文件 / 当前地图视图）」「审批模式下拉（下拉给两项完整说明）」「上下文 chip（点击向上弹出用量明细并提供「压缩上下文」）」——当前实现与 DESIGN 不一致，属于用户可见缺陷（非数据损失）。

## 3. 根因

1. **回归引入点**：计划 [2026-11-10-003](2026-11-10-003-顶栏画布卡片融合与输入栏单行工具条修改计划.md)（D3=A「恒单行 + 分级收纳」，提交 `1769a23c`，2026-11-10）把 `.chat-toolbar` 改为 `flex-wrap: nowrap; overflow: hidden;`（`client/src/styles.css:6697-6711`，其中 `:6709` 为 `overflow: hidden`）。注释写明“overflow 只作最后兜底”，用于窄宽度下横向裁切多余控件、保证工具条恒单行。
2. **浮层仍在工具条内部**：
   - 上下文用量浮层：`.context-ring-pop` 位于 `.context-ring-wrap.inline` 内（`ChatPanel.jsx:8189`），CSS `position:absolute; bottom:calc(100% + 6px)`（`styles.css:803`、`:830`）——向上展开、超出工具条盒子。
   - 审批模式下拉：`.approval-mode-menu`（`ChatPanel.jsx:8286`），CSS 同样 `bottom:calc(100% + 6px)`（`styles.css:854`）。
   - 添加内容菜单：`.composer-add-menu`（`ChatPanel.jsx:5812`），CSS `bottom:calc(100% + 6px)`（`styles.css:874`）。
   三者在 DOM 上都是 `.chat-toolbar` 的后代，`overflow:hidden` 以**整个工具条盒子**为裁剪框，向上部分 100% 被裁。
3. **同类问题已有先例与修复**：模型浮层此前也被 `.center-chat-slot{overflow:hidden}` 裁切（`ChatPanel.jsx:875-877` 注释），已改为 Portal + `position:fixed` + 视口夹取；本次是同一类问题的剩余三处。
4. **为什么测试没抓住**：`scripts/工作区面板与输入栏收敛测试.mjs` 仅做源码正则断言（`:60` 断言存在 `.approval-mode-menu`、`:64` 断样式存在、`:69` 断言 `.context-ring-wrap.inline .context-ring-pop { top:auto; bottom:calc(100% + 6px) }`），只验证“写没写”，不验证浮层是否可见（无真实几何断言）。

## 4. 方案对比

### 方案 A（推荐）：工具条“横向裁切、纵向放行”（CSS 轴向分离）

把两处工具条规则的 `overflow: hidden` 改为 `overflow-x: clip; overflow-y: visible;`：

- 保留 D3=A 的**恒单行**与“超宽时横向兜底裁切”的原意（`overflow-x: clip` 仍裁掉横向溢出、不产生滚动条）；
- 纵向不再裁剪，工具条内的向上浮层恢复可见；
- 纯 CSS，不改组件结构、JavaSript 与交互逻辑，不新增依赖；既有静态测试（断言向上规则存在）无需改写。

**为什么合法**：CSS Overflow 3 允许 `clip` 与 `visible` 分轴组合（一侧 `clip` 不产生滚动容器，另一侧保持可见）；Electron 33 = Chromium 130、桌面 Chrome/Edge 均支持。

**改动清单（实施时）**：

| 文件 | 位置 | 改动 |
|---|---|---|
| `client/src/styles.css` | `:6709` `.chat-toolbar` 内 `overflow: hidden;` | 改为 `overflow-x: clip; overflow-y: visible;`，补注释引用本计划 |
| `client/src/styles.css` | `:10315` `.center-chat-slot.map-mode .chat-toolbar` 内 `overflow: hidden;` | 同上（地图模式窄栏共用同一 ChatPanel，同样被裁） |
| `scripts/输入栏浮层裁切回归测试.mjs` | 新增 | 静态回归（见 §5） |
| `package.json` | scripts | 新增 `"test:composer-popover-clip"` |
| `变更日志.md` | 顶部 [未发布] | Fixed + Tests |
| `DESIGN.md` | §6 输入栏工具条 | 补一句验收口径：工具条允许横向裁切，但不得裁掉向上浮层；浮层不可见视为缺陷 |

**残留风险/已知限制**（接受则写入实施记录）：

- 极短窗口（视口高度 ≲520px）时，360px 高的上下文浮层顶部仍可能被聊天区祖先 `.chat{overflow:hidden}` 裁到；正常桌面窗口不受影响。彻底解决需方案 B。
- 地图模式窄栏（`.center-chat-slot.map-mode`）宽度极窄时，浮层若横向超出工具条会被 `overflow-x: clip` 裁到；实施时在 1024/900 宽度与地图模式下复验。
- 浮层仍无“向上空间不足时向下翻转”能力（与现状一致，不属于回归）。

### 方案 B（备选，彻底）：三浮层 Portal 到 body + 锚点 `position:fixed` 定位

做与模型浮层一致的彻底修复：

- 抽出共享定位 helper：以触发器 `getBoundingClientRect()` 计算左/上/宽/`maxHeight`，视口夹取、上下翻转、`resize/scroll` 重算；
- 上下文用量 / 审批模式 / 添加内容三处渲染改为 `createPortal`，CSS 增加 fixed 变体；
- 外部点击关闭判断从 `wrapRef.contains` 扩展为 `popRef.contains`（与模型浮层 `:944-948` 一致）；
- 同步改写 `scripts/工作区面板与输入栏收敛测试.mjs:69` 的向上规则断言（该断言绑定非 Portal 的绝对定位）。

优点：任何祖先 `overflow` 都裁不到，短窗口自动翻转，完全符合 DESIGN“浮层不被裁切”的既有验收（另见 `docs/plans/2026-09-30-001…`“浮层不被裁切”、`docs/plans/2026-10-28-005…`“Tooltip 被 overflow:hidden 裁剪 → fixed/portal”）。
代价：改 3 处组件渲染 + 3 处交互关闭逻辑 + CSS，回归面（外部点击/Esc/焦点/滚动跟随/地图窄栏/多标签）明显大于 A；需要真实浏览器逐项复验。

## 5. 推荐结论与验收口径

**推荐先做方案 A**：改动仅 2 行 CSS + 注释 + 回归测试，当日可验证，直接恢复 DESIGN §6 要求的三处入口；方案 B 作为后续可选升级（若出现短窗口/窄栏裁切再立项）。

新增回归测试 `scripts/输入栏浮层裁切回归测试.mjs`（`npm run test:composer-popover-clip`）断言：

1. `.chat-toolbar` 基础规则含 `overflow-x: clip` 与 `overflow-y: visible`，且该规则内不再出现整体 `overflow: hidden`；
2. 地图模式 `.center-chat-slot.map-mode .chat-toolbar` 同样分轴，且 `flex-wrap: wrap` 保留（地图窄栏允许换行）；
3. 基础工具条仍保留 `flex-wrap: nowrap`（守住 D3=A 恒单行，防止修复回退换行）；
4. `ChatPanel.jsx` 中三处浮层仍渲染在工具条内（因此必须依赖纵向放行），模型浮层仍走 `createPortal`（防止未来回退）。

**验收矩阵**（实施后记录 DOM 几何 + 截图）：

- 窗口 1440×900 / 1280×800 / 1024×768 × {画布面板开 / 关}；
- 分别点开三个浮层：浮层 `getBoundingClientRect` 完全在视口内、不被祖先裁切（`elementFromPoint(浮层中心)` 命中浮层内部）、项可点击（审批切到「每次询问」、添加菜单两项可见、上下文「压缩上下文」按钮可见）；
- Esc / 点击外部可关闭；工具条仍为单行（高度不增）；页面无横向滚动；控制台无新增错误；
- 回归：`npm run verify`、`npm run test:workspace-panel`、`npm run test:chat-layout`、`npm run test:a11y`、`npm run test:ui-guard`、`npm run test:css-syntax`、新增 `npm run test:composer-popover-clip` 全部通过；既有失败需在实施记录中列明并证明与本次无关。
