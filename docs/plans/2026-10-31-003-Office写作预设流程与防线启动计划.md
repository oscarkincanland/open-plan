## 0. 结论先行

1. **预设流程已经建好，缺的是把模型引导上去的防线通电。** `editorial_pipeline`（Planner→Writer→Formatter 原生 OOXML 直写→Evaluator，支持 sourceMarkdown 直通）与 `create --styled`（O-17）就是既定的"预设写报告流程"；run_05198175 的 20 次失败不是能力缺失，而是防线默认断电后模型走了 CLI 野路子。
2. **防线代码全部在位但默认不生效**：`OAW_OFFICE_FORMAT` 默认关 → 执行闸门、澄清首问、流水线 10 回合提醒全部休眠；`OAW_RUN_BUDGET_ENFORCE` 默认 soft → 45 回合硬预算只报警不停车（实测 11 次 `run_budget_blocked`，一路跑到 55 回合）。
3. **CLI 兜底路径缺"工具书"**：模型 57 次 officecli 调用中 15 次在读 `help docx`、约 15 次在 test.docx 探针上试错；样式 raw-set 连环失败 7 次是因为 `create` 不预置样式集，模型被迫手写 styles.xml XPath。
4. 本次四件事：①写作路由默认通电（可显式退出）+ 补决策记录；②给 CLI 兜底路径注入"写作工具书"（五步流程 + 命令速查 + 样式禁令）；③`create` 预置标准样式集 + 图片引用预检物化，从源头消灭两类高频失败；④配套小修：Run 终态落盘、bash/WSL 预检、预算"受限收尾"真实化。
5. 合计 **N-01～N-09 共 9 项功能、10 个任务、约 3.5 人日**。不改 SSE 契约、不新增运行时依赖、不动 Chat/Review 边界。

## 2. 目标与非目标

### 目标（全部可验收）

写作路由（template/generate）下复跑同款写报告任务（L3 验收，见 §5）：

- 工具失败 ≤3 次（基线 20）；
- `officecli help` ≤1 次（基线 15）；
- 0 次 raw-set styles.xml（基线 7 次失败）；
- 澄清首问出现（基线 0 次 ask_user）；
- 产物进入 artifacts 并通过 9 项规则闸门（基线 0）；
- 回合数 ≤45（基线 55）。

### 非目标

- 不新做文档生成器、不改 Office CLI 二进制；
- 不动 Chat/Review 只读边界与工具白名单结构；
- 不改 SSE 事件契约（复用 `run_budget_blocked` / `tool_gate_denied` / `pipeline_*` 既有事件）；
- 不把闸门扩大到非写作路由；不引入新依赖。

## 3. 方案设计

### N-01 防线通电：写作路由自动启用 Office 闸门

- **现状**：`agent.mjs:4430` `entry.officeGateOn = Boolean(RUNTIME_FLAGS.officeFormat)`，`task.mjs:336` 同条件；`OAW_OFFICE_FORMAT` 未设 → 全链休眠。
- **改法**：改为"路由即开"——`route ∈ {template, generate}` 且 `mode=agent` 时默认 `on`；`OAW_OFFICE_FORMAT=off` 显式退出；chat/review/edit 行为不变。三处条件（agent.mjs:4430、agent.mjs:1328、task.mjs:336）同步调整，判定逻辑收敛到 `运行开关.mjs` 新增 `officeGateActiveFor(route, mode)` 单一函数，避免三处漂移。
- **通电后自然生效的既有机制**（无需新写）：
  - 执行闸门拦截 bash 生成脚本 / 管线产出前的 create/add/set/batch 绕过（`office规范/执行闸门.mjs`，agent.mjs:1555、1624；`--allow-manual` 逃逸阀保留）；
  - 流水线 10 回合提醒（agent.mjs:3788）；
  - 澄清首问注入（agent.mjs:4436 `clarificationPending`）。
- **决策记录**：新增 `docs/决策记录/0012-Office写作闸门按路由自动启用.md`——在 0004"开关默认关"的框架下收窄为"写作路由场景默认开、env 可退出"，不全局翻默认。

### N-02 CLI 兜底路径"写作工具书"注入

- **现状**：officecli 工具描述已有 7 条英文 STRICT RULES（agent.mjs:1615），但无流程引导、无样式禁令、无错误速查；写作路由提示只有一句（task.mjs:421-437）。
- **改法**（追加到 officecli 工具描述 + 写作路由提示各一段，中文）：
  - **标准五步流程**：① `read` 模板 → ② `editorial_pipeline`（已有 markdown 直通；不适合管线时用 `create`，样式已预置见 N-04）→ ③ 逐章 `add <file> / --type markdown --prop src=章节.md`（write 后即插，勿攒批）→ ④ `validate` / `view issues` 自检 → ⑤ `complete_task`；
  - **样式禁令**：禁止 `raw-set` 直接改 styles.xml；样式在 create 时已预置（Normal/Heading1-4/Title/TOC/页眉页脚），改样式用 `set <file> paragraph style=Heading2` 或 `batch --commands`；
  - **错误速查表**（每条一行，与 office.mjs 返回的错误码一一对应）：`Style not found` → 先 `view <f> styles`；`Image file not found` → 先用 write 物化真实路径再插图；`Malformed XML` → 停止编辑该文件，改用 editorial_pipeline 重建；`decompression_bomb` → 拆文件，勿重试。
- **落点**：agent.mjs officecli 工具描述、task.mjs 写作路由提示（`写作路由：模板优先…`句尾追加"按写作工具书五步流程执行"）；同步 `docs/audits/2026-10-28` 对照文档。

### N-03 editorial_pipeline 升为写作默认能力条目（预设流程主链）

- **现状**：pipeline 是隐式工具（白名单里有、能力计划不声明）；模板路由实测缺口"planTaskCapabilities 静默"在 006 计划已部分修复（template 条目），但 pipeline 仍无条目。
- **改法**：`task.mjs` `planTaskCapabilities` 在 `route ∈ {template, generate}` 且 mode=agent 时声明 `{id:"editorial_pipeline", label:"编辑流水线", status:"preferred", provider:"native", reason:"成文走 Planner→Writer→Formatter 原生直写→Evaluator 确定性管线"}`；能力契约测试同步 v3→v4（仅追加字段，不改既有语义）。
- **产物登记**：确认 pipeline 产物路径同样写入 `写入清单.json` 与 `artifact_materialized` 事件（当前 `writeEvent("write_locked", {path:"."})` 粒度过粗，修正为真实目标文件）。

### N-04 `create` 预置标准样式集（CLI 路径去 raw-set 化）

- **现状**：文档引擎.mjs `create` 原生直写（docx@9），`--styled` 支持版式参数（O-17），场景参数.json / 设计令牌.mjs / 封面配方.mjs 参数源齐备；但默认 create 不注册任何段落样式 → 模型被迫 raw-set。
- **改法**：docx `create` 默认注入标准样式集：Normal（按场景参数 report 档：宋体/小四/1.5 倍行距/两端对齐）、Heading1-4、Title、TOC1-2、页眉（文档标题）/页脚（页码）；`--no-styles` 显式退出；edit 路径不注入（保留用户既有文档）。
- **错误增强**：`office规范/officecli检查.mjs` 对 `Style not found` 类错误附加可用样式 id 列表与 `add /styles --type style` 修复命令，替代模型盲试 XPath。
- **测试钩子**：create 后 `view <f> styles` 返回非空标准集合。

### N-05 图片/文件引用预检与自动物化

- **现状**：agent.mjs:1661 已按参数引用物化暂存文件（`写入协调.mjs:443`），office参数.mjs:70 已修过 `src=` 引号前缀变体；但 run 实测 `.work/figs/*.svg` 仍 6 次找不到——引用抽取未覆盖 image/attachment 形态，且引用不存在时原样透传 CLI 收到模糊报错。
- **改法**：
  - `office参数.mjs` 引用抽取白名单扩展：`--prop image=/src=/attachment=`、`add/set` 位置参数中的本地文件路径；
  - `office.mjs` 调用前预检：引用路径磁盘不存在且暂存区也没有 → 不发 CLI，直接返回结构化错误 `{code:"ref_missing", missing:[…], hint:"先用 write 生成该文件，或从命令中去掉该引用"}`；
  - 自动创建引用文件的父目录（figs/ 等）。
- **验收口径**：write 图片 → 插图全链一次成功；缺图时 1 次失败内给出可执行修复建议（基线：6 次盲目重试）。

### N-06 预算"受限收尾"真实化

- **现状**：硬预算事件文案承诺"不得再改文件"（运行预算.mjs `evaluateTurnGate`），但执行层仅 `enforce=hard` 才整 Run abort（agent.mjs:593-596）；默认 soft 下 45→55 回合继续改文件。
- **改法**：硬预算触发时置 `budget.restricted=true`；`工作台把关.mjs evaluateToolGate` 对 mutating 工具（write/edit/bash 非只读形态/officecli create|add|set|batch|remove|move|swap|delete）返回 `TOOL_RESTRICTED`（提示改用 complete_task 或 ask_user 收尾）；只读工具与 complete_task/ask_user/todo 放行。语义分层：`off`=完全放行（旧行为）｜`soft`（默认）=受限收尾｜`hard`=整 Run abort（原语义保留）。
- **不误伤**：只拦"改文件"，不拦只读与收尾；软提醒文案不变。

### N-07 Run 终态落盘（配套小修）

- **现状**：进程退出后 `running` 永挂（run_05198175 至今 `running`）；runs.mjs 无启动清扫。
- **改法**：服务启动时扫描 `.oaw/runs/*.json`，`status=running` 且 `updatedAt` 距今 >30 分钟 → 标记 `interrupted` + `finishedAt` + 收尾原因字段；运行中维持既有 updatedAt 心跳。

### N-08 bash/WSL 预检（配套小修）

- **现状**：bash 依赖 WSL，本机未装 → 每次失败透传 UTF-16 乱码（run 内 3 次；10-30 任务修复未成）。
- **改法**：启动时探测一次 WSL 可用性（`wsl.exe --status` 超时 3s），结果缓存 `.oaw/运行时记录.json`；不可用时：bash 工具描述追加"当前机器 bash 不可用，文档处理请用 officecli/read/write"；工作台把关对 bash 返回结构化 `{code:"bash_unavailable"}` 而非透传乱码。探测可用则零改动。

### N-09 文档同步

- REQUIREMENTS.md：R6/R13 验收口径补"写作任务工具失败率 ≤3 / 产物必须过规则闸门"口径；
- DESIGN.md：无界面改动，不涉及；
- `变更日志.md`：一条 `feat(office)`；
- audits 对照文档补 N-01～N-09 落地记录。

## 5. 验证与测试设计

对齐 `docs/规范/功能验证测试规范.md` 四层口径；新测试全部离线、无模型调用，进 `npm run verify`。

### L1 新增单测（4 个脚本）

**`scripts/Office写作闸门通电测试.mjs`（`test:office-gate-auto`）**
1. `officeGateActiveFor("template","agent")` / `("generate","agent")` 未设 env → true；
2. `OAW_OFFICE_FORMAT=off` → false（显式退出优先）；
3. route=edit / read，或 mode=chat/review → false（边界不变）；
4. 闸门 on 时：管线产出前 officecli 变更子命令被拦（复用执行闸门既有断言）、bash 生成脚本被拦、`--allow-manual` 逃逸放行；
5. 澄清：shouldAsk=true 时首问注入；"你看着办"跳过；
6. turnCount≥10 且未走管线 → office-pipeline steer 触发一次；
7. WSL 不可用探测桩 → bash 返回 `bash_unavailable` 结构化错误。

**`scripts/Office样式预置测试.mjs`（`test:doc-engine-styles`）**
1. `create 报告.docx`（无 --styled）→ styles 含 Normal/Heading1-4/Title/TOC1-2；
2. `--no-styles` → 不注入；xlsx/pptx 不受影响；
3. `set <f> paragraph style=Heading2` 引用预置样式成功；
4. 引用不存在样式 → 错误消息含可用样式 id 列表；
5. `batch` 重复 add 同 id 样式幂等不报错；
6. edit 路径（既有文档）不注入样式。

**`scripts/Office引用预检测试.mjs`（`test:office-ref-preflight`）**
1. 暂存区 `figs/a.svg` + officecli 参数引用 → 自动物化后 CLI 收到真实路径；
2. 引用磁盘与暂存区均无 → 返回 `ref_missing`（不发 CLI），missing 列表正确；
3. 引用父目录不存在 → 自动创建；
4. `--prop image=` / `src=` / 位置参数三种形态均被抽取；
5. 引号前缀变体（`image="x.svg"`）不回归（office参数.mjs:70 既有用例）。

**`scripts/预算受限收尾测试.mjs`（`test:budget-restrict`）**
1. turns≥45 → `evaluateTurnGate` hard + `restricted=true`；
2. restricted 后：write/edit/bash(非只读)/officecli(add) → `TOOL_RESTRICTED`；

5. `=hard` → abort 语义保留（stopRunByBudget 生效）；
6. `grantBudget`（用户显式继续）→ 解除 restricted。

### 7.2 与原计划的两处偏差（实施中发现的事实修正）

**① N-07 缩减为阈值调整。** 原计划假设"进程退出后 Run 永挂 running"，据此设计"启动清扫"。实施时核查发现：

- `server/runs.mjs` `recoverActiveRuns` 已处理重启后的活跃 Run；
- `server/index.mjs` `reapStalledRuns` 每 30 秒清扫一次静默 Run，`RUN_STALL_MS` 默认 3 分钟；
- 实测 Run `run_05198175` 最终 `status=completed`、`finishedAt=15:15:34Z`、产物 259KB docx——**它并没有永挂**，此前读到的 `running` 是 23:05 的中间快照。

故 N-07 改为：把 `RECOVER_MAX_RUNNING_MS` 由 6 小时降到 30 分钟（长任务不再长时间显示"执行中"），不新增清扫逻辑。

**② 产物并非 0 登记。** 原计划 §1 称该 Run "产物 0 登记"，实际 artifacts 含 `规划文本编制说明与续写清单.md`（write-ledger 检出），todos 八项全部 completed。失败分析本身不受影响（20 次工具失败、55 回合、15 次 help 是实情），但"防线断电导致任务失败"的因果表述需修正为：**模型最终靠试错硬扛过去了，代价是 23% 工具失败率与 55 回合**——这恰恰印证了本计划要消除的浪费。

### 7.4 实施中发现并修复的缺陷

**本轮引入、由 L3 实测抓出：**

1. **样式 id 与 docx 默认集重复** → `view issues` 直接抛 "An item with the same key has already been added. Key: Heading1"，整份文档的 issues/validate 全废。根因：docx@9 默认已生成 Heading1-6/Title，我又用 `paragraphStyles` 追加了一遍。修复：内置样式改走 `styles.default.*` 覆盖，只有默认集没有的（Normal/TOC1/TOC2/Header/Footer）才用 `paragraphStyles`；新增 `DOCX_BUILTIN_STYLE_IDS` 与"产物 styles.xml 无重复 styleId"测试。
2. **`create --force` 回退 CLI** → pipeline 先建了同名产物，模型再 `create --force` 时原生 create 因"文件已存在"回退，产物没有样式集 → 后续 `Style not found`。修复：原生 create 支持 `--force`/`-f` 覆盖。
3. **引用抽取把命令目标文件当素材引用** → `create 新文档.docx` 会因"目标不存在"被预检阻断。修复：`collectReferencedPaths` 跳过 `args[1]`。
4. **流水线原始返回落盘只给 basename** → 模型按提示去工作区根目录找 `.writer.raw.txt` 而读不到，多产生一次 ENOENT。修复：`diagnoseUnparsable` 传 workspace，输出工作区相对路径。
5. **工具描述把 `--compact` 列成通用选项** → 实测模型把 `--compact` 用在 `get` 上累计 9 次 "Unrecognized command or argument"。修复：描述改为按子命令区分 + 执行层 `stripUnsupportedOptions` 过滤。
6. **WSL 探测判据错误** → `wsl.exe --status` 即使一个发行版都没装也返回 0（实测本机 `--status` 退出码 0，而 `wsl.exe -l -v` 退出码 -1）。修复：改用 `wsl.exe echo` 实测能否执行。
7. **受限模式状态与事件快照的时序** → 硬预算事件在 `enterRestrictedMode` 之前发出，快照里 `restricted` 恒为 false，事后无法从事件流判断受限模式是否生效。修复：先切状态再发事件。
8. **模板路径用相对路径** → 提示词写 `templates/traffic-material/`，模型按当前工作区解析，而模板在项目目录，实测每一轮都产生一次 "Path not found"。修复：三处提示统一改用 `PROJECT_DIR` 绝对路径。
9. **流水线 planner 超时过短** → planner 角色默认 60 秒，但流水线要它规划整篇文档骨架，实测常被停掉。修复：新增 `PIPELINE_PLANNER_TIMEOUT_MS`（默认 120 秒）。
10. **工具描述里嵌套双引号导致语法错误** → 写 `"Unrecognized command or argument '--compact'"` 时双引号提前结束字符串，`node --check` 直接失败。修复：改用单引号。

**既有缺陷（由本轮测试或 L3 抓出）：**

11. `collectReferencedPaths` 的引号变体（`--prop src="ch01.md"`）抽不出路径 → 物化失败与 `markdown source file not found`。
12. `test:office-route` 的 O-28 断言与「常用技能短清单」拆分冲突（断言硬编码 `localSkillCatalog().length` 字面量，而新实现用 `const catalog = localSkillCatalog()` + `catalog.length`）。**未回退新实现**，而是把断言改为语义检查（技能计数必须来自目录实况，两种写法都接受），并用负向验证确认该断言确实能挡住"写死数字"的回归。
