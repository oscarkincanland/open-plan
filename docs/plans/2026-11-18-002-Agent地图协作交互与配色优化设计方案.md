## 1. 背景与目标

用户要求：交叉验证当前地图模块的交互、配色，以及 agent 与地图交互的前端渲染，并调研 GitHub 上 agent 与地图协作的主流做法，形成完整优化设计方案。

- **目标 1（交互）**：让 agent 的地图操作"看得见、可预览、可核对、可回退"，审批信息充分。
- **目标 2（配色）**：地图层色值全部令牌化，建立预注册色阶词汇表供 agent 引用，深浅主题适配，色盲安全。
- **目标 3（渲染）**：草稿渲染从"整层销毁重建 + 全量重拉"升级为增量更新，消除闪烁与静默失败。

不改变产品模式边界（地图能力只在 Work）、审批策略语义（auto 不放行固化/破坏性操作）、共享数据集禁写与锁定拒写等硬约束。

## 4. 业界调研结论

### 4.1 开源项目与工具 schema 粒度

- **qgis_mcp**（[GitHub](https://github.com/jjsantos01/qgis_mcp)）：15 个**图层级**工具（load/add/remove/zoom/get_features/render）+ `execute_code` 逃生舱——粒度设计的推荐区间。
- **ArcGIS Pro MCP**（[GitHub](https://github.com/Knight60/ArcGIS-Pro-MCP)）：112 工具，如 `set_layer_renderer` 一个工具完成分级设色+色带+描边；arcpy-mcp 1300+ 工具为**反例**（需白名单收紧）。
- **Mapbox Agent Skills**（[GitHub](https://github.com/mapbox/mapbox-agent-skills)、[教程](https://docs.mapbox.com/help/tutorials/build-your-own-agent/)）：**数据 agent 与视图 agent 分离**（一个产出 GeoJSON 由 GL JS 渲染，一个专管相机 flyTo）；官方技能教 AI 避坑（空白地图、glyphs 缺失）。
- **CARTO《Making deck.gl AI-ready》**（[博客](https://carto.com/blog/making-deckgl-ai-ready)、[原型](https://github.com/CartoDB/carto-agentic-deckgl)）：最有价值的架构参考——两条路线（有状态工具逐动词编辑 vs 无状态整份 spec 替换）；实测痛点：spec 无 schema 导致失败**全部静默**（agent 报成功但地图空白）、模型**编造不存在的配色 helper**；提案方向：JSON Schema 校验 + 转换报告 + **状态回读** + **patch 增量语义** + **标准化色阶词汇表**。

### 4.2 UX 交互模式

- **Applied-but-pending 范式**（WebMCP tripcanvas，[Devpost](https://devpost.com/software/tripcanvas-yewm6j)）：agent 每次修改 = "已应用但待确认"——**琥珀色高亮**、逐条 Revert、Accept All、一次规划为**原子 pending 批次**、agent 回读修订流。
- **审批门四要素**（[AI agent approval UX](https://dev.to/artemkireev/ai-agent-approval-ux-show-the-side-effects-not-a-yesno-2e16)）：Anthropic 数据显示 93% 权限弹窗被无脑批准 = 设计失败；审批卡应展示 **before/after diff、影响半径（改了多少对象）、可逆性声明、一行理由+证据**；按钮文案复述范围（"固化 212 个要素"）而非"Yes"。
- **按可逆性分级授权**（[HATP 草案](https://dev.to/murthyg/undo-for-ai-agents-a-draft-spec-for-taking-back-what-an-agent-already-did-41e0)）：工具返回可撤销窗口，可逆自动放行、不可逆必须人工确认——与本项目"草稿免审批、固化需审批"边界天然同构。
- **Before/after 对比**：社区惯用 [maplibre-gl-compare](https://maplibre.org/projects/gl-js/) swipe。
- **流式渲染**：业界**无成熟"流式 GeoJSON 边生成边画"公开实现**，主流是整层替换或整份 spec 替换；CARTO patch 语义是最接近增量的方案。

### 4.3 配色实践

- CARTO 实证：放任 agent 选色，所有模型默认 YlOrRd 万金油、偏态数据不做处理、不画图例、甚至编造 helper——结论是**渲染引擎侧提供唯一一套预注册色阶词汇表**供 agent 引用，而非自由传色值。
- [苏格兰政府地图设计系统](https://designsystem.gov.scot/guidance/maps/using-colour-in-maps)：按数据类型选 qualitative/sequential/diverging；相邻色 3:1 对比；禁用纯灰阶；避免仅靠颜色编码（加图案/描边/标签）。
- 无障碍：ColorBrewer 科学色带、3–7 分级、避免红绿对、明度差 ≥3:1。
- 深浅主题：业界收敛到 CARTO Positron（浅）/ Dark Matter（深）成对底图；agent 产出层样式须随底图主题切换。

## 6. 优化设计方案

### 6.1 方向 A：草稿层"已应用待确认"体验（applied-but-pending）

**理念**（借鉴 tripcanvas，适配 ADR 0019）：草稿层本就是"免审批、可丢弃"的暂存区，把"待确认"语义做足，而不是引入操作级 undo 历史（不违反 [ADR 0019](file:///Users/ouyangjincan/claude%20code%20本地文件夹/office-agent-web/docs/决策记录/0019-图层作用域与基线重置语义.md)）。

1. **草稿默认色改琥珀系**：草稿默认色由 `#2563eb` 改为琥珀令牌 `--map-draft-pending`（初稿：浅主题 `#f59e0b`、深主题 `#fbbf24`），保留虚线。"琥珀 = 待确认"与"蓝 = 正式"形成全局一致的语义色；需要在用户确认后同步更新 DESIGN §9.3 的"草稿蓝色系"表述。
2. **agent 批次聚合**：同一轮 agent 连续产生的草稿以 `batchId` 聚合（服务端在草稿元数据上标记），图层面板草稿区按批次分组展示，提供"整批固化 / 整批丢弃"快捷操作（现有逐草稿操作保留）。
3. **逐条回退（限当前批次）**：批次内每条草稿保持独立的丢弃入口（现状已有）；新增"整批丢弃"不触碰已固化历史——回退粒度仍是草稿对象级，不是操作历史级。
4. **对话流草稿摘要卡**：agent 产出草稿后在对话流插入一条轻量摘要（批次名、几何类型、要素数、[打开地图预览] 按钮），弥补"草稿事件不在对话流播报"带来的感知断层（现状 ChatPanel 收到 `map_draft_changed` 静默处理）。

### 6.2 方向 B：固化审批卡升级

对齐"审批门四要素"，改造对话流审批卡（[DESIGN.md §4](file:///Users/ouyangjincan/claude%20code%20本地文件夹/office-agent-web/DESIGN.md#L277) 人机协作卡）：

1. **影响半径**：展示草稿要素数、几何类型分布、bbox 范围、目标分组/名称。
2. **可逆性声明**：固化卡明示"固化后不可通过对话撤销，仅可经 `map_reset` 基线重置或 `.trash/` 恢复"；丢弃/重置等破坏性卡明示"不可撤销"。
3. **理由 + 证据**：卡片显示发起工具名、来源任务、（若 agent 提供）一句话固化理由。
4. **按钮文案复述范围**："固化（128 个要素 → 正式图层·路网分析）"而非通用"确认"。
5. **缩略预览**：审批卡内嵌 MiniMapPreview 式小地图快照（复用现有只读回放能力），让用户不切面板即可核对。

### 6.3 方向 C：渲染链路增量与就绪握手

1. **草稿增量渲染**：前端按 `draftId` 维护 Map 缓存；`action=update` 时对既有 GeoJSON source 执行 `setData`（MapLibre 原生增量），仅新增/删除草稿才 add/remove；不再"每次事件整层销毁重建"（替换 [MapViewer.jsx#L383-L436](file:///Users/ouyangjincan/claude%20code%20本地文件夹/office-agent-web/client/src/components/MapViewer.jsx#L383-L436) 的 clear-then-replay 为主路径，重放逻辑保留给样式热更场景）。
2. **免重拉数据**：`map_draft_changed` payload 已含 `features` 字段；前端优先消费事件 payload，仅 payload 缺失/超限（如 >2MB）才回退 GET。落地时需先核实 payload `features` 是否完整（此处存在不确定性，按现状裁剪）。
3. **就绪队列替代盲重试**：`showAnalysis` 的 250ms×12 重试改为"事件携带 revision/seq，前端在 style 就绪（markReady/applyStyle）后消费的待处理队列"，与草稿重放机制同构。
4. **渲染失败不静默**：单草稿/分析层渲染失败时（现 catch 后仅吞掉，[MapViewer.jsx#L433](file:///Users/ouyangjincan/claude%20code%20本地文件夹/office-agent-web/client/src/components/MapViewer.jsx#L433)），向面板/对话流上报一条可读警告（"草稿 X 渲染失败：几何无效"），并在事件 payload 中带错误标记。
5. **事件 schema 登记**：`map_draft_changed` 目前 persist:false 且无 schema；本轮为其补 payload schema 并通过校验（对齐 DoD"新增/变更事件已登记"）。

### 6.4 方向 D：配色令牌化 + 色阶词汇表（核心）

#### D1. 地图专属令牌族（styles.css，深浅两套）

```

--map-demo-badge         演示数据徽标色
--map-boundary-city      市界（现 #e4572e 收敛）
--map-boundary-county    县界（现 #b8b8c8 收敛）
--map-road-highway       高速（红绿盲安全改色，见 D2）
--map-road-rural         乡道
--map-road-generic       普通公路
--map-point-toll / --map-point-generic
```

服务端 [map.mjs layerStyle()](file:///Users/ouyangjincan/claude%20code%20本地文件夹/office-agent-web/server/map.mjs#L279-L318) 与 MapViewer 各硬编码处全部改为引用共享色板模块（**单一来源**：`client/src/地图/色板.js` 导出 + server 侧以 JSON 同源引用，避免双处漂移）。

#### D2. 预注册色阶词汇表（供 agent 引用，CARTO 实证驱动的强约束）

新建色板库（语义命名，深浅两套变体，每个色带含图例文案与色盲校验状态）：

| 色阶名 | 语义 | 类型 | 初稿色标 |
|---|---|---|---|
| `sequential.heat-flow` | 客流/出行强度热力 | sequential | `rgba(45,156,219,0)→#2d9cdb→#f2c94c→#f97316→#dc2626`（收敛现有 heatmap，两变体合一） |
| `sequential.density` | 密度/强度分级填色 | sequential | 单色明度梯度 `#dbeafe→#93c5fd→#3b82f6→#1d4ed8` |
| `diverging.od-balance` | OD 净流入/流出 | diverging | `#dc2626（流出）← #e5e7eb → #2563eb（流入）`，中点有意义（替代现 flow 紫→红混色带） |
| `qualitative.road-class` | 道路等级 | qualitative | 高速 `#dc2626` / 主干 `#f59e0b` / 次干 `#3b82f6` / 乡道 `#94a3b8`（**消除红绿对**，以明度差+线宽冗余编码） |
| `qualitative.mode-family` | 交通方式分组 | qualitative | 蓝橙紫青 4–6 色组合 |

**约束机制**：草稿样式与分析工具的配色参数增加 `palette` 枚举（只能引用上表色阶名，可选 `variant: light|dark`）；裸 hex 降级为"仅用户手调时经 UI 传入，agent 提示词引导用 palette"。工具 schema 变更需同步 [server/task.mjs](file:///Users/ouyangjincan/claude%20code%20本地文件夹/office-agent-web/server/task.mjs) 白名单相关参数、`planTaskCapabilities` 与 `test:capability-contract`（AGENTS §5）。

#### D3. 图例与编码冗余

- agent 用 palette 生成 choropleth/色带层时，强制产出图例（色带名 + 分级说明）——回应"prompt 不强制就不画图例"的业界实证。
- 道路等级等 qualitative 层保留线宽/虚线冗余编码，不只靠颜色。

#### D4. 校验

- 扩展 `scripts/设计令牌一致性测试.mjs`：扫描 `client/src/components/Map*.jsx`、`LayerPanel.jsx`、`server/map.mjs` 中残留裸 hex（棘轮：只减不增）。
- 色值落地前用 chroma.js 脚本输出对比度与色盲模拟报告（一次性脚本，不入运行时依赖）。

### 6.5 方向 E：深浅主题与底图联动

1. **令牌先行**：D1 令牌全部按 `data-theme` 提供深浅值，UI 面板/草稿/分析层颜色随主题切换（P0，不依赖底图）。
2. **底图联动（可选，P2）**：主题切换时底图自动映射（light→carto-positron / dark→carto-dark，高德底图不强制切换）；图层深浅变体随底图应用。需更新 DESIGN.md 与 [预览策略.js](file:///Users/ouyangjincan/claude%20code%20本地文件夹/office-agent-web/client/src/地图/预览策略.js) 相关行为，列为决策点。

### 6.6 方向 F：Before/After 对比（可选，P2）

固化前对"当前视图 vs 草稿叠加"提供 swipe 对比：

- **方案 F1**：引入 `maplibre-gl-compare` 依赖（需用户确认，AGENTS §4.3 新增运行时依赖）。
- **方案 F2**：自实现 swipe（双实例或 clip 裁剪草稿容器），无新依赖但维护成本高。
- **方案 F3**：不做，以 B 方向审批卡内嵌快照替代（推荐——改动小、已覆盖"核对"诉求）。

### 6.7 方向 G：状态回读与渲染校验（可选，P2）

1. 新增只读工具 `map_read_state`（返回：当前项目、正式层计数、草稿计数与要素数、当前 bbox、指定草稿渲染状态），让 agent 能"看"到渲染结果，消除 CARTO 实测的"agent 报成功但地图空白"。
2. 同步事项：`server/task.mjs` 白名单、`planTaskCapabilities`、`test:capability-contract`；事件注册表不新增事件（走工具返回值）。

## 8. 不做清单与约束遵守

- 不引入 deck.gl/OpenLayers/新地图框架；不 fork MapLibre。
- 不做操作级 undo 历史（遵守 ADR 0019）；不改 `map_reset` 三级基线语义。
- 不做流式逐要素 GeoJSON 渲染（业界无成熟实现，收益/成本比低；增量以"层"为粒度）。
- 不改审批策略语义：auto 不放行固化与破坏性操作；共享数据集禁写、锁定拒写不变。
- 地图能力仍只在 Work 模式；Chat/Review 不新增任何 map 工具。
- 事件仍经 [server/事件注册表.mjs](file:///Users/ouyangjincan/claude%20code%20本地文件夹/office-agent-web/server/事件注册表.mjs) 登记与管理；`map_draft_confirmed/discarded` 审计事件不删。
- P2 各项（依赖、底图联动、新工具）单独经用户确认后实施。
