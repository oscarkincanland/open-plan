## 1. 背景与目标

用户要求：交叉验证当前地图模块的交互、配色，以及 agent 与地图交互的前端渲染，并调研 GitHub 上 agent 与地图协作的主流做法，形成完整优化设计方案。

- **目标 1（交互）**：让 agent 的地图操作"看得见、可预览、可核对、可回退"，审批信息充分。
- **目标 2（配色）**：地图层色值全部令牌化，建立预注册色阶词汇表供 agent 引用，深浅主题适配，色盲安全。
- **目标 3（渲染）**：草稿渲染从"整层销毁重建 + 全量重拉"升级为增量更新，消除闪烁与静默失败。

不改变产品模式边界（地图能力只在 Work）、审批策略语义（auto 不放行固化/破坏性操作）、共享数据集禁写与锁定拒写等硬约束。

## 4. 业界调研结论

### 4.1 开源项目与工具 schema 粒度

- **qgis_mcp**（[GitHub](https://github.com/jjsantos01/qgis_mcp)）：15 个**图层级**工具（load/add/remove/zoom/get_features/render）+ `execute_code` 逃生舱——粒度设计的推荐区间。
- **ArcGIS Pro MCP**（[GitHub](https://github.com/Knight60/ArcGIS-Pro-MCP)）：112 工具，如 `set_layer_renderer` 一个工具完成分级设色+色带+描边；arcpy-mcp 1300+ 工具为**反例**（需白名单收紧）。
- **Mapbox Agent Skills**（[GitHub](https://github.com/mapbox/mapbox-agent-skills)、[教程](https://docs.mapbox.com/help/tutorials/build-your-own-agent/)）：**数据 agent 与视图 agent 分离**（一个产出 GeoJSON 由 GL JS 渲染，一个专管相机 flyTo）；官方技能教 AI 避坑（空白地图、glyphs 缺失）。
- **CARTO《Making deck.gl AI-ready》**（[博客](https://carto.com/blog/making-deckgl-ai-ready)、[原型](https://github.com/CartoDB/carto-agentic-deckgl)）：最有价值的架构参考——两条路线（有状态工具逐动词编辑 vs 无状态整份 spec 替换）；实测痛点：spec 无 schema 导致失败**全部静默**（agent 报成功但地图空白）、模型**编造不存在的配色 helper**；提案方向：JSON Schema 校验 + 转换报告 + **状态回读** + **patch 增量语义** + **标准化色阶词汇表**。

### 4.2 UX 交互模式

- **Applied-but-pending 范式**（WebMCP tripcanvas，[Devpost](https://devpost.com/software/tripcanvas-yewm6j)）：agent 每次修改 = "已应用但待确认"——**琥珀色高亮**、逐条 Revert、Accept All、一次规划为**原子 pending 批次**、agent 回读修订流。
- **审批门四要素**（[AI agent approval UX](https://dev.to/artemkireev/ai-agent-approval-ux-show-the-side-effects-not-a-yesno-2e16)）：Anthropic 数据显示 93% 权限弹窗被无脑批准 = 设计失败；审批卡应展示 **before/after diff、影响半径（改了多少对象）、可逆性声明、一行理由+证据**；按钮文案复述范围（"固化 212 个要素"）而非"Yes"。
- **按可逆性分级授权**（[HATP 草案](https://dev.to/murthyg/undo-for-ai-agents-a-draft-spec-for-taking-back-what-an-agent-already-did-41e0)）：工具返回可撤销窗口，可逆自动放行、不可逆必须人工确认——与本项目"草稿免审批、固化需审批"边界天然同构。
- **Before/after 对比**：社区惯用 [maplibre-gl-compare](https://maplibre.org/projects/gl-js/) swipe。
- **流式渲染**：业界**无成熟"流式 GeoJSON 边生成边画"公开实现**，主流是整层替换或整份 spec 替换；CARTO patch 语义是最接近增量的方案。

### 4.3 配色实践

- CARTO 实证：放任 agent 选色，所有模型默认 YlOrRd 万金油、偏态数据不做处理、不画图例、甚至编造 helper——结论是**渲染引擎侧提供唯一一套预注册色阶词汇表**供 agent 引用，而非自由传色值。
- [苏格兰政府地图设计系统](https://designsystem.gov.scot/guidance/maps/using-colour-in-maps)：按数据类型选 qualitative/sequential/diverging；相邻色 3:1 对比；禁用纯灰阶；避免仅靠颜色编码（加图案/描边/标签）。
- 无障碍：ColorBrewer 科学色带、3–7 分级、避免红绿对、明度差 ≥3:1。
- 深浅主题：业界收敛到 CARTO Positron（浅）/ Dark Matter（深）成对底图；agent 产出层样式须随底图主题切换。

## 6. 优化设计方案

### 6.1 方向 A：草稿层"已应用待确认"体验（applied-but-pending）

**理念**（借鉴 tripcanvas，适配 ADR 0019）：草稿层本就是"免审批、可丢弃"的暂存区，把"待确认"语义做足，而不是引入操作级 undo 历史（不违反 [ADR 0019](file:///Users/ouyangjincan/claude%20code%20本地文件夹/office-agent-web/docs/决策记录/0019-图层作用域与基线重置语义.md)）。

1. **草稿默认色改琥珀系**：草稿默认色由 `#2563eb` 改为琥珀令牌 `--map-draft-pending`（初稿：浅主题 `#f59e0b`、深主题 `#fbbf24`），保留虚线。"琥珀 = 待确认"与"蓝 = 正式"形成全局一致的语义色；需要在用户确认后同步更新 DESIGN §9.3 的"草稿蓝色系"表述。
2. **agent 批次聚合**：同一轮 agent 连续产生的草稿以 `batchId` 聚合（服务端在草稿元数据上标记，落盘于 `agent/drafts/*.json` 现有元数据结构，[map.mjs#L1748-L1763](file:///Users/ouyangjincan/claude%20code%20本地文件夹/office-agent-web/server/map.mjs#L1748-L1763)），图层面板草稿区按批次分组展示，提供"整批固化 / 整批丢弃"快捷操作（现有逐草稿操作保留）。升级前历史草稿无 batchId，面板回退为现状平铺展示（不分组），不做存量迁移。
3. **逐条回退（限当前批次）**：批次内每条草稿保持独立的丢弃入口（现状已有）；新增"整批丢弃"不触碰已固化历史——回退粒度仍是草稿对象级，不是操作历史级。
4. **对话流草稿摘要卡**：agent 产出草稿后在对话流插入一条轻量摘要（批次名、几何类型、要素数、[打开地图预览] 按钮），弥补"草稿事件不在对话流播报"带来的感知断层（现状 ChatPanel 收到 `map_draft_changed` 静默处理）。实施前先查《会话流渲染通道清单》（AGENTS §10"改渲染前先查"），摘要卡必须复用既有渲染通道、不新增第 8 条通道；触及 `client/src/会话流/**` 高风险区，配套 `npm run test:ui-smoke`。

### 6.2 方向 B：固化审批卡升级

对齐"审批门四要素"，改造对话流审批卡（[DESIGN.md §4](file:///Users/ouyangjincan/claude%20code%20本地文件夹/office-agent-web/DESIGN.md#L277) 人机协作卡）：

1. **影响半径**：展示草稿要素数、几何类型分布、bbox 范围、目标分组/名称。
2. **可逆性声明（v2 订正）**：固化卡明示"固化生成新正式层，`.trash/` 不覆盖固化新增的层；如需回退须删除该正式层（删除后入 `.trash/`，删除属正式写、需审批），或整体 `map_reset` 基线重置"；丢弃/重置等破坏性卡明示"不可撤销"。口径以 [ADR 0019](file:///Users/ouyangjincan/claude%20code%20本地文件夹/office-agent-web/docs/决策记录/0019-图层作用域与基线重置语义.md) 对 `.trash/` 覆盖范围的定义为准。
3. **理由 + 证据**：卡片显示发起工具名、来源任务、（若 agent 提供）一句话固化理由。
4. **按钮文案复述范围**："固化（128 个要素 → 正式图层·路网分析）"而非通用"确认"。
5. **缩略预览（v2 细化）**：审批卡内嵌 MiniMapPreview 小地图快照——已核实该组件仅依赖 props、无会话上下文依赖（[MiniMapPreview.jsx#L23](file:///Users/ouyangjincan/claude%20code%20本地文件夹/office-agent-web/client/src/components/MiniMapPreview.jsx#L23)），可行；需新增按 `draftId` 过滤草稿的扩展 prop（现组件自拉全项目草稿，[MiniMapPreview.jsx#L62-L63](file:///Users/ouyangjincan/claude%20code%20本地文件夹/office-agent-web/client/src/components/MiniMapPreview.jsx#L62-L63)）。审批卡安全语义（DESIGN §4 人机协作卡）不得变更，仅增展示字段。

### 6.3 方向 C：渲染链路增量与就绪握手

1. **草稿增量渲染**：前端按 `draftId` 维护 Map 缓存；`action=update` 时对既有 GeoJSON source 执行 `setData`（MapLibre 原生增量），仅新增/删除草稿才 add/remove；不再"每次事件整层销毁重建"（替换 [MapViewer.jsx#L383-L436](file:///Users/ouyangjincan/claude%20code%20本地文件夹/office-agent-web/client/src/components/MapViewer.jsx#L383-L436) 的 clear-then-replay 为主路径）。

### 审查结论原文（v1）

**一、重复造轮子 — 有问题（部分通过）**
- 色板与令牌族确无等价物：`client/src/地图/` 仅 预览策略/地图上下文/CSV解析 三文件，无色板实现；styles.css 仅 `--map-accent: #4a90d9`（styles.css:113）等 3 个 map 变量。✅
- "就绪队列"大半已存在：`draftListRef` 已实现"样式未就绪先记账、就绪后重放"（MapViewer.jsx:396-400），临时层重放已有 `client/src/图层注册表.js:23-56`。方案应写明复用这两套，而非新建第三套队列。
- 棘轮冲突：`scripts/设计令牌一致性测试.mjs:24-26` 基线 {总数:125,不同值:87} 只许下降，D1 往 styles.css 新增十余个 hex 必然抬升计数，方案未提更新基线（且 DESIGN.md:137 记 393/129，文档已与脚本漂移）。

**二、遗漏边界 — 有问题**
- 增量 setData 与样式热更竞态无人管：`map.setStyle` 会清掉运行时图层（图层注册表.js:4-7），update 事件落在热更窗口内对已删 source `setData` 会抛错；方案只说"重放保留给热更"，未定义仲裁。
- props 时序：MapViewer.jsx:438-439 明示"MapPanel 在懒加载完成前已拿到草稿列表"，按签名重放+短重试；C1 只替换事件主路径，未说明 props 同步路径如何共存。
- 升级前历史草稿无 batchId 的分组回退未提；batchId 落盘位置（`agent/drafts/*.json`，map.mjs:1748-1763）未写。
- maplibre paint 不支持 CSS var()，草稿/分析层颜色在 JS 设值，"随主题切换"需 getComputedStyle+主题变更监听机制，E1 未给机制。

**三、冲突 — 有问题**
- A1 琥珀 vs DESIGN.md:438"蓝色系"：已列为决策点并承诺同步 §9.3，可接受。
- B2 表述不准：".trash 恢复"仅覆盖删除/重置移除的层（ADR 0019 L31-32）；固化是新增层、不在 .trash，撤销固化实为"删除该正式层（再入 .trash，需审批）"，照抄会误导用户。
- D2 "同步 task.mjs 白名单相关参数"错位：task.mjs:45-46 只存工具名，参数 schema 在 agent.mjs defineTool；palette 枚举不需动白名单，且 capability-contract 不断言工具参数（能力契约测试.mjs:30-44），须新增独立测试。
- A4 摘要卡/B 审批卡新增对话流渲染物，未引用《会话流渲染通道清单》（AGENTS §10"改渲染前先查"），B 触及 client/src/会话流（高风险清单），也未提 DESIGN.md:285 审批卡安全语义不得变更。

**四、不可行假设 — 有问题（核心）**
- **C3 免重拉不成立**：payload 的 `features` 是计数不是几何——map.mjs:1711 `features: Number(stats.features || 0)`（draftSummary），事件注册表.mjs:173 schema 亦声明 `features:"number"`。带几何需改 payload，而草稿上限 20MB（map.mjs:1677），SSE 体积风险大。须改写 §6.3.2（维持 GET 或服务端带 geojson+硬上限）。
