## 2. 前置发现：动效令牌在默认主题下不存在（既有缺陷，批次 1 必须一并修）

**证据**：
- `--dur-fast/base/slow` 与 `--ease-out` 只在 `client/src/styles.css:13022-13026`（`:root[data-oaw-style="qoder"]`）与 `:13082-13086`（其亮色变体）定义；全仓 `*.css` 无第三处。
- `qoderStyle` 开关默认关（`client/src/App.jsx:578-582`）。
- **影响面实测**：`client/src/styles.css` 共 33 处 `var(--dur-*|--ease-out)` 引用、14 个规则行；去掉 qoder 作用域自身的 2 行后，**默认主题真正失效的是 12 条规则**——`11884 / 11901 / 11905 / 11933 / 11934 / 11936 / 12032 / 12045 / 12053 / 12058 / 12394 / 12415`，全部位于 v3 会话流段，不涉及全站。

**后果**：按 CSS 规范，`var()` 无 fallback 且未定义时，整条声明在计算值阶段无效。因此默认主题下：
- 所有 `transition: … var(--dur-base) var(--ease-out)` 退化为 `none`；
- 所有 `animation: … var(--ease-out) …` 退化为 `none`（例：`styles.css:11933` 的 `.tl-state.run` 今天就没有呼吸）。

**这解释了「质感差」的一部分**：不是动画做得不好，而是一批动画根本没跑。

**修法**：把三档周期令牌与 `--ease-out` 一并写入文件顶部的全局 `:root`（`styles.css:2-120`），qoder 块保留同名覆盖（皮肤仍可改）。并加一条测试断言：动效令牌必须存在于全局 `:root`，不得只在皮肤作用域。**断言落点**：写进 `scripts/动效治理测试.mjs`（该套件不在已知失败基线内，且已在做同类结构断言，见 `:87-89`「闸门必须排在所有动画定义之后」）；**不要**写进 `scripts/设计令牌一致性测试.mjs`——该套件本身在基线里 `expect: fail`，新断言会被既有失败吞掉。

## 3. 规范怎么改（§8 修订，不废除）

保留不动：§2 一轮结构、§3 字体族、§4 字号三档、§5 结语来源、§6 交互条目、§7 历史恢复一致性、§9 宽度对齐、§11 禁止项中除动效外的全部条款。这些是 `test:chat-layout`、`test:chat-timeline`、`test:排版回归` 的断言依据。

改写 §8，拆成三层：

1. **红线（不可协商）**：只允许 `transform` / `opacity` / `grid-template-rows`；**例外**——渐变文字流允许动画 `background-position`（不触发布局，只重绘，与既有跑马灯 shine 同款）。其余不变：必须进统一动效闸门；降级后信息不丢；历史回放不重播；折叠头不加无限动画；持续动画必须登记白名单与测试清单。
2. **令牌（可调整）**：周期、缓动、扫光带宽一律引用令牌，不写裸数值。令牌表在 `DESIGN.md` §11 维护，本规范只引用不复述。
3. **形态（可选）**：扫光具体形态由 `.tl-shimmer` 样式决定，规范只约束「只有运行中的行允许挂载、行结束即移除」。

同时澄清 §1「不为好看新增动画、渐变、阴影」的边界：**禁止的是结论区用渐变/描边强调结论**；过程行的运行态渐变属于状态指示，不在此列（与本条现存语义一致，只补澄清，不放松）。

### 批次 2（P1）：扫光改渐变文字流

**改哪里**：`client/src/会话流/TextShimmer.jsx`（高风险目录）、`styles.css` 的 `.tl-shimmer-*` 规则与两处闸门、`docs/规范/会话流前端规范.md` §8、`DESIGN.md` §11。

**复用既有实现**：跑马灯 shine 已有生产验证的渐变文字流写法（`styles.css:10764-10786`，含 `@supports` 守卫与「宁可不做效果，也不能让文字变透明看不见」的注释）。批次 2 照搬该写法，只把配色从 `--marquee-a` 换成 `currentColor`：

```css
/* 守卫必须同时覆盖 background-clip 与 color-mix：只检前者时，
   支持 clip 但不支持 color-mix 的浏览器会让 background-image 整条失效，
   叠加 -webkit-text-fill-color: transparent 就是「文字不可见」。 */
@supports (((-webkit-background-clip: text) or (background-clip: text))
  and (color: color-mix(in srgb, red 50%, transparent))) {
  .tl-shimmer {
    background-image: linear-gradient(100deg,
      color-mix(in srgb, currentColor 35%, transparent) 0%,
      currentColor 45% 55%,
      color-mix(in srgb, currentColor 35%, transparent) 100%);
    background-size: 260% 100%;
    background-position: 140% 0;
    -webkit-background-clip: text;
    background-clip: text;
    -webkit-text-fill-color: transparent;
    animation: tl-shimmer-flow var(--pulse-base) var(--ease-out) infinite;
  }
}
@keyframes tl-shimmer-flow {
  from { background-position: 140% 0; }
  to { background-position: -40% 0; }
}
/* 系统高对比模式强制恢复可读文字（透明填充在 forced-colors 下不可靠） */
@media (forced-colors: active) {
  .tl-shimmer { background-image: none; -webkit-text-fill-color: currentColor; animation: none; }
}
```

> **实施记录（2026-11-18）**：`@supports` 的条件里 `color-mix()` 必须写成声明 `(color: color-mix(...))`，写成裸函数会让整个 `@supports` 块被浏览器判为无效语法并跳过——静态测试与 `@supports` 条件都"看起来对"，只有真实浏览器暴露了渐变未生效。已修复并复测。

**为什么用 `currentColor`**：思考行 `.tl-verb` 是 `--dim` / `--muted`，完成态压到三级灰（`styles.css:12296`、`12304-12307`、`12331`）。用 `var(--text)` 会把思考行提亮到正文色，违反《会话流前端规范》§4 的颜色层级（审查 P0-4）。

**DOM 简化**：从三层（`.tl-shimmer` > `.tl-shimmer-text` + `.tl-shimmer-deco` > `.tl-shimmer-sweep`）降为一层，删除 `aria-hidden` 文字副本。必须保留 `styles.css:12427` 的 `display: inline-block; max-width: 100%; min-width: 0; vertical-align: top`——换单层后这些布局属性容易丢。

**连带必须同步的四处**：

1. `scripts/动效治理测试.mjs:103-113` 的 `期望持续动画`：`transcript-shimmer-sweep` → `tl-shimmer-flow`。
2. 同文件 `:137` 宿主映射：`.tl-shimmer-sweep` → `.tl-shimmer`。
3. `styles.css` 两条闸门规则（`15138` 与 `15139`）：`.tl-shimmer-sweep { animation: none }` 与 `.tl-shimmer-deco { display: none }` 改为 `.tl-shimmer { animation: none; background-image: none; -webkit-text-fill-color: currentColor; }`，并删除将成死规则的 `.tl-shimmer-deco` / `.tl-shimmer-sweep`。**注意**：`12499` 附近是 `.thinking-text::after` 与 `.message-process-fold…::after`，与 `.tl-shimmer` 无关，不要改错位置。
4. `scripts/性能与流量基线测试.mjs:84` 的 21 种预算：一换一，数字不变。

**降级保证**：`@supports` 不命中时整块不生效，文字回到纯色（不是透明）；闸门命中时 `-webkit-text-fill-color: currentColor` 强制可读。

### 10.2 实施偏差（如实记录）

1. **`.tl-state.run` 未按计划剔除**：实施时并行会话已把它改成 `dot-breathe-soft 2.6s`，本计划直接改为 `var(--pulse-base)`，一次性落实了原计划的「交接要求」；`test:component-spec` 的 ① 断言同步。这比留待 C4 之后再改更干净。
2. **C4 死通道的裸时间也令牌化**：`.execution-flow-live i`、`.efp-pulse`、qoder 段的 `.execution-flow-item.running` 仍是 2.4s / 2.6s 裸值，会被新增的「脉冲不得写裸时间」断言抓到；改为令牌无害，C4 真正删除时整行消失。
3. **`@supports` 语法缺陷（真实浏览器才暴露）**：审查给的条件 `and (color-mix(...))` 是错的——`@supports` 的条件必须是声明，裸函数会被判为无效语法并跳过整块。首次实测 `background-image: none`、文字无渐变；改为 `and (color: color-mix(...))` 后复测生效。
4. **`设计令牌一致性测试.mjs` 的既有缺陷**：`取块` 用裸 `indexOf` 会命中 `:root[data-skin="ocean"][data-theme="light"] { ... }` 单行块里的子串，导致「全局亮色基线」取到皮肤覆盖块并误报缺少 `--body-bg`（HEAD 同样失败）。改为行首锚定后该失败消失，套件只剩基线签名「硬编码色值棘轮」。
5. **周期统计修正**：计划 v1 写的「13 种 / 0.8s」不准确；实际排除 C4 与旋转/光标类后为 8 种脉冲周期，`0.8s` 属 `spin` 旋转，不在脉冲族内。
