## 1. 交付

### 1.1 意图路由

- `client/src/components/ChatPanel.jsx` 发送 payload 新增 `intentText`（只含用户原始输入）；`text` 仍保留完整 prompt（当前文件/地图/引用/附件）。
- `server/index.mjs` 能力规划优先使用 `intentText`，旧客户端回退 `task.goal`，最后才 `stripAutoContextPrefix`。
- `server/task.mjs`：
  - 新增 `stripAutoContextPrefix`：移除 `[当前打开文件: ...]`、地图视图、附件、检索/注入上下文、`@智能体[...]` 前缀；
  - `routeTaskIntent` 改为 `edit` 优先：既有 Office 文件 + 编辑意图先于模板关键词；
  - 模板关键词只在“无既有文件”时用于新建；
  - 新增 `previousRoute` + 短句延续：`继续/继续修改` 沿用上一轮 `edit/template/generate`；
  - `planTaskCapabilities` 透传 `previousRoute`。
- `server/index.mjs` 从 `entry.lastOfficeRoute` 或最近 Run 的 `capabilityPlan.route` 恢复上一轮路由；本轮规划后写回。

### 1.2 Office CLI 调用规约

- 新增 `server/office规范/OfficeCLI调用规约.mjs`：
  - 只读命令：`view/get/query/validate/dump/help/watch/unwatch`；
  - 写命令：`create/add/set/batch/import/remove/move/swap/delete/save/close`；未知命令按写处理；
  - `officeCliPolicy({ mode, route, command, args, pipelineProduced, clarificationPending, manualAllowed })` 唯一判定源；
  - 模式矩阵：Chat 不可见；Work/Review 可见；Review 原文保护在 `assertReviewWriteAllowed`；
  - 路由矩阵：`edit` 放行，`read` 写拒绝 `OFFICE_READONLY_ONLY`，`template/generate` 澄清前置且 `pipelineProduced` 前拒绝写；
  - 预检：`edit` 阻塞，`template/generate` 惰性，`read` 无。
- `server/office规范/执行闸门.mjs`：
  - officecli 分支改走 `officeCliPolicy`；`classifyToolCall` 不再依赖 `officeFormat` 作为 officecli 后门；
  - `save/close` 按写处理；
  - `cp/copy/mv/move/zip/tar` 移出 `DOCX_GENERATION`，复制/移动不再被当成生成 docx；
  - `isMutatingOfficecli` 改为只读白名单取反。
- 新增 `docs/规范/Office CLI 调用规约.md`，并在 `AGENTS.md` §10 增加索引行。

### 1.3 终稿边界

- 新增 `server/终稿.mjs`：`assistantText` / `finalAnswerState`。
- `server/agent.mjs`：
  - `message_end` / `agent_end` 记录 `lastAssistantState`；`agent_end` 不再用上一条 assistant 文本兜底；
  - 识别 `thinkingOnly` 后补一次正文（同一 Run 最多一次），发 `final_text_missing`（`recovering:true/false`）；
  - prompt 开始重置 `lastAssistantState/finalAnswerNudged`。
- `server/执行句柄.mjs`：`resolveRunCompletion` 对 thinking-only 的 completed Run 标 `partial` + `completion.incomplete=["final_answer_missing"]`。
- `server/事件注册表.mjs`：登记 `final_text_missing`。
- `client/src/components/ChatPanel.jsx`：
  - 权威终稿只来自 `assistant_final`/run finalText；不再把最后一个 text 块当答案；
  - 新增 `.final-answer-missing`（“本轮没有最终答复”，提供继续/重试）；
  - 工具标签清洗：`<ask_user .../>`、`<tool .../>`、`<function_calls>` 不进入成果区；
  - 过程 text 标签由“阶段结论”改为“进度”。
- 新增 `client/src/工具标签清洗.js`。

### 1.4 中断分类

- `server/runs.mjs`：新增 `classifyRunInterruption`，`publicRunView` 与 `runSummaryView` 输出 `interruption`（kind/label/detail/action）。
- 支持：`final_text_missing / provider_auth / provider_config / service_restart / budget_hard / pipeline_timeout / watchdog / user_cancel / unknown`。
- `server/index.mjs` 会话列表新增 `lastRunStatus/lastSuccessfulRunAt/lastSuccessfulRunId/lastSuccessfulRunStatus`；`SessionSidebar` 在“最近失败但此前完成”时显示“最近失败（此前已完成）”。
- `ChatPanel` 按 `interruption` 显示原因与“继续/重试”动作。

### 1.5 供应商与服务退出

- `server/agent.mjs` 新增 `MODEL_COMPAT_OVERRIDES`：`opencode-go/claude-haiku-5-5`、`PLAN_OPENCODE_ZEN_GO/claude-haiku-5-5` 关闭 reasoning，避免 `400 thinking.type.enabled is not supported`；在 `localStoredModels`、`resolveInitialModel`、`applyModelSpec`、`fallbackModel`、模型目录 normalize 中统一应用。
- `server/index.mjs` 新增 `运行日志/服务退出.log`：记录退出码、uptime、原因、pid，便于区分服务重启与模型失败。

## 3. 已知边界

- `final_text_missing` 的自动补正文只尝试一次；模型再次只输出 thinking 时按 partial 收尾，不循环。
- 401 仍需用户到设置重新保存 `opencode-go` API Key；没有自动切换模型。
- `thinking.type.enabled` 的根因在 Pi SDK/Anthropic SDK 对模型能力的判断；本仓库通过模型能力覆盖关闭该模型的 reasoning，未修改 `node_modules`。
- `runSummaryView.error`（401/400 原始错误）是并发会话留下的未提交改动，本提交没有包含；`interruption.detail` 已足以显示原因。
- 浏览器验收覆盖 thinking-only 终稿；401/400/服务重启的 UI 文案由 `终稿与中断分类测试` 的 8 类 fixture 覆盖，未逐一造真实 Run。
- 复制 docx 现在放行的是“复制动作”，不改变写入锁与审批；Review 仍优先 `review_copy`。
