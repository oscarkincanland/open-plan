## 2. 事实源判定

按 AGENTS.md §2 效力顺序：**用户 > AGENTS > `docs/规范/` > `docs/决策记录/` > PRD > DESIGN > 计划**。

由此推出三条判定，构成整份方案的前提：

1. **呈现形态以《会话流前端规范》v2.0 + ADR 0014 为基线**（层级 3/4 高于 PRD/DESIGN）。PRD 是验收口径，应当回写成与新规范一致，而不是让规范迁就 PRD 的旧措辞。
2. **DESIGN §14 的「与 PRD 冲突时以 PRD 为准」需要修正**——它与 AGENTS §2 的效力顺序冲突，且会造成"设计细节永远跟着 PRD 漂"。应限定为"范围与验收口径以 PRD 为准，呈现细节以本文件 §6/§7 与本规范为准"。
3. **规范 §10「全部通过 / CI 38/38」是事实性错误**，必须改成可复验的记录；这不是"降低标准"，而是让规范重新可信（《文档管理规范》§9：不得承诺未经验证的能力）。

## 4. 逐条修改清单

### 4.1 `REQUIREMENTS.md` R3

#### 4.1.1 R3:114（折叠头）

**现状**
> - Run 轮次整轮折叠呈现：收起为一行「已运行 · 工具数 · 文件数 · 验收状态」，展开为按真实输出顺序的时间流（思考/阶段小结/工具/系统提醒，各占一行条目，点击展开明细）。

**拟改为**（已按 **A1** 落地）
> - Run 轮次整轮折叠呈现：收起为一行折叠头（状态点 +「已完成 · 用时 9 分 8 秒 · 12 步」；存在未决交互时追加「等待你回答 / 等待你审批」），展开为按真实输出顺序的时间流（思考/阶段小结/工具/子代理/系统提醒，各占一行条目，点击展开明细）。工具数、文件数、验收状态不由折叠头承载，统一在任务中心与「本轮产物」卡呈现。

**理由**：① 折叠头一行塞 4 个字段会挤压主信息；② 三份文档给了四种格式，必须收敛为一种；③ 工具/文件/验收在任务中心与产物卡已有，重复表达违反"一轮只留必要信息"（ADR 0014 §6）。
**风险**：若后续想恢复 chips，需要在规范里重新定义，不能靠 PRD 单独要求。

#### 4.1.2 R3:116（总结结构）

**现状**
> - 运行结束后框外依次展示：本轮总结（做了什么 / 结论 / 详细展开，取模型最终答复全文，含表格与代码块）与「本轮产物」卡（类型图标 / 名称 / 路径 / 大小 / 打开·定位·回滚）。

**拟改为**
> - 运行结束后框外依次展示：本轮总结（**结论与详细展开合并为一篇连续正文**，取模型最终答复全文，含表格与代码块；不分节标签、不单列「做了什么」行）与「本轮产物」卡（类型图标 / 名称 / 路径 / 大小 / 打开·定位·回滚）。

**依据**：ADR 0014 §4.1、规范 §5、DESIGN:286 已一致，仅 PRD 未回写。

#### 4.1.3 R3:119（折叠单元与分组）

**现状**
> - 一轮一个折叠单元：运行结束后过程折叠为一行“运行了 X 小时 X 分 · N 步 · M 个产物”，展开可见按 turn 分组的过程；**折叠的是过程，中间小节结论与本轮总结留在折叠体外常显**，不删除内容。

**拟改为**（已按 **B1** 落地：保留「按 turn 分组」要求，代码列 P2）
> - 一轮一个折叠单元：运行结束后过程折叠为一行折叠头（格式同「整轮折叠呈现」条），展开可见按 turn 分组的过程；**折叠的是过程，中间小节结论与本轮总结留在折叠体外常显**，不删除内容。

#### 4.1.4 R3:132（全文渲染口径）

**现状**
> … 界面以模型最终答复为主内容，缺失时才回退 Run 摘要；前端在「详细展开」中全文渲染、不截断。

**拟改为**
> … 界面以模型最终答复为主内容，缺失时才回退 Run 摘要；前端在**总结正文**中全文渲染、不截断。

**理由**：「详细展开」是已删除的 UI 结构标签，留着会让实现者去找一个不存在的区块。

#### 4.1.5 R3:121（不改，仅登记）

「每轮显示用时与 token」保留为**需求**；当前代码在 `timelinePath` 下只显示用时、不显示 token，属**代码偏差**，登记在第 5 节，不改 PRD。

### 4.2 `DESIGN.md`

#### 4.2.1 §6.1:229（折叠行格式）

**现状**
> - 折叠行必须包含运行时长与步数：`已完成 · 运行了 2 小时 13 分 · 45 步 · 3 个产物`；运行中为 `正在运行 · 已用 12 分 · 当前：写入文档`。

**拟改为**（已按 **A1** 落地）
> - 折叠行必须包含运行时长与步数：`已完成 · 用时 2 小时 13 分 · 45 步`；运行中为 `已运行 12 分`，能确定当前动作时追加 `· 当前：写入文档`（数据源 `summarizeTimeline().runningLabel`）。状态词与状态点的对应关系见[会话流前端规范](docs/规范/会话流前端规范.md) §2.1。

#### 4.2.2 §6.1:230（分组）

仅按**决策 B** 调整：选 B1 不改；选 B2 改为"按真实输出顺序排列，保证同一过程区连续；不强制按 turn 分组"。

**拟改为**
> - 与 PRD 冲突时：**范围与验收口径**以 PRD 为准，设计不能扩大或缩小产品能力；**呈现形态**（折叠、字号、文案格式、动效）以本文件 §5/§6/§7 与[会话流前端规范](../规范/会话流前端规范.md)为准。三者仍冲突时，按 AGENTS.md §2 效力顺序裁决（规范 > 决策记录 > PRD > DESIGN）。

## 6. 需要你裁定的三个口径

### 决策 A：折叠头格式

| 选项 | 格式 | 代价 |
|---|---|---|
| **A1** 精简（规范现状） | `已完成 · 用时 X · N 步` | 改 PRD+DESIGN；代码零改动；产物数只能去产物卡看 |
| **A2** 富格式（DESIGN 现状） | `已完成 · 用时 X · N 步 · M 个产物` | 改 PRD+规范+代码（`RunFoldBar` 加 prop）；信息最全 |
| **A3** 折中（**推荐**） | `已完成 · 用时 X · N 步`，有产物时 `· M 个产物` | 改 PRD+DESIGN+规范一句话；代码加一个可选 prop（1 行数据、3 行渲染） |

推荐 A3：既满足「折叠行必须包含运行时长与步数」的硬要求，又在有产物时给出关键信息；`M=0` 不显示，避免纯问答轮出现「0 个产物」。

> **已选：A1（2026-11-06 用户确认）**。产物数不进折叠头，改由「本轮产物」卡承载；代码零改动。

### 决策 B：过程分组

| 选项 | 口径 | 代价 |
|---|---|---|
| **B1** 保留「按 turn 分组」 | PRD/DESIGN 不动，代码待补 | 需把时间流条目映射到 `turnIndex`（trace 里有 turn 计数，但块与事件的对应要另建索引），工作量中等 |
| **B2** 放宽为「按真实输出顺序」 | 改 PRD/DESIGN 各一句 | 文档即刻与实现一致；但失去"同一轮的过程聚在一起"的读感 |

推荐 **B1**（保留要求，代码列为 P2 backlog）：这是 DESIGN 与 PRD 一致的产品意图，且 trace 已能提供 turn 边界，属于"可修的真缺陷"而非"文档过度承诺"。

> **已选：B1（2026-11-06 用户确认）**。PRD:119 与 DESIGN:230 保留「按 turn 分组」；代码差距登记为 P2。

### 决策 C：PRD 的「工具数 / 文件数 / 验收状态」

| 选项 | 处置 | 代价 |
|---|---|---|
| **C1** 移交任务中心与产物卡（**推荐**） | 从折叠头要求中删除，PRD 注明承载位置 | 折叠头更轻；用户看验收要开任务中心/产物卡 |
| **C2** 保留为折叠头 chips | 文档保留要求，代码 P1 实现 | 折叠头一行 5–6 个字段，窄屏必然换行；实现成本最高 |

推荐 C1：与 ADR 0014「一轮只留必要信息」一致，也避免窄屏折叠头溢出。

> **已选：C1（2026-11-06 用户确认）**。PRD:114 已删除「工具数 · 文件数 · 验收状态」，并注明由任务中心与产物卡承载。
