## 0. 结论

路由层已经按计划工作，**执行层没有**：

- Work 模式两次输入都正确命中模板（08 汇报材料 / 04 工可），说明 `routeTaskIntent` 有效。
- 但 `editorial_pipeline` **0 次调用**，`office_format_applied` / `office_qa_finished` **0 次触发**。
- 模型改用 `bash`（40 次）+ `officecli`（28 次）+ 手写生成脚本，两次触发 45/45 回合硬预算。
- `shouldAsk=true` 算出来了，但写前 **0 次 ask_user**；唯一一次提问在交付之后。
- 两轮产物事后跑闸门均不合格：行距 5 种取值、表格 0 边距、缩进缺失、占位符、模板覆盖率 95% / 0%。

**本计划的核心不是再加提示词，而是把"必须走管线、必须先问"变成工具边界的硬约束。**

## 2. 目标与成功判据

在 Work 模式且 `OAW_OFFICE_FORMAT=1` 时：

1. `route=template|generate` 的第一次文档写操作必须是 `editorial_pipeline`（或先 `ask_user`）。
2. `clarification.shouldAsk=true` 时，回答前拒绝一切写操作。
3. 产物规则闸门 0 error；模板覆盖率 ≥95%（草稿/框架类允许占位符豁免）。
4. 标准汇报材料一轮 ≤12 个模型回合（对比实测 45+）。
5. 不再出现"md → officecli 转换 → 手工调样式"的路径。

**一句话判据**：同一句"写一篇汇报材料"，第一次写操作是 `editorial_pipeline`，产物 QA 通过，回合数 ≤12。

## 3. 范围与不做

**范围**：执行闸门、澄清前置、模板结构解析、Markdown 直通管线、Chat 模式提示、OfficeCLI 错误预防。

**不做**：

- 不新增模型可见工具（闸门是内部拦截，不是新工具）。
- 不改写 `templates/traffic-material/` 正文。
- 不改 Pi 内核、不改运行预算硬上限。
- 不默认开启 `officeFormat`（保持默认关）。
- 不升版本号。

## 4. 方案

### 4.1 执行闸门（P0-1，核心）

**新增** `server/office规范/执行闸门.mjs`：

```js
export function classifyToolCall({ tool, input, context }) 
// → { blocked: boolean, code, reason, suggestion }
```

`context`：`{ route, officeFormat, pipelineProduced, clarificationPending, mode }`。

规则：

| 工具 | 条件 | 处置 |
|---|---|---|
| `bash` | `route=template/generate` 且命令命中 docx 生成特征（`node .*build.*\.mjs`、`python .*docx`、`pandoc .*\.docx`、`.docx` + 重定向/复制/zip） | 拒绝，`OFFICE_PIPELINE_REQUIRED`，提示改用 `editorial_pipeline` |
| `bash` | 只读命令（`ls`/`grep`/`cat`/`sed -n`/`unzip -p`/`wc`） | 放行 |
| `officecli` | `route=template/generate` 且 `pipelineProduced=false` 且命令是 `create/add/set/batch/import/remove/move/swap/delete` | 拒绝，提示先生成再精修 |
| `officecli` | `view/get/query/validate/dump` | 放行 |
| `write` | 目标 `.docx` | 拒绝（二进制应由管线生成） |
| `editorial_pipeline` | 任意 | 放行，成功后置 `pipelineProduced=true` |

**接线**（`server/agent.mjs`）：

- `bash` 工具 execute 前调用闸门；被拒时 `writeEvent("tool_gate_denied", { code:"OFFICE_PIPELINE_REQUIRED", ... })`，返回可执行的提示文本。
- `officecli` 工具 execute 前调用闸门；读命令不受影响。
- `write` 工具 execute 前检查扩展名。
- `editorial_pipeline` 成功后设置 `entry.pipelineProduced = true`（按 Run 重置）。

**逃逸阀**：命令显式带 `--allow-manual` 或用户在当轮明确说"手工生成/我自己来"时放行，避免误杀高级场景。

### 4.2 澄清前置（P0-2）

**状态**：Run 开始时若 `capabilityPlan.clarification.shouldAsk`，设置 `entry.clarificationPending = { question, missing }`。

**闸门**：`clarificationPending` 非空时：

- 允许 `read/grep/ls/kb_search/web_search` 等信息收集工具；
- 拒绝 `write/edit/officecli` 写命令/`bash` 文档生成/`editorial_pipeline`，返回 `CLARIFICATION_REQUIRED`，附问题与选项；
- `ask_user` 被调用后清除 pending（回答或超时都清除）。

**授权默认值**：用户输入含"你看着办/随便/按你的判断"时 `shouldAsk=false`（已有逻辑），不触发闸门。

**效果**：把"提示词要求问"变成"不问就写不了"。

### 4.3 模板结构解析补齐（P1-1）

当前 `模板结构.mjs` 只认 04 的 `### 第X章` + `- ✅` 列表；08 是 `### 2.1 四段式主结构` + `标注` 表格，所以覆盖率算出 0/0。

扩展解析：

1. **标注表格**：识别表头含"标注"的表格，按单元格 ✅/🔧 归类必备/可选（08 的 2.2 节）。
2. **必备标题**：`### ...（必备）` 记为必备段落。
3. **代码块章节**：结构骨架代码块里的顶层 `一、二、三、四、` 记为章节（08）。
4. **合并图表清单**：兼容 `### 5.2 必备图表清单`（08，图表同一表）与 04 的 5.2/5.3 分离式。
5. **推断标记**：无法识别时按 `## 二、结构骨架` 下的标题推断，结果标 `inferred: true`；推断结构的缺失项降为告警，不阻断。

**验收**：08 解析出 4 个主章节、≥8 个必备/可选项、表 2-1～2-3 与图 2-1～2-2；04 结果保持不变。

### 4.4 Markdown 直通管线（P1-2）

**新增** `markdownToBlocks(markdown)`（`server/文档引擎.mjs`）：

- `#/##/###` → heading block；
- 连续 `|` 行 → table block；
- 其余非空行 → paragraph；
- 代码块跳过或按段落处理。

**扩展** `runEditorialPipeline({ sourceMarkdown })`：

- 提供 `sourceMarkdown` 时跳过 Planner/Writer，直接 `markdownToBlocks` → Formatter（场景令牌 + 封面/目录/页码）→ QA；
- 大纲由 Markdown 标题派生，用于覆盖率；
- 返回 `source: "markdown"`。

**提示词/工具描述**：已有 Markdown 时用 `editorial_pipeline` 的 `sourceMarkdown`，不要用 `officecli add --type markdown` 后再手工调样式。

### 4.5 Chat 模式提示（P1-3）

- `planTaskCapabilities` 在 `mode=chat` 且文本含写作意图（output + office/template）时返回：

```js
hint: { code: "MODE_SWITCH_REQUIRED", message: "当前是 Chat 只读模式；生成文档请切换到 Work。" }
```

- `ChatPanel.jsx` 渲染为输入区上方提示条；若已有模式切换回调，附"切到 Work"按钮；没有则只提示。
- 不改变 Chat 的只读边界。

### 4.6 OfficeCLI 错误预防（P2）

在 `officecli` 工具描述/提示词补充三条高频错误：

1. `/styles/Normal` 不存在 → 先 `add /styles --type style --prop id=Normal ...`。
2. 表格路径只支持 `/body/tbl[1]`；不要 `tbl[*]`、不要 `//p`，按行/单元格逐个处理。
3. 表格元素不接受 `size` 属性；字号请对单元格内段落设置。

### 4.7 预算与回合（P2）

- 管线化后回合数应显著下降；不调整 45 回合硬上限。
- 增加一条运行期提醒：`route=template/generate` 且 10 回合内未调用 `editorial_pipeline` 时，注入一次"请改用管线"的系统提醒。
- 记录 `pipelineProduced` 与回合数到 Run 详情，便于后续对比。

### 11.2 偏差与修复

- **表格此前从未被渲染**：`buildDocxFromBlocks` 的 `!text` 守卫把无文本的 table block 跳过了；本次修复为允许 `table/pagebreak/toc`，并给表格加 `tblCellMar`。这解释了此前 pipeline 产物"有表结构但 XML 无表"。
- **`sourceMarkdown` 触发 revise**：Evaluator 判 revise 时会回 Writer 调模型；已改为 sourceMarkdown 直接 break，不调用模型。
- **08 覆盖率测试**：章节与必备项同名，删一处仍被另一处覆盖；测试改为同时移除同名必备项。
