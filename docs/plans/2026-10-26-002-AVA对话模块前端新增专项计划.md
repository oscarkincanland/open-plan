## 0. 结论

1. 前端是本轮对标的主要工作面：90 个功能条目中，除 Goal 持久化、消息级分支、`#` 解析、Schema 提问、会话分页、欢迎页接口外，其余差异都落在交互与状态层。
2. 首发前端工作量约 **124.5 人天**（含 I0 设计走查 3 人天、I6 回归修复 8 人天与自测），集中在 `ChatPanel.jsx`、`App.jsx`、`SessionSidebar.jsx`、`ChatTimeline.jsx`、`工作产物面板.jsx` 与 `styles.css`。
3. `ChatPanel.jsx` 已 321KB，是本项目最高风险文件。前端策略是**新增子组件/ Hook + 最小侵入接线**，不做“顺手拆分大重构”；只有 QueueDock、GoalBar、QuestionForm、WelcomeMessage 等新功能独立成文件。
4. 不建议把当前三栏工作台改成 AVA 的对话优先布局。会话分组、工作区菜单、链接页签等优先放进现有侧栏/历史抽屉/右栏，而不是重排 `App.jsx` 的主布局。
5. 消息编辑/fork/regenerate 的前端实现必须等后端“按活跃分支返回历史”契约稳定后再做，否则会出现旧分支与新分支同屏、工具卡错配。

## 1. 前端现状与改造边界

### 1.1 组件与状态


- `App.jsx:1481-1531` 向 `ChatPanel` 传 30+ props；`ChatPanel.jsx:535-795` 维护消息/运行态；`:1542-1693` 维护 SSE 连接、游标、重连、看门狗。

- 草稿：模块级 `Map`，LRU 20（`ChatPanel.jsx:297-317`）。

- UI 持久化：`persist-ui.js:7-25` 只存 tabs/模块/工作区/侧栏开关/最后会话，不存草稿。

| 无障碍 | 新按钮可 Tab、可 Enter/Space、焦点可见；菜单 `aria-haspopup/expanded`；动态状态 `aria-live`；Esc 关闭浮层 |
| 键盘 | Enter 发送、Shift+Enter 换行、IME 组合态不误发；候选浮层方向键/Enter/Esc；行内编辑 Enter 保存/Esc 取消 |

| 事件 | 任何新 SSE 事件先在 `server/事件注册表.mjs` 登记，前端只在 `事件展示.js`/`ChatPanel` 归约处消费；不私自发事件 |
| 数据 | 草稿/面板宽度等 UI 状态可 localStorage；业务状态（队列/Goal/分支）以服务端或会话文件为准，避免双写 |

## 3. 新增功能交互实现明细

### 3.1 P0：队列与状态可信

#### 3.1.1 QueueDock

| 项 | 实现要求 |
|---|---|
| 位置 | 输入框上方、`PendingActionBar` 之下；空队列不渲染；≥2 条默认折叠 |
| 结构 | 折叠头“N 条排队消息”+ 展开列表；每条：通道图标（⚡插话 / ⧶排队）、单行预览（200 字截断）、附件缩略（最多 3 个 + “+N”）、编辑/删除/提升按钮 |
| 状态 | `channel: "queue" \| "steer"`；`status: "waiting" \| "editing" \| "sending" \| "failed"`；编辑时自动展开并聚焦输入 |
| 编辑 | 行内 textarea 或复用输入框；Enter/对勾保存，Esc 放弃；保存后同步 `messages` 中对应 `queued` 气泡文本 |
| 删除 | 删除单条，二次确认仅对“插话已发送中”生效；删除后同步消息流气泡 |
| 提升 | “插话发送”：运行中调用 `send(..., { force: true })` 并标记 `channel:"steer"`；空闲时直接发送；失败保留原队列项并显示错误 |
| 键盘/无障碍 | 折叠头 `aria-expanded`；列表 `role="list"`；每项按钮有 `aria-label`；编辑态 Esc 不冒泡到全局 |
| 边界 | 队列项附件已失效（文件被删）→ 显示“附件不可用”并允许移除；超长文本显示 200 字 + title 全文；发送中禁用重复操作 |
| 验收 | 5 条排队→编辑第 2 条→删除第 4 条→提升第 1 条；消息流与队列一致；刷新前不丢（本轮内存态可接受） |

#### 3.1.2 发送/停止三态

| 项 | 实现要求 |
|---|---|
| 状态机 | `idle+empty` 禁用；`idle+hasDraft` 发送；`busy+empty` 停止；`busy+hasDraft` 排队发送（按当前 `busyInputMode` 显示“排队/立即/注入”） |
| 视觉 | 单主按钮 + 停止按钮（运行中）；禁用态降低对比度但保留 tooltip；排队态用警示色 send 图标 |
| 键盘 | Enter 与主按钮一致；停止按钮可 Tab；运行中 Esc 不触发停止（避免误触），沿用现有确认窗口 |
| 边界 | `frozen` 优先禁用；`compacting` 禁用发送（见 3.1.4）；`stopping` 显示“中断中”不可重复点击 |
| 验收 | 四态截图；键盘/鼠标行为一致；空输入按 Enter 不产生请求 |

#### 3.1.3 停止后保留队列回执

| 项 | 实现要求 |
|---|---|
| 数据 | 读取 `/api/agent/abort` 返回 `stillQueued`；若 >0，toast“已中断，保留 N 条排队消息，可在队列中继续” |
| UI | QueueDock 保留条目；停止后不自动 flush；提供“继续队列”按钮 |
| 边界 | `stillQueued=0` 不提示；abort 返回 `cancelled:false` 沿用现有“没有找到正在运行的任务”提示 |
| 验收 | 运行中排 3 条→停止→toast 3 条→队列仍可见→点继续按顺序执行 |

#### 3.1.4 压缩中禁止发送

| 项 | 实现要求 |
|---|---|
| 守卫 | `send()` 开头检查 `compacting`，直接提示“正在压缩上下文，请稍候”；按钮 disabled |
| 状态 | 压缩按钮显示“压缩中…”并旋转；压缩结束/失败恢复输入 |
| 边界 | 服务端 `_enqueuePrompt` 仍会等待 `compactionPromise`，前端守卫只负责体验一致，不替代服务端 |
| 验收 | 压缩中点发送/按 Enter 均不产生新消息；压缩失败后可正常发送 |

#### 3.1.5 队列单事实来源

| 项 | 实现要求 |
|---|---|
| 原则 | 前端 `queueItems` 是 UI 事实源；只有 dispatch 时才调用 `/api/agent/prompt`；服务端 `_enqueuePrompt` 作为竞态兜底 |
| 同步 | `agent_queued` 事件只用于显示服务端兜底队列状态，不复制成第二条 UI 队列；收到 `agent_queue_update` 时以事件更新计数 |
| 失败 | prompt 调用失败时把队列项标记 `failed` 并保留文本/附件，允许重试；不静默丢弃 |
| 测试 | 连续排队 5 条、停止、切换会话、刷新；断言无重复执行、无丢失、顺序稳定 |
| 验收 | 前后端队列计数一致；任务中心/会话列表运行态不出现两条“执行中” |

### 3.2 P1：消息、目标、输入与历史

#### 3.2.1 消息操作：编辑 / fork / regenerate

| 项 | 实现要求 |
|---|---|
| 编辑用户消息 | 操作条“编辑”把文本、图片、附件、引用回填输入框；发送时携带 `editOfMessageId`；后端从该消息分叉；成功后旧消息标记“已被编辑”，可展开查看旧分支 |
| fork | 仅助手消息显示；live 临时 id 时 disabled + tooltip“回答完成后可创建分支”；点击调用 `forkSession(id,label,{sourceMessageId})`；成功后切到新会话 |
| regenerate | 仅末轮、空闲态显示；调用后端“从该轮用户消息分叉重跑”；旧回答保留为版本 1，新回答为版本 2；顶部显示“版本 1/2”切换；错误回合显示“重试续跑” |
| 操作条 | 复制/编辑/fork/regenerate 按消息角色与状态显隐；末轮常显，历史轮 hover 显示；按钮不换行 |
| 边界 | 分支会话中不显示“编辑上一条”造成二次分叉；fork 失败保留当前会话并 toast；regenerate 失败恢复旧版本 |
| 验收 | 编辑/ fork/ regenerate 后旧分支仍可查看；工具调用与结果配对；刷新后版本不丢 |

#### 3.2.2 GoalBar

| 项 | 实现要求 |
|---|---|
| 位置 | 输入框正上方、QueueDock 之下；目标完成（complete）后消失；无目标时不占位 |
| 结构 | 阶段标签 + 目标文本（单行省略，hover 全文）+ 状态操作图标 + 编辑/清除/详情 |

#### 3.2.3 草稿持久化

| 项 | 实现要求 |
|---|---|
| 存储 | `localStorage` key 按 `threadId` 隔离；结构 `{text, updatedAt, version:1}`；debounce 300ms |
| 读取 | 切换会话/画布标签时读回；与模块级 Map 合并，Map 优先（当前会话最新） |
| 清理 | 发送成功/清空输入/删除会话时删除；LRU 上限 50；超限清理最旧 |
| 降级 | localStorage 不可用（隐私模式/配额）时静默回退 Map；不阻断输入 |
| 边界 | 同一浏览器多标签页同时编辑同一会话：以最后写入为准，不合并；切换会话时不做跨会话迁移 |
| 验收 | A 会话输入→切 B→切回 A 恢复；刷新/重启恢复；清空后不再出现 |

#### 3.2.4 历史分页 50/页 + 视口锚点

| 项 | 实现要求 |
|---|---|
| 数据 | `getSession(id,{view:"chat",before,limit:50})`；首屏仍可用 360 窗口，但“加载更早”必须走服务端游标 |
| UI | 顶部“加载更早 50 条（前面还有 N 条）”；加载中禁用并显示 spinner；无更多时隐藏 |
| 锚点 | 加载前记录 `bodyRef.scrollHeight/scrollTop`；加载后 `scrollTop += newHeight - oldHeight`；不改变当前阅读消息位置 |
| 冲突 | 与现有 `MESSAGE_PAGE_SIZE=80`/`messageWindowSize` 合并：本地窗口只控制渲染，服务端游标控制数据；两者不能重复扣减 |
| 边界 | 会话切换/运行中到达新消息时，不把锚点补偿应用到新会话；`historyWindow.hasMore` 提示文案同步更新 |
| 验收 | 1000 条历史连续加载 10 页无跳顶、无重复、无漏项；切会话后位置正确 |

## 5. 状态管理适配

| 状态切片 | 当前实现 | 目标实现 | 事实源 | 持久化 |
|---|---|---|---|---|
| 消息/运行态 | `ChatPanel` useState/useRef + SSE reducer | 保持；新增 `branchId/leafId/versions` 字段 | 服务端会话/Run | 否（服务端持久化） |
| 队列 | `queueRef` + `queuedMessages` + `messages` 中 `queued` 气泡 | `useMessageQueue` reducer：`items[]` 单一状态；`itemsRef` 供异步 flush | 前端 UI；dispatch 后服务端 | 否（本轮可接受；刷新丢失需提示） |
| 待注入上下文 | `injectedContext` | 保持；与队列共用 `channel:"context"` | 前端 | 否 |
| Goal | 无 | `goal {status, text, turns, tokens, budget, startedAt}`；服务端接口 | 服务端 `.oaw/goals` | 服务端 |
| 草稿 | 模块 Map | `useSessionDraft(threadId)` + localStorage | 前端 | localStorage |
| 历史 | `historyMessages` + `historyWindow` + `messageWindowSize` | 增加 `historyCursor/hasMore`；保留本地窗口 | 服务端 JSONL | 否 |
| 模型档位 | `THINKING_OPTIONS` 常量 | 服务端 `thinkingLevels` 动态生成；`effort="default"` | 服务端模型目录 | localStorage |
| 会话分组 | 日期分组 | `groupKey(projectId/cwd)` + 折叠集合 | 服务端 sessions | localStorage（折叠） |
| 右画布 | `previewOpen/browserPanelOpen/workspaceTab` | 扩展 `canvasTabs[]` + `activeCanvasTab`；保留 CSS 显隐 | 前端 | localStorage |
| 消息操作 | 复制/重发 | `editOfMessageId`、`forkSourceMessageId`、`regenerateOfTurn` | 服务端 | 否 |

实现约束：

1. 不引入 Redux/Zustand；复杂局部状态用 `useReducer`，跨组件通过 props/现有 App 状态传递。
2. 队列的 `itemsRef` 与 state 必须同步；异步 `flushQueued` 只读 ref，避免闭包旧值。
3. 会话切换时用现有 `navGenerationRef`/`loadSeq` 机制丢弃在途请求；新增 welcome/links/goal 请求也要带 generation 守卫。
4. SSE 归约新增 case 必须与 `server/事件注册表.mjs` 同步；前端不得自造事件名。
5. 乐观更新（Goal 编辑、队列编辑）失败必须回滚并提示，不留下“界面成功、服务端失败”。

## 10. 风险与完成定义

### 10.1 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| `ChatPanel.jsx` 单文件改动引发重渲染/回归 | 高 | 新功能独立组件；只加必要 state；MemoMessage 依赖不扩大；每步跑 `test:chat-flow`/`smoke:chat` |
| 队列 state 与 messages 双写不一致 | 高 | 单一 reducer；所有更新走 action；删除/编辑同步气泡；契约测试 |
| 分支历史过滤不稳，旧版本同屏 | 高 | 后端先冻结 chat view leaf 契约；前端版本切换只消费稳定字段 |
| Goal 状态与 Run 状态混淆 | 中 | Goal 只管跨轮目标；Run 终态仍由 `run_finished` 决定；UI 分开展示 |
| 新事件漏登记 | 中 | 前端事件名从 `事件展示.js` 单一来源取；提交前跑 `test:event-registry`/`test:event-payload` |
| 窄屏下 QueueDock/GoalBar 压扁消息区 | 中 | 1024/900/768 截图验收；折叠/限高；沿用 `chat-compose` 布局约束 |
| 附件过大导致内存/卡顿 | 中 | 100MB 上限、读取进度、失败重试；不自动播放视频 |
| 多标签页草稿互相覆盖 | 低 | 以最后写入为准；不做合并；提示“其他标签页已更新”可选 |
| 新增样式污染旧组件 | 中 | 限定 class 前缀；只用 token；暗/亮/窄屏回归；`test:design-tokens` |
