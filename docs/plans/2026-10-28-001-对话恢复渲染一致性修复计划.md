# 对话恢复渲染一致性修复计划

> 状态：已实施（待用户验收）　日期：2026-10-28　分支：`feature/zcode-harness-align`
> 基线：`0da6671c`（Harness 对标）+ `8180a515`（工作区收尾基线）
> 关联需求：R3 对话流与运行可信度（“刷新/重连后运行状态与消息不丢失、不串轮”）、R5 会话管理（会话恢复）

## 一、问题

在同一工作区打开两个会话并来回切换后，同一会话的助手回复会出现：

1. 同一个 Run 的助手过程被拆成多条气泡，每条重复头像、折叠行和“复制/分叉”操作条；
2. 气泡之间出现异常留白；
3. 工具卡图标看起来“丢失”（实际是被分散进各自收起的折叠区）；
4. 用户气泡多出“当前文件:（无）”；
5. 历史消息的模型名显示成当前选中模型。

## 二、根因

- 实时消息在发送响应里直接带 `runId`，按 `runId` 合并。
- 历史消息的 `runId` 只能由 `associateRunMessages` 反推；它遇到任意真实 user 消息即停止。
- 模型连接中断后，服务端以 **user 角色**注入自动续跑提示（`server/agent.mjs`），客户端只识别 `[系统提醒]` / `系统提醒：`，于是该提示被当作真实用户提问，截断归约。
- 实测会话 `01a17258-…`：113 条 assistant 中 94 条关联不到 Run；把旧格式续跑提示识别为内部消息后降为 0。

## 三、修改范围

### P0 核心

- [x] 服务端续跑提示加 `[系统提醒]` 前缀，沿用既有内部提示约定。
- [x] `运行展示投影.js` 提供 `isInternalHarnessMessage`，兼容旧格式续跑提示。
- [x] `ChatPanel` 历史归一化与渲染兜底统一使用该判定；真实用户消息边界不变。

### P1 恢复一致性

- [x] 历史用户消息忽略“当前文件:（无）”占位。
- [x] 历史 assistant 消息带出 Pi 条目的 `provider/model`。
- [x] `run_finished` 后按权威终稿回填 assistant `entryId/parentId`，实时/恢复操作条一致。

### P2 测试与文档

- [x] `运行展示投影测试` 增加内部提示、Run 归约、终稿匹配用例。
- [x] `启动与会话恢复测试` 增加源码契约断言。
- [x] 更新 `变更日志.md` 与实施记录。

## 四、验收口径

- 同一 Run 在实时和恢复后均只有一条助手气泡、一个过程折叠、一条操作条。
- 续跑提示不再显示为 “You”。
- 用户气泡不出现“当前文件:（无）”。
- 历史助手标题显示当轮 `provider/model`。
- 真实用户消息边界测试保持通过。
- `npm run verify`、`npm run build` 及相关 `test:*` 全绿。

## 五、明确不做

- 不修改 Pi SDK / `node_modules`；
- 不改 SSE 事件类型或契约（回填使用现有 REST 接口）；
- 不做历史数据迁移；
- 不新增默认开启的运行时开关；
- 不改变真实用户消息的归约边界。

## 六、风险与回滚

| 风险 | 评估 | 回滚 |
|---|---|---|
| 给续跑提示加 `[系统提醒]` 前缀 | 低，已有大量同类内部提示 | 还原字符串 |
| 旧格式识别误伤真实用户消息 | 极低，按完整句首匹配并有单测 | 删除 legacy 分支 |
| 回填 `entryId` 增加一次小请求 | 每轮一次，首次未命中再试一次 | 单独回滚该提交 |
