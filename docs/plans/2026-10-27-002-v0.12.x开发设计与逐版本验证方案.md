> 状态：已实现（v0.12.0–v0.12.9 随 v0.13.2 交付）
> 基线：v0.13.2
> 更新：2026-10-27
> 关联：[AVA 对话模块开发进度与测试验证计划](2026-10-27-001-AVA对话模块开发进度与测试验证计划.md)、[AVA 对话模块全量对标与迭代修改计划](2026-10-26-001-AVA对话模块全量对标与迭代修改计划.md)、[AVA 对话模块前端新增专项计划](2026-10-26-002-AVA对话模块前端新增专项计划.md)、`.trae/specs/refine-small-version-iteration-plan/spec.md`
> 说明：本文件是 v0.12.x 的开发设计，不直接写代码；每个 patch 实施时按本文契约开独立分支，并补齐对应测试证据。

## 0. 结论

1. v0.12.x 主题为“队列与消息基础”，按 v0.12.0–v0.12.9 十个小版本交付；合计约 41.5 人天，W1 从 2026-11-04 起算，约 10 周。
2. 三个核心设计决策：
   - **前端队列是 UI 事实源**：排队项先进入前端 `queueItems`，只有 dispatch（空闲或 `run_finished` 后）才调用 `/api/agent/prompt`；服务端 `_enqueuePrompt` 仅作为竞态兜底。
   - **历史模型先稳定，再做消息版本**：v0.12.5 先按活跃 leaf 过滤历史；v0.12.6–v0.12.8 的编辑/fork/regenerate 不得绕过该契约。
   - **不引入数据库/新状态库**：草稿用 localStorage，队列按 thread 存在前端内存，目标（v0.13.x）用 `.oaw/` JSON 文件。
3. v0.12.0 只做 QueueDock 基础切片（折叠/200 字预览/单条删除/附件缩略），不提前做编辑、提升、单源或消息版本。
4. 每个 patch 必须有自己的“用户可见验证功能 + 测试命令 + 退出标准”；v0.12.9 只做线内回归与发布候选。

### 1.2 设计约束

- 三栏布局不变：左侧项目/文件/能力，中间文档画布，右栏对话（`DESIGN.md:21-22`）。
- 不新增 Redux/Zustand、UI 框架或数据库；不修改 Pi SDK。

## 2. 共享设计

### 2.1 QueueItem 数据模型

```js
// 前端队列项（仅内存；不写服务端 JSONL）
{
  id: "q_<uuid>",              // 队列项唯一 id，同时作为消息气泡 id
  channel: "queue" | "steer",  // 排队 / 插话
  text: "发送文本（已拼接引用）",
  rawText: "用户原始输入",
  images: [{ mediaType, data, dataUrl, name }],
  attachments: [{ mediaType, data, dataUrl, name }],
  references: [{ id, kind, target, status }],
  contextNotes: [],            // 本轮注入上下文
  currentDoc: "当前文件路径或 null",
  editMode: "chat" | "agent" | "review",
  effort: "low" | "medium" | ...,
  status: "waiting" | "editing" | "sending" | "failed",
  errorText: "",
  createdAt: 0
}
```

状态机：

```text
waiting ──编辑──> editing ──保存──> waiting
waiting ──发送──> sending ──成功──> 移出队列 / 气泡改为已发送
waiting ──失败──> failed ──重试──> sending
waiting ──提升为插话──> steer/sending
waiting ──停止/中断──> waiting（保留，不自动发送）
waiting ──删除──> 移出队列 + 移除气泡
```

### 2.2 队列单事实来源

| 规则 | 设计 |
|---|---|
| UI 事实源 | `queueItems`（当前 thread）是唯一可编辑列表；`queueRef` 只是异步 dispatch 的镜像 |
| 服务端事实源 | 服务端 `_enqueuePrompt` 只处理“已经 dispatch 的请求”；前端不再把排队项提前发给服务端 |
| dispatch 时机 | 空闲时立即 send；运行中只入队；`run_finished` 且状态非 `cancelled/aborted` 时发送队首 |
| 防重复 | `dispatchingRef` + 队列项 `status:"sending"`；同一 `id` 未成功前不得再次 dispatch |
| 服务端事件 | `agent_queued`/`agent_queue_update` 只用于显示服务端兜底计数；若与本地队列重叠，以本地队列为准并在调试日志标注 |
| 切会话 | 队列按 `threadId` 存入模块级 `Map`（LRU 20），切回时恢复；恢复时只渲染 QueueDock，不重复插入历史气泡 |
| 刷新 | 前端内存队列丢失；服务端仍排队的轮次由 abort/状态回执提示；v0.12.x 不持久化队列（草稿仅文本） |
| 失败 | dispatch 失败保留该项 `failed`，可重试/删除；不静默丢弃 |

### 2.3 停止/压缩与队列联动

- 停止：调用 abort 后读取 `stillQueued`；本地队列保留，`status` 回到 `waiting`；不自动 flush，等待用户“继续队列”或下一次发送。
- 压缩：`compacting` 期间禁止 `enqueue`、`send`、`flushQueued`；QueueDock 显示“压缩中不可发送”，按钮禁用；压缩完成后恢复。
- 压缩卡：`context_compacted` 增加 `messageCount`（v0.12.3），显示“压缩 N 条 · pre → post tokens”。

### 2.4 草稿持久化

- localStorage key：`oaw_draft_v1:<threadId>`；值：`{version:1, text, updatedAt}`。
- 写入：输入变化 debounce 300ms；发送/清空/删除会话时删除。
- 读取：组件挂载、切 thread 时读取；与模块级 Map 合并，Map 优先（当前会话最新）。
- 降级：localStorage 不可用/配额满时静默用 Map；不阻断输入。
- 上限：LRU 50；超限清理最旧。
- 隐私：不写附件/图片 base64，只写文本；附件仍只在内存。

### 2.5 历史分页与活跃分支

#### 历史分页（v0.12.5）

- API：`GET /api/sessions/:id?view=chat&before=<historyEnd>&limit=50`。
- 响应保留 `historyStart/historyEnd/historyHasMore/historyTotal`。
- 首屏：取 120 条（与现有 360 兼容），之后每次“加载更早”取 50 条；本地可见窗口 `messageWindowSize` 增加 50。
- 锚点：加载前记录 `scrollHeight/scrollTop`，加载后 `scrollTop += newHeight - oldHeight`；不改变当前阅读位置。
- 禁止：本地窗口扩展不扣减服务端游标；两者分别维护。

#### 活跃分支（v0.12.5 契约，v0.12.6–8 使用）

- 会话 header 增加 `activeLeafId`（增量字段，兼容旧会话）。
- chat view 解析：`activeLeafId` 存在→沿 `parentId` 回溯到根，只返回该路径；不存在→回退当前扁平返回。
- fork/regenerate 后写 `activeLeafId`；旧分支仍在 JSONL，但 chat view 不渲染。
- 版本切换：`GET /api/agent/session-tree` 返回树；前端只切换 `activeLeafId`，不复制整份历史。
- 工具配对：路径必须包含 `toolCall` 与其 `toolResult`；前缀复制/回溯时校验。

### 2.6 消息版本（v0.12.6–v0.12.8）

| 能力 | 设计 |
|---|---|
| 编辑用户消息 | 前端回填文本/图片/附件/引用；发送时携带 `editOfMessageId`；后端从该用户消息分叉新用户消息，旧分支保留；成功后旧消息显示“已被编辑”并可查看旧版本 |
| 助手消息 fork | 只对已完成助手消息显示；live 临时 id 置灰；后端按 `sourceMessageId` 找到 entry，复制截至该 entry 的前缀到新 JSONL；header 写 `parentSessionId/branchSourceMessageId/activeLeafId`；新会话自动切换 |
| regenerate | 仅末轮空闲；从该轮用户消息分叉新版本重跑；旧回答保留为版本 1；新回答版本 2；版本切换只切 `activeLeafId`；错误回合显示“重试续跑” |
| 失败/边界 | fork 失败保留当前会话；regenerate 失败恢复旧版本；历史路径缺 toolResult 时拒绝并提示；分支会话禁止再次分叉同一条用户消息造成链式歧义 |

### 3.1 v0.12.0 QueueDock 基础

- 位置：`chat-compose` 内、`PendingActionBar` 之下、输入框之上；空队列不占位；≥2 条默认折叠。
- 折叠头：`N 条排队消息` + 展开/收起；`aria-expanded`；编辑时自动展开。
- 每条：通道图标、200 字单行预览（title 全文）、最多 3 个附件缩略 + “+N”、删除按钮。
- 删除：从 `queueItems` 移除并移除对应 `messages` 中 `id` 相同的 queued 气泡；不调用 abort。
- 空态：不渲染 QueueDock；保留现有“待执行 N 条”仅作为兜底（v0.12.1 后移除重复计数）。
- 验收：排 5 条→折叠/展开→预览→删除第 2 条→不执行；`test:ava-queue` 基础通过。

### 3.2 v0.12.1 队列单源

- `queueByThread: Map<threadId, QueueItem[]>`；`queueRef` 指向当前 thread 的数组。
- `enqueue(item)`：只更新 `queueItems` + queued 气泡，不调用 prompt。
- `dispatchHead()`：`busy || compacting || stopping` 时直接返回；取队首，`status:"sending"`，调用 `send({payload:item}, {force:true})`；成功后移除；失败 `status:"failed"`。
- `run_finished`：非 `cancelled/aborted` 时 `dispatchHead()`；`aborted/cancelled` 不自动发送。
- `thread` 切换：保存当前队列到 Map；从 Map 取新 thread 队列；只渲染 QueueDock，不重复插入历史气泡。
- `agent_queued`：只更新“服务端兜底计数”显示；若与本地队列重叠，以本地 `queueItems` 为准，不复制。
- 验收：排 5 条→顺序执行不重复；切 A/B 队列表不串；刷新提示“队列未持久化”。

### 3.3 v0.12.3 停止/压缩联动

- stop：`retained = result.stillQueued`；本地队列 `waiting`；系统通知 + 输入区提示；不自动 flush。
- compact：`compacting` 时 `enqueue` 也禁用（不仅是 send）；QueueDock 显示“压缩中不可发送”；压缩完成恢复。
- 压缩卡：`context_compacted.messageCount`；`pre → post` tokens；无字段时回退旧文案。
- 验收：排 3 条→停止→提示 3 条→队列保留；压缩中按 Enter/点排队均不产生新项；压缩卡显示 N 条。

### 3.4 v0.12.5 历史分页与活跃 leaf

- 首屏 120；每次 50；`historyCursor` 初始 `historyStart`；`historyHasMore` 来自服务端。
- 锚点：`beforeHeight/beforeTop`；加载后 `scrollTop = beforeTop + (newHeight - beforeHeight)`；用 `useLayoutEffect` 在 DOM 更新后执行。
- `activeLeafId`：v0.12.5 先实现 header 字段与 chat view 回溯；旧会话无字段时保持当前扁平逻辑。
- 验收：1000 条连续 10 页无重复/漏项/跳顶；旧会话打开不白屏；`test:startup` 覆盖恢复。

### 3.5 v0.12.6–v0.12.8 消息版本

- 编辑：`editOfMessageId` 必须指向用户消息；后端从该消息的父节点分叉，新用户消息文本替换；旧分支保留；前端发送成功后把旧消息标记 `edited:true`。
- fork：`sourceMessageId` 必须指向已完成助手消息；后端按 entry 前缀复制；保留 `toolCall/toolResult` 配对；新 header `activeLeafId` 为最后一条 entry；前端切换新会话。
- regenerate：只允许末轮；从该轮 user entry 的父节点分叉，重跑同一 prompt；旧 assistant 版本保留；版本切换器读 session tree；错误回合可 “续跑” 重试。
- 共同约束：任何分支操作前 `busy` 必须为 false；live 临时消息禁止；失败不改变当前会话。
