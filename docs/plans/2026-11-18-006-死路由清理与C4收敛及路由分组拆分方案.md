## 0. 一句话

分三批推进：先删掉 10 组死路由并用静态测试锁住注册顺序；再删掉 v3 与基线里重复的 C4「旧执行流」渲染通道（保留时间线数据链，C5 / C3 / C6 不动）；最后把知识库与模板库路由抽成 `server/路由/` 模块，作为 index.mjs 拆分的试点。

## 1. 要解决什么与外部可见变化

### 批次 1：死路由清理（行为不变）

代码事实（已核验）：

- 10 组重复注册（同一 method + path 注册多次）：
  - `/api/map/demo-analysis`、`/api/demo/cambodia-od`、`/api/m3/bus-routes`、`/api/m3/station-heatmap`、`/api/m3/od-lines`、`/api/m3/network-stats` 各 2 份：第一份在 `server/index.mjs:1125-1151`，是运行时实际生效的一份；第二份在 `server/index.mjs:7235-7265`，被 Express 首个同路径处理器遮蔽。
  - `/api/bus/routes`、`/api/bus/stops`、`/api/bus/od`、`/api/bus/stats` 各 3 份：`server/index.mjs:7397-7418`、`7525-7546`、`7847-7868`。三份都注册在 `server/index.mjs:7394` 的 `/api` 404 兜底之后，运行时恒为 404。
- 前端与测试均未调用 `/api/bus/*`；`/api/m3/*` 等 6 条接口有 `scripts/验证脚本.mjs:192-197` 与地图可视化测试覆盖。

外部可见变化：**无**。`/api/bus/*` 删前删后都是 404（实施时先复现再删）；其余 6 条接口响应保持不变。

改前 → 改后：同一接口只剩一份实现；新增一条静态测试，以后出现重复注册、或把 `/api` 路由注册到 404 兜底之后，测试直接失败。

### 批次 2：C4 通道删除（运行中/完成态 UI 有可见变化）

代码事实（已核验）：

- C4「旧执行流」事件卡在 `client/src/components/ChatPanel.jsx` 有 4 处渲染点：`:7439`（旧块式渲染 C7 内）、`:7547`（运行中分支）、`:7557`（v3 分支内但被 `!transcriptV3` 门控，实际不可达）、`:7586`（基线折叠 C3 内）。
- `ExecutionFlow` 组件定义在 `ChatPanel.jsx:8631-8838`（约 207 行）。
- **删除边界必须精确**：`executionEvents`、`appendExecutionFlowEvent`、`showExecutionFlow`、`executionFlow` 对象不是 C4 专属——它们是 C1/C2 时间线的数据源与运行态判定位（`ChatPanel.jsx:5643`、`:6993-7018`、`:6910-6913`）。本轮只删除：4 个渲染点、`ExecutionFlow` 组件、`messageExecutionFlow`（`:6976`，仅用于 `:7327` / `:7439` / `:7547` / `:7557` / `:7586`）、`:7327` 的 flow-only 补段，以及逐个确认后无其他消费方的 C4 专属 props。
- **连带死代码**：`visibleExecutionEvents`（`:6954`，唯一消费方 `:6976`）随 `messageExecutionFlow` 一并删除，去重职责由时间线自身的投影规则承担；`recentNarration`（`:5408-5420`）在删除 `note` prop 后无消费方，一并删除。`compaction` 只删传给 C4 的副本，`ContextUsageRing` 仍用 `runState.compaction`（`:6076`）。`statusChips` / `statusDotClass` 本就未传值，随组件清理。
- 两个字段在删 C4 后没有渲染出口，必须以**常驻节点**迁入过程区（运行中分支没有折叠体，不能只放折叠内）：`nextStepText`（`:5322` → `:5657`，唯一消费点）与 `systemNotes`（`:1039-1043` → `:5650`，唯一消费点）。
- 落点：运行中分支在 `.tl-list`（`:7544`）之后新增常驻 `.tl-next-step` 状态行与 `.tl-system-notes` 摘要行；收尾分支在折叠体内保留同样两行。`nextStepText` 用 `role="status"`，仅在没有流式正文（`.flow-stream-text` 不存在，`:7389`）时 `aria-live="polite"`，否则 `aria-live="off"`，保证任一时刻只有一条播报出口；`systemNotes` 不做 live 播报。
- 「活动显示」外观设置 `activityDisplay`（隐藏 / 紧凑 / 展开）当前经 `flowHidden` / `flowDefaultExpanded` 传给 C4（`ChatPanel.jsx:947-951`），设置面板入口在 `SettingsPanel.jsx:900-902`。
- **五态状态点归属**：`DESIGN.md:224-232` 的运行/完成/降级/失败/无状态五态，由两个既有选择器共同承担，不新增没有生产者的 `.tl-state.warning`：
  - 运行 → 行级 `.tl-state.run`：改为 `var(--accent)` + `dot-breathe-soft`（现为 `var(--warning)` + `pulse`，`styles.css:11930-11933`）；
  - 完成 / 失败 → 行级 `.tl-state.ok`（`--success`）/ `.tl-state.err`（`--error`）；
  - 降级 / 无状态 → Run 级 `.run-fold-dot.warn`（`--warning`）/ `.run-fold-dot` 默认中性灰（`styles.css:12036-12039`，`describeRunFold` 已产出 `ok/warn/err/cancelled`，`会话流投影.js:409`）。
  - 同步 `scripts/动效治理测试.mjs:119-120` 的动画宿主映射，并在 DESIGN §6.1 写明两个选择器的五态分工。

外部可见变化：

- 改前：运行中有「执行流事件卡」，结束后折叠体内也可能出现同一份 SSE 轨迹的旧卡片。
- 改后：运行中与完成态统一由时间线 / 过程组呈现，不再出现重复的「执行流事件卡」。
- 「活动显示」设置继续可用，改为控制过程区（隐藏 = 不渲染过程区；展开 = 默认展开折叠；紧凑 = 默认收起）；「隐藏」态在过程区位置保留一行「过程区已隐藏 · 显示」入口，避免只能回设置页恢复。
- 「下一步指引」与「系统提示聚合」以常驻行保留：运行中显示在过程列表之后，收尾后进入折叠体内，不再依赖 C4 的常驻卡片。
- 五态状态点视觉与 DESIGN §6.1 一致（运行 = 强调蓝 + 呼吸；降级 = 琥珀；无状态 = 中性灰）。

不做：不删 C5 结论卡、C3 基线折叠、C6 运行结果卡、C7 块式渲染；不改 `transcriptV3` 默认值；不改设置项键名与取值。

### 批次 3：路由分组拆分试点（行为不变）

代码事实（已核验）：

- `server/index.mjs` 7868 行、316 个路由全部内联；全仓无 `express.Router`。
- 知识库路由 `:500-552`（11 条）+ `:588-608`（2 条）共 13 条，只依赖 `kb`（`import * as kb from "./kb.mjs"`，`:22`）；模板库路由 `:555-584`（4 条）只依赖 `tpl`（`:23`）与 `notice.mjs` 动态导入。两者在 index.mjs 中没有其他使用点。

外部可见变化：无。URL、响应、注册顺序完全不变；index.mjs 预计减少约 140-180 行。

不做：本轮不拆 map / agent / canvas / sessions 等大路由组；不动 `server/agent.mjs`、`ChatPanel.jsx` 其他部分、`styles.css` 中与本次无关的部分；不引入新框架、不引入 Router 层级；只删 `index.mjs` 里的静态 import，不删除 `m3-xinchang.mjs`、`柬埔寨OD.mjs` 模块本身（仍被 `交通数据源.mjs:255`、`index.mjs:6320` 使用）。

## 3. 关键取舍、异常与兼容边界

1. **重复路由保留哪一份**：保留第一份（运行时实际生效、现有测试一直针对它），删除第二份；同时删除因此不再使用的 `cambodiaOD` import（`index.mjs:25`）与 `index.mjs:7249` 的 `m3` 静态导入。`createDemoAnalysis`（`:26`）仍被 `:6324` 使用，保留。

3. **「活动显示」设置语义**：设置项与存储键不变，`activityDisplay` 转接到过程区；「隐藏」态保留流内恢复入口。这是本轮唯一的产品语义迁移点。
4. **DESIGN 五态迁移（需用户确认）**：`DESIGN.md:224-232` 五态保留，按既有选择器分工表达，不新增无生产者的类——运行 = `.tl-state.run`（改 `var(--accent)` + `dot-breathe-soft`）；完成 = `.tl-state.ok`；失败 = `.tl-state.err`；降级 = `.run-fold-dot.warn`；无状态 = `.run-fold-dot` 默认中性灰。同步 `styles.css` 与 `动效治理测试.mjs` 的动画宿主映射，并在 `DESIGN.md` §6.1 写明两个选择器的五态分工与新增常驻行 `.tl-next-step`、`.tl-system-notes` 的样式归属。随本方案一并请用户确认。

6. **路由分组形态**：采用 `registerXxxRoutes(app, deps)` 工厂函数，不引入 `express.Router`；硬约束：注册调用必须位于鉴权中间件（`index.mjs:239`）之后、`/api` 404 兜底（`:7394`）之前，注册位置与原来路由定义位置一致。异步处理、try/catch 错误映射、`notice.mjs` 动态导入逐字搬迁。依赖方向：路由模块 → L2（`kb.mjs` / `tpl.mjs`），禁止反向。
