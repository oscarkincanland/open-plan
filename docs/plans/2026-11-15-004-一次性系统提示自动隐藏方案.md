# 2026-11-15-004 一次性系统提示自动隐藏方案

> 状态：待用户确认（2026-11-15）　基线：v0.13.25（develop @ 487b5d37 + 未提交 010/011/012 改动）　需求来源：用户反馈截图（「已中断；保留 1 条排队消息，可在输入区队列中继续编辑或发送。」）——这类一次性提示显示过就可以自动隐藏。

## 1. 现象

会话流里的虚线气泡提示（`.msg.system > .bubble`，例如「已中断；保留 1 条排队消息…」「已排队第 2 条，当前任务完成后自动执行。」「已切换到 Work」）会**永久留在会话里**。多轮之后堆叠，挤占正文、打断阅读节奏。

这些提示只在前端内存（`pushSystem` 直接 `setMessages`），刷新即消失，不落盘；问题只在同一会话内越积越多。

## 2. 现状与来源

- `ChatPanel.jsx` 的 `pushSystem(text, key)`：追加 `{ role: "system", text, status: "done" }`，按 key 去重后永久保留。
- 渲染：`Message()` 的 `m.role === "system"` 分支 → `<div className="msg system"><div className="bubble">`。
- 另有 `pushSystemNote()`（上下文压缩状态）是另一条链路，不在本次范围。
- 输入栏旁的 `setModelMsg` 提示本就有自动消失（3.6s），与会话流气泡是两套。

## 4. 方案（推荐 A）

### A. 淡出后移除（推荐）

- `pushSystem(text, key, { sticky = false })`：非 sticky 的消息标 `transient: true` + `expiresAt`。
- 计时：`TRANSIENT_NOTICE_TTL_MS = 6000`（6 秒，够读完一句）；**鼠标悬停暂停**，移开继续；同 key 重复触发重置计时。
- 到点：加 `.is-leaving` 类做 200ms 淡出 + 轻微上移，然后从 `messages` 移除；`prefers-reduced-motion` / `data-motion-level="off"` 下直接移除（无动画）。
- 抽屉式回看：**不保留**（这类确认语已由输入栏队列、模式和目标入口复述，丢正文不影响操作）。

### B. 收进可展开的「系统提示 N 条」行（备选）

淡出后不移除，而是折进会话流顶部/尾部的一行 `系统提示 · N`，点击可展开回看。信息不丢，但多一层交互与状态。

## 6. 验收口径

1. 发一条排队消息 → 出现「已排队第 N 条…」→ 6 秒后淡出消失；鼠标停在上面时暂停计时。
2. 中断并保留队列 → 截图那条提示 6 秒后消失，队列本身仍在输入区可用。
3. 失败/需行动类提示（中断未确认、中断失败、备用模型切换失败、目标操作失败）**不消失**。
4. 减少动效档位下：提示直接消失，无过渡动画。
5. `npm run test:chat-layout`、`test:motion`、`test:main-flow`、`npm run verify` 通过。

## 7. 不做清单

- 不改 `pushSystemNote`（上下文压缩状态）与运行/结论卡。
- 不改未读计数与滚动跟随。
- 不把提示落盘到会话历史（仍为纯前端临时态）。
- 不新增开关（默认行为，避免加运行时开关）。
