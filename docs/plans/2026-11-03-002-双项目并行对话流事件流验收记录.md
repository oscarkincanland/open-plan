## 4. 问题清单（按严重度）

### P1-1 长 Run 后“上一轮提问”被历史窗口裁掉（对话流看似丢失）

- **现象**：切回长会话时，B 轮 user 消息（22:52 “请统计当前工作区根目录下有多少个 .md 文件…”）从流中消失，只保留 assistant；顶部出现“加载更早的 50 条历史”+“历史较长，当前先加载最近 50 条”。
- **根因（证据）**：历史窗口按 **JSONL 原始条目数**（message_start/message_end/turn/tool/stats…）计 50，而非“消息条数”。单个 7m46s 的 Run 产生 100+ 条目，足以把本轮提问挤出窗口。会话 UI 只有 6 条消息，却触发“历史较长”提示。
- **影响**：用户明确关心的“切换/刷新后会话流丢失”在首屏复现（数据未丢，点“加载更早”可找回）。
- **建议**：窗口裁剪改为按“消息级条目数”计数（或同一 run 的流式条目按 run 合并计数）；提示文案改为“最近 N 条消息”。

### P1-2 运行中刷新恢复的首载竞态（旧式“运行结果”气泡 + 前轮折叠条缺失）

- **现象**（任务 D 运行中刷新后立即重开会话）：
  - 运行中的 Run（run_73eb7f53，status=streaming）以旧式 `RunSummary` 气泡呈现：“本轮任务仍在执行中…技术详情（运行 ID、事件与原始错误）{JSON}”；
  - 同会话上一轮已完成 Run（C 轮 22s）的折叠条缺失，assistant 以未折叠过程文本展示；
  - 运行中 Run 的 assistant 消息未出现（完成后才补入）。
- **对照**：切走再切回后自动恢复（folds=3、bubbles=0、消息补齐）——说明是首载合并竞态，而非持久损坏。
- **建议**：恢复加载时同批取回该 session 全部 run 摘要并按时间窗统一 associate；streaming 状态的 summary 卡应渲染为“运行中折叠条”（RunFoldBar running 态）而不是 RunSummary 旧卡；恢复窗口内对 streaming run 的 assistant 占位做占位合并。

### P2-3 步数口径实时/历史不一致

- **现象**：B 轮实时折叠条“38 步”，事后历史折叠条“15 步”（同一 run，events 216、tool 18）。思考字数 297→1,035 属快照差异可接受，但步数会让用户误以为数据变了。
- **建议**：折叠条步数与历史投影统一取同一数据源（run.steps / 工具去重计数），实时累计与终态同口径。

### P2-4 切换会话时主界面先清空、骨架 1.6–2.6s

- 切换项目后主界面先变为 0 消息再加载，快速连点会看到骨架闪烁。非缺陷，建议保留上一屏直到新会话首帧（或骨架下沉）。
