> 文档类型：实施计划（**已实施，2026-11-11**；实施记录见 [2026-11-11-002-实施记录](2026-11-11-002-实施记录.md)）
> 日期：2026-11-11　计划号：2026-11-11-002
> 基线：v0.13.25（`develop @ 7a4279b1`）
> 关联：`REQUIREMENTS.md` **R15 模型供应商与配置**、`DESIGN.md` §7.1 设置面板（模型页）、`docs/规范/代码规范.md`
> 本文回答用户两问：① 现在有没有“自主选择模型提供商”“自主添加模型”的能力；② 缺的部分怎么补。

## 0. 结论先行

### 0.1 现状：**大部分能力已有，缺两个关键入口与一处字段**

| 能力 | 现在是否支持 | 证据 |
|---|---|---|
| 选择模型（含按供应商筛选） | ✅ 支持 | 输入栏模型浮层有供应商 chips（全部/各供应商）+「全部模型」按供应商分组；`ChatPanel.jsx` 模型选择区 |
| 在设置里选择/管理供应商 | ✅ 支持 | 模型页左栏「已接入 / 套餐 / 国内 / 国际 / 自定义 / 其他」分组 + 右栏 master-detail（`模型设置页.jsx`） |
| 从内置目录一键添加供应商 | ✅ 支持 | 供应商库/目录详情「添加供应商」「手动配置」，走 `/api/agent/provider-catalog/import` |
| 给已接入供应商添加模型 | ✅ 支持（入口较深） | 供应商详情「+ 添加模型」（仅 模型 ID/显示名/上下文 tokens） |
| 从 URL 拉取模型列表 | ✅ 支持 | 详情「从 URL 拉取」，`/api/agent/model-configs/fetch-models` |
| 启用/停用/移除模型、删除供应商、测试连接、设为默认 | ✅ 支持 | 同页 |
| **从零新建任意自定义供应商**（任意 ID + Base URL + API Key，不依赖内置目录） | ❌ **无 UI 入口** | 后端 `POST /api/agent/model-configs` 已完整支持任意 provider；`POST /api/agent/custom-provider` 也存在，但**前端从未调用**（`agentCustomProvider` 无使用点） |
| **新增模型时指定视觉/推理能力** | ❌ 新增表单没有这两个字段 | 表单只有 id/name/contextWindow；服务端 `validateModelConfigInput` **已支持** `vision` / `reasoning`，列表只读展示 |
| 模型浮层直接进入“添加模型/供应商” | ❌ 无入口 | 浮层只有「重新扫描模型」与列表；需要用户自己找到“设置 → 模型” |

**一句话**：不是“没有自主选择/添加能力”，而是**能力被埋在后端与设置深处**——任意自定义供应商目前只能靠外部调用 API 或手改配置；新增模型无法配置能力字段；模型浮层没有“管理/添加”入口。

### 0.2 本计划的建议范围（UI 为主，后端零改动）

1. **D1 自定义供应商入口**：模型页左栏/空态/全部供应商页增加「+ 自定义供应商」，空白表单填写供应商 ID、名称、Base URL、协议、API Key、模型列表，保存复用现有 `POST /api/agent/model-configs`；保存后进入「自定义」分组并选中。
2. **D2 模型能力字段**：新增模型表单补「视觉输入」「推理/思考」两个勾选（上下文 tokens 保留可选），保存后 `/api/models` 立即带出能力；服务端已支持，无需改 API。
3. **D3 模型浮层入口**：浮层底部增加「管理模型与供应商」；搜索无结果时显示「+ 添加模型/供应商」；点击打开设置模型页（必要时预选“新建供应商”），解决“不知道去哪加”的问题。
4. **D4 死代码收敛**：`/api/agent/custom-provider` 前端不使用；本次**不删除公开 API**，在代码注释/文档标注 legacy，UI 统一走 `/api/agent/model-configs`（避免双写路径）。

**非目标**：不改 SDK、不改模型目录合并逻辑、不新增后端 API/事件、不做任意协议插件、不改模型切换语义（会话级、全局偏好不回切）。

## 2. 交互设计

### 2.1 D1：自定义供应商入口

**入口位置（三个）**

1. 模型页左栏底部，与「全部供应商」「导入与凭据」并列：`+ 自定义供应商`。
2. 全部供应商页（`selection.type === "library"`）头部：`+ 新建自定义供应商`。
3. 左栏「自定义」分组为空时显示引导按钮（空态）。
4. 模型浮层「管理模型与供应商」/「+ 添加」也落到同一入口（见 D3）。

**表单字段**（沿用现有 draft 模型，不需要新组件体系）

| 字段 | 必填 | 校验/默认 |
|---|---|---|
| 供应商 ID | ✅ | 2–64 位字母/数字/点/下划线/短横线；不可与已接入 provider 重复（重复时提示“已存在，已为你打开”） |
| 显示名称 | ❌ | 默认 = 供应商 ID |
| Base URL | ✅ | 必须 `http(s)://`；保存前做一次 `new URL()` 校验 |
| 接口协议 | ✅ | 沿用 `MODEL_API_OPTIONS`（OpenAI Completions / OpenAI Responses / Anthropic Messages / Google / Mistral 等，以现有白名单为准） |
| API Key | 视协议 | 保存到服务端凭据文件；留空表示稍后再配 |
| 模型列表 | ✅ ≥1 | 复用现有「添加模型 / 从 URL 拉取」，字段见 D2 |

**行为**：保存成功 → 左栏「自定义」出现该供应商并自动选中 → 顶部「当前 Agent 模型」下拉与输入栏模型浮层在刷新后出现其模型 → 可点「测试连接 / 设为默认」。

**安全**：Key 不回显、不写日志、不进提交；前端只传 `apiKey`，响应不返回 Key（沿用现有服务端行为）。

### 2.2 D2：模型能力字段

在「添加模型」内联表单补两个复选框：

```
[✓] 支持图片输入（vision）   [✓] 支持推理/思考（reasoning）
```

- 默认：`vision=false`、`reasoning=true`（与当前硬编码一致，保持基线）。
- 上下文 tokens 保持可选（留空由服务端按同名内置模型自动补全，已有逻辑）。
- 已添加的模型行内展示现有「图片」「思考」徽标不变；本期不做逐行编辑能力字段（避免把列表变成表单；如需修改可移除后重加）。

### 2.3 D3：模型浮层快捷入口

- 浮层底部（「重新扫描模型」下方）新增一行按钮：
  - `管理模型与供应商` → 打开设置面板的“模型”页；
  - 搜索无结果时显示 `+ 添加模型 / 供应商` → 同上并预选“新建供应商”。
- 不改变模型切换语义；仅新增导航入口。
- 实现方式：`ChatPanel` 通过现有回调/自定义事件通知 `App` 打开设置面板（`initialSection="model"` 已有机制），必要时新增可选参数 `openModelPage({ mode: "new" | "manage" })`，由 `App` 传给 `SettingsPanel` → `模型设置页` 预选。

### 2.4 D4：`/api/agent/custom-provider` 处置

- 本期**不删除**该路由（避免影响可能的外部脚本），在路由上方注释标注 `legacy：工作台前端不再使用，统一走 /api/agent/model-configs`。
- 不新增前端调用；`api.js` 的 `agentCustomProvider` 可保留但标注 legacy（或删除死代码——见决策 6）。

## 3. 需求与验收

### 3.1 PRD R15 追加（需用户确认）

**需求追加**

> - 支持在界面中**从零新建任意自定义供应商**：供应商 ID、显示名称、Base URL、协议、API Key 与至少 1 个模型；不依赖内置目录。
> - 支持在新增模型时声明上下文窗口、图片（视觉）输入、推理/思考能力；能力保存后模型选择器与能力标签如实展示。
> - 模型选择浮层提供「管理模型与供应商」入口；搜索无结果时提供添加入口。

**验收追加**

> - 任意 `http(s)` OpenAI/Anthropic 兼容网关，无需修改配置文件，可在界面完成新增、保存、测试连接、设为默认、删除。
> - 新供应商模型在保存后无需重启服务即出现在 `/api/models` 与输入栏模型浮层，并可按供应商筛选。
> - 新增模型时勾选视觉后，模型行出现「图片」徽标且发送图片不再被非视觉确认拦截；勾选推理后出现「思考」徽标。
> - Key 仅存于服务端凭据文件，接口响应与前端状态均不回显明文。

## 7. 风险与回退

| 风险 | 概率 | 影响 | 缓解 | 回退 |
|---|---|---|---|---|
| 自定义 provider 与内置 provider 同名覆盖 | 中 | 配置被覆盖 | 保存前检测已存在 → 提示并转为编辑现有；ID 正则限制 | 删除该 provider 或从备份恢复 `模型配置.json` |
| Base URL/协议填错导致请求失败 | 中 | 模型不可用 | 表单校验 + 「测试连接」；错误信息沿用现有诊断 | 编辑或删除 |
| Key 泄露 | 低 | 安全 | 沿用现有“只写不读”链路；前端不存明文；测试断言脱敏 | 删除凭据 |
| 模型列表为空/重复 | 低 | 保存失败 | 前端至少 1 个 + 去重提示；后端已有校验 | 修正后重存 |
| 保存后浮层不刷新 | 低 | 体验 | 保存后调用 `onModelsRefresh`（现有链路）；必要时在 ChatPanel 监听刷新事件 | 重新扫描模型 |
| 改动与并行会话冲突 | 中 | 合并冲突 | 只改上述文件；确认无并行改动后再动 | 重新排序/最小重放 |
