## 1. 整改目标与原则

1. **以 DESIGN 为唯一事实源**：把多套皮肤收敛回「暗/亮主题 + Qoder 受控视觉层」，或在用户确认后为皮肤补 ADR，二者只能选一。
2. **保留清晰组合，逐步图标化**：按 DESIGN §5.8，Chat/Work/Review、菜单与状态卡保持现状；纯图标按钮补应用内悬停提示；次要文字按钮能图标化则图标化，主操作与不可逆操作保留文字；一个图标只表达一个语义。
3. **先修守护，再改视觉**：先让 `test:design-tokens`、`test:motion` 恢复绿色，避免整改过程把基线继续推高。
4. **先修交互，再做装饰**：原生弹窗、键盘可达、回滚确认优先于配色与圆角微调。
5. **最小侵入**：不引入 UI 框架、CSS-in-JS、全局状态库；不重写地图/文档预览；只改必须改的规则与组件。
6. **每阶段可独立验收、可回滚**：一个阶段一个提交序列，配对应测试与截图。

## 7. 风险与回滚

| 风险 | 影响 | 缓解/回滚 |
|---|---|---|
| 删除皮肤影响已选用户 | 观感突变 | 读取旧 `oaw_skin` 迁移为默认并提示；保留整段 CSS 于提交历史，可整提交回滚 |
| 字号/圆角整体调整导致布局溢出 | 密集面板错位 | 分批替换 + 每批 1024/781 截图对比；单批可 revert |
| 开启 `feedbackV2` 改变交互习惯 | 用户误以为操作未生效 | 保留 `OAW_FEEDBACK_V2=0` 回退；先灰度手测关键路径 |
| 令牌替换在亮色主题改变渲染 | 局部对比度下降 | 按测试提示的 111 处逐项人工评估；亮色截图比对 |
| 键盘化改造引入焦点顺序问题 | Tab 流程混乱 | 复用命令面板焦点模式；补 a11y 回归与手测清单 |
| Tooltip 被 `overflow:hidden` 容器裁切或遮挡 | 提示不可见 | fixed/portal 定位 + 顶层 `z-index`；在浮层、滚动容器、窄屏内复验 |
| 文字按钮图标化后辨识度下降 | 误操作 | 只改低风险次要操作；主操作保留文字；Tooltip + `aria-label` 双保险 |
| 悬停提示成为唯一信息源 | 触屏/键盘不可用 | 提示只作补充；可访问名称始终存在，关键操作保留文字 |
| 断点合并导致其它宽度回归 | 响应式退化 | 保留 781/1024/1280 三档回归截图；逐档验收 |
