## 0. 决策摘要（用户 2026-11-09 确认）

| # | 决策 | 落地含义 |
|---|---|---|
| D1 | **子画布 = 画板/页** | 不新增“画布组/父画布”层级；一个 `canvas.json` 下的多个画板（board）就是“子画布”，`pages` 作为画板分组/章节。 |
| D2 | **不引入画布套画布** | 保持 ADR-0031 的“一个 canvas = 一个文件夹”模型；`designs/<slug>/` 仍是一级画布。 |
| D3 | **实时 = 板级增量** | Agent/UI 每次写板，只增量刷新受影响画板；不做对象级流式 patch。 |
| D4 | **版本 = 画布级时间线** | 以画布为单位记录版本（文件级 changes + 内容寻址），支持整画布/单板恢复；对象级 diff 放二期。 |
| D5 | **选中加入对话 = 页 + 对象** | V1 先做“当前页/画板”引用，V1.1 补“选中元素”引用；复用现有 `references` 管线，不新造消息通道。 |
| D6 | **边界不变** | 仅 Work、`OAW_CREATIVE_CANVAS` 默认关、`.dc.html` 只读、不写回外部画布、不做多人实时协同。 |

### 1.4 外部参照：baoyu-design（本地构建）

仓库内 `.claude/skills/claude-design` 是 baoyu-design 的本地构建，可作为 3/4/5 的参考实现：

- **一个 canvas = 一个文件夹 + `canvas.json` + 每画板一个 `.dc.html`**；画布内是画板/页，**没有画布套画布**——与 D1/D2 一致。
- **实时**：编辑器 `fs.watch` 画布目录，通过 SSE 把文件变化推给页面，“你写文件，页面立刻显示”（`scripts/server.mjs:532-546`、`:1800`）。这验证了“板级增量”的可行路径。
- **版本**：`history/index.json` 版本号递增，记录 `by: agent/human/system`、`changes: 文件 → 内容哈希 | null(删除)`、`restoredFrom`、`overwrote`；内容按哈希存 `history/objects/`；支持整包/部分恢复。样例 `designs/open-plan-deck/history/index.json` 中 Agent 一轮写 8 个文件只生成 1 条版本。
- **选中/评论**：`comments.json` 把评论锚定到画布/文件/位置，owner 可 “send to agent”，Agent 可 wait。本计划不引入评论线程，但“锚定到板/元素再送 Agent”的思路用于 D5。

## 2. 目标 / 非目标 / 成功标准

### 2.1 目标

1. 一个画布内可创建、切换、重命名、复制、排序、删除多个画板；`pages` 成为可用的分组。
2. 画布工具条提供常驻“画布切换器”，多画布之间来回切换不依赖标签栏。
3. Agent 和 UI 的写板都能实时反映：按 `workspace + slug + boardPath` 路由，只增量刷新受影响板，保留当前板/选中/撤销栈。
4. 当前板/选中元素可作为结构化引用加入对话，Agent 只改引用范围。
5. 画布级版本时间线：一次保存批次/Agent 一轮 = 一条版本；支持文件级 diff、整画布/单板恢复、删除恢复。

### 2.2 非目标

- 不做“画布组/父画布”层级（D2）。
- 不做对象级流式 patch（D3 之外）。
- 不做多人实时协同、评论线程、共享链接。
- 不做对象级 diff（V2 后续；本计划只做文件级）。
- 不做设计系统/组件库/动画/交互原型。
- 不新增前端框架、画布引擎、数据库或运行时依赖。
- 不改地图“AI 画布”语义，不合并模块。
- 不改变 `OAW_CREATIVE_CANVAS` 默认关闭、仅 Work 的边界。

### 2.3 成功标准

- 空画布 UI 新建 3 块板 → 切换/改名/排序/删除 → 刷新后一致。
- Agent 连续写 3 块板，界面 1s 内逐板出现，无需手动刷新；当前选中和当前板不丢。
- 选中板 3 说“标题改大”，只改板 3；选中元素只改该元素。
- Agent 一轮生成 5 板 = 1 条版本；恢复上一版后 5 板内容与顺序正确；删除的板可从版本恢复。
- 关闭开关后入口、工具、API 全部回到基线。

## 3. 需求与验收口径

### 3.1 R-C1 一个画布内多画板/多页

**功能点**

1. 空画布提供“新建画板”（空白/模板），可选择加入哪一页。
2. 画板导航常驻（左侧栏或底部缩略条）：切换、重命名、复制、拖拽排序、删除（软删到 `.trash/`）。
3. 页管理：新建/重命名/排序/删除页；按页筛选；导出顺序仍由 `order` 决定（页只做画布内分组，不参与导出拆分）。
4. 服务端新增 `POST board`、`DELETE board`、`POST board/duplicate`；`PATCH canvas` 支持 `pages` + `expectedRev`。
5. Agent 工具同步：`add_board` 支持 `page`；新增 `duplicate_board`；`delete_board` 走模块软删。

**验收**

- UI 新建 3 板 → 切换/改名/排序/删除 → 刷新后一致。
- Agent 能完成同样的操作；导出板顺序由 `order` 保持，页不改变导出顺序。
- 删除的板进入 `designs/<slug>/.trash/<时间戳>/`，可从版本或 `.trash/` 恢复。
- 页删除不删除板：未指定 `moveTo` 时，板归入第一页；`moveTo` 无效时报 `CANVAS_INVALID`。

### 3.2 R-C2 画布内切换入口

**功能点**

1. 画布工具条常驻“画布切换器”：当前工作区全部画布（标题/更新时间/缩略图）、搜索、最近、新建、导入。
2. 工具条切换器显示当前画布；页标签条显示当前页上下文（不新增独立面包屑组件）。
3. 切换不重复开标签；切回历史会话恢复“上次画布 + 当前板”。
4. 空态/加载/失败态明确；键盘可达。

**验收**

- 3 个画布之间 ≤2 次点击切换；不丢当前板；不重复开标签。
- 画布关闭后仍可从切换器重新打开。
- 切换器不改变右侧标签栏的既有行为（拖拽、溢出、Ctrl+Tab）。

### 3.3 R-C3 板级增量实时

**服务端**

1. 所有写路径（Agent 工具 + HTTP）统一发 `canvas_changed`，补齐 `workspace/slug/scope/boardPath/pageId/revision/actor/runId/action/changedPaths`。
2. `canvas_created` / `canvas_exported` 补齐 `workspace/actor/runId`；前端消费。
3. HTTP 路由通过 `appendEvent` + `/api/agent/events` 全局流广播（该流已有 seq/cursor 与跨标签页 leader 机制，见 `App.jsx:1240-1335`）。
4. 连续事件在客户端按 `workspace + slug` 合并 100–300ms。

**前端**

1. App 维护 `canvasRevisions`（按 `workspace::slug`）与 `canvasActivity`（按 slug/boardPath），替换现有全局 `canvasRevision`/`canvasAgentBusy`。
2. 有 `changedPaths` 时只增量拉这些板；索引变化时重读 `canvas.json`，但保留当前板（仍存在时）与选中。
3. 脏画布不自动覆盖：显示“远端更新：查看差异 / 刷新 / 保留我的”。
4. 顶部状态显示“Agent 正在编辑《板名》”，按画布隔离。
5. 当前会话新建的画布自动开标签；非当前会话不抢焦点（只刷新最近画布列表）。
6. 工具条加“手动刷新”和“最后更新 HH:mm:ss”。
7. 修复 G7（冲突错误码）与 G8（索引 CAS）。

**验收**

- Agent 连续写 3 板，1s 内逐板出现、无需刷新。
- 另一个已打开画布不闪、不重读。
- UI 自己的保存能同步到同工作区其他标签页。
- 有未保存修改时不丢内容；远端更新只提示。
- 断线重连后事件回放能补齐（复用现有 cursor）。

### 3.4 R-C4 选中页/对象加入对话

**功能点**

1. 引用类型新增 `canvas`（见 §4.6），复用现有 `references` 管线与 chip 体系。
2. 入口：当前板“加入对话”、选中元素“让 Agent 修改这个”、右键菜单。
3. chip 显示“画布名 / 板名”；可多引用、可移除（点击 chip 定位回画布列为后续增强）。
4. 服务端把引用解析为结构化上下文（画布摘要、板摘要、选中元素 JSON），并明确提示 Agent 只改引用范围。
5. 消息历史保留引用；刷新/重开后仍可解析。

**验收**

- 选中板 3 说“标题改大”只改板 3；选中元素只改该元素；不误改其他板。
- chip 显示板名/元素 id；多个引用不串；引用失效（板已删）时给出明确提示。
- 引用解析长度受限（建议 ≤4000 字符），不把整块画布塞进上下文。

### 3.5 R-C5 画布级版本时间线

**版本模型**

- 一次保存批次 / Agent 一轮 / 导入 / 删除 / 恢复 = 一条版本。
- 字段：`n / first / at / by / user / runId / summary / changes{path: sha|null} / restoredFrom?`。
- 内容按哈希存 `objects/`，天然去重。
- Agent 同一 `runId` + 10 分钟内合并为一条；UI 同一 actor + 2 秒内合并为一条。
- 保留策略：最近 20 条不删；最多 200 条或 90 天（可配置），超限 GC 未被引用的对象。

**UI**

1. 时间线（按时间倒序，显示 actor/runId）：时间、变更文件数、摘要。
2. 文件级 diff（新增/修改/删除）；对象级 diff 二期。
3. 恢复整画布 / 单板；删除的板可恢复。
4. 恢复前自动留存当前版本。

**兼容**

- 外部 `.dc.html` 永远只读、不写回。
- 可读取并保留 baoyu 的 `history/index.json`（不修改）；自有历史使用 `designs/<slug>/.history/`，与 baoyu 的 `designs/<slug>/history/` 分离。
- 旧板级 JSONL 快照懒迁移到新索引；迁移失败保留旧文件并回退到旧版板级历史。

**验收**

- Agent 一轮生成 5 板 = 1 条版本；恢复上一版后 5 板内容和顺序正确。
- 删除板可恢复；diff 列表准确；历史总量不超配额。
- 兼容画布不写回原文件。

## 4. 数据模型与契约

### 4.1 画布模型（保持 v3 兼容）

不新增目录层级。继续使用：

```text
designs/<slug>/
├─ project/
│  ├─ canvas.json                 # v3 超集：title/kind/rev/pages/boards/order/notes
│  ├─ boards/*.board.json         # 可编辑对象板
│  ├─ assets/                     # 素材
│  └─ legacy/                     # 兼容 .dc.html（原样保留）
├─ exports/
├─ .trash/                        # 板级软删除
├─ .history/                      # 新：index.json + objects/（旧 JSONL 保留）
└─ operations.jsonl               # 操作日志（新增查询入口见 §4.3）
```

`canvas.json` 只做兼容性扩展：

- `pages` 保持 `[{id,name}]`，`order` 表示页顺序；新增 `pages[].collapsed?`（前端偏好，可不持久化）。
- `boards[path].page` 已存在，作为板归属页；缺省归第一页。
- `boards[path].role` 保持 `board|slide`。
- 不把“父画布/子画布”写进 `canvas.json`，避免与外部格式冲突。

### 4.2 页面与删除规则

| 操作 | 规则 |
|---|---|
| 新建页 | 生成 `p<n>`（避开已用 id）；追加到 `pages` 末尾 |
| 重命名页 | 只改 `name`，不改 id |
| 排序页 | 只改 `pages` 顺序；板顺序仍由 `order` 决定 |
| 删除页 | 必须指定 `moveTo`（目标页 id）或默认第一页；不删除板；无其他页时拒绝删除 |
| 删除板 | 文件移入 `.trash/<时间戳>/`；从 `boards/order` 移除；生成版本（changes 中为 `null`） |
| 复制板 | 新文件 + 新路径；元素 id 重新生成；插入到源板之后 |

### 4.3 HTTP API 变更

| 方法/路径 | 变更 | 说明 |
|---|---|---|
| `POST /api/canvas/:slug/board` | 新增 | 创建板：`{path?, title?, page?, template?, elements?}`；原子登记 `canvas.json` + 写板 + 版本 |
| `DELETE /api/canvas/:slug/board` | 新增 | 软删除：`{path, confirmed:true}`；移动 `.trash/` + 移除登记 + 版本 |
| `POST /api/canvas/:slug/board/duplicate` | 新增 | `{path, newPath?, newTitle?, page?}`；复制板 + 重生成元素 id |
| `PATCH /api/canvas/:slug` | 扩展 | 支持 `expectedRev`（索引 CAS）与 `pages` 整体替换；返回新 rev |
| `GET /api/canvas/:slug/history` | 扩展 | `scope=canvas` 返回画布级版本；保留 `scope=board` 兼容 |
| `GET /api/canvas/:slug/history/:n` | 新增 | 单版本详情（changes 元数据，不含内容） |
| `GET /api/canvas/:slug/history/diff` | 新增 | `from`/`to`，文件级 diff（新增/修改/删除 + 行数变化可选） |
| `POST /api/canvas/:slug/history/restore` | 扩展 | `{version:n, paths?:[]}`；省略 `paths` 恢复整画布；保留旧 `{board,id}` 形式 |
| `GET /api/canvas/:slug/operations` | 新增 | 操作日志查询（现有 `listOperations` 已实现但无入口） |

错误码沿用：`CANVAS_*`；新增 `CANVAS_PAGE_NOT_FOUND`、`CANVAS_VERSION_NOT_FOUND`（HTTP 404）。

### 4.4 事件契约扩展

保持事件名不变，只加可选字段；注册表 schema 同步。

`canvas_changed`：

```json
{
  "workspace": "office-workspace",
  "slug": "demo",
  "action": "add_board|patch_board|delete_board|duplicate_board|update_canvas|delete_element|import|export",
  "scope": "canvas|board|list",
  "boardPath": "boards/page-1.board.json",
  "pageId": "p1",
  "changedPaths": ["boards/page-1.board.json", "project/canvas.json"],
  "revision": 3,
  "actor": "ui|agent|system",
  "runId": "run_...",
  "at": "2026-11-09T..."
}
```

约定：

- `scope=board` 时 `revision` 是板 rev；`scope=canvas` 时是画布 rev。
- `boardPath`/`pageId` 在画布级变更时可缺省。
- `canvas_created` 补 `workspace/title/kind/actor/runId`；`canvas_exported` 补 `workspace/actor/runId/jobId`。
- 不新增事件名，避免注册表膨胀；HTTP 路由通过 `appendEvent` 写入全局流。

### 4.5 版本存储

`designs/<slug>/.history/index.json`：

```json
{
  "format": 1,
  "next": 12,
  "base": { "project/boards/a.board.json": "<sha256>" },
  "versions": [
    {
      "n": 11,
      "first": "2026-11-09T06:53:33.634Z",
      "at": "2026-11-09T06:53:33.634Z",
      "by": "human",
      "user": { "id": "local", "name": "jijec" },
      "runId": null,
      "summary": "保存前版本（rev 3）",
      "changes": {
        "project/boards/a.board.json": "<sha256>",
        "project/canvas.json": "<sha256>",
        "project/boards/old.board.json": null
      },
      "restoredFrom": 8
    }
  ],
  "notices": []
}
```

- `objects/<sha256>` 存内容字节；引用计数由 index 计算，GC 只删未被任何版本引用的对象。
- 版本合并：Agent 同 `runId` + 10 分钟；UI 同 actor + 2 秒。
- 旧 `.history/*.jsonl` 懒迁移：首次打开/写入时导入为版本（`by` 取原 `actor`，`changes` 取板路径），原文件保留；迁移失败回退旧板级历史。

### 4.6 选中引用协议

复用现有 `references` 管线，新增 `kind: "canvas"`：

**标记形式**（客户端/服务端 parity）：

```text
@画布[designs/demo/project/boards/page-1.board.json]
@画布[designs/demo/project/boards/page-1.board.json#element=el-title]
```

**结构化字段**：

```json
{
  "kind": "canvas",
  "target": "designs/demo/project/boards/page-1.board.json",
  "range": { "element": "el-title" },
  "label": "规聚汇报 / 03 定位",
  "meta": { "slug": "demo", "boardPath": "boards/page-1.board.json", "pageId": "p1", "elementIds": ["el-title"] }
}
```

**服务端解析**（`server/context.mjs` 新增分支）：

- 校验路径位于当前工作区 `designs/<slug>/project/` 内；
- 读取 `canvas.json` 与目标板，生成 ≤4000 字符的上下文块；
- 明确写出 `slug`、`boardPath`、`elementIds`，并提示“只改引用范围；未选中元素时只改该板”；
- 板已删除/路径非法时返回 `CANVAS_NOT_FOUND`，不静默降级为普通文件。

**前端**：

- `REFERENCE_KINDS` 增加 `canvas`，`REFERENCE_KIND_META` 增加图标/文案（`引用标记.js`）；
- chip 显示 `label`，缺省回退“画布 / 板名”；
- 引用来自画布工具条/选中元素右键菜单，不要求输入栏候选面板支持画布搜索（V1）。

### 4.7 Agent 工具变更

| 工具 | 变更 |
|---|---|
| `canvas_read` | 不变；返回板数据足以让 Agent 按引用定位 |
| `canvas_write` | `add_board` 支持 `page`；新增 `duplicate_board`；`update_canvas` 支持 `pages` + `expectedRev`；`delete_board` 改调模块 `deleteBoard`（软删） |
| `canvas_delete` | `delete_board` 同样走软删；`delete_canvas` 不变 |
| `canvas_export` | 不变（按 `boards` 过滤；`pages` 过滤列为 V2） |
| 工具元数据 | 新增 `duplicate_board` 能力描述；`delete_board` 的 destructive 语义与实现对齐 |

> 白名单仍以 `server/task.mjs` 为唯一事实来源；不新增工具名，只扩展 `canvas_write` 的 action，避免能力契约扩散。

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 事件风暴（Agent 连续写多板） | 前端频繁重读 | 客户端 150ms 合并 + 只拉 `changedPaths` |
| 版本存储膨胀 | 占满 256MB 限额 | 内容寻址去重 + 保留策略 + GC |
| 增量刷新与本地未保存冲突 | 丢编辑 | 脏画布只提示，不自动覆盖；保留当前板/选中 |
| 索引并发写 | 最后写入者获胜 | `PATCH canvas` 加 `expectedRev`；冲突 UI 修复 |
| 页删除误删板 | 数据丢失 | 页删除必须 `moveTo` 或默认第一页；不删板 |
| 引用上下文过大 | 模型上下文膨胀 | 服务端截断 4000 字符；只带选中元素 |
| 兼容画布被误写 | 破坏外部文件 | 写路径只允许 `.board.json`；版本恢复只作用于对象板 |
| 多标签/多窗口 | 状态不一致 | 全局事件流 + BroadcastChannel；手动刷新兜底 |
| 测试只做静态断言 | 运行时 bug 漏网 | 关键路径补真实浏览器人工 E2E；CI 保留模型测试 |
