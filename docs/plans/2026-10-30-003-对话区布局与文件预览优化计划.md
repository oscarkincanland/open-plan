# 对话区布局与文件预览优化计划

> 状态：已实施（待用户验收）　日期：2026-10-30　基线：`69b20004`（v0.13.11 + 地图修复）
> 决策：D1=CodeMirror 6 只读；D2=760px；D3=10 类颜色令牌 + 14% 底；D4=警告 + 二次确认
> 关联需求：R1 文档办公与预览、R2 AI Agent 对话协作、R13 任务中心/产物
> 关联规范：DESIGN §5.6 字体与排版、§5.7 间距与图标、§5.9 文件类型扁平图标
> 用户提出的 4 项：① 对话栏与任务/SSE 编排栏同宽 + 字体与全屏宽度；② 文件树按类型着色图标；③ 预览支持代码源文件（类 VSCode）；④ 粘贴图片进一步优化

---

## 一、现状与证据

### 1.1 对话栏与任务/输入栏宽度不一致

截图里红框可以直接看到：消息正文（含“执行过程”卡）比下方“任务 + 输入框”窄一截，左右边缘都不齐。代码层原因是两套互相冲突的规则：

| 位置 | 现状 | 影响 |
|---|---|---|
| `client/src/styles.css:5986-6010` | `.center-chat-slot .chat-body { padding: 34px clamp(28px, 7vw, 104px) 28px }`；`.msg-main { max-width: 820px }`；`.chat-input { margin: 0 24px 18px }` | 一套居中规则 |
| `client/src/styles.css:8732-8760` | 同选择器又写了一遍：`padding: 34px clamp(20px, 5vw, 72px)`；`.msg-main { max-width: 880px }`；`.msg.user .msg-main { max-width: min(78%, 540px) }` | 后写的覆盖前一套，且数值不同 |
| `client/src/styles.css:687` | `.chat-body { padding: 16px 34px 16px 16px }` | 基础规则左右不对称（右侧 34px 是给滚动条留的） |
| `client/src/styles.css:746` | `.bubble { max-width: 85% }` | 消息宽度随列宽膨胀 |
| `client/src/styles.css:234` | `.app-chat-slot > .chat { max-width: none }` | 主对话槽位不设上限 → 全屏时对话列过宽 |
| `client/src/styles.css:9331-9360` | `.chat-compose > .task-card` 独立宽度 | 任务卡与消息列不共享宽度 |

结论：**消息列（820/880 居中 + 大 padding）与输入/任务列（24px margin，接近满宽）不是同一个内容列**；全屏下 880px 上限又偏宽，所以观感“上面窄、下面宽、整体又太宽”。

### 1.2 文件树图标没有类型区分

- 文件树已经用了 `FileTypeIcon`（`client/src/components/SessionSidebar.jsx:29-35`，使用处 `:1096`），映射来自 `client/src/产物类型.js:7-48`，docx/xlsx/pptx/pdf/html/md/code 都有独立图标名。
- 但 `.file-type-icon` 固定 `color: var(--muted)`（`client/src/styles.css:554-567`），所有类型**同色**；小尺寸（12px）下 doc/xls/ppt/txt 都是“折角纸张 + 小记号”，肉眼几乎分不出。
- 结论：不是缺映射，而是**缺颜色语义**。用户要的“Word/Excel/PDF/PPT/HTML 用不同颜色”正好补这一层。

### 1.3 预览不支持代码源文件

- 服务端 `GET /api/doc/:path` 的类型分派在 `server/index.mjs:1136-1170`：只有 `md/markdown/txt/csv/json` 返回 `kind:"text"`；`html/htm` 返回 `kind:"htmlfile"`（整页渲染）；其余扩展走兜底（不支持预览）。
- `DocViewer` 对 `kind:"text"` 的渲染仍是 Markdown（`client/src/components/DocViewer.jsx:799-802` 的 `.mdview/.markdown-body`）——没有行号、等宽字体、语法高亮，代码里的缩进/空行会被当 Markdown 折叠。
- `.js/.py/.ts/.css/.yml/.sh` 等代码文件目前打不开源码视图；`.html` 只能看渲染页，看不到源码。
- 现有 `产物类型.js` 已把 js/ts/py/sql 标成 `icon:"code"`，说明“识别得到、但预览不到”，缺口在预览分派与渲染器。

### 1.4 粘贴图片现状

- `handleClipboardPaste`（`client/src/components/ChatPanel.jsx:3751-3759`）只取 `clipboardData.items` 里 `kind==="file"` 且 `type` 为图片的项；部分应用（微信/Office/截图工具）只往 `clipboardData.files` 放图，会漏。
- `handleFiles`（`:3712-3745`）对传入文件 `slice(0, 6)`：**第 7 张起静默丢弃**，只提示“跳过 N 个”，用户不知道是数量上限。
- `fileToBase64`（`client/src/api.js:501-526`）已对 >2MB 图片做 canvas 压缩（最长边 1800），但：
  - `canvas.toBlob(callback)` 未指定类型/质量 → 默认 PNG，截图压完仍可能很大；
  - 2MB 以下不压缩；4K 截图（<2MB 但分辨率高）仍按原图发送；
  - 没有方向校正（手机照片可能旋转）、没有去重、没有单张/总量上限。
- 图片同时保留 `dataUrl` 与 `data`（`ChatPanel:3723`），内存双份；消息里 `msg-images` 只显示小缩略图（`:5547`），输入区 chip（`:4357`）没有尺寸/压缩信息。
- 没有“当前模型是否支持视觉”的提示；选了非视觉模型时，图片仍会被发送并可能报错。

## 二、目标

| # | 目标 | 可验收结果 |
|---|---|---|
| P1 | 对话区、执行过程卡、任务卡、输入区**共用同一内容列宽**；全屏不再过宽；字体按内容层级优化 | 1920/1440/1280/1024 下左右边缘对齐（误差 ≤2px）；全屏内容列 ≤760px；正文/代码/元数据字号符合 DESIGN |
| P2 | 文件树按类型着色 | Word 蓝、Excel 绿、PPT 橙、PDF 红、HTML 紫、Markdown 青、代码靛、图片青蓝、压缩包琥珀；明暗主题都可读 |
| P3 | 预览支持代码源文件，类 VSCode 只读查看 | `.js/.ts/.py/.json/.md/.html/.css/.yml/.sh` 可打开；行号、语法高亮、复制、搜索；1MB 文件 <1s |
| P4 | 粘贴图片更稳、更省、更清楚 | 截图粘贴自动压缩、去重、显示前/后大小；上限有明确提示；文本粘贴不受影响 |

## 三、非目标

- 不做代码编辑/保存（v1 只读）；不改 Pi 内核、不执行预览内容。
- 不新增数据库/服务；代码高亮依赖见 D1，需用户确认后才引入。
- 不改附件 100MB 上限、不改音视频策略；不重做整个 ChatPanel 架构。
- 不做虚拟滚动/超大文件（>2MB）源码预览的完整实现（先截断并提示）。
- 不调整左侧栏/右侧面板的信息架构。

## 四、方案

### P1 对话区与任务栏同宽 + 排版

**设计**

1. 引入单一内容宽度令牌（DESIGN §5.7）：
   ```css
   :root {
     --chat-content-w: 760px;   /* D2 待确认：720 / 760 / 800 */
     --chat-gutter: clamp(16px, 4vw, 40px);
   }
   ```
2. 给对话区加一个统一内容列（优先 CSS，不改 DOM 结构）：
   - `.center-chat-slot .chat-body > *`、`.chat-compose > *`、`.chat-input`、
     `.task-card`、`.busy-input-mode`：
     ```css
     width: min(100% - 2 * var(--chat-gutter), var(--chat-content-w));
     margin-inline: auto;
     ```
   - 保留 `.chat-body` 只做纵向滚动与 gap；删除其左右 padding 中的大值，统一由内容列控制。
   - `.msg-main { max-width: 100% }`（容器已经限宽）；`.msg.user .msg-main { max-width: min(78%, 540px) }` 保持不变；`.bubble { max-width: 100% }`。
3. **清理重复规则**：把 `styles.css:5986-6010` 与 `8732-8760` 合并成一套（以较新的 20–72px/880 为基线，改成新令牌），删除另一套，避免以后再漂移。
4. 全屏宽度：`--chat-content-w: 760px`（或 D2 选择值）；宽屏 ≥1600px 可放宽到 800（同一令牌的媒体查询），窄屏 <1100px 用 `100% - 2*24px`。
5. 排版（DESIGN §5.6）：
   - 助手正文 `.flow-markdown/.markdown-body`：14px / 1.75（当前 14/1.8，微调行高；标题按层级 1.35–1.15em，不继承正文字号）。
   - 用户气泡：13px / 1.6（当前 13/1.7）。
   - 代码块/路径：12.5px / 1.65 等宽栈；行内 code 12px。
   - 元数据（时间、模型、工具计数）：10–11px，仅元数据，不用于正文。
   - 段落最大行宽由内容列控制（760px ≈ 中文 50–55 字/行），避免全屏长行。
6. 任务卡/执行过程卡：与消息列同宽；`details` 摘要行内边距不变，只改外层宽度。
7. 不改 DOM 结构也能完成；若要让滚动条不占内容宽度，`.chat-body { scrollbar-gutter: stable }`（验证不产生双滚动条）。

**改动文件（预估）**

- `client/src/styles.css`（主改，合并两套 center-chat-slot、令牌、字体）
- `client/src/components/ChatPanel.jsx`（仅在需要时给 `.chat-body` 加内容包裹层；优先不改）
- `DESIGN.md` §5.6/§5.7（新增内容列令牌与字号说明）

**测试/验收**

- 视觉：1920×1080、1440×900、1280×800、1024×768 四档截图，量测消息列与输入/任务卡左右边缘（≤2px 误差）。
- 组件：`test:a11y`、`test:component-spec`、`test:design-tokens`（不得新增硬编码色值/散值）。
- 回归：长消息、表格、代码块、图片、执行过程折叠、任务卡展开、忙时输入模式都不横向溢出。
- 可复跑脚本：Playwright 读取 `.chat-body` 内首个 `.msg-main` 与 `.chat-input` 的 `getBoundingClientRect()`，断言 left/right 差 ≤2px（新增 `test:chat-layout`，L4）。

### P2 文件类型彩色图标

**设计**

1. `产物类型.js` 的 `EXT_KINDS` 增加 `kind`（语义类别）与 `tone`（颜色令牌名），不改变现有 `icon/label`：
   ```js
   docx: { icon: "doc", label: "文档", kind: "doc", tone: "doc" },
   xlsx: { icon: "xls", label: "表格", kind: "sheet", tone: "sheet" },
   pptx: { icon: "ppt", label: "演示", kind: "slides", tone: "slides" },
   pdf:  { icon: "pdf", label: "PDF",  kind: "pdf", tone: "pdf" },
   html: { icon: "html", label: "网页", kind: "html", tone: "html" },
   md:   { icon: "md", label: "Markdown", kind: "md", tone: "md" },
   js/ts/py/sql: { icon: "code", kind: "code", tone: "code" },
   png/jpg/...: { icon: "image", kind: "image", tone: "image" },
   geojson/shp/kml: { icon: "map", kind: "map", tone: "map" },
   zip/7z/rar: { icon: "package", kind: "archive", tone: "archive" },
   ```
2. 颜色令牌（DESIGN §5.2/§5.3 两层主题各一份，禁止硬编码）：
   - `--file-doc: #2f6fed` 系（Word 蓝）
   - `--file-sheet: #1f8a4c` 系（Excel 绿）
   - `--file-slides: #d9730d` 系（PPT 橙）
   - `--file-pdf: #d64545` 系（PDF 红）
   - `--file-html: #7b4fd6` 系（HTML 紫）
   - `--file-md: #0f8f8f` 系（Markdown 青）
   - `--file-code: #4a5fc1` 系（代码靛）
   - `--file-image: #0e8ea8` 系（图片青蓝）
   - `--file-map: #2f7d4f` 系（地图绿）
   - `--file-archive: #a8770f` 系（压缩包琥珀）
   - 亮色主题全部降饱和/加深一档，保证在浅底上 ≥3:1 对比度（装饰性图标仍要可辨）。
3. `.file-type-icon` 增加 `data-kind` 选择器：
   ```css
   .file-type-icon { width: 20px; height: 20px; border-radius: 5px; }
   .file-type-icon[data-kind="doc"] { color: var(--file-doc); background: color-mix(in srgb, var(--file-doc) 12%, transparent); }
   ...
   .file-type-icon.dir { color: var(--accent); background: transparent; }
   ```
4. 复用范围：文件树、产物弹窗、预览标签、命令面板（都走 `FileTypeIcon`/`artifactTypeInfo`，一处改全局生效）。
5. 图标形状：保留现有线性 SVG；若 `doc` 与 `file` 仍难区分，再补一个“文档内横线”细节（不新增 emoji/字母徽章）。
6. 无障碍：`title` 已含类型文案；图标纯装饰不重复播报（`aria-hidden="true"`）。

**改动文件**：`client/src/产物类型.js`、`client/src/components/SessionSidebar.jsx`（FileTypeIcon 加 `data-kind`）、`client/src/styles.css`、`DESIGN.md` §5.2/§5.3/§5.8。

**测试/验收**

- 新增 `test:file-type-icons`（纯函数：docx→doc/蓝、xlsx→sheet/绿、pdf→pdf/红、pptx→slides/橙、html→html/紫、js→code/靛、未知→file/中性）。
- `test:design-tokens`、`test:icons`、`npm run verify`。
- L4：明暗两套主题截图，文件树中 5 类文件一眼可分。

### P3 源码预览（只读，类 VSCode）

**设计**

1. 服务端分类（`server/index.mjs` doc open 路由）：
   - 新增 `CODE_EXTENSIONS`：`js/mjs/cjs/ts/tsx/jsx/py/sql/css/scss/less/yaml/yml/toml/ini/xml/sh/bat/ps1/java/go/rs/c/cpp/h/md?`（md 仍走 Markdown 预览，另外提供“源码”切换）。
   - 命中返回 `kind:"code"`，携带 `language`（扩展名→语言名）、`content`、`truncated`（>2MB 截断并标记）。
   - 二进制/非文本（图片、zip、office）维持现有分支；不执行、不解析、不写入。
   - 身份校验沿用 `identity` + `Cache-Control: no-store`。
2. 前端新增 `CodeViewer`（懒加载独立 chunk）：
   - 行号、等宽字体、语法高亮、搜索（Ctrl+F）、复制全文/复制路径、自动换行开关、字号 12–14、明暗主题跟随。
   - 只读；无保存/编辑；大文件截断提示。
   - HTML 预览增加「预览 / 源码」切换（当前 `kind:"htmlfile"` 只渲染页面）；Markdown 增加「预览 / 源码」。
   - 其他文本（txt/csv/json）也走 CodeViewer 的纯文本模式（无高亮），替代当前 Markdown 渲染。
3. 依赖决策 D1（需用户确认，AGENTS.md 要求新增运行时依赖先确认）：
   - **A（推荐）CodeMirror 6 只读**：`@codemirror/state` + `@codemirror/view` + `@codemirror/language` + 常用语言包；按需懒加载，gzip 约 200–300KB；行号/搜索/高亮成熟，最接近 VSCode。
   - B 轻量高亮：`highlight.js`（~100KB gzip，按语言按需加载）+ 自写行号/搜索；实现简单，交互不如 CodeMirror。
   - C 零依赖：`<pre><code>` + 行号 + 等宽；无高亮，仅满足“能看源码”。
   - 若选 A/B，需要 `npm install` 并在 `package.json` 记录；不做则走 C。
4. 安全：源码只作为文本渲染；HTML 源码切换不执行脚本；不引入代码运行/终端。
5. 打开入口：文件树、产物卡、命令面板、预览标签均走同一 `open()`；无扩展名文件按文本尝试，二进制探测（NUL 字节）失败则提示用系统打开。

**改动文件**：`server/index.mjs`（分类）、`client/src/components/CodeViewer.jsx`（新增）、`client/src/components/DocViewer.jsx`（分派/切换）、`client/src/App.jsx`（按需加载/标签标题）、`client/src/styles.css`、`package.json`（若 D1 选 A/B）、`REQUIREMENTS.md` R1 验收补一条。

**测试/验收**

- 新增 `test:code-preview`：服务端扩展名分类（js/py/json/css/html/md/未知/二进制）、组件源码契约（行号/高亮/只读/切换）。
- `test:doc-engine`、`test:preview-identity`、`test:design-tokens`、`npm run build`、`npm run verify`。
- L4：分别打开 `.js`（300 行）、`.py`、`.json`（1MB）、`.md`、`.html`；确认行号、高亮、复制、搜索、明暗主题、无脚本执行。

### P4 粘贴图片优化

**设计**

1. 抽出 `client/src/图片处理.js`（纯逻辑，便于 Node 测试）：
   - `clipboardImageFiles(event)`：优先 `items`，回退 `files`；只取 `image/*`。
   - `imageFileName(file)`：无文件名时生成 `粘贴图片-YYYYMMDD-HHmmss.png`。
   - `dedupeKey(file)`：`type|size|lastModified|name`（同一张截图重复粘贴只保留一张）。
   - `limitImages(list, max=8)`：超过返回 `{kept, rejected}`，UI 明确提示“最多 8 张，已忽略 N 张”，不再静默。
   - `compressImage(file, { maxSide=1600, quality=0.85 })`：`createImageBitmap` 校正方向 → canvas → 不透明图输出 `image/jpeg`，带透明通道输出 `image/png`；目标单张 <1MB；返回 `{mediaType,data,dataUrl,originalBytes,compressedBytes}`。
   - 小图（<300KB 且最长边 ≤1600）不重编码，避免无谓损失。
2. UI：
   - 输入区图片 chip 显示缩略图、名称、`原 2.4MB → 480KB`、删除按钮；总数/总大小提示。
   - 粘贴成功 toast：“已粘贴 2 张图片（压缩 62%）”；第 9 张提示上限。
   - 空态/占位提示支持“可直接粘贴截图或拖入图片”。
   - 拖拽遮罩文案补充“图片”。
3. 视觉模型守卫（D4）：
   - 读取当前模型 `vision` 能力；不支持时在 chip 区显示警告“当前模型不支持图片，请切换视觉模型”，发送前二次确认（或直接阻止，按 D4）。
4. 内存与请求：
   - 发送只用 `{mediaType,data}`；缩略图用 `URL.createObjectURL(blob)`，移除时 revoke；不再长期保留两份 base64。
   - 单条消息图片数上限 + 总字节上限（例如 8 张 / 10MB），超限提示。
5. 服务端不改（仍按 images 数组接收）；若后续需要，可在 `/api/agent/prompt` 增加图片数量/体积校验（本轮不做）。

**改动文件**：`client/src/api.js`（`fileToBase64` 或改为调用新模块）、`client/src/components/ChatPanel.jsx`（粘贴/上传/渲染）、`client/src/图片处理.js`（新增）、`client/src/styles.css`（chip）、`DESIGN.md`（输入区附件规范，可选）。

**测试/验收**

- 新增 `test:image-paste`：命名、去重键、数量上限、压缩参数决策（纯函数）；`test:ava-attach` 扩展附件白名单断言。
- L4：从截图工具复制 1/3/9 张分别粘贴；重复粘贴同一张；大图（4K）压缩前后大小；文本粘贴不受影响；非视觉模型提示。
- 验收：单张压缩后 <1MB；9 张被明确拒绝；重复不新增；chip 可删除；输入区不横向溢出。

## 五、实施顺序与门禁

## 八、风险与回滚

| 风险 | 对策 |
|---|---|
| 合并 `.center-chat-slot` 两套规则导致其他布局回归 | 先只做“单一内容列 + 删除旧块”，逐档截图对比；出问题回滚单个 CSS 提交 |
| 760px 在 1024 窄屏过窄 | 断点内改为 `100% - 2*24px`；D2 可调 |
| 彩色图标在亮色主题对比不足 | 亮色令牌加深一档；`test:design-tokens` + 对比检查 |
| CodeMirror 增加包体/加载时间 | 懒加载独立 chunk；首屏不加载；D1 选 C 则无此风险 |
| canvas 压缩在旧浏览器/HEIC 失败 | 失败回退原图并提示；HEIC 暂不支持则明确提示 |
| 图片仍过大导致请求失败 | 单张/总量上限 + 发送前校验；错误信息可操作 |

- 不重做 ChatPanel 的 DOM/状态架构；不改 SSE 协议。
- 不改附件 100MB 策略与音视频处理。
