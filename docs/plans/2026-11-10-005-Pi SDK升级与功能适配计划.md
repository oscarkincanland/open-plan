## 0. 结论先行

### 0.1 一句话结论

**可以升级，但属于“接口兼容、行为需适配”的升级，不是零改动升级。** 项目直接使用的 SDK 导出符号 **0 个被删除**（1.1.0 的 298 个导出 → 1.5.1 的 299 个，仅新增 `formatReadLineRange`），`createAgentSession` 所在 `sdk.d.ts` **完全一致**；但 1.2–1.5 有 4 类行为变更，其中 **3 项必须在代码/测试里显式适配**，另有 6 项需要真实 Run 回归验证。

### 0.2 升级可行性判断

| 维度 | 结论 |
|---|---|
| Node 引擎 | 不变：`>=22.19.0`（本机 Node 24.15，满足） |
| 主入口/导出符号 | 兼容：仅新增 1 个导出，项目使用的 18 个符号全部存在 |
| 核心会话 API | `sdk.d.ts` 无差异（`createAgentSession`/`defineTool`/`ModelRuntime`/`SessionManager`/`SettingsManager` 入口签名稳定） |
| 工具定义 API | `create*ToolDefinition` 签名不变；工具校验器由 TypeBox 改为 pi-schema（**行为变更**） |
| 设置/缓存 | `SettingsManager.inMemory` 可用；**缓存保活默认值 `streaming` → `idle`（行为+成本变更）** |
| 模型/供应商目录 | 项目快照 `Pi内置供应商.json` 为 1.1.0 时代生成（41 供应商/1142 模型，2026-10-12），**升级后必须重建** |
| 会话格式 | 1.1.0 会话应由 1.5.1 向后读取；**反向不保证**（回退需备份） |
| 桌面打包 | `extraResources` 直接打包 `node_modules`，升级后需重建安装包验证体积/asar |
| 综合风险 | **中**（接口低风险、行为中风险、目录/测试需要更新） |

### 0.3 三个必须改的点（不做的后果）

1. **缓存保活默认值**：1.1.0 默认 `cacheWarming: "streaming"`（仅运行中保活），1.5.1 默认 **`"idle"`（Run 之间也保活，最长 30 分钟）**。项目现在在开关关闭时**不写该字段**，升级后会静默继承 `idle`，导致额外的后台请求与费用。→ 必须显式写 `cacheWarming`。
2. **供应商/模型快照过期**：`server/Pi内置供应商.json` 由 1.1.0 的 dist bundle 提取；1.5.1 新增/下线模型、供应商变化，`供应商目录与一键导入测试` 又硬编码了“41 家供应商 / deepseek 17 模型”等断言。→ 必须重建快照并更新测试。
3. **内核版本号硬编码**：`server/Pi运行时管理.mjs` 的 `PI_PACKAGE_VERSION = "1.1.0"` 会经 `/api/status` 展示错误版本。→ 改为从已安装 package.json 动态读取（并保留降级兜底）。

### 4.1 三个 ❌ 项的具体适配方案

**F-06 缓存保活（必须显式）**

现状（`server/Pi运行时管理.mjs`）：

```js
const settingsManager = SettingsManager.inMemory({
  compaction: { enabled: true, reserveTokens: 16384, keepRecentTokens: 20000 },
  ...(RUNTIME_FLAGS.cacheWarming ? { cacheWarming: "streaming" } : {}),
  retry: { ... },
});
```

问题：1.1.0 的 SDK 默认值是 `streaming`；1.5.1 默认值改为 `idle`。开关关闭时省略字段 → 升级后自动变成 `idle`（Run 间保活 30 分钟）。

建议改为显式基线（保持当前行为，不引入新成本）：

```js
cacheWarming: RUNTIME_FLAGS.cacheWarming ? "streaming" : "streaming", // 语义待定，见 §9 决策 3
```

或更清晰：`cacheWarming: RUNTIME_FLAGS.cacheWarming ? "idle" : "streaming"`（把开关升级为“空闲保活”开关）。**推荐先 `streaming` 恒定**，保持 1.1.0 行为；开关含义另立 ADR 决策。

**F-08 供应商/模型快照（必须重建）**

- 当前 `server/Pi内置供应商.json`：`generatedAt 2026-10-12`，41 供应商 / 1142 模型（1.1.0 bundle）。
- 1.5.1 上线新模型/新供应商，快照过期会直接影响：模型下拉、供应商一键导入、`/api/models`、前端选择器。
- 步骤：升级依赖 → 运行 `node scripts/提取Pi供应商目录.mjs`（先 `--check` 看差异）→ 人工抽查新增/删除项 → 提交快照 → 同步更新 `供应商目录与一键导入测试` 的硬编码断言（41、deepseek 17 等，建议改为“按快照实况 + 关键供应商存在”的动态断言）。

**F-16 版本号（必须动态）**

```js
// 旧：export const PI_PACKAGE_VERSION = "1.1.0";
// 新：从已安装 package.json 读取，失败兜底 "unknown"
```

同时更新 `docs`/`/api/status` 展示口径；若 `AGENTS.md §1` 的“1.1.0”仍需保留为历史基线，需在升级完成后由用户确认后修改（AGENTS 修改需确认）。
