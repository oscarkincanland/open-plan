# 2026-11-11-006 画布开关持久化与 Work 空态排版修复

> 状态：已实施（用户直接指令"确保能打开画布/开始修改/修复挤在一起"）
> 基线：v0.13.25（develop）　关联：`AGENTS.md` §4.3、`server/运行开关.mjs`

## 1. 现象与定位

### 1.1 创作画布"时有时无"

- 画布能力由运行时开关 `OAW_CREATIVE_CANVAS` 控制：关闭时画布 API 全部 404、前端过滤 design 标签并隐藏「工作区 → 创作画布」入口。
- 该开关**只读进程环境变量**（`server/运行开关.mjs`），没有配置文件/持久化；服务监督进程 `spawn(server/index.mjs, { env: process.env })` 继承启动它的终端环境，自动重启继续继承。
- 实测时间线：11-10 22:04、22:07 带开关重启 → 画布在；11-11 10:40 一次无环境变量的前台启动（PID 142548，父进程已退出）→ `creativeCanvas=False` 至今，三个工作区 `/api/canvas/list` 全 `not found`。
- 另：前端只在页面加载时读一次开关快照，重启后不刷新会看到旧状态；画布按工作区存 `designs/`，切工作区列表不同属正常。

### 1.2 Work 空态"挤在一起"

- `欢迎卡片` 的智能体建议沿用 `.chat-empty-example` 胶囊样式（`border-radius:999px`、无最大宽度、文本不截断）。智能体描述较长，每个建议占 3–4 行，整屏被撑满；小窗口下最后一行被输入区裁掉，看起来像卡片与输入框叠在一起。
- `model-fallback-chip`（模型自动变化提示）`max-width: 420px` 且不收缩，窄输入框里把工具条顶出框外。

## 2. 修改

### 块 A：开关持久化（`server/运行开关.mjs`、`server/index.mjs`、`scripts/运行开关.mjs`）

- 优先级改为 **环境变量 > `.oaw/runtime-flags.json` > 代码默认**（`.oaw/` 已 gitignore，属本机配置）。
- 新增 `flagSource()` 诊断与 `/api/status.runtimeFlagSources`、`runtimeFlagSourcesFile`（持久化文件路径），排查"为什么这次是关的"。
- 新增 CLI `npm run flags -- list|get|set`，写入持久化文件并提示需重启；`OAW_RUNTIME_FLAGS_FILE` 可指向临时文件（测试用）。
- 本机已写入 `{"creativeCanvas": true}`：清空环境变量重启后验证 `creativeCanvas=True source=file` 且 5 个画布可见。

### 块 B：空态与提示排版（`client/src/styles.css`）

- 智能体建议改两列卡片（≤720px 单列）：左对齐、圆角 `--radius-md`、两行截断（`-webkit-line-clamp:2`），容器 `max-width:680px` 居中。
- `.chat-empty.mode-agent` 顶部留白 40px → 20px、底部 14px，避免最后一行提示被输入区裁掉。
- `.model-fallback-chip` 允许收缩（`flex:0 1 auto; min-width:0; max-width:min(320px,100%)`），文本省略、按钮不换行，不再溢出工具条。

## 4. 限制与后续

- 工具条里「模型被切换为 X」提示本身是**有意保留**的（模型确实被自动切换时不再静默），本次只修溢出；如觉得打扰可加"本会话不再提示"。
- 若希望不写文件也能持久，可后续在设置面板加「创作画布」开关（需走 PRD/DESIGN 与确认）。
- 验证命令 `verify` 对系统内存敏感（vite build 峰值 >1GB）；内存紧张时建议先关闭大应用再跑。
