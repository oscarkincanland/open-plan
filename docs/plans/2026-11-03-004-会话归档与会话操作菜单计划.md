## 0. 结论先行

用户要的两件事，本质是同一处交互收敛：

1. **归档**：会话 header 增加 `archived/archivedAt`，文件不移动、不删除；默认列表隐藏，进入「已归档」视图后可恢复或永久删除。运行中的会话不允许归档（与批量删除的跳过规则一致）。
2. **会话操作菜单**：把当前悬停露出的 5 个小图标（置顶/重命名/分支/冻结/删除）收进行右侧一个 `⋮` 菜单；归档后该菜单变为「恢复/重命名/永久删除」。入口仍是同一个 `SessionList`，左侧栏与对话栏历史抽屉同时生效。

不改会话打开、恢复、fork、SSE 与运行归属逻辑；归档只是 header 元数据 + 列表过滤。

## 1. 现状调查（证据）

### 1.1 会话数据与接口

| 层 | 位置 | 现状 |
|---|---|---|
| header 字段 | `server/index.mjs:2246` `SESSION_LIST_FIELDS` | 只有 `label/pinned/frozen/freezeReason/projectId/cwd/parentSessionId/agentId/threadId`，**没有 archived** |
| header 解析 | `server/index.mjs:3134` `sessionMetaFor()` | 解析 `pinned/frozen/freezeReason/contextSnapshot/...`，未解析 archived |

| 单删/批删 | `server/index.mjs:4368`、`:4403` | 批删对 `running/queued/waiting_user/recovering/cancel_requested` 直接跳过；单删无运行态保护 |

| 菜单组件 | `client/src/components/ContextMenu.jsx` | 固定定位、点击外部/Escape 关闭；**无键盘方向键导航** |

### 1.2 为什么用户感觉“只有一个编辑名称”

当前代码并非只有重命名，而是 5 个按钮全部 `opacity: 0`，只在 hover/focus 时显示（`styles.css:472`、`:6867-6868`）。小图标没有文字，最容易被识别的是铅笔（重命名），所以主观上像“只有编辑名称”。方案不是再加一个按钮，而是把这一排收成一个有文字的 `⋮` 菜单。

### 1.3 现有“归档”语义可复用的部分

- 地图项目归档：`server/index.mjs:869`、`:3655`，只改状态、不移动目录；UI 文案明确“仅移除记录，不删除磁盘文件”（`scripts/AVA附件测试.mjs:75-82`）。
- 事件流归档：是文件切片，与会话归档无关，不复用。
- 会话「冻结」：`frozen/freezeReason/contextSnapshot` 已经存在，语义是保留上下文快照；归档应与之区分：**冻结 = 防止继续写/恢复；归档 = 从默认列表收起**。两者可并存。

### 1.4 影响面

- 列表默认隐藏归档会话后，`GET /api/sessions` 的其他消费者（任务中心打开会话、项目历史、文件关联会话）需要显式选择是否包含归档。当前客户端主要入口是 `App.jsx` 的 `refreshSessions()`；计划先用默认隐藏 + 归档视图单独拉取，避免扩大 payload。
- 归档当前打开的会话：不关闭、不丢消息；只是从列表消失，顶部给一条可撤销提示（或提示去「已归档」恢复）。

## 2. 方案设计

### 2.1 数据与接口

**header 新字段**

```json
{ "archived": true, "archivedAt": "2026-11-03T08:12:00.000Z" }
```

- `archived` 布尔；`archivedAt` ISO 字符串（恢复时清空或保留 `lastArchivedAt` 均可，MVP 只清空）。
- 不移动、不重命名会话文件；不删除消息。
- 加入 `SESSION_LIST_FIELDS`，保证归档/恢复后列表缓存立即失效。

**接口**

| 方法 | 路径 | 行为 |
|---|---|---|
| `POST` | `/api/sessions/:id/archive` | body `{ archived: true }`；归档/恢复。运行中归档返回 `409 { code: "SESSION_RUNNING", error: "会话正在运行，不能归档" }`；恢复不限制运行态 |
| `POST` | `/api/sessions/batch-archive` | body `{ ids: [] }`；逐条归档，返回 `{ archived, skipped, missing }`，运行中跳过，规则与批删一致（P1，可与单条同批实现） |
| `GET` | `/api/sessions?archived=only` | 只返回归档会话，按 `archivedAt` 倒序 |
| `GET` | `/api/sessions?archived=all` | 包含归档（供导出/诊断/兼容） |
| `GET` | `/api/sessions`（默认） | 排除归档；其余过滤与排序不变 |

**缓存**：`cacheable` 条件增加 `!req.query.archived`；`sessionMetaFor` 增加 `archived/archivedAt`；列表 payload 增加这两个字段。归档视图单独请求，不参与主列表热缓存。

**运行态保护**：复用 `listRunSummaries` 的活跃集合（与 `batch-delete` 同一份状态列表），避免“界面归档了、任务还在跑、恢复后状态错位”。

### 2.2 交互

**行右侧 `⋮` 菜单（未归档）**

| 菜单项 | 行为 | 状态 |
|---|---|---|
| 置顶 / 取消置顶 | 现有 `onPin` | 正常 |
| 重命名 | 进入行内输入 | 正常 |
| 归档 | 调用 archive；`toast`「已归档，可在『已归档』中恢复」 | 运行中 disabled，title 说明原因 |
| 从此会话创建分支 | 现有 `onFork` | 正常 |
| 冻结 / 解冻 | 现有 `onFreeze` | 正常 |
| 删除 | 现有确认弹窗 + `onDelete` | danger，与前五项用分隔线 |

**归档视图行内菜单**

| 菜单项 | 行为 |
|---|---|
| 恢复 | `archive(false)`，回到普通列表 |
| 重命名 | 保留（归档后仍可整理名字） |
| 永久删除 | 原删除逻辑 + 确认，danger |

**入口**

- 在 `SessionList` 批量工具条右侧增加「已归档」按钮（带数量徽标），点击切换视图；再点「返回会话」回到默认视图。
- 不把「已归档」塞进 `session-filters`（那是 Run 状态筛选，语义不同）。
- 归档视图复用同一 `renderItem`，只是 `archived` 行换菜单项；不做第二套列表。

**触发与可访问性**

- `⋮` 默认 hover/focus 显示，菜单打开时保持显示；`@media (hover: none)` 下常显。
- 按钮 `aria-label="会话操作" aria-haspopup="menu" aria-expanded`；菜单 `role="menu"`，项 `role="menuitem"`；Escape 关闭并把焦点还给 `⋮`。
- `ContextMenu` 目前只支持点击 + Escape，本计划顺手补最小键盘导航（ArrowUp/Down、Home/End、Enter），避免新增不可访问的菜单。

**当前会话归档**

- 不关闭会话、不清历史；列表隐藏该行；对话区顶部显示一条弱提示「本会话已归档，可在左侧『已归档』恢复」。
- 用户切走后，该会话不在默认列表；恢复后按 `modified` 回到原日期分组。

### 2.3 视觉

- `⋮` 按钮 28×28、透明底、无外框，与 2026-11-03 输入栏/顶栏图标收敛口径一致。
- 菜单宽度 180–220px，字号 13px，danger 项用 `--danger`；分隔线用 `--border`。
- 归档行整体降一级对比度（`--muted`），不改变栅格与行高。

## 4. 验收口径

| 编号 | 场景 | 期望 |
|---|---|---|
| AC1 | 归档普通会话 | 默认列表立即消失；`GET /api/sessions` 不含；`?archived=only` 含 |
| AC2 | 恢复 | 回到原日期分组/置顶区；状态、消息、产物、地图绑定不变 |
| AC3 | 运行中归档 | 接口 409；界面菜单项 disabled 并说明原因；不产生半归档状态 |
| AC4 | 归档当前打开会话 | 对话不关闭、不丢消息；顶部有恢复提示；切走后不在默认列表 |
| AC5 | 永久删除归档会话 | 二次确认；删除后文件不存在；当前会话被删除时行为与现有删除一致 |
| AC6 | `⋮` 菜单 | 鼠标、键盘、触屏均可打开；Escape 关闭并还焦点；菜单项与权限符合上表 |
| AC7 | 列表缓存 | 归档/恢复后 1 次刷新内可见，不出现“刷新后还在/不见了” |
| AC8 | 批量归档 | 运行中跳过并提示；其余全部归档；数量徽标同步 |

## 5. 测试计划

- **纯函数单测**（新 `scripts/会话归档测试.mjs`）：
  - `isSessionArchivable(status)`：6 个活跃状态 false，其余 true；
  - `applyArchivePatch(header, archived, now)`：归档写 `archived/archivedAt`，恢复清空；
  - `filterSessionsByArchive(list, "default" | "only" | "all")`；
  - 排序：归档视图按 `archivedAt` 倒序。
- **静态契约断言**：
  - `SESSION_LIST_FIELDS` 含 archived；
  - `GET /api/sessions` 默认排除、`?archived=only` 分支存在；
  - `SessionSidebar` 只有一个 `.session-actions` 入口且为 `⋮`；
  - 未归档/已归档菜单项齐全；运行中归档 disabled；
  - `App.jsx` 归档不清 `currentSessionId`。
- **手工/浏览器验收**：在 127.0.0.1:3002 用真实会话走 AC1–AC8；重点看右侧画布开/关时会话行宽度与 `⋮` 命中区域。
- **回归**：`npm run verify`；会话相关 `test:startup`、`test:interaction-owner`、`test:session-*`（以 `package.json` 实际脚本名为准）；CI 同步新增步骤。

## 6. 不做清单

- 不移动会话文件到 `archive/` 目录（保持路径稳定，避免恢复/fork/运行归属出问题）。
- 不做自动归档策略（按天数/数量）——需要单独决策与用户确认。
- 不把归档等同于冻结；不自动解冻/冻结。
- 不改会话打开、resume、SSE、fork 的既有逻辑。
- 不新增会话“回收站”二级页面；归档视图就是唯一入口。
- 不做跨工作区批量归档。
