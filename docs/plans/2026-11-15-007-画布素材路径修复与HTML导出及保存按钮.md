# 2026-11-15-007 画布素材路径修复 + HTML 导出 + 显式保存按钮

> 状态：已实施（2026-11-15，用户确认「HTML 单文件内嵌 + 保留自动保存并加显式按钮」）　基线：v0.13.25（develop @ 487b5d37 + 未提交 010/011/012 改动）　需求来源：用户三点提问「画布里的视频是不是播不了？」「画布能否导出 HTML？」「画布上直接改能不能有保存按钮？」

## 1. 现场结论（已实测）

### 1.1 视频播不了 = 真实缺陷（素材路径口径不一致）

- 元素 `src` 按设计是**板文件相对路径**：`server/创作画布.mjs` 的 `validateAssetSrc()` 用 `path.resolve(boardDir, raw)` 校验并**原样保存**。实际数据：`project/boards/vid1.board.json` 里 `src = "../assets/canvas_5x.mp4"`，指向 `project/assets/canvas_5x.mp4`（文件存在，2.3MB）。
- 但素材接口 `GET /api/canvas/:slug/asset` 把 `path` 按**项目根**解析，且 `rel.includes("..")` 直接 400：`server/index.mjs:6589`。
- 实测（本机运行中服务）：

| 请求 path | 结果 |
|---|---|
| `../assets/canvas_5x.mp4`（现有数据） | **400 CANVAS_PATH_DENIED** |
| `assets/canvas_5x.mp4` | 200 `video/mp4` |
| `boards/assets/canvas_5x.mp4` | 404 |

→ 画布里的 `<video>` 和 `<img src="../assets/...">` 全部拿不到文件，所以视频播不了（图片同样受影响，只是用户先注意到视频）。浏览器控制台此前抓到的一批 404（`path=boards/boards/assets/...`）是同一类路径口径问题的另一形态。

### 1.2 导出格式现状

`server/创作画布导出.mjs`：`CANVAS_EXPORT_FORMATS = ["svg", "png", "pdf", "pptx"]`，**没有 HTML**。其中 SVG/PPTX 对 video 只嵌封面图（`svgVideoElement` 回退 `poster`），导出物里视频天然不可播放。

### 1.3 保存现状

已有**自动保存**：本地乐观更新 + 400ms 去抖 + `expectedRev` CAS（`创作画布.jsx` 保存逻辑），工具栏右侧有状态位（`保存中` / `已保存`，L1932-1942），并有冲突与失败提示。**没有**手动「保存」按钮——用户看不到「我改的存了吗」的显式入口。

## 2. 方案

### A. 修素材路径（缺陷修复，必须）

统一「素材 src 相对谁」这一个口径，二选一（推荐 A1）：

- **A1（推荐，改动最小）**：渲染前把板相对路径解析成项目相对路径再拼 URL。前端已有当前板路径（`当前板路径`/`板所属页`），用 `path.posix.join(dirname(boardPath), src)` 归一化后传 `asset?path=`；服务端保持不变（仍拒绝 `..`，安全边界不放松）。
- **A2**：服务端接受 `..` 但按「项目根 + 规范化后必须仍在项目内」校验。会放松入参形态，安全面变大，不推荐。

配套：

- `image` / `svg` / `video` 三种带 `src` 的元素统一走同一个 `素材地址(元素, 板路径)` 解析函数（含 `poster`）。
- 服务端 `svgVideoElement` 导出仍用封面（HTML 导出才会真正嵌视频，见 B）。
- 回归测试：`scripts/创作画布模型测试.mjs` / 新增断言——`../assets/x.png` 在 `boards/` 板里解析为 `assets/x.png`；越界路径仍拒绝；接口 400 不再出现。

### B. 新增 HTML 导出

- `CANVAS_EXPORT_FORMATS` 增加 `"html"`；`创作画布导出.mjs` 新增 `buildCanvasHtml(...)`：
  - 一个自包含 `.html`：每板一段绝对定位 DOM（复用 SVG/文本/图片序列化口径），键盘 ←/→ 翻页、页码、可选打印样式；
  - `image/svg` 内嵌 base64（沿用现有 `resolveAssetAsBase64` 与 `sanitizeSvgMarkup`）；
  - **`video` 用 `<video controls>` 嵌真实视频**（本次用户诉求的核心：导出的 HTML 里视频能播）；
  - 资源打包两种口径（待确认，见 §4）：①单文件（视频 base64 内嵌，体积大但可直接分享）；②引用 `exports/<name>/assets/` 相对目录（体积小，需整个目录一起分发）。
- 导出落盘沿用现有作业与 `exports/` 目录约定（`.jobs.json` 一致），前端导出对话框加一项「HTML · 网页演示（视频可播放）」。

### C. 显式保存按钮

- 工具栏加「保存」按钮（与现有状态位同一区域）：
  - `有脏` 时可用并高亮；点击 = 立即保存所有脏板 + 画布索引（跳过 400ms 去抖），完成后状态回「已保存」；
  - `保存中` 时禁用并显示 loading；失败时按钮旁保留错误文案（现有 `保存错误`）；
  - 快捷键 `Ctrl/Cmd+S` 触发（阻止浏览器另存为），只在画布编辑态生效。
- **保留自动保存**（不动既有 CAS 与冲突处理），按钮只是「立刻存 + 可见反馈」。

## 4. 待确认（影响实现）

1. **HTML 导出打包口径**：单文件（媒体 base64 内嵌，可单文件分享；视频大时文件可能几十 MB）／ 引用 `assets` 相对目录（体积小，需连同目录分发）／ 两者都给（对话框里选）。
2. **保存按钮与自动保存**：保留自动保存 + 加显式按钮（推荐）／ 关掉自动保存、只手动保存。
3. 导出 HTML 的**范围**：全部板 / 当前板（沿用现有导出范围选择即可）。

## 5. 不做清单

- 不改视频编码/转码链路（`.mp4` 已存在且服务端支持 Range，播放依赖的是路径修复）。
- 不改 SVG/PNG/PDF/PPTX 既有导出口径（HTML 是新增格式，不动旧的）。
- 不改画布冲突（CAS）与版本历史机制。
- 不在本次引入画布内的视频编辑（裁剪/音量等）。
