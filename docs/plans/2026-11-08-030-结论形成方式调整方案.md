# 2026-11-08-030 结论形成方式调整（方案 C：必答项 + 自由结构）

> 状态：已实施
> 决策来源：用户 2026-11-08 讨论结论
> 关联：`REQUIREMENTS.md` R3、[ADR 0030](../决策记录/0030-Chat讨论记录由系统自动归档.md)、《会话流前端规范》§5、`server/agent.mjs`、`server/讨论记录.mjs`

## 1. 问题

「结论」此前由提示词强制五个逐字标题（`## 结论 / ## 关键结果 / ## 产物 / ## 验证 / ## 风险与未完成`），实际读起来像填表单：

- 没有开场，一上来就是标题，缺少"同事汇报"的亲和度；
- 纯执行轮次（跑命令、改错别字）也要套五段，形式与内容不匹配；
- 有价值的论证只存在于对话里，事后不可复用。

## 2. 用户拍板的四条

| # | 决策 | 落地 |

| 1 | **方案 C**：必答项清单 + 自由结构；研究/评估/方案对比/审查且结论可复用的轮次写文档，纯执行不写 | `buildOutputPolicyLines()` 重写；PRD R3 重写 |

## 3. 实施内容

### 3.1 提示词（`server/agent.mjs`）

- 最终答复：先 1–2 句人话 → 正文覆盖五项必答（结果结论 / 关键数据或依据 / 产物位置 / 怎么验证的 / 没做完或风险）→ 结构自由（标题用内容词，禁止空模板词）→ 结尾一句下一步建议。
- 新增「结论文档（仅研究型轮次）」条目：落 `回报/YYYY-MM-DD-<主题>.md`，纯执行不写。

### 3.2 Chat 讨论记录归档（`server/讨论记录.mjs` + `server/执行句柄.mjs`）

- `appendChatDiscussion(workspace, { title, question, answer, runId, at })`：`回报/讨论-<会话标题>.md`，一份会话一个文件、按轮追加；首轮写标题与来源说明。
- 收尾接线：`completed && task.mode === "chat"` → 归档；取消/失败不归档；异常只记 `chat_discussion_archive_failed` 诊断，不影响 Run 终态。
