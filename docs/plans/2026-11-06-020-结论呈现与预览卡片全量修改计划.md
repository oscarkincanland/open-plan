## 1. 体检结果：你的结论格式到底怎么样

样本：`.oaw/runs` 最近 150 个 Run 中 69 条有 `finalText`（本地真实产物，未读用户文档正文）。

| 指标 | 实测 | 判定 |
|---|---|---|
| 平均长度 / 中位 | 857 字 / 624 字 | 偏"一段式长文"，非提纲式 |
| 首段平均长度（结论先行） | 89 字 | ✅ **结论先行做得好** |
| 有 `##` 二级标题 | **30%** | ❌ 结构层级不足 |
| 有 `###` 三级标题 | 1% | ❌ 几乎没有子层级 |
| 有 `#` 一级标题 | 0% | ✅ 合理（消息里不该用 h1） |
| 用无序列表 | 41% | 🟡 可用 |
| **用有序列表（1./2./3. 或 一、二、）** | **12%** | ❌ 并列结论几乎不编号 |
| 用表格 | 30% | 🟡 可用 |
| 用代码块 | 4% | 🟡 合理 |
| 出现"结论"字样 | 42% | 🟡 一半的终稿没有显式结论段 |
| 提到产物 | 64% | 🟡 |
| 提到验证/校验 | 65% | 🟡 |
| **提到风险 / 未完成** | **32%** | ❌ 与 PRD R3:132「未完成项或风险」要求差距大 |
| 平均加粗处数 | 2.7 | 🟡 用来代替标题时会破坏层级 |

**四类典型问题（来自真实终稿形态）**：

1. **标题层级缺失**：三段式长文（结论 → 明细 → 下一步），但没有 `##`，读起来是"一大段文字"。
2. **加粗冒充标题**：用 `**改了什么**` 当小标题——没有锚点、没有 16px 层级、无法折叠/TOC。
3. **脏前缀混入结论**：出现 `Final summary.` 连续重复、`进度小结：…本轮无剩余动作，直接给出最终结论。` 这类过程口吻进了终稿。
4. **语言漂移**：个别长任务终稿整篇英文内部推理（13k 字），与"面向用户用用户语言"冲突。

**结论：结论先行合格，结构层级和并列编号明显不足；且渲染层有一个会把"更丰富的结论"吃掉的隐患（见 §3.2）。**

## 2. 根因：不是模型不会写，是提示词不让它写

`server/agent.mjs:70-80` `buildOutputPolicyLines()`：

| 轮次类型 | 现行提示词 | 效果 |
|---|---|---|
| Chat / Review | "先直接说结论，用 1-3 句自然语言即可；**不要输出固定的 Markdown 分段模板**" | 天然没有一二三 |
| Work | "纯问答用 1-3 句；**产生成果时**用简洁但完整的 Markdown：可用小标题 + 要点列表，覆盖做了什么/关键结果/产物/验证/风险；**但不要用固定模板标签**" | 允许但没骨架，且"不要模板"与"要五要素"互相拉扯 → 模型自由发挥，30% 才有标题 |
| 进度结论 | "不要输出 Markdown 标题、加粗、项目符号" | 合理（但没防住进度口吻混进终稿） |

这解释了实测：**Work 轮也不是不会写结构，而是提示词同时说"要五要素"和"不要模板"**，模型只能选一个折中——一段话。

## 3. 目标与设计原则

### 3.1 结论骨架（推荐、非强制）

**Work / Review（有产出或审查结论时）推荐骨架**——

```markdown
## 结论
一句话给判断或结果（首段不超过 3 行）。

## 关键结果
1. 并列结论用有序列表，每条一行结论 + 必要数据支撑
2. 有对比就用表格，不写成长段落

## 产物
| 文件 | 说明 |
|---|---|

## 验证
怎么验证的、验证结果（读了哪份文件/跑了什么检查/关键数字）。

## 风险与未完成
没有就写"无"；有就列 1-2 条并给下一步。
```

规则（写进提示词）：

- **推荐不是强制**：内容不适用可省略对应节；但**不得出现空标题**；
- 并列结论**优先有序列表**（1./2./3.），不要用加粗行冒充标题；
- 加粗只做行内强调，**不能当小节标题**；
- 表格用于 3 项以上对比；代码块只放命令/代码；
- Chat 与 Work / Review **一致**：同一套推荐骨架（用户 2026-11-06 决定）；不再保留"Chat 只给 1-3 句"的旧口径；
- 终稿里**禁止**出现"进度小结 / 本轮无剩余动作 / 接下来我将"这类过程口吻，也**禁止**英文内部推理段落。

### 3.2 渲染层必须修，否则"更丰富的结论"会被吃掉

`client/src/会话流投影.js` `splitCompletionSummary()` 现状（约 362-364 行）：

```js
if (conclusionSection) {
  conclusion = firstParagraph(bodyOf(conclusionSection)); // 只取首段
  removeSection(conclusionSection);                        // 整节从 detail 删除
}
```

**后果**：一旦模型按推荐骨架写 `## 结论` 且有 2 段以上，**第 2 段起会从页面上消失**（既不进结论也不进详细）。
这条不修，"让结论更丰富"的提示词改动会直接导致内容丢失。同类问题：`removeSection(whatSection)` 会整节删除。

### 3.3 预览：DSH 的做法与你的差距

| 能力 | DSH | 你现在 | 计划 |
|---|---|---|---|
| 结论内代码块 | Shiki 高亮 + sticky 代码条 | highlight.js 高亮，无工具条 | P1：语言标签 + 复制 + 在代码预览打开 |
| 图片 | 内联预览 + lightbox | 仅限宽图片，`ImageViewer` 未接 | P1：接灯箱 |
| 文件提及 | 行内代码 → 右侧栏预览 | ✅ 已有（`ArtifactFileChip`） | 保持 |
| 改动文件 | 改动文件卡 + review tab（双栏 diff） | ❌ | P2：改动卡 + 右侧 diff |
| 显式交付 | `present` 卡片（≤4，两列） | ✅ 产物卡（`ArtifactCard`） | 保持 |
| HTML 预览 | **右侧栏页签**（不在对话内弹 iframe） | `DocViewer` 已支持本地 HTML iframe 预览（右侧画布） | P1：从结论里的 `.html` 一键右侧打开；**对话内 iframe 卡列为可选**（需你确认） |

> 注意：DSH **没有**"在对话里弹 HTML 窗口"，它是卡片 + 右侧栏。你要的"弹出来那种感觉"，建议优先做"结论里的文件条 → 右侧预置页签"，比 inline iframe 更安全（iframe 需要 sandbox 且禁脚本）。
