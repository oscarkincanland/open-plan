## 0. 调查结论（2026-11-10 实测）

### 0.1 一句话结论

**技能调不起来不是因为"工作区没依赖"，而是：① 设备上没有可用的 Python 3.10+（只有 QGIS 自带 3.9.5，且不在 PATH）；② 技能 SKILL.md 没写 `requires` 声明，依赖预检给出"假绿灯"（SKILL_DEPS_NONE → ready）；③ 设计好的补救路径（技能广场"安装到工作区"）从未执行，工作区 `.oaw/skill-deps/` 不存在。**

### 0.2 实测证据

| # | 事实 | 证据 |
|---|---|---|
| E1 | `python` / `python3` / `py` 在 PATH 上全部找不到 | PowerShell `Get-Command` 三者均 CommandNotFoundException（2026-11-10） |
| E2 | 唯一的 Python 是 QGIS 3.34.1 自带 **3.9.5** | `C:\Program Files\QGIS 3.34.1\apps\Python39` 存在；`%LOCALAPPDATA%\Programs\Python` 不存在 |
| E3 | 技能 frontmatter 只有 `name` + `description`，**无 `requires`** | `.claude/skills/ultimate-ppt-master-skill/SKILL.md:1-15` |
| E4 | 未声明依赖的技能预检直接返回 ready | `server/技能依赖.mjs:243-245`（`parseRequires` 返回 null → `SKILL_DEPS_NONE`） |
| E5 | 技能真实依赖 15 个 Python 包 + Python 3.10+ | `.claude/skills/ultimate-ppt-master-skill/requirements.txt`（15 项）、SKILL.md Runtime 段、AGENTS.md |
| E6 | 工作区从没走过"安装到工作区" | `office-workspace/.oaw/skill-deps/` 不存在（2026-11-10 探测） |
| E7 | 依赖解析本身支持"设备级安装" | `server/技能依赖.mjs:147-155`：venv 优先，其次 PATH；包检测对解析到的解释器做 `import`（全局 site-packages 算数） |
| E8 | 2026-11-08 修复已覆盖发现/读取/闸门三环 | frontmatter 块标量解析、skills_read 64KB 全文、目录 name-only 兜底、`python *.py` 正则收窄 + `@技能` 白名单通道 |

### 0.3 环 1/2/3 与残留问题的对应

- **环 1（运行时缺失）**：E1/E2 成立——"设备装了 Python"实际是 QGIS 的 3.9.5，技能与预检都无法使用。
- **环 2（依赖无声明）**：E3/E4 成立——审查报告 §6.3 建议的 `requires` 声明机制已实现（D1），但技能包本身从未补声明，预检形同虚设。
- **环 3（安装路径未走通）**：E6 成立——加上审查报告证实本机 pip 直连 PyPI SSL 失败（清华镜像可用），即使点击安装也可能失败。

### 2.1 M1 的 `requires` 块（草案）

```yaml
requires:
  runtime: [{ kind: python, version: ">=3.10" }]
  python: [python-pptx, cairosvg, PyMuPDF, mammoth, markdownify, ebooklib, nbconvert, Pillow, numpy, requests, beautifulsoup4, curl_cffi, google-genai, openai, PyYAML]
  exec: [python]
  network: true
  platform: [win32, darwin, linux]
install:
  python: requirements.txt
```

- 包清单以技能目录下 `requirements.txt` 15 项为准，实施时逐项核对（审查报告 §6.3 曾给出同款清单，仍以文件实读为准）。
- `platform` 中的 win32 是当前实机；技能正文要求 POSIX venv 路径（`.venv/bin/python`）的段落已有"自备 3.10+"兜底，不在本期修改。
- `install` 仅作提示，产品不自动执行（既有 D1 口径）。

### 2.2 预期行为变化（M1 落地后）

| 场景 | 修改前 | 修改后 |
|---|---|---|
| 本机无 PATH Python 时 `skills_read("ultimate-ppt-master")` | 预检 ready（假绿灯），模型读完说明后 bash 调 python 直接失败 | 预检 `blocked / SKILL_DEP_RUNTIME_MISSING`，`<skill_requires>` 明确写"缺少 Python 运行时"，引导走 editorial_pipeline 或请用户装环境 |

- V3 首跑失败：Windows 文件系统大小写不敏感，`findExecutable` 按 PATHEXT 命中 `.EXE`，断言改为大小写无关。

- docx 技能依赖按实读修正（pandoc + npm docx），未照抄审查报告的 python-docx 猜测。

### 5.4 用户侧待办（非代码）

## 6. 风险与未验证项

- **预检变 blocked 的体验代价**：M1 落地后，在用户装好环境前，点名 PPT master 会明确得到"缺 Python 运行时 + 替代方案"，比现在的"假绿灯后脚本失败"更早失败——这是预期行为，但用户感知上会从"跑了但失败"变成"直接说不行"。
- **用户级 powerpoint 技能**在 `~/.claude/skills`（仓库外），修改前需确认该文件存在且用户同意修改。
- **V1 断言依赖磁盘文件**：`.claude/skills` 在 gitignore 中（审查报告 §7），测试以磁盘扫描为准；若技能目录被移动/改名，测试会失败——这是期望的守护行为。
- 未在真实 Run 中验证修复后行为（本计划阶段为文档确认，实施后才跑 V1–V4）。
