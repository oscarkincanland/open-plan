## 1. 背景（审查结论摘要）

1. **结论渲染顺序**：`splitCompletionSummary` 在“有分节但无『结论』分节”时，把首个分节首段提升为 conclusion 并在 detail 之前渲染，导致“一是…”跑到开场白/标题前（可确定性复现）。
2. **产物归属**：docx 属于 cancelled Run，最新回答轮 artifact=0，所以“本轮产物”卡为空；`materialize_skipped`（target_changed_since_stage）静默跳过 `.work/*.md`，源稿未落盘。
3. **模型自动切换**：会话 model_change 链 claude → deepseek-v4.1-flash → deepseek/deepseek-flash → minimax；全局 `oaw_model` 已是 minimax；旧标签页/服务端回退均可能触发。
4. **列表读取慢**：`/api/runs` 峰值 4s、`/api/sessions` 峰值 1.7s，412 run/146MB，高负载下客户端超时会出现“读取失败，已保留上一次可用数据”。

---

## 2. 目标 / 非目标

### 目标

- 结论区按模型终稿的原始顺序渲染，标题不再被段落“越过”；同类结构有回归测试。
- 回答轮能展示“本会话最近产物”，cancelled Run 的产物有明确状态与重试/确认入口；materialize 跳过不再静默。
- 模型回退/切换有持久、可追溯的提示；旧标签页构建版本不一致时主动提示刷新；落地 006 的客户端修复并补服务端回退提示。
- 列表接口在现有数据规模下稳定（P95 明显下降，超时有明确降级），不因瞬时失败清空列表。

### 非目标

- 不重写结论区虚拟列表/渲染架构；不引入新状态库。
- 不改变“Run 产物归属写入(rev)”的既有语义，只补展示与恢复路径。
- 不默认开启任何运行时开关；不引入数据库/服务。
- 不在本计划内做模板库/画布功能（004 另行确认）。

## 3. 修复方案

### 块 A：结论渲染顺序（P0）

文件：`client/src/会话流投影.js`（`splitCompletionSummary`）、`client/src/components/ChatPanel.jsx`（`6797` 附近）、`SummaryBlock`。

- 规则改为：
  - 只有标题以 **“结论”** 开头的分节才提升为 conclusion（保持大字/结论位）；
  - 无“结论”分节时，**conclusion 置空、detail 保留完整原文**（不提升首段、不删除首段）；
  - “做了什么/完成工作/工作内容”分节仍可提取 what，但同样从 detail 原位删节（不影响其余顺序）。
- 结论 + detail 的拼接逻辑改为：conclusion 非空时放在最前（其来源是显式“结论”节，语义正确）；否则直接渲染 detail，不做首段迁移。
- 兼容：老会话（历史 summary 已按旧规则生成）不做数据迁移，渲染时按新规则重算。
- 测试：新增 `scripts/会话结论渲染顺序测试.mjs`（或扩展既有会话流测试）：
  - 有内容词小标题、无“结论” → 顺序与源文本一致；
  - 有“结论”节 → 结论在前，detail 不重复；
  - 无标题纯文本 → 保持原“首段为结论”的既有行为（仅此场景允许）；
  - `numberTopLevelSections` 叠加后 heading 位置仍正确。

### 块 B：产物归属与可见性（P0/P1）

文件：`server/runs.mjs` / `server/artifacts.mjs` / `client/src/components/工作产物面板.jsx` / `client/src/components/ChatPanel.jsx` / `client/src/会话流投影.js`。

1. **回答轮产物兜底**：本轮 `run.artifacts` 为空但正文引用了本会话近期产物时，在“本轮产物”区展示“本会话最近产物”，明确标注“来自前一轮”，不改变台账。
2. **cancelled Run 产物**：在产物面板与行内卡片增加“已取消”状态说明；提供“重新归属/确认”入口（确认后标记为 accepted，仍保留 cancelled 事实）。
3. **materialize 跳过可见化**：`artifact_materialize_skipped` 在 UI 显示为“源稿未落盘（目标在暂存后被修改）”，提供“重试落盘”按钮（调用新接口重放 materialize；仅当目标未再变化）。
4. **写入即登记**：officecli/bash 写入后立即生成 artifact 记录（现状已有）并保证 `run.artifacts` 在 run 结束时刷新（c9abf693 只读不写，自然为 0；不作为缺陷，但要解释）。

接口（如需）：`POST /api/runs/:id/artifacts/:artifactId/retry-materialize`（确认后新增，走审批/只读校验）。

### 块 C：模型切换治理（P0/P1）

落地 [006](2026-11-10-006-模型切换失效与跨窗口污染修复计划.md) 的客户端块（当前工作树已有实现，需确认后完成测试/提交），并补充：

1. **旧标签页检测**：前端定期/加载时比对 `/api/status.build`（或 index.html 资源 hash）与自身 build；不一致时显示“有新版本，请刷新后继续”，并禁止自动改模型。
2. **服务端回退可见**：`agent_model_fallback` / `model_switched` 事件携带 `reason`（user/fallback/queued）、`from`、`to`、`attempt`；ChatPanel 持久横幅（不 2.5s 消失），提供“切回原模型”按钮（需用户点击，不自动回切）。
3. **来源去重**：同一会话短时间多次 model_change（如 13:50:34/38）合并为一条“模型回退链”提示，避免刷屏。
4. **测试**：`scripts/模型切换与会话隔离回归测试.mjs` 扩展：全局偏好不驱动现有会话、sessionStorage 恢复、回退提示持久、旧 build 提示。

### 块 D：列表加载稳定性（P1）

文件：`server/index.mjs`（`/api/runs`、`/api/sessions`）、`client/src/App.jsx`（loadErrors/loadRetry）。

- `/api/runs?fields=summary` 按需读取摘要文件/分页（默认 50，`cursor`）；避免每次全量扫描 412 个 run。
- `/api/sessions` 增加短 TTL 缓存（文件 mtime 变化失效），返回分页/增量；首屏只取最近 N 条。
- 客户端：瞬时失败保留旧列表（已有），连续 2 次失败再显示横幅；重试按钮走同一分页参数。
- 验收：412 run 规模下 P95 < 500ms；SSE/轮询并发时无“读取失败”横幅闪烁。

## 5. 风险与回滚

| 风险 | 对策 |
|---|---|
| 修改结论规则影响历史会话展示 | 只改渲染规则、不迁移数据；逐场景快照测试；可开关回退 |
| 展示“本会话最近产物”造成误归属 | 明确“来自前一轮”标签；不写入台账；可关闭展示 |
| materialize retry 覆盖用户修改 | 重试前校验 hash/mtime；仍变化则拒绝并说明 |
| 旧 build 提示骚扰 | 仅当 API 版本/hash 不一致时提示；提供“本次忽略” |
| 列表分页改变前端行为 | 默认参数保持 50 条；保留旧接口兼容；灰度开关（默认开仅影响性能） |

回滚：各块独立提交，可单独 revert；不改数据结构，不迁移文件。
