| 议题 | 你的决定 | 本计划落点 |

## 1. 目标架构

```
┌ L0 运行宪法（server/智能体运行宪法.mjs，内置只读，版本化）
├ L1 工作区 AGENTS.md（用户可改，Pi 原生上下文加载一次）

└ L3 Skills（简单任务用默认短清单；复杂任务才检索；草稿经用户确认才安装）
```

职责边界：

- **L0 禁止用户编辑**，也不写入工作区文件；设置里只能只读预览。
- **L1 只加载一次**：由 Pi 的 `agentsFiles` 注入，`readMemoryContext` 不再重复读取。
- **L2 只放事实/偏好/经验**，不抄规则；初始化时按交通规划场景预置。
- **Skills 不再全目录注入**；简单任务用默认清单，复杂任务才开发现钩子。

## 2. 归档历史（设置 tab）

### 2.1 位置与交互

- `SettingsPanel.jsx:960-972` 的分类导航新增 `["archive", "归档历史"]`；`settingsSection === "archive"` 渲染 `ArchiveSettingsSection`。
- 该 tab 是归档会话的唯一管理入口：
  - 顶部：搜索（标题/工作区）、筛选（模式 Chat/Work/Review）、归档数量；
  - 列表：标题、模式、工作区、归档时间、最后状态；行内「恢复」「永久删除」；
  - 批量：全选/清空、「批量恢复」「批量永久删除」；
  - 空态：说明“归档不会删除文件和消息，可随时恢复”。
- 单条归档：`SessionSidebar.jsx:262-285` 的悬停按钮收成一个 `⋮`，菜单项为置顶/重命名/归档/分支/冻结/删除；归档行（只在设置 tab 出现）菜单为恢复/重命名/永久删除。
- 批量归档：`SessionSidebar.jsx:300` 的批量工具条新增「批量归档（N）」；与批量删除一样，运行中的会话跳过并提示原因。
- 归档历史里点击标题默认只选中，不直接打开会话；「恢复并打开」作为次级按钮（可选），避免归档会话在用户没察觉时变成当前会话。

### 2.2 数据与接口

header 新增：

```json
{ "archived": true, "archivedAt": "2026-11-03T08:12:00.000Z" }
```

| 方法 | 路径 | 行为 |
|---|---|---|
| `POST` | `/api/sessions/:id/archive` | body `{ archived: true }` 归档 / `false` 恢复；归档运行中会话返回 `409 { code: "SESSION_RUNNING" }` |
| `POST` | `/api/sessions/batch-archive` | body `{ ids: [], archived: true }`；返回 `{ archived, restored, skipped, missing }`；归档时跳过运行中会话 |
| `GET` | `/api/sessions?archived=only` | 只返回归档会话，按 `archivedAt` 倒序；供设置 tab 使用 |
| `GET` | `/api/sessions?archived=all` | 包含归档，供导出/诊断 |
| `GET` | `/api/sessions`（默认） | 排除归档；其余过滤/排序不变 |

实现点：

- `SESSION_LIST_FIELDS`（`server/index.mjs:2246`）加 `archived/archivedAt`，归档后列表缓存立即失效；
- `sessionMetaFor`（`:3134`）解析这两个字段，列表 payload 带上；
- `GET /api/sessions` 的 `cacheable` 条件加 `!req.query.archived`，避免归档视图命中主列表热缓存；
- 复用 `listRunSummaries` 的活跃状态集合（与 `batch-delete` 同一份状态列表）做运行态保护；
- 归档/恢复不移动、不重命名、不删除会话文件，不改消息、产物、地图绑定。

### 2.3 边界行为

| 场景 | 行为 |
|---|---|
| 归档运行中会话 | 禁止，菜单项 disabled + 接口 409；批量归档跳过并提示 |
| 归档当前打开的会话 | 不关闭、不丢消息；设置 tab 可恢复；切走后不在默认列表 |
| 归档已置顶会话 | 保留 `pinned` 字段，但默认列表不显示；恢复后回到置顶区 |
| 归档已冻结会话 | 允许；恢复后仍是冻结状态，不自动解冻 |
| 恢复 | 回到原日期分组；`modified` 不变，不伪造活跃时间 |
| 永久删除 | 沿用现有删除确认；删除当前会话时行为与现有删除一致 |
| 批量删除归档项 | 与批删相同：运行中跳过（理论上归档项不会在跑，但保留兜底） |

### 2.4 前端接线

- `client/src/api.js`：
  - `archiveSession(id, archived = true)`
  - `archiveSessions(ids, archived = true)`
  - `listSessions({ archived: "only" })`（扩展现有 options key 列表，`api.js:208-214`）
- `App.jsx`：
  - `handleArchiveSession(id, archived)` → 调接口 + `refreshSessions()`；归档当前会话不清 `currentSessionId`；
  - `handleBatchArchiveSessions(ids)` → 调接口 + 刷新 + 提示跳过原因；
  - 给 `SessionSidebar` 与 `SettingsPanel` 传 `onArchiveSession / onBatchArchive / onSessionsChanged`；
- `SettingsPanel` 两个渲染点都要传：
  - `App.jsx:2878` 的外部设置模块传 `onSessionsChanged={refreshSessions}`；
  - `SessionSidebar.jsx:1258` 的底部设置弹窗传 `onSessionsChanged={onRefreshSessions}`。
- `ArchiveSettingsSection` 自己拉 `archived=only`，操作后调用 `onSessionsChanged` 并局部刷新；不依赖 `sessions` 主列表。
- `ContextMenu.jsx` 顺手补最小键盘导航（ArrowUp/Down/Home/End/Enter），`⋮` 按钮带 `aria-haspopup="menu"`、`aria-expanded`，Escape 关闭并还焦点。

## 3. 运行宪法与“只读一次”

### 3.1 L0 运行宪法

新增 `server/智能体运行宪法.mjs`：

- `RUNTIME_CONSTITUTION_VERSION = "1.0"`；
- `renderConstitution({ mode })` 返回内置文本（附录 A 为草案）；
- 不读工作区文件、不提供写接口、不出现在设置的可编辑项里；
- 在 `server/agent.mjs` 的 `agentsFilesOverride` 中作为**第一个**上下文条目注入，路径用只读虚拟标识（不落盘），例如 `(builtin)/runtime-constitution.md`。

设置 → 「项目设置与记忆」底部增加只读卡片：版本、生效范围、“运行宪法由产品内置，不可编辑”；不提供输入框/保存按钮。

### 3.2 只加载一次：上下文文件选择

Pi 的 `loadProjectContextFiles` 会从 `cwd` 一路向上加载每一级目录的 `AGENTS.md`（`resource-loader.js:116`、`:165-191`）。当前默认工作区 `office-workspace/` 在仓库内，所以仓库根研发宪法会被加载。修法：

新增纯函数 `server/上下文文件.mjs`：

```js
export function selectAgentsFiles(files, { workspace, agentDir }) {
  // 保留：agentDir 全局 AGENTS.md；workspace 自身 AGENTS.md；合成 L0；.agent-context.*
  // 丢弃：workspace 之上、且不属于 agentDir 的祖先 AGENTS.md（研发宪法）
}
```

- `agent.mjs:1355-1395` 的 `agentsFilesOverride` 改为：
  1. 先放 L0 合成条目；
  2. 用 `selectAgentsFiles` 过滤后的 L1（工作区 AGENTS.md）；
  3. 再放 agentDir 全局规则；
  4. 最后追加 `.agent-context.<thread>.md`（本轮工作区/当前文件/记忆摘要）。
- 如果工作区本身就是仓库根，仓库根 `AGENTS.md` 属于 workspace 自身，**保留**（这是用户显式选择用研发宪法当项目规则）。
- 去重按 realpath，避免 Windows 大小写/分隔符导致同一文件两次。

### 3.3 去掉记忆摘要里的重复 AGENTS.md

`server/agent.mjs:1005-1063` 的 `readMemoryContext` 目前会读 `<workspace>/AGENTS.md` 放进 `rules`，而 L1 已经由 Pi 注入一次。修改：

- `readMemoryLayers` 保留 `memory/*.md` 的归类逻辑；
- `readMemoryContext` **不再拼接** `## 工作区准则（AGENTS.md）`，只输出项目信息/偏好/经验/其他；
- `.agent-context` 的「工作区记忆」段改名为「项目记忆（不含项目规则）」；
- 系统提示词（`agent.mjs:1388-1389`）改为：“工作区规则已作为 `AGENTS.md` 上下文加载一次；不要再用 read 重复读取同一文件；记忆段只含 memory/*.md。”
- 保留回退开关 `OAW_NATIVE_CONTEXT_FILES`：关闭时才按旧行为把 AGENTS.md 放进记忆摘要，避免极端运行形态丢规则。

### 3.4 诊断

- 新增一次性事件 `context_files_resolved`（runId、workspace、files[{path, source}]、constitutionVersion），用于回答“这轮到底读了哪份规则”；
- 事件注册表补登记；测试断言同一路径只出现一次；
- 设置里可显示“最近一轮上下文文件”只读列表（可选，P1）。

### 3.5 单次读取验收

- 在临时工作区放 `AGENTS.md`，内容写唯一标记 `RULES_MARKER_7f3a`；
- 解析本轮实际注入的 agentsFiles + `.agent-context`，断言：
  - `RULES_MARKER_7f3a` 只出现 1 次；
  - 仓库根研发宪法的唯一标记不出现；
  - L0 宪法版本出现 1 次。

## 5. 技能策略：简单默认，复杂才开钩子

### 5.1 简单 vs 复杂

新增 `server/任务复杂度.mjs` 纯函数 `estimateTaskComplexity({ text, task, references, attachments, mode })`：

| 信号 | 分值 |
|---|---|
| 有输出意图（文档/表格/PPT/报告/图表/地图） | +2 |
| 附件 ≥1 | +1/个（上限 2） |
| 结构化引用 ≥1 | +1/个（上限 2） |
| 文本含“多份/批量/完整/方案/研究/对比/全流程” | +1 |
| 有 `workflowId` | +2 |
| 预计工具调用 ≥5（沿用现有计划触发条件） | +1 |
| Review 模式 | +1 |

- `score ≤ 2` → `simple`；`score ≥ 3` → `complex`；
- 返回 `{ level, score, reasons }`，写入 `planTaskCapabilities` 的 `complexity` 字段；
- 纯函数，单测覆盖边界。

### 5.2 简单任务：默认技能清单

- `TOP_SKILLS_IN_PROMPT = 8` 不变；默认优先级从 `lark-*` 改为本项目常用（最终以实际安装为准）：

```
docx, pptx, xlsx, pdf, officecli, baoyu-echarts, frontend-design, ultimate-ppt-master-skill
```

- 简单任务提示词：“本轮是简单任务：只使用默认技能清单中的技能，不要调用 `skills_search`；用户显式 `@技能` 除外。”
- 不注入技能卡，不增加上下文预算。

### 5.3 复杂任务：技能发现钩子

- `planTaskCapabilities.routing.skills`：
  - 简单任务 → `default`；
  - 复杂任务 → `discover`；
  - 用户显式 `@技能` / `workflowId` → `preflight`（现有行为）。
- `discover` 时：
  - 系统提示词要求“先 `skills_search` 一次（limit ≤5），只对前 1–2 个真正匹配的 Skill `skills_read`，每轮最多 2 次”；
  - 服务端可预先给出 ≤3 张技能卡（名称 + 40 字描述 + “用 skills_read 加载”），预算 ≤600 字节；不注入 SKILL.md 正文；
  - 事件 `skill_search`、`skill_read`、`skill_suggested`。
- 设置开关（项目设置 → 项目设置与记忆）：
  - 「技能策略」：`auto`（简单默认 / 复杂检索，默认）/ `always`（总是检索）/ `off`（不自动检索，只认 `@技能`）；
  - 「技能草稿」：`off`（默认）/ `complex`（仅复杂任务允许生成草稿）。
- 持久化：扩展 `DEFAULT_PROJECT_SETTINGS`（`server/项目管理.mjs:98-112`）字段 `skillsPolicy`、`allowSkillDrafts`，旧项目自动补默认值。

### 5.4 复杂任务：创造 Skills 的钩子（必须用户确认）

- 新增 `skill_draft` 工具，只在 `allowSkillDrafts === "complex"` 且本轮 `complexity === "complex"` 时动态注入；
- 行为：把草稿写到 `<workspace>/.oaw/skill-drafts/<slug>/SKILL.md`，**不写技能库**；
- 校验：`name` slug、`description` ≤200 字、正文 ≤20KB、frontmatter 完整；不接收可执行附件；
- 用户确认链路：
  1. 草稿生成后事件 `skill_draft_created`；
  2. SkillsManager 增加「草稿」区，展示草稿正文与来源任务；
  3. 用户点「安装到技能库」→ 二次确认 → `POST /api/skills/drafts/:slug/install` 复制到 `AGENT_DIR/skills/<name>`；已存在时默认拒绝，需显式覆盖；
  4. 安装成功事件 `skill_installed`。
- 明确禁止：模型直接写 `AGENT_DIR/skills`、直接修改既有 Skill、自动安装。
- 该能力涉及工具白名单/审批，按 AGENTS.md §4.3 需补一条 ADR（建议 0022）后再实施。

### 5.5 引用口径统一

- `server/context.mjs:90` 解析 `#技能[...]`；`server/index.mjs:4694` 解析 `@技能[...]`；`ChatPanel.jsx:1197` 插 `#技能`，`:1647` 又生成 `@技能`。
- 统一为一个解析器：`#技能` 为主，`@技能` 兼容归一；`task.skills` 结构化传递；SkillsManager「调用」写入本轮 task payload，不只插文本。

## 9. 风险与不做清单

| 风险 | 对策 |
|---|---|
| 过滤祖先 AGENTS.md 误伤“仓库当工作区” | 只过滤 workspace 之外的祖先；workspace 自身始终保留；诊断事件可见 |
| 初始化覆盖用户内容 | 只写缺失文件；已有文件一律跳过；默认工作区只执行一次并记录版本 |
| 归档接口改变 `/api/sessions` 默认返回 | 默认排除归档是契约变更，更新 PRD/DESIGN 与调用方；提供 `archived=all` 兼容 |
| 复杂任务技能检索增加延迟 | 最多 1 次搜索 + 2 次读取；技能卡 ≤600 字节；用事件度量 |
| 草稿污染技能库 | 草稿只在 `.oaw/skill-drafts`；安装必须二次确认；禁止模型直写技能库 |
| 运行宪法与提示词漂移 | 条款在代码常量；测试断言关键句；文档只解释，不复制整段 |
| Pi 升级改变上下文加载行为 | 锁定版本；`selectAgentsFiles` 单测；升级时跑上下文诊断 |

**不做**：

- 不新建第二个根目录 `AGENT.MD`/`AGENTS.md`；根文件继续只做研发宪法。
- 不在左侧栏新增「已归档」视图（归档历史只在设置 tab）。
- 不自动归档、不做按天数/数量的归档策略。
- 不把归档做成“移动文件到 archive 目录”。
- 不允许用户编辑运行宪法；不提供写接口。
- 不默认开放模型直接写技能库；不执行 SKILL.md 脚本。
- 不把全量 Skill 目录重新注入每轮上下文。
