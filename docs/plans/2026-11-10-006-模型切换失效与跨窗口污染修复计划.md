### 1.2 根因 A（主因）：全局模型偏好跨窗口共享 + 恢复竞态回切

模型偏好 `oaw_model` 存 **localStorage**——同一浏览器 profile 的所有窗口/标签页共享：

1. [App.jsx:764](file:///d:/Claude code文件/office-agent-web/client/src/App.jsx#L764)：`selectedModel` 初始化直接读 `localStorage("oaw_model")`；
2. [ChatPanel.jsx:2350-2356](file:///d:/Claude code文件/office-agent-web/client/src/components/ChatPanel.jsx#L2350-L2356)：`selectedModel ≠ model`（会话 runtime 上报的模型）时**自动调用 `changeModel(selectedModel)`**——把会话 runtime 真的切过去；
3. 用户切模型 → [changeModel](file:///d:/Claude code文件/office-agent-web/client/src/components/ChatPanel.jsx#L2372-L2394) → `applyModel` 写 `oaw_model`（L2361）。

由此产生的污染场景（全部成立）：

| 场景 | 过程 | 用户感知 |
|---|---|---|
| **两个同事/两个窗口共用同一浏览器 profile** | 窗口 A 切模型 → 写 `oaw_model` → 窗口 B 刷新/切会话/新建会话时 ChatPanel 重初始化（effect 依赖 threadId）→ `selectedModel`（App 级，也读 `oaw_model`）= A 的选择 ≠ B 会话真实模型 → effect 自动 `changeModel` → **B 的会话被切成 A 的模型** | B："我的模型自己变了"；A："我切了怎么 B 那边没效果" |
| **单人单窗口，切换后刷新页面** | 切换成功（runtime=新模型）→ 刷新 → `selectedModel` = `oaw_model`（=新模型）vs 会话 runtime 恢复=会话模型 → 若两者不同 → effect 回切 | "刚才切好的，刷新又变回去了" |
| **会话缓存丢失放大** | 会话模型缓存 `threadCacheRef` 是**内存级**（ChatPanel L2334），刷新即丢 → 初始化 `preferred` 落到 `saved`（全局偏好）→ 显示 + 回切双污染 | 刷新后模型显示错 |

## 2. 修改方案

### 块 1：会话模型优先，切断"全局偏好自动回切"（核心修复）

- [ChatPanel.jsx:2350-2356](file:///d:/Claude code文件/office-agent-web/client/src/components/ChatPanel.jsx#L2350-L2356) effect 增加用户意图闸门：
  - `changeModel` 拆分出**用户显式切换**路径（模型选择器 onPick、设置面板默认模型）与**外部同步**路径（App 级 selectedModel 恢复/初始化）；
  - 只有用户显式切换才允许触发对会话 runtime 的 `setAgentModel` 调用；`selectedModel` 因页面加载/跨窗口变化产生的差异**只对齐显示，不回切 runtime**；
  - 实现上用 `userModelIntentRef`（onPick 时置位、effect 消费后清除），effect 命中闸门时仅 `setModel(selectedModel)` 对齐显示。
- [App.jsx:764](file:///d:/Claude code文件/office-agent-web/client/src/App.jsx#L764) 保留读取 `oaw_model`（它继续承担"新会话默认模型"语义，见决策点 D1），但初始化值不再作为对既有会话的切换指令。

### 块 2：会话模型按窗口持久化，刷新后不丢

- 新增 `thread → model` 映射存 **sessionStorage**（`oaw_thread_model_v1`）：
  - sessionStorage 按**浏览上下文（窗口/标签页）隔离**——天然规避跨窗口污染（决策点 D2）；
  - 写入时机：`changeModel` 成功、`model_switched(effective=now)`、`applyModelForSession` 收到会话上报模型；
  - 读取时机：ChatPanel 初始化 `preferred = cachedModel(内存) || sessionStorage(thread) || saved || default`，替换现有 `threadCacheRef` 的内存级兜底。

### 块 3：切换结果提示持久化

- fallback/失败提示不再自动消失：`modelMsg` 常驻显示在模型触发器副标题（`model-control-current small`），直到用户下一次显式操作；"已切换为 X"成功提示保持短时（4s）不变；
- fallback 后模型按钮副标题显示 `回退 · {model}`，用户一眼可见当前实际生效模型。

### 块 4：回归测试

- 新增 `scripts/模型切换与会话隔离回归测试.mjs`（`npm run test:model-switch`）：
  - 静态契约：effect 用户意图闸门存在、sessionStorage 会话模型缓存读写点齐备、fallback 提示不自动消失；
  - 服务端契约：`/api/agent/model` 两段式 spec 成功、三段式（错误拼法）返回 500 的行为不变（沿用隔离实例实测脚本模式）。

## 3. 验收口径

- 同一浏览器双窗口：A 切模型后，B 窗口**已打开会话的模型不变**；B 新建会话默认模型 = 全局偏好（`oaw_model`，语义见 D1）。
- 单窗口：切换 → 刷新页面 → 会话模型保持用户选择，不回切。
- 运行中切换：提示排队 → 本轮结束 → `model_switched(now)` → 模型按钮更新为新模型。
- fallback：按钮副标题持续显示回退结果与原因，不再 2.5s 消失。
- `npm run test:model-switch`、`test:ava-composer`、`npm run verify` 通过；`test:ui-guard` 既有失败不新增。
