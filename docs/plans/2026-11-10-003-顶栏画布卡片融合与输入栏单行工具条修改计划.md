## 1. 调研结论（三处割裂的根因）

### 1a 顶栏与对话区割裂

- 顶栏 `.center-content > .topbar`（[styles.css:9200-9206](file:///d:/Claude%20code文件/office-agent-web/client/src/styles.css#L9200-L9206)）是**贴边通栏**：全宽 `--panel-bg` 实底 + `border-bottom`，无圆角。
- 而下方对话区在 002 计划后已是**内缩 10px 的圆角卡片**（`.center-chat-slot { padding: 0 10px 10px }` + `.chat` 圆角 + 1px 边框）。
- 同屏出现"通栏实底条 + 内缩卡片"两种形态：宽度不对齐、圆角不连续、边框重复（顶栏下边框 + 卡片上边框），即用户说的"割裂"。

### 1b 预览页签栏未融合 + 三栏间隙偏宽

- 画布结构：`.app-canvas-slot`（版面底色，左右 padding 10px）→ `.canvas-tabbar`（页签行，[styles.css:12910-12920](file:///d:/Claude%20code文件/office-agent-web/client/src/styles.css#L12910-L12920)：自绘 `color-mix` 底 + `border-bottom`，**不在卡片内、无圆角**）→ `.app-canvas-body`（002 计划的圆角卡片）。页签行浮在版面底色上，与卡片呈两段式，同样割裂。
- 三栏间隙（可见底色空隙）：
  - 侧栏↔中间：resizer 5px + 中间槽左 padding 10px = **15px**；
  - 中间↔画布：中间槽右 padding 10px + resizer 5px + 画布槽左 padding 10px = **25px**；
  - resizer 是 5px 透明 flex 项（[styles.css:269-277](file:///d:/Claude%20code文件/office-agent-web/client/src/styles.css#L269-L277)）。
  - 两侧不一致、整体偏宽，卡片之间空隙过大显得松散。

### 1c 输入栏工具条换行与收纳缺失

- `.chat-toolbar` 使用 `flex-wrap: wrap`（[styles.css:6691](file:///d:/Claude%20code文件/office-agent-web/client/src/styles.css#L6691)）：容器变窄时工具**换行成多行**，破坏"一张卡片"的整体感。
- 自适应收纳不完整且判断基准错位：
  - 容器查询（≤560px，[styles.css:6737-6740](file:///d:/Claude%20code文件/office-agent-web/client/src/styles.css#L6737-L6740)）只收纳了模式切换的文字标签；
  - 上下文环文字标签、审批模式文字走的是**视口媒体查询**（≤520px，[styles.css:6766-6771](file:///d:/Claude%20code文件/office-agent-web/client/src/styles.css#L6766-L6771)）——但输入框实际宽度由三栏布局决定，与视口宽度解耦，收纳时机不准；
  - 模型触发器：模型名已有 145px 截断（[styles.css:6808](file:///d:/Claude%20code文件/office-agent-web/client/src/styles.css#L6808)），但第二行"供应商 · 深度"（`small`）无截断、无收纳，长供应商名（如"OpenCode Go · 深度"）占宽明显。

## 2. 修改方案

### 块 1：顶栏融合为对话卡片的"卡头"（决策点 D1，推荐 A）

**方案 A（推荐，纯 CSS，DOM 不动）**：
- `.center-content > .topbar`：`margin: 10px 10px 0`（与对话卡片同宽对齐）、四边 1px 边框（去掉 border-bottom）、顶部 `--radius-xl` 圆角、底色 `--panel-bg`；
- `.center-chat-slot > .chat`：顶部圆角归零、去掉顶边框（center 布局恒有顶栏，卡片体始终紧跟卡头）；
- 结果：视觉上成为一张复合卡片——顶栏是卡头（标题 + 状态 + 团队 + 搜索），会话流是卡身。
- map 模式下同一套规则自动生效（顶栏与窄对话列同宽成卡）。

**方案 B（不推荐）**：DOM 把顶栏移进卡片内部。效果相同但要重排 `preview-maximized`、map 模式、玻璃皮肤等十余处祖先状态选择器，风险与收益不成比例。

### 块 2：画布页签行融合为预览卡片的"卡头"

- `.canvas-tabbar`：与块 1 同规格——顶圆角 `--radius-xl` + 四边边框（无下边框）+ `--panel-bg`，去掉自绘 `color-mix` 底；
- `.app-canvas-body`：顶部圆角归零、去掉顶边框，与页签行拼成一张卡；
- 同步检查 `.app.browser-fullscreen .app-canvas-slot`、`.preview-maximized`、≤820/768px 覆盖层断点的边角口径，保证全屏/覆盖态不出双圆角或缺口。
- 说明：PPT/浏览器查看器**自己内部的工具行**（播放/缩放/保存模板等）是查看器功能条，本次不收敛。

### 块 3：三栏间隙收紧统一（决策点 D2，推荐 A）

- 中间槽与画布槽的左右 padding 由 10px 收到 **4px**，resizer 保持 5px：
  - 中间↔画布：25px → **13px**；侧栏↔中间：15px → **9px**；
- 卡片底部 padding 10px → 8px；
- 结果：三张卡片（侧栏、对话卡、预览卡）以一致的窄间隙并排，割裂感明显下降。
- 备选：更紧（padding 2px → 9px/7px）或保持 10px 只统一两侧（15px/25px→不动）。

### 块 4：输入栏工具条恒单行 + 分级收纳（决策点 D3，推荐 A）

- `.chat-toolbar` 改 `flex-wrap: nowrap` + `overflow: hidden`，spacer 允许收缩到 0，工具条**任何宽度下保持一行**；
- 收纳分级（全部改为**容器查询**，替换现有 ≤520px 视口媒体查询，以输入框实际宽度为准）：

| 输入区宽度 | 收纳动作 |
|---|---|
| ≤600px | 模型第二行（供应商 · 深度）隐藏；审批模式文字隐藏（留图标）；模式切换文字隐藏（沿用现有 560 规则并统一到 600） |
| ≤520px | 上下文环的百分比/token 文字隐藏（迷你环保留）；模型名截断上限随宽度收缩（145px → 约 110px） |
| ≤440px | 模型触发器收纳为"供应商徽标 + 模型名（截断）"，隐藏思考程度小字与多余间距；添加/审批/上下文/模型/新建对话全部只剩图标 |

- "类似卡片页的效果"：输入区本就是一张卡（本轮目标 chip + 输入框 + 工具条），本次把工具条分隔线由 `dashed` 改为细实线、收紧工具条与输入框的间距，强化整卡一体感；
- 各控件原始语义全部保留（title/aria 不变，悬停仍可看全名）。
