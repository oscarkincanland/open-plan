## 2. 两个问题的定性

### 2.1 "渲染结论时把 md 文件渲染了"——是有意的产物引用 chip，非缺陷

终稿正文里模型提到交付物文件名时，渲染层生成 `artifact-inline` 文件 chip（文件名 + 大小，可点击打开）；md 文件**没有**内嵌预览/iframe/全文复制。这是产物引用设计。若你不想要这种 chip，另行确认后我再调整。

### 2.2 "终稿没有分点"——模型没写 `##` 标题，编号无从生效

编号（一、二、三）只对终稿里**已有的二级标题**编号；模型输出纯段落/列表时不会凭空分点。OD 那轮终稿有 4 个 `##` 小节，所以有编号 + 目录。若希望"每轮结论强制分节"，需要在系统提示层约定模型输出格式（另立需求，不在本计划）。

## 3. 图片内嵌 FAIL 的根因与修复

**根因**：MarkdownBody 的 `img` 组件直接使用模型写的路径作为 `<img src>`——工作区相对路径被浏览器解析成站点根路径 URL（如 `http://127.0.0.1:3002/回报/截图/xxx.png`），服务端无此路由 → 破图。而项目已有完整的文件服务链路：`normalizeLocalFileHref`（链接→工作区相对路径，扩展名白名单含 png/jpg/jpeg/gif/webp）→ `buildDocUrls({cwd, relativePath}).raw`（→ `/api/doc/<rel>/raw?cwd=...`）。

**修复（最小侵入）**：

| # | 文件 | 改动 |
|---|---|---|
| 1 | `client/src/components/MarkdownBody.jsx` | 新增 `cwd` prop（并入 handlersRef）；`img` 组件：`normalizeLocalFileHref(src)` 命中 → 剥离 cwd 绝对路径前缀 → 以 `buildDocUrls({cwd, relativePath}).raw` 作为展示 src；未命中（外链 / data: URL）或无 cwd → 原 src 直通。灯箱复用改写后的 URL |
| 2 | `client/src/components/ChatPanel.jsx` | `SafeMarkdown` 增加 `cwd` 透传；会话流内全部 SafeMarkdown 调用点（v3 终稿、兜底、非时间线终稿、时间线 text、lifted 小节、SummaryBlock）传 `cwd={workspace}` |
| 3 | `scripts/会话流排版回归测试.mjs` | 补 2 条源码契约：img 走 `normalizeLocalFileHref` + `buildDocUrls(...).raw`；调用点带 cwd |

**不做**：DocViewer / 任务中心等非会话流场景的图片改写（后续按需）；`<a>` 链接改写（已有产物 chip 机制）；服务端改动。

## 4. 端到端验证中另发现的两个独立异常（本计划不修，需单独立项）
