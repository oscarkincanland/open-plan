## 0. 结论先行

1. AVA 对话模块是“对话优先”的桌面客户端形态：左侧会话/工作空间，中间轮次消息流，输入区承载队列、目标、语音、附件、模型与 Agent 切换，右侧工作面板与画布可并存。
2. 当前 Open Plan 是“文档/地图工作台优先”的三栏形态：左侧项目/文件/能力，中间文档画布，右栏对话。两者不是同一信息架构，不能按“逐像素复刻”理解对标。
3. 按本文口径共梳理 **90 个可验证功能条目**：当前**完全实现 22 项、部分实现 38 项、未实现 30 项**。其中真正影响对话可信度的 P0 缺口集中在队列与压缩状态：压缩中仍可发送、停止后未展示保留队列数、QueueDock 不能逐条编辑/删除/提升、前端队列与服务端队列语义未统一。
4. 未实现项分为三类：
   - **可直接补齐（P0/P1）**：队列逐条管理、消息编辑/分支/重新生成、GoalBar、Links 页签、草稿持久化、推理等级全档位、历史 50 条分页、`#` 提及、Schema 提问卡、会话按工作区分组等。
   - **需结构性适配（P2，首发内可选）**：上次 Agent 继承、欢迎页个性化、工作区菜单、画布文件树/新会话/代码/网页、视频音频附件、`@` 智能体提及。
   - **与 PRD/架构冲突（暂缓或不做）**：Team/SOLO 多人协作、Plan 模式、`/swarm`、终端页签、语音输入、定时任务、工作面板与画布常驻并存。
5. 首发建议范围（P0 + P1 + 部分 P2）约 **113.5 人天**；按 20% 测试与回归余量计约 **136 人天**。按 2 前端 + 1 后端、13 周（2026-10-28 至 2027-01-26）约 195 人天毛容量，留有约 59 人天缺陷与波动缓冲。
6. 语音、定时任务、工作面板/画布并存建议放到首发后独立迭代；Team、Plan、`/swarm`、终端必须先补决策记录，且当前不建议纳入路线图。

### 1.3 限制与假设

- AVA 文档是终端用户使用指导，不是工程规格；未给出 API、事件 schema、数据库结构、时延/吞吐指标。本文只能按“可观察行为”对标。
- 文档声明“界面元素名称、快捷键、交互行为均与 2026-10-19 的代码保持一致”，但未提供源码；因此 AVA 侧细节以其文档与截图为上限。
- 当前代码行号基于 v0.11.55；实施后行号会漂移，应以“文件 + 符号名 + 行号区间”共同定位。
- 本文不把“未实现”等同于“必须实现”。与 PRD 非目标或工程宪法冲突的条目，明确标注“需 ADR/不建议”，不排入首发。
- 工时按“熟悉本仓库的 1 名前端或后端工程师”的有效人天估算，含自测，不含跨团队等待、评审与发布窗口。

## 2. AVA 功能全景与量化规则

### 2.1 信息架构

```text
┌───────────────┬──────────────────────────────────────────┬─────────────────────┐
│ 左侧边栏       │ 对话区                                    │ 右侧面板             │
│ SOLO / Team   │ ChatHeader：标题/搜索/面板/画布/侧栏       │ WorkPanel（可开关）   │
│ 一级导航       │ MessageList：轮次、分页、TurnRail          │  ├ TodoPanel         │
│ 会话列表       │ QueueDock：排队/插话                      │  ├ Links             │
```

### 2.2 量化与交互规则

| 规则 | AVA 规定 | 当前项目对应 |
|---|---|---|
| 会话列表分批 | 每批 20 条，显示“加载更多（剩余 N 条）” | 全量返回，无分批（`server/index.mjs:3695`） |
| 队列预览 | 单行截断，超过 200 字符省略 | 无逐条预览（`ChatPanel.jsx:3770-3776`） |
| 历史分页 | 每页 50 条，游标分页，加载后视口不跳顶 | 前端一次窗口 80 条，服务端尾部窗口 360（`ChatPanel.jsx:80`、`index.mjs:3776-3785`） |
| TurnRail 显示 | 消息 ≥ 2 轮且窗口宽度 ≥ 900px | 设置项控制，无轮次/宽度门槛（`ChatPanel.jsx:3730`、`ChatTimeline.jsx:117-129`） |
| 上下文用量 | used / max tokens，余量不足警示色 | 有占比环与 60/85% 观感阈值（`ChatPanel.jsx:5365-5445`） |
| 推理等级 | off / low / medium / high / xhigh / max / 跟随默认 | 服务端 7 档，前端仅 low/medium/high/max（`ChatPanel.jsx:89-94`、`agent.mjs:698-717`） |
| 附件方式 | 选择器、粘贴、拖拽；图片/视频/音频/任意文件 | 选择器 + 图片粘贴 + textarea 拖拽；仅图片与文档白名单（`ChatPanel.jsx:3220-3254`） |
| 画布最大宽度 | 窗口宽 − 对话区最小宽度 − 工作面板宽度 | Resizer 固定 min/max，无对话最小宽度联动（`App.jsx:1859-1861`） |
| 目标状态 | active/paused/blocked/max_turns/budget_limited/complete | 无长期目标（`task.mjs:184` 仅单轮 goal） |
| 提问表单 | schema 驱动文本/选择/文件上传 | 仅问题 + 快捷选项 + 自由文本（`agent.mjs:2618-2700`） |
| 欢迎页快捷卡 | 后端个性化，2 列 | 静态三模式示例（`ChatPanel.jsx:257-273`） |
| 消息操作 | 复制、编辑用户消息、助手消息 fork、末轮 regenerate | 仅复制、用户消息重发（`ChatPanel.jsx:4877-4889`） |
| 会话运行标识 | 旋转加载图标 | 状态点 + 跑马灯（`SessionSidebar.jsx:190-229`） |
| 会话时间 | 相对更新时间 | 相对/绝对时间函数（`SessionSidebar.jsx:64-79`） |
| 队列计数 | “N 条排队消息”折叠头 | 待执行/待注入计数条，无折叠头（`ChatPanel.jsx:3770-3776`） |

> 性能指标说明：AVA 文档未给出首字延迟、SSE 吞吐、消息渲染帧率等数值。本文的性能验收沿用 Open Plan 既有的 N3 指标与 `test:first-token-latency`、`test:stream-budget`、`test:perf-budget`，要求新增功能不造成显著回退（首字延迟 p95 回退不超过 10%，长会话滚动不出现持续掉帧）。

### 4.3 结构性冲突专题

#### 4.3.1 三栏工作台 vs AVA 对话优先

- 当前 `DESIGN.md:21-22` 明确“桌面式 Web 工作台：左侧栏 + 中间画布 + 右侧对话栏，三栏可拖拽”。
- AVA 的会话列表、工作空间、新建会话、用户栏都在左侧，消息流占主区，右侧才是面板/画布。
- 若完整复刻 AVA 布局，会推翻 `DESIGN.md` 的信息架构与大量 `App.jsx` 布局状态。建议：**不做整体换位**，只在现有右栏补齐 AVA 的“对话内能力”（QueueDock/GoalBar/Links/TurnRail/欢迎页），把会话分组与工作区菜单放进现有历史抽屉/项目卡片。这样能把冲突从“高”降到“中/低”。

#### 4.3.2 单用户本地服务 vs Team

- `AGENTS.md:9-15` 明确本地优先、单服务、无数据库/消息队列/微服务；`REQUIREMENTS.md:42-49` 明确不做多租户 SaaS、账号计费、组织权限、多人实时协同。
- Team 模式需要账号、成员、群聊、权限、消息广播与冲突解决，属于新产品形态，不是对话模块增量。
- 结论：**不纳入本次对标实施**；如未来要做，先立“多用户隔离与团队协作”ADR，按内网团队版 → 桌面节点 → SaaS 的顺序推进（已有 `docs/多用户隔离与桌面端路线梳理.md` 可复用）。

#### 4.3.3 Pi 线性 JSONL vs 消息级分支

- 当前会话文件是 `.规聚会话/<uuid>.jsonl`，首行 header + Pi entries（`index.mjs:2007`、`:3702-3723`）；entries 有 `parentId`，但 chat 视图按扁平数组返回（`:3764-3830`）。
- 当前 fork 复制整份 JSONL（`:3382-3410`），不按 `sourceMessageId` 截断；前端传 null（`App.jsx:1191-1194`）。
- Pi 已提供会话树读取/导航（`agent.mjs:3502-3536`、`index.mjs:3963-3988`），可作为 regenerate 的基础；但 chat 历史必须先按活跃 leaf 过滤，否则旧分支会和新分支一起显示。
- 结论：消息编辑/fork/regenerate 不是“加按钮”，而是**消息历史模型升级**；必须与 CF12/CF13/CF14 一起设计，不能分散实现。

#### 4.3.4 三模式 vs Plan/Swarm

- `task.mjs:10` 的 `TASK_MODES` 是唯一事实来源；`AGENTS.md:17-25` 规定只暴露 Chat/Work/Review；`REQUIREMENTS.md:47` 明确不宣称官方 plan mode。
- `/swarm` 可以复用 `子代理编排器.mjs`，但 AVA 的“多智能体协同”是对话级编排，需要新的角色协议、汇总协议与 UI，不应伪装成 Pi 原生能力。
- 结论：Plan/Swarm 若要做，必须走 ADR，并明确“项目 Harness 能力，不是 Pi 原生”；本次不排期。

## 6. 全量迭代修改计划

### 6.1 迭代假设

- 周期：I0 为 1 周（决策与基线），I1–I6 每 2 周，共 13 周。

### 8.2 关键假设

1. AVA 的“工作空间”约等于当前“项目 + 工作区目录”的组合；对标时按“工作区目录”优先、项目分组其次处理。
2. AVA 的“智能体”约等于当前 `AgentMarket` 的 Agent + 项目 `agentProfile`；当前没有会话级绑定，故按“未实现”计。
3. AVA 的“供应商:模型”与当前 `provider/model` 视为同一唯一标识语义，仅展示格式不同。
4. AVA 的“画布”是右侧内嵌画布，当前是中间文档画布 + 右侧工作产物画布；对标时按右栏能力优先，不要求整体换位。
5. 工时估算不含产品/设计/评审/发布值守；若团队规模不同，按 §5.6 容量公式换算。
