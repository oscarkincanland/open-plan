# 工作区画布浏览器式整合计划

> 状态：已实施（有偏差，待用户验收）　日期：2026-10-31　分支：`feature/workspace-canvas`
> 关联需求：R1 文档办公与预览、R5 会话管理、R8 主题/个性化与视觉、R13 任务中心/产物与成果验收
> 关联规范：`AGENTS.md`、`DESIGN.md`、`docs/规范/架构规范.md`、`docs/规范/代码规范.md`、`docs/规范/功能验证测试规范.md`
> 实施记录：[2026-10-31-001-工作区画布浏览器式整合实施记录.md](2026-10-31-001-工作区画布浏览器式整合实施记录.md)

## 一、背景与问题

右侧目前已经是一个画布容器，但实际使用中仍表现为多个独立栏，主要原因有四个：

1. **多个独立开关**：`previewOpen`、`browserPanelOpen`、`filesTabOpen`、`newchatTabOpen` 各自维护打开状态，关闭一个不会关闭其他，容易留下“关不干净”的栏。
2. **双面板模式**：`dualPaneActive` 在宽屏下把工作产物与浏览器并排渲染，右侧实际变成两栏。
3. **两级页签**：外层是“工作产物 / 浏览器 / 文件树 / 新会话”，内层又是“预览 / 改动 / 产物 / 链接 / 子代理”，信息架构重复。
4. **宽度不统一**：每个页签使用不同的 CSS 宽度变量（`--preview-w` / `--browser-w` / `--objects-w` / `--workflows-w`），切换页签会跳宽度，且宽度未持久化。
5. **文件树不识别目录**：右侧“文件树”页签直接过滤 `isDir`，只显示当前目录文件；服务端 `/api/files` 与左侧文件页已经支持目录导航。
6. **链接与任务摘要位置零散**：链接是内层页签，任务摘要没有独立视图，与“产物/改动”的关系不清晰。
7. **新会话语义容易误解**：当前“新会话”页签实际是新建当前工作区的独立 thread 并切换主对话，不是并排第二个聊天窗口。

## 二、拍板决策

### 2.1 链接

**决定：并入“工作产物”，不单独占一级标签。**

工作产物内部结构：

```text
工作产物
┌ 任务摘要卡 ─────────────────────────────┐
│ 状态 / 结论 / 验证 / 未完成项 / 风险       │
└────────────────────────────────────────┘
[ 产物 ] [ 链接 ]
```

- 摘要卡使用现有 Run 数据（`completion`、`summary`、`verificationStatus`），不新增后端接口。
- 链接复用现有 `LinksPanel`，只移动位置，不改数据结构。
- 不新增“链接”一级标签，也不做右侧链接抽屉。

理由：链接与产物都属于“会话产出与来源”，放在同一页签内比单独开页更符合心智，也避免一级标签膨胀。

### 2.2 文件树

**决定：做成画布右侧可收起抽屉，文件夹优先，支持进入子目录与面包屑返回。**

- 文件树不是一级标签，也不替代左侧“文件”页。
- 标签栏最右侧提供文件夹图标，切换抽屉。
- 抽屉内部自己维护当前目录，直接调用现有 `/api/files?dir=...`，不改变左侧文件页的 `currentDir`。
- 第一版支持“进入目录 + 上一级 + 面包屑”；第二版再做“原地展开/折叠”的懒加载树。
- 点击文件作为 `doc` 标签打开；文件树本身不产生标签。
- 左侧“文件”页继续负责上传、删除、排序、项目文件管理。

理由：文件树是预览的导航器，不是独立工作内容；放进预览画布更符合使用路径，也解决当前看不到文件夹的问题。

### 2.3 侧边对话

**决定：本轮不做真正的并排聊天。**

- `+` 菜单保留“新建对话”；沿用现有 `handleNewSession`：在当前工作区创建一个独立 thread，并切换主对话。
- 旧会话仍保留在历史列表；历史、草稿、产物互相独立。
- 不出现“侧边对话”假入口。
- 真正的并排侧边对话（第二个 `ChatPanel`、多 Runtime、多 SSE、审批归属）单独排期，不并入本次画布整合。

理由：并排聊天不是布局问题，而是会话/Runtime/事件归属问题；与画布标签重构捆绑会显著放大风险。

### 2.4 补充决定

- **任务摘要**：放在工作产物顶部，不单独开一级标签。
- **终端**：当前产品没有终端面板，本轮不引入。
- **对象栏 / 领域工作流**：仍作为运行时开关控制的可选标签保留，不删除。
- **文档标签**：最终提升为一级标签，形成浏览器式标签栏。
- **布局档位**：移除 50% 档，只保留“默认 / 最大化”两态；宽度由拖拽决定。
- **关闭与收起**：标签 `×` 关闭视图；右上角 `⌄` 收起画布但保留标签；关闭最后一个标签才真正收起。

## 三、目标信息架构

```text
┌ 工作区画布 ───────────────────────────────────────────────┐
│ [📄 规划报告.docx ×] [📦 工作产物 3 ×] [🌐 浏览器 ×] [+] [⌄] │
│                                                          │
│  主视图                                       ┌ 文件树 ┐ │
│  （文档 / 工作产物 / 改动 / 浏览器 / 对象 / 流程）│ 📁 项目 │ │
│                                               │ 📁 数据 │ │
│                                               │ 📄 ...  │ │
│                                               └────────┘ │
└──────────────────────────────────────────────────────────┘
```

- 右侧只有一栏画布，一个宽度 `--canvas-w`，一个主拖拽条。
- 文件树抽屉宽度 `--canvas-side-w`，单独拖拽；窄屏改为覆盖层。
- 顶部为浏览器式标签栏：可关闭、可排序、可横向滚动、可溢出收纳。
- 关闭当前标签后自动选中相邻标签；不再出现“关了一个还有另一根独立栏”。
- 标签体保持挂载、CSS 显隐，切换不丢 DocViewer / 浏览器状态。

## 四、标签模型与交互

### 4.1 标签类型

| 标签类型 | 实例 | 标题 | 打开方式 | 关闭行为 |
|---|---|---|---|---|
| `doc` | 多实例 | 文件名 | 打开文件、点击产物、文件树 | 关闭当前文档，切相邻标签 |
| `artifacts` | 单例 | 工作产物 | 任务完成、`+` 菜单“任务摘要” | 关闭后切相邻 |
| `changes` | 单例 | 改动 | `+` 菜单、查看改动 | 关闭后切相邻 |
| `browser` | 单例 | 浏览器 | `browser_*` 工具、`+` 菜单 | 关闭后切相邻；本轮不再自动弹开 |
| `objects` | 单例 | 对象 | 对象栏开关打开时 | 关闭后切相邻 |
| `workflows` | 单例 | 工作流 | 领域工作流开关打开时 | 关闭后切相邻 |
| `subagent` | 多实例/临时 | 子代理 | 点击子代理卡片 | 关闭即移除 |

- `files` 不是标签，是右侧抽屉。
- `newchat` 不是标签，是 `+` 菜单动作。
- `links` 不是标签，是工作产物内部段。
- `summary` 不是标签，是工作产物顶部摘要卡。
- `doc` 按 `workspace + relativePath` 去重；文件 revision 更新时刷新原标签，不重复开新标签。
- 单例标签重复打开时只激活，不创建第二份。
- 标签上限 12 个；超出时提示先关闭部分标签。

### 4.2 加号菜单

点击 `+` 弹出菜单，结构参考浏览器“打开新视图”：

```text
搜索文件名或命令…                  Ctrl/Cmd+P
────────────────────────────
任务摘要
文件
浏览器
代码变更
对象栏          （仅对象栏开关打开时）
领域工作流      （仅领域工作流开关打开时）
────────────────────────────
新建对话
```

- 搜索框复用现有命令面板或 `/api/files/search`，不新增后端。
- “任务摘要”打开工作产物并滚动到摘要卡。
- “文件”切换右侧文件树抽屉。
- “浏览器”打开/聚焦浏览器标签。
- “代码变更”打开/聚焦改动标签。
- “新建对话”调用 `handleNewSession`，创建当前工作区独立 thread 并切换主对话。
- 不显示“终端”死入口。

### 4.3 标签操作

- 点击切换；`×` 关闭当前标签；中键关闭；`Ctrl/Cmd+W` 关闭。
- 关闭当前标签后自动选中右邻；没有右邻选左邻；为空则画布收起。
- 右上角 `⌄` 收起画布，保留标签；顶栏开关重新打开时恢复上次激活标签。
- 标签可拖拽排序；超出宽度横向滚动，右侧提供“更多标签”菜单。
- 标签最大宽度限制，标题省略；hover 显示完整路径。
- 未保存文档显示 dirty 点，关闭前确认（DocViewer 暴露 `onDirtyChange`）。
- 标签栏支持键盘：左右箭头切换、Home/End、Delete 关闭、关闭后焦点归位。

### 4.4 自动打开与焦点守卫

保留现有行为并改为标签激活：

- 打开文件：新增/激活 `doc` 标签。
- 任务完成/产物更新：激活 `artifacts` 标签；用户正在输入或查看其他文件时只记录 `artifactNotice`，不抢焦点。
- 文件变更：刷新已打开文档的 revision；不主动切换标签。
- 浏览器活动：激活 `browser` 标签；用户本轮手动关闭后只亮活动徽标，不自动重开。
- 子代理卡片：新增/更新临时 `subagent` 标签。
- 用户最近 10 秒内手动切换过标签时，自动打开不得覆盖用户选择。

## 五、状态与持久化

新增 `client/src/画布状态.js`，把画布逻辑从 `App.jsx` 抽出：

```js
canvas = {
  open: true,
  width: 420,
  activeTabId: "doc:...",
  tabs: [
    { id, kind, title, icon, payload, closable, dirty }
  ],
  side: { kind: "files" | null, width: 260 }
}
```

核心操作：

- `openCanvasTab(kind, payload)`：单例去重；文档按工作区与相对路径去重。
- `closeCanvasTab(id)`：移除后选右邻，没有右邻选左邻；为空则画布收起。
- `collapseCanvas()`：只隐藏，不清空标签。
- `reorderCanvasTab(from, to)`：拖拽排序。
- `loadCanvasState(workspace)` / `saveCanvasState(workspace, state)`：按工作区持久化。
- `canvasTabTitle(tab)`：统一标题与图标。

持久化键：

| 键 | 内容 |
|---|---|
| `oaw_canvas_v2` | 按工作区保存标签 kind/id/标题/payload、激活标签、抽屉状态 |
| `oaw_canvas_w` | 画布宽度（320–760px） |
| `oaw_canvas_side_w` | 文件树抽屉宽度（200–340px） |

迁移规则：

- 旧 `oaw_workspace_tab`、`oaw_dual_pane` 只读一次后忽略；双面板偏好直接废弃。
- 恢复标签时校验文件存在；缺失的文档标签丢弃。
- 只持久化标签身份，不持久化文档正文。
- 恢复后若标签为空，画布保持关闭，不显示空面板。

### 5.1 状态替换表

| 旧状态 | 新状态 |
|---|---|
| `previewOpen` | `canvas.open` |
| `browserPanelOpen` | `browser` 标签是否存在 |
| `filesTabOpen` | `canvas.side.kind === "files"` |
| `newchatTabOpen` | `+` 菜单动作 |
| `workspaceTab` | `canvas.activeTabId` 对应的 kind |
| `previewTab` | 工作产物内部段或独立标签 |
| `dualPanePref` | 删除 |
| `previewLayout` | `canvas.maximized`（默认/最大化两态） |

## 九、风险与回滚

| 风险 | 处理 |
|---|---|
| 文档标签从 DocViewer 内部提升到画布，可能影响文档状态/刷新 | Phase 1/2 先不动 DocViewer；Phase 3 单独提交，保留 `hideTabBar` 兼容；必要时回滚该提交回到内部标签 |
| 画布状态迁移导致刷新后标签丢失 | 纯函数 `画布状态.js` + 单测；恢复时校验文件存在；旧键只读不写 |
| 自动打开抢焦点或回归 | 保留 `artifactNotice`、浏览器手动关闭、10 秒手动优先；补测试 |
| 测试大面积改写 | 删除双面板测试、重写画布测试、更新链接/浏览器/启动/对话流断言，与对应功能提交一起提交 |
| 标签过多导致内存增长 | 标签上限 12；只挂载已打开标签；超出提示关闭 |
| 窄屏/浏览器全屏/最大化互相冲突 | 断点与全屏规则统一到画布容器；手工矩阵覆盖 |
| 当前工作区存在并行未提交改动 | 从当前分支拉独立 worktree/分支实施；不混入并行会话改动 |

回滚策略：

- Phase 1–5 各自独立提交，可单独 revert。
- Phase 3 是最高风险项，回滚后仍保留 Phase 1/2 的单画布与扁平标签。
- 后端无改动，无需数据迁移回滚。
