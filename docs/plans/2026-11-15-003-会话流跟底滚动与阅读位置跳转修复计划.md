# 2026-11-15-003 会话流跟底滚动与阅读位置跳转修复计划

> 状态：已确认（2026-11-15，用户「还有一个问题，回到对话的底部的时候，为什么还要跳转呢？几轮对话之后还得跳转？」）　基线：v0.13.25（develop @ 487b5d37 + 未提交 010/011/012 改动）　需求来源：用户现场反馈

## 1. 现象

用户在会话里回到底部（手动滚动或点「回到底部」）后，视口仍会继续跳；几轮对话之后每次回到底部依旧跳。

## 2. 取证与根因

**根因一：自动跟随其实是「一次接一次的平滑动画」。**

- `client/src/styles.css`：`.chat-body { scroll-behavior: smooth; }`（动效基线，`动效治理测试` 锁定）。
- `ChatPanel.jsx` 跟底定时器（60ms）用的是：
  ```js
  el.scrollTo({ top: el.scrollHeight, behavior: "auto" });
  ```
- 按 CSSOM View 规范，`behavior: "auto"` 会取元素的 CSS `scroll-behavior` 计算值——这里是 `smooth`，于是**每次跟底都是平滑动画**。
- 浏览器实测（`client-2jc5ynvu` 会话、`.chat-body`）：
  - `getComputedStyle(el).scrollBehavior === "smooth"`；
  - `el.scrollTo({top: 0, behavior: "auto"})` 后**同一帧内 `scrollTop` 不变**（仍是 924.375），证明它不是瞬时定位，而是被 CSS 接管成了动画；
  - 把 inline `scroll-behavior` 临时设为 `auto` 再滚动，则同步生效。
- 流式期间 `messages` 每 ~16ms 变一次，跟底每 60ms 触发一次动画；每一次新动画都会从当前半途位置重新开始 → 视口持续「追」底部，观感就是一直在跳；点「回到底部」的平滑动画同样会被下一帧内容打断。

**根因二：阅读位置恢复被重复「武装」。**

`ChatPanel.jsx` 的会话水合 effect 依赖 `[historyMessages, historyThreadId, threadId]`，每次都执行：
```js
const savedScroll = scrollPositionsRef.current.get(threadId);
pendingScrollRestoreRef.current = (savedScroll != null && !hydratedIsLive) ? savedScroll : null;
```
刷新/补拉历史（`historyMessages` 变化）会重跑该 effect，用 `scrollPositionsRef` 里的旧值**重新武装**一次恢复。用户已经滚到底部或读到别处后，下一次水合又把他拽回旧位置——即「几轮之后还在跳」。

## 3. 修复方案（最小侵入，前端 3 处）

### 3.1 自动跟随改为瞬时定位 — `ChatPanel.jsx`

新增辅助函数（与 `updateScrollFollowState` 同段）：

```js
const jumpScrollTo = (el, top) => {
  if (!el) return;
  const previous = el.style.scrollBehavior;
  el.style.scrollBehavior = "auto";
  el.scrollTop = top;
  el.style.scrollBehavior = previous;
};
```
- 跟底定时器改用它（不再用 `scrollTo({behavior:"auto"})`）。
- 「回到底部」：运行中（`runInProgressRef` / `busy`）走瞬时定位，避免动画被新内容打断；空闲时仍走 `motionScrollBehavior()`，保留设计动效。
- CSS `.chat-body { scroll-behavior: smooth; }` **保持不变**（用户主动滚动/定位仍有动效，动效治理测试不动）。

### 3.2 阅读位置只在真正换会话时武装 — `ChatPanel.jsx`

```js
if (previousThreadRef.current !== threadId) {
  const savedScroll = scrollPositionsRef.current.get(threadId);
  pendingScrollRestoreRef.current = (savedScroll != null && !hydratedIsLive) ? savedScroll : null;
}
previousThreadRef.current = threadId;
```
同一会话的后续水合不再重新武装，避免把已到底部/已移动的视口拽回旧位置。

### 3.3 测试

- `scripts/会话流排版回归测试.mjs`：新增两条
  - 「跟底滚动瞬时定位，不被 CSS smooth 拖成动画」：`jumpScrollTo` 存在、临时改 inline `scroll-behavior`、跟底调用它、禁止再出现 `scrollTo({behavior:"auto"})`；同时断言 CSS smooth 仍在（设计基线不退化）。
  - 「阅读位置只在真正换会话时武装」。
- `scripts/AVA时间线测试.mjs`：「回底按钮清零」断言改为「清零 + 定位到底部（运行中瞬时）」，与 3.1 对齐。
