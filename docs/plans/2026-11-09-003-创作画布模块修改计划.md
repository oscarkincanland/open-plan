## 0. 决策摘要（用户 2026-11-09）

| # | 决策 | 落地含义 |
|---|---|---|
| D1 | **画布真源可编辑** | 画布不是只读预览，也不是纯 SVG 源码列表：`canvas.json` + 板级 JSON 为可编辑对象模型；用户在画布内直接移动/缩放画板、编辑文本框、调整样式，Agent 通过工具做同样的事。 |
| D2 | **PPTX 文本可编辑** | 导出 PPTX 时，文本对象映射为真正的文本框（可改字），形状映射为形状，图片/SVG 块映射为图片；不做“整页截图当幻灯片”（HTML 兼容板除外，见 D3）。 |
| D3 | **V1 兼容 `.dc.html` 画布** | 能直接打开 `claude-design` / `baoyu-design` 格式的画布目录（`project/canvas.json` v3 + `.dc.html`）：只读渲染、可移动/缩放/整页导出；V1 不编辑其内部对象、不写回原 `.dc.html`。 |
| D4 | **多画布、多标签** | 同一工作区可有多个创作画布，在右侧画布以多个 `design` 标签并行打开；不采用地图的“单活动画布”（ADR-0018）。 |
| D5 | **命名：创作画布** | 与地图“AI 画布”、右侧“工作区画布”、地图“草稿层”区分；工具前缀 `canvas_*`，运行开关 `OAW_CREATIVE_CANVAS`。 |
| D6 | **仅 Work 模式** | 与地图一致：Chat/Review 不持有任何 `canvas_*` 工具；入口只在 Work 开放（历史会话可只读查看已有画布文件）。 |
| D7 | **零新依赖** | 渲染用 React + DOM/SVG；导出复用内置浏览器 CDP（PNG/PDF）与 `pptxgenjs`（PPTX）；打包用已有 `jszip`。新依赖需先 ADR，本模块不引入。 |
| D8 | **默认关闭** | `OAW_CREATIVE_CANVAS=0` 为基线：无入口、无工具、API 404；关闭态有守护测试。 |
| D9 | **会话绑定恢复（提议）** | 画布 slug 写入会话 header，切回会话时带出上次创作画布（类比 `mapProject`）；本项用户未明确，按“提议”实现，待确认。 |

## 2. 目标 / 非目标 / 成功标准

### 2.1 目标

1. 提供“创作画布”作为 Work 模式的可视化设计工作台：多画布、多标签、可保存、可恢复。
2. 画布内容为**可编辑对象模型**：文本、形状、图片、SVG 矢量块；用户与 Agent 都能改。
3. 兼容打开 `canvas.json v3 + .dc.html` 格式画布（只读渲染 + 整页导出）。
4. 一套内容多路导出：SVG / PNG / PDF / PPTX（文本可编辑）。
5. Agent 工具与 UI 走同一数据模型与同一写入通道；关闭开关时完全回到基线。
6. 产物进当前工作区、可被产物面板追踪、可回滚（导出文件与画布文件均落 `designs/`）。

### 2.2 非目标

- 不做 Figma 级多人实时协同；不做组件库/设计系统管理（`designSystems` 字段保留但不实现）。
- 不做 HTML 画板的内部对象编辑（V1 只读兼容）。
- 不做动画、交互原型、代码导出。
- 不新增前端框架/画布引擎/数据库；不做云同步。
- 不改地图“AI 画布”语义，不合并两个模块。

### 2.3 成功标准

- 新建画布 → 添加文本板 → 直接改字/移动/缩放 → 刷新后内容与位置一致。
- Agent 生成 2 块板（含 1 个 SVG 块）→ 画布出现、可继续人工编辑、可撤销。
- 导出 PPTX：文本框可编辑、页数与尺寸正确；HTML 板在导出对话框明确标注“图片页”。
- 导出 SVG/PNG/PDF 可打开、尺寸正确、中文不丢字。
- 打开 `designs/open-plan-deck` 这类已有画布：能渲染、能整页导出、原文件字节不变。
- 关闭开关：无标签入口、无 `canvas_*` 工具、API 404（守护测试通过）。
- 多画布同时打开、切换、关闭、刷新恢复均不串数据。

## 3. 数据模型（唯一事实来源：工作区文件）

### 3.1 目录结构

```text
office-workspace/designs/<slug>/
├─ project/
│  ├─ canvas.json                 # 画布索引（v3 兼容超集）
│  ├─ boards/
│  │  ├─ cover.board.json         # 对象板（可编辑）
│  │  └─ body.board.json
│  ├─ assets/                     # 图片、SVG、字体等素材
│  └─ legacy/                     # 兼容导入的 .dc.html（原样保留，不改写）
├─ exports/                       # 导出产物（PNG/PDF/SVG/PPTX）
└─ .trash/                        # 软删除（画布/画板/素材，可人工恢复）
```

- 画布必须位于当前工作区内；跨工作区访问拒绝。
- `exports/` 与 `.trash/` 不进画布渲染与导出视图。

### 3.2 `project/canvas.json`（索引）

```json
{
  "v": 3,
  "format": "oaw-canvas",
  "title": "规聚 10 分钟汇报",
  "kind": "deck",
  "rev": 12,
  "pages": [{ "id": "p1", "name": "主页面" }],
  "boards": {
    "boards/cover.board.json": {
      "x": 0, "y": 0, "w": 1280, "h": 720,
      "title": "封面", "role": "slide", "page": "p1"
    },
    "legacy/Main.dc.html": {
      "x": 1360, "y": 0, "w": 1280, "h": 720,
      "title": "兼容画板", "role": "board", "kind": "html"
    }
  },
  "order": ["boards/cover.board.json", "legacy/Main.dc.html"],
  "notes": {},
  "designSystems": [],
  "createdAt": "2026-11-09T02:00:00Z",
  "updatedAt": "2026-11-09T02:10:00Z"
}
```

规则：

- `boards` 键 = 相对 `project/` 的路径；值至少含 `x/y/w/h`（CSS px，40–8000），可选 `title/role/page/kind`。
- `role`: `slide`（deck 模式按 `order` 出片）| `board`（普通画板）。
- `kind`: 缺省按扩展名判断：`.board.json` → 对象板；`.dc.html`/`.html` → 兼容板；`.svg` → 导入的只读矢量板（V1 仅整板显示）。
- `order` = 层级顺序，必须覆盖全部 boards；第一块对象板建议 `cover`。
- `pages` ≤ 40；`boards` ≤ 200；画布总文件 ≤ 512、总大小 ≤ 256MB（对齐 claude-design 限制，防失控）。
- `rev` 单调递增，用于 CAS 与前端冲突提示。

### 3.3 板级文件 `boards/<name>.board.json`（对象板，可编辑）

```json
{
  "v": 1,
  "w": 1280,
  "h": 720,
  "background": "#ffffff",
  "rev": 7,
  "elements": [
    {
      "id": "el-cover-title",
      "type": "text",
      "x": 80, "y": 64, "w": 960, "h": 120,
      "text": "规聚 · 交通规划 AI 工作台",
      "style": {
        "fontSize": 56, "fontWeight": 700, "fontFamily": "Microsoft YaHei",
        "color": "#141413", "textAlign": "left", "lineHeight": 1.2
      }
    },
    { "id": "el-line", "type": "rect", "x": 80, "y": 220, "w": 1120, "h": 2, "style": { "fill": "#d6dce5" } },
    { "id": "el-shot", "type": "image", "x": 80, "y": 260, "w": 520, "h": 300, "src": "../assets/map.png", "fit": "cover" },
    { "id": "el-chart", "type": "svg", "x": 640, "y": 260, "w": 520, "h": 300, "src": "../assets/flow-chart.svg" }
  ]
}
```

元素类型（V1）：

| type | 字段 | 渲染 | 导出映射 |
|---|---|---|---|
| `text` | `text/style/x/y/w/h` | DOM 文本（行内编辑） | PPTX `addText`（可编辑）；SVG `<text>` |
| `rect` | `x/y/w/h/style.fill/stroke/radius` | SVG/DOM | PPTX `addShape`；SVG `<rect>` |
| `line` | `x1/y1/x2/y2/style` | SVG | PPTX `addShape(line)`；SVG `<line>` |
| `image` | `src/fit/x/y/w/h` | `<img>`（本地素材） | PPTX `addImage`；SVG `<image>`（base64 内嵌） |
| `svg` | `src` 或 `markup`（二选一，`markup` 需 sanitize） | 沙箱 `<img>`/受限 inline SVG | PPTX 渲染为 PNG 后 `addImage`；SVG 导出时内嵌 |

约束：

- 元素 id 唯一（`[A-Za-z0-9_-]{1,64}`），单板 ≤ 500 元素，单板文件 ≤ 5MB，文字 ≤ 20000 字符/元素。
- `src` 只能是 `project/` 内相对路径（禁 `..`、绝对路径、盘符、URL）；外部图片需先导入 `assets/`。
- 文本字体仅允许白名单（系统字体 + 已上传字体），避免不可控网络字体。
- 对象板 `rev` 单调递增；PUT 必须带 `expectedRev`，冲突返回 409 并提示刷新/覆盖。

### 3.4 兼容规则（V1：`.dc.html` / claude-design v3）

- **打开**：目录含 `project/canvas.json` 且 `boards` 的键以 `.dc.html` 结尾 → 识别为兼容画布；用沙箱 iframe（`srcDoc` 或受限静态服务）渲染每块板，按 `boards` 的 `x/y/w/h` 摆放；可移动/缩放画布上的板框（写回 `canvas.json` 的坐标，不写 `.dc.html`）。
- **编辑**：V1 不提供 HTML 板内部对象编辑；画布内显示“只读·兼容板”角标。
- **导出**：PNG/PDF/PPTX 以**整页图片**处理（每板一页），导出对话框明确标注“兼容板为图片页，文字不可编辑”。
- **不写回**：`.dc.html` 与兼容画布的原始文件字节保持不变；所有坐标/标题变更只写 `canvas.json`。
- **元数据**：兼容画布新增 `format: "oaw-canvas"` 时为“已纳管”，否则视为“外部画布”，只在 `canvas.json` 写最小字段（`x/y/w/h/title/role`），不补 `rev/pages` 等运行字段，避免破坏外部工具。
- 对象板与兼容板可**混合**放在同一画布（导出时分别按可编辑/图片页处理）。

### 3.5 路径与命名

- `slug`：`^[\p{L}\p{N}][\p{L}\p{N}_-]{0,63}$`（允许中文，禁空格、点、斜杠）；创建时由标题生成，可手改。
- 板文件名：`[A-Za-z0-9_-]{1,64}.board.json`（中文标题放 `title`，不放文件名）。
- 所有路径经 `path.resolve` 后必须仍在 `designs/<slug>/` 内；符号链接、`..`、绝对路径一律拒绝。
- 导出文件名：`<画布标题>-<板标题>-<时间戳>.<ext>`，经文件名清洗（禁 `\/:*?"<>|`）。

### 4.1 `REQUIREMENTS.md` 新增 R17 创作画布（Work）

**需求**

- 创作画布仅在 Work 模式可用；Chat/Review 不持有任何 `canvas_*` 工具，入口只在 Work 开放。
- 画布为可编辑对象模型：多画布、多画板、多页；对象含文本、矩形/线、图片、SVG 矢量块；支持移动、缩放、文本编辑、样式编辑、撤销/重做、保存与脏标记。
- 多画布多标签：同一工作区可创建多个创作画布，以右侧画布标签并行打开、关闭、恢复。
- Agent 工具：`canvas_read / canvas_write / canvas_delete / canvas_import / canvas_export`（写入工作区 `designs/`；导出落 `designs/<slug>/exports/`）。
- 兼容：可直接打开 `claude-design` / `baoyu-design` 的 `project/canvas.json` + `.dc.html` 画布目录；只读渲染与整页导出，V1 不编辑其内部对象、不改写原文件。
- 导出：SVG（对象板）、PNG、PDF（同尺寸多板分页）、PPTX（对象板文本为可编辑文本框、形状为形状、图片/SVG 为图片；兼容板为整页图片并在界面标注）。
- 运行开关 `OAW_CREATIVE_CANVAS` 默认关闭；关闭时无入口、无工具、API 404，行为回到基线。
- 画布 slug 与会话绑定，切回历史会话可恢复上次创作画布（与地图预览同一恢复口径）。

**验收**

- 新建画布 → 添加文本板 → 改字/移动/缩放 → 刷新后一致；撤销/重做有效。
- Agent 生成 2 块板（含 1 个 SVG 块）→ 画布出现、可继续编辑、可导出。
- 导出 PPTX 打开后文本可编辑、页数/尺寸正确；兼容板标注“图片页”。
- 导出 SVG/PNG/PDF 可打开、尺寸正确、中文不丢字。
- 打开既有 `designs/open-plan-deck` 画布可渲染/导出，原 `.dc.html` 字节不变。
- 关闭开关后入口、工具、API 全部不可用（基线守护测试通过）。
- 多画布多标签同时打开/切换/刷新恢复不串数据；画布文件全部位于当前工作区。

### 4.2 `REQUIREMENTS.md` R13 产物补充

> 产物验收扩展：`.svg` 纳入图片类预览与验收（尺寸/可预览性）；`.pptx` 沿用既有验收；画布导出产物记录来源画布 slug 与板路径。

### 4.3 `DESIGN.md` 新增 §8.4 创作画布

- **标签**：右侧工作区画布新增 `design` 标签，可多实例（按工作区 + slug 去重）；`+` 菜单新增「创作画布」（新建 / 打开最近）。标签标题 = 画布标题，未保存时显示 dirty 点。
- **视图**：无限画布（缩放/平移/适配窗口）、画板框、网格背景（可关）、画板列表/缩略图（左侧或底部）、顶部工具条（选择/文本/矩形/线/图片、撤销/重做、缩放比例、导出）。画布宽度仍受 `--canvas-w` 约束，最大化/收起沿用现有规则。
- **对象编辑**：单选 → 拖动/八向缩放；双击文本进入行内编辑（Enter 换行、Esc 提交、失焦保存）；右侧属性条改字号/粗细/颜色/对齐/行高/圆角/填充；Delete 删除；`Ctrl+Z/Ctrl+Shift+Z` 撤销重做；保存去抖 400ms + 关闭前脏确认。
- **deck 模式**：`kind=deck` 时按 `order` 与 `role=slide` 生成幻灯片缩略条，支持拖拽排序。
- **兼容板**：显示“只读·兼容板”角标；可移动/缩放/重命名/导出，不提供内部编辑；不可从兼容板创建对象。
- **状态**：空态（新建/打开/导入三个入口，说明能力边界）；加载/失败/只读/脏/保存中；导出对话框列出格式、板范围、尺寸与“兼容板=图片页”提示。
- **无障碍**：工具栏可 Tab 聚焦；画布对象可通过画板列表键盘选择；文本编辑可用键盘完成；颜色对比遵循 DESIGN 令牌；窄屏（≤768px）画布为覆盖层，工具条换行不遮内容。
- **文件树抽屉**：`design` 标签允许显示（与文档一致），`exports/` 与 `.trash/` 不出现在树中。

## 5. 架构与技术方案

### 5.1 前端渲染器 `client/src/components/创作画布.jsx`

- React 函数组件 + DOM/SVG，无画布引擎依赖。
- 结构：`CanvasToolbar`（工具/撤销/缩放/导出）→ `CanvasViewport`（pan/zoom/fit，画板框按 `x/y/w/h` 绝对定位）→ `BoardFrame`（对象板渲染 DOM/SVG；兼容板沙箱 iframe）→ `BoardInspector`（属性条）/`BoardList`（缩略图与排序）。
- 文本编辑：`contentEditable` + `beforeinput` 限制粘贴为纯文本；提交时写 `text` 字段；不支持富文本（V1）。
- 撤销/重做：每板快照栈（最多 50 步），操作级合并（拖拽结束/文本失焦入栈）。
- 保存：`PUT /api/canvas/:slug/board` 带 `expectedRev`；400ms 去抖；失败保留本地脏状态并提示重试/覆盖。
- 只读降级：无法写（权限/锁/兼容板）时进入只读并说明原因。
- 性能：仅渲染视口内画板（简单求交）、文本编辑不重排整画布、缩略图按需生成（`ResizeObserver`）。

### 5.2 服务端模块 `server/创作画布.mjs` + API

| API | 方法 | 说明 | 校验 |
|---|---|---|---|
| `/api/canvas/list` | GET | 列出工作区画布（标题/kind/板数/更新时间） | workspace 归一化 |
| `/api/canvas/:slug` | GET | 读 `canvas.json` + boards 摘要（不返回板内容） | slug/路径 |
| `/api/canvas/:slug/board` | GET | 读单板（`?path=`） | 路径在 project 内 |
| `/api/canvas/:slug/board` | PUT | 保存单板（`expectedRev` CAS） | schema/大小/元素数 |
| `/api/canvas/:slug` | PATCH | 改 title/pages/order/板坐标 | schema/CAS |
| `/api/canvas` | POST | 新建画布（`slug/title/kind/template`） | slug 唯一/路径 |
| `/api/canvas/:slug` | DELETE | 软删除到 `.trash/` | 二次确认字段 |
| `/api/canvas/:slug/import` | POST | 导入兼容画布（复制到 `legacy/`，不改原目录） | 来源必须是工作区内或用户指定目录 |
| `/api/canvas/:slug/export` | POST | 导出任务（格式/板范围），异步队列 + 状态查询 | 格式白名单/尺寸 |
| `/api/canvas/exports/:jobId` | GET | 导出进度/结果 | 任务归属 |

实现要点：

- 所有写盘经 `写入协调.mjs` 的 `withPathWriteLock(workspace, "designs/<slug>")`；原子写用 `持久化工具.mjs`。
- 读取只读、无锁；写入校验“文件必须已存在或显式创建”，防路径穿越。
- 兼容画布导入 = **复制**（原目录不动）；导入后在 `canvas.json` 写最小字段，`.dc.html` 保持原字节。
- 画布操作写 `designs/<slug>/operations.jsonl`（创建/保存/删除/导入/导出，含 actor/时间/摘要），便于追溯与产物归属。

### 5.3 Agent 工具（仅 Work，5 个）

| 工具 | 用途 | 关键参数 | 审批（默认规则） | 事件 |
|---|---|---|---|---|
| `canvas_read` | 读画布索引/板/列表 | `slug`、`board`（可选）、`workspace`（可选） | allow（只读） | 无 |
| `canvas_write` | `action=create_canvas / add_board / patch_board / update_canvas / delete_element` | `slug`、`action`、`board`、`elements`、`layout`、`title` | allow（与 `write` 同类；受白名单/工作区边界） | `canvas_changed` |
| `canvas_delete` | 删板/删画布（软删到 `.trash/`） | `slug`、`board`、`confirmed` | **ask + forceConfirm**（destructive） | `canvas_changed` |
| `canvas_import` | 导入 `.dc.html` 兼容画布 | `sourcePath`、`slug`、`title` | ask（写工作区） | `canvas_changed` |
| `canvas_export` | 导出 SVG/PNG/PDF/PPTX | `slug`、`format`、`boards`、`outputName` | ask（交付文件） | `canvas_exported` |

- 能力计划 `planTaskCapabilities`：Work 且开关开时 `capabilities.canvas = true`；Chat/Review 恒为 `false`；不新增关键词路由，避免抢占既有“生成 PPT”写作路由（工具可用性按模式而非意图）。
- 白名单：`task.mjs` 的 `AGENT_TOOLS` 用 `...(RUNTIME_FLAGS.creativeCanvas ? [...] : [])` 追加，与 `cadAgent` 同模式。
- 工具元数据：`readOnly`（read）/`sideEffectScope`（`workspace:designs`）/`riskLevel`/`needsApproval`/`forceConfirm`（delete）/`resultBudget`。
- 事件注册：`canvas_changed`、`canvas_exported`（见 5.4）。

### 5.4 事件

| 事件 | payload | 消费方 |
|---|---|---|
| `canvas_changed` | `{ slug, boardPath, action, revision, actor, workspace }` | 创作画布（按 revision 重读对应板）、工作产物面板（刷新）、标签标题/脏状态 |
| `canvas_created` | `{ slug, title, workspace }` | App（打开新标签/通知，不抢焦点） |
| `canvas_exported` | `{ slug, format, files: [{path,bytes}], jobId }` | 产物面板、导出对话框、通知 |

- 登记于 `事件注册表.mjs`（`lifecycle`/`persist`/`schema`），payload 校验测试与发射点测试必须通过。
- 前端不新增第二套解析：走既有事件投影/`运行展示投影` 的消费点。

### 5.5 导出

| 格式 | 生成方式 | 说明 |
|---|---|---|
| SVG | 服务端按板 JSON 序列化为 `<svg>`：text→`<text>`、rect→`<rect>`、line→`<line>`、image→内嵌 base64、svg 块→内嵌（sanitize） | 对象板适用；兼容板不导出 SVG（提示改用 PNG/PDF/PPTX） |
| PNG | 导出视图 `?export=canvas&slug=&board=`（CDP 截图） | 尺寸 = 板 CSS px，上限 2400×1600（内置浏览器限制）；超限自动等比缩放并提示 |
| PDF | 导出视图按 `@page { size: <板宽>px <板高>px }` 逐板分页，一次 `printToPDF` | V1 要求同尺寸；混合尺寸提示“逐板导出 PNG” |
| PPTX | 服务端读取板 JSON，用 `pptxgenjs` 映射：text→`addText`（可编辑）、rect/line→`addShape`、image→`addImage`、svg 块→先渲染 PNG 再 `addImage`；兼容板→CDP 截图整页 `addImage` | 1280×720 px → 13.333×7.5 in；字号 pt = px × 0.75；导出后对话框中标注哪些页是图片页 |

- 输出目录 `designs/<slug>/exports/`；文件名清洗；导出任务串行（同一画布导出不并发），进度可查。
- 导出任务复用地图批导的会话模式：`browserSessionKey("canvas-export", jobId)`，打开导出视图 → 轮询 `__OAW_EXPORT_READY` → 截图/打印 → 落盘 → 登记产物。
- 产物登记：导出文件进入现有产物台账/验收（PNG/PDF/PPTX 走既有规则；SVG 走“可读”兜底，必要时补 SVG 分支）。

### 5.6 标签、持久化与会话绑定

| 项 | 方案 |
|---|---|
| 标签 kind | `design`；非单例；id `design:<workspaceKey>:<slug>`；`payload = { slug, workspace, path, title }` |
| 多画布 | 同工作区可开多个 `design` 标签；同一画布只保留一个标签（id 去重） |
| 持久化 | 沿用 `oaw_canvas_v2`（按工作区）；`sanitizeTab` 允许 `design`（仅存身份，不存板内容）；刷新后按 `slug` 重新拉取 |
| 上限 | 受 `MAX_CANVAS_TABS=12` 约束；超限时保留最近打开的标签（现有行为） |
| 会话绑定 | 会话 header 新增 `creativeCanvas: "<slug>"` + `/api/sessions/:id/canvas-context`；恢复逻辑复用地图“点会话带出预览”的纯函数模式；多画布时恢复“最后聚焦的一个” |
| 打开入口 | `+` 菜单「创作画布」（新建/最近）、文件树点击 `canvas.json`、Agent `canvas_created` 事件（不抢焦点）、工作产物面板中导出文件可回到画布 |

### 5.7 审批与安全

- **审批**：`canvas_read` allow；`canvas_write/import/export` ask 或按用户规则；`canvas_delete` forceConfirm，`auto` 模式不得放行。
- **路径**：所有输入先归一化，最终路径必须位于 `designs/<slug>/` 内；拒绝 `..`、绝对路径、盘符、UNC、符号链接逃逸。
- **HTML 板**：iframe `sandbox`（无 `allow-scripts`；仅 `allow-same-origin` 与展示所需），禁止外链与 `javascript:`；兼容画布导入前扫描危险标签（`<script>`/`on*`/`foreignObject`/外部 URL）并提示风险。
- **SVG 块**：`markup` 走 sanitize（去 script/事件属性/外链/foreignObject）；`src` 仅本地素材；渲染用 `<img>`（不执行脚本）。
- **写入**：`withPathWriteLock` + 原子写 + `operations.jsonl`；Agent 与 UI 共用服务端校验，前端不直写文件。
- **工作区边界**：画布必须属于当前工作区；导出产物不得写出工作区。
- **不读密钥/不联网**：渲染与导出不加载外部字体/CDN；素材必须本地化。

### 5.8 性能与配额

- 单画布 ≤ 200 板、512 文件、256MB；单板 ≤ 5MB、500 元素、20000 字/文本。
- 前端只渲染视口内板；文本编辑只重绘该板；缩略图 200ms 去抖生成。
- 导出队列串行，最多 1 个任务/画布；批量导出按板展开但单次 ≤ 50 页。
- 事件刷新：按 `revision` 比对，只重读变化板（不整画布重载）。

## 8. 风险与回滚

| 风险 | 影响 | 对策 |
|---|---|---|
| 编辑体验（拖拽/文本）打磨不足 | 用户仍想用外部工具 | V1 先做“够用”的移动/缩放/文本/撤销；复杂排版交给 Agent 与模板；V2 再增强对齐/多选 |
| PPTX 保真度 | 与设计稿视觉差异 | 明确映射规则（文本/形状/图片），导出对话框提示“PPTX 为近似还原”；关键页可用图片页兜底 |
| 兼容画布期望落差 | 用户以为能编辑 `.dc.html` | 角标 + 导出提示 + 文档写明 V1 只读；提供“转为对象板”列为 V2 |
| CDP 导出依赖内置浏览器 | 导出失败 | 导出前置检查浏览器可用；失败给可重试原因；PNG 备选前端 `canvas` 渲染 |
| SVG/HTML 安全 | XSS/外链 | sanitize + iframe sandbox + `<img>` 渲染 + 本地素材白名单 |
| 并发编辑冲突 | 覆盖用户/Agent 修改 | board `rev` CAS + 409 冲突提示（刷新/覆盖二选一）；写锁串行 |
| 大画布性能 | 卡顿 | 板级懒渲染、缩略图去抖、单板限额、导出分页 |
| 开关默认关但测试漏守护 | 关闭态仍生效 | `test:canvas-ui` 断言关闭时无入口/无工具/API 404 |
| ADR/文档未同步 | 索引守护测试红 | P0 先落 ADR 与索引，文档与代码同提交 |

**回滚**：开关置 0 即回到基线（入口/工具/API 全部关闭）；已产生的 `designs/` 文件与导出产物保留，可后续再启用；代码回退不影响工作区数据。

## 9. 不做清单

- 不做多人实时协同/评论/共享链接。
- 不做设计系统（`designSystems`）与组件库。
- 不做 HTML 板内部对象编辑、不做 `.dc.html` 写回。
- 不做动画、交互原型、代码导出、视频。
- 不引入画布引擎/前端框架/新依赖；不做云同步。

## 附录 A：ADR-0031（已采纳）

**标题**：创作画布采用可编辑画布文档、多画布标签与“对象板 + 兼容板”混合模型

- 状态：已采纳
- 记录日期：2026-11-09
- 决策者：用户
- 基线：v0.13.24
- 关联：本计划、`REQUIREMENTS.md` R17、`DESIGN.md` §8.4、[开发收敛规范](../规范/开发收敛规范.md) §1/§7，完整决策见 [ADR-0031](../决策记录/0031-创作画布采用可编辑画布文档与多画布标签.md)

### 1. 背景

`designs/` 下已有 claude-design/baoyu-design 格式画布，但产品内没有渲染、编辑与导出入口；地图“AI 画布”是地图工程入口，不能复用为通用设计画布；用户要求“可编辑画布 + 可编辑 PPTX 文本 + V1 兼容 + 多画布多标签”。

### 2. 问题

如何在**不引入画布引擎、不破坏外部 skill 工作流**的前提下，提供产品内可编辑的设计画布，并让 Agent 与用户共用同一数据模型？

### 3. 备选方案

**方案 A：纯 SVG 文件为真源（只读渲染）**
- 做法：Agent 写 `.svg`，前端 `<img>`/沙箱 iframe 预览。
- 优点：零编辑复杂度；导出 SVG 直接。
- 代价：无法满足“可编辑画布/可编辑文本框/PPTX 文本”；放弃。

**方案 B：canvas.json 对象模型 + 对象板 + 兼容板（本计划）**
- 做法：`canvas.json` 索引 + `.board.json` 对象板（text/rect/line/image/svg）+ `.dc.html` 只读兼容板；React DOM/SVG 渲染与编辑；导出走 CDP + pptxgenjs。
- 优点：满足编辑与 PPTX 文本；兼容外部画布；零新依赖；可逐板 CAS 保存。
- 代价：自研编辑器工作量最大；PPTX 为近似还原；HTML 板不可编辑。

**方案 C：引入 konva/fabric/tldraw 画布引擎**
- 做法：用成熟引擎承载对象编辑。
- 优点：编辑体验好。
- 代价：新增依赖/包体/许可/学习成本，需 ADR 与体积评估；与“零新依赖”和当前收敛方向冲突。

### 4. 决策

选择**方案 B**：画布真源为 `canvas.json` + `.board.json` 对象板；`.dc.html` 作为只读兼容板；多画布多标签；工具仅 Work、默认关；导出采用“对象映射 + 图片兜底”。

不适用的边界：不做 HTML 内部对象编辑；不做多人协同；不做设计系统。

### 5. 理由

- 用户明确要求可编辑、可编辑文本、V1 兼容，方案 B 是唯一同时满足三项且不引依赖的形态。
- 对象板与 PPTX 文本框一一对应，导出可验证；兼容板整页图片兜底，风险可控。
- 与现有画布标签体系、产物台账、审批与事件契约同构，改动可收敛。

### 6. 影响

- 正面：产品内获得设计画布与导出闭环；外部画布可直接打开；Agent 获得可视化产出能力。
- 负面：编辑器维护成本；PPTX 近似还原；兼容板只读可能低于部分用户预期。
- 迁移/回滚：开关置 0 即基线；数据保留；不改外部画布文件。

### 7. 验证

- `test:canvas-model` / `test:canvas-export` / `test:canvas-ui` / 契约测试 / `npm run verify`。
- 人工：PPTX 改字、四格式导出、兼容画布导入导出、多标签、关闭开关基线。

### 8. 复审触发条件

- 对象板/画布规模或编辑操作复杂度显著上升（需要引擎）；
- PPTX 保真成为主要投诉（需要原生形状/文本增强或换导出器）；
- 外部画布格式升级导致兼容层维护成本上升。
