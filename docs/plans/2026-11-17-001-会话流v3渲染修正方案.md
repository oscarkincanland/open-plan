1. 最老式的动画依旧出现。

3. 对话流整体字体要缩小——现在过程文本和最终结论差不多大；参考 DSH 前端渲染。
4. 最终结论输出需要进一步明确：没有"分点"，是不是远端仓库已经做了修改？必要时补充表格与代码块样式。

## 2. 根因分析（附证据）

### 2.1 问题 1/2（旧动画、带框工具卡）：浏览器旧构建缓存，代码已修复

- 服务端 `GET /api/status` 返回 `clientBuild: index-Dxq3rI5i.js`、`runtimeFlags.transcriptV3: true`。
- 当前 `client/dist`（构建于 11-15 21:56）**已包含**全部三项修复：
  - ExecutionFlow 事件卡在 v3 下不再渲染（`ChatPanel.jsx:7445/7455` 的 `!transcriptV3` 门禁）；
  - 工具卡去外框（`styles.css` `[data-transcript-v3="1"] .tool-card { border:0 !important; … }`，来自提交 7fa33087）；
  - 旧「执行过程」折叠头扫光在 v3 下关闭（`[data-transcript-v3="1"] .message-process-fold.run-activity-fold.is-live>summary::after { animation:none!important; opacity:0 }`，未提交改动）。
- 浏览器实测（11-17，headless Edge 打开 `127.0.0.1:3002` 并展开历史会话过程区）：工具行为**扁平发丝线行**（0 边框 / 0 圆角 / 透明背景），折叠头无扫光动画。截图中的"框"与旧动画来自**未刷新的浏览器标签页**（其内存中运行的是更早的构建）。
- **处理：硬刷新（Cmd+Shift+R）即可消除，不需要改代码。**

### 2.2 实测新发现的残留缺陷：已完成轮次内残留"正在子代理"运行动画

- 已完成会话的过程组里残留一条 `tool-card pending`（"正在子代理"），仍带 tool-icon pulse、SVG spin、tl-shimmer 三重运行态动画。
- 根因：历史回放的子代理/工具块缺少终态时，渲染层按"未完成"处理，动画一直跑。
- **处理（最小侵入）：渲染层兜底——消息不在运行中（`!isTaskLive` / `!streaming`）时，pending 工具行不再呈现运行态动画，显示中性"未结转"状态。**

### 2.3 问题 3a：「阶段小结」标签

- 标签来源：`client/src/会话流投影.js:175` 给每个 text 条目硬编码 `cap: "阶段小结"`；`ChatPanel.jsx:7124-7127` 渲染 `tb-cap`（12px）。
- **处理：v3 下不再渲染该标签**（折叠体内与折叠体外都不渲染；终稿本来就不带标签）。

### 2.4 问题 3b：阶段小结的"时机"

- 截图中顺序为「阶段小结文本 → 已调用工具」——这是**模型真实输出顺序**：模型先写"我先看一下…再动手生成"（行动前旁白），然后才调用工具。时间流按时间顺序如实呈现，不应把文本挪到工具之后（那会伪造时序）。
- "小结在工具之前"的错位感来自「阶段小结」这个标签本身（标签暗示"对上一段的总结"）。**去掉标签后，该文本读起来就是过程旁白，位置不再有歧义。**
- 因此 2.3 的改动同时回答了时机问题：**位置不动，标签去掉。**

### 2.5 问题 3c：字号层级

- 现状：`styles.css:1177-1183` `.flow-markdown .markdown-body { font-size: 14px }` 对折叠体内的阶段小结正文与折叠体外的终稿**一律 14px**——过程文本与结论同字号，层级消失（用户反馈属实）。
- DSH 参考（2026-11-14-001 方案 §DSH 过程行）：过程行 13px 层级、结论正文 14px。
- **处理：仅 v3 折叠体内的过程正文降为 13px / 1.7（含表格等内嵌元素跟随），结论保持 14px / 1.75；行内明细（tl-verb/tl-obj 13px、思考 12.5px）已达标不动。**

### 2.6 问题 4：终稿"没有分点"

- **远端没有改这个行为**：远端 9 个提交不涉及 `MarkdownBody` / `SummaryBlock` 的编号与目录（远端改的是结构化小节沉底 `splitRunTimelineSections`、扫光、开始页等）。
- 真正原因：本地 v3 改动（未提交）把终稿从 `SummaryBlock`（带 `numberSections` 编号 + `docToc` 目录 + 复制 Markdown，见 `ChatPanel.jsx:7559` 非时间线路径）改为普通 `SafeMarkdown`（`ChatPanel.jsx:7463`，**未传 `numberSections docToc`**），编号/目录/复制能力在 v3 下丢失。
- 表格与代码块：提交 f4c09a0a 的「文档表」（发丝线表格）与「代码块 8px 圆角 + 0.5px 描边」都是全局 `.markdown-body` 规则，v3 终稿路径自动命中，无需新写。
- **处理：v3 终稿渲染补齐 `numberSections docToc` 并挂 `.assistant-final-answer` 容器类，与非时间线路径（7559）对齐。**
