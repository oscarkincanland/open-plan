> 日期：2026-11-12　计划号：2026-11-11-012
> 基线：v0.13.25（工作区含 005/007/008/009/010 未提交改动）
> 关联：[2026-11-11-010-五项体验修复计划](2026-11-11-010-五项体验修复计划.md)（其 F3/F4 对象误判为创作画布，本计划修正）、`REQUIREMENTS.md` R10、[ADR-0038](../决策记录/0038-地图创建即绑定交付与map_export工具.md)
> 用户澄清（2026-11-12）："地图模块的画布"指**地图项目画布**（`map_project_create` 创建的空白 AI 画布/地图项目），不是创作画布——① agent 新建项目画布后应及时切换到新画布；② agent 编辑项目画布（草稿层等）时用户看不到在编辑什么。

---

## 0. 根因（一条链）

用户在地图模块让 agent 做 OD demo：`map_project_create`（新项目画布）→ `map_draft_layer`（写草稿）。现状：

| 环节 | 代码 | 行为 |
|---|---|---|
| 新建项目事件到达面板 | `MapPanel.handleMapAction` L1785：`action.project !== project` 即 return | `project_created` 带新项目名 ≠ 面板当前项目 → **直接丢弃**，面板不切换 |
| 会话项目跟随 | `MapPanel` L552-557 跟随 `initialProject`，但要求项目已在本地 `projects` 列表 | 列表只在挂载/面板内操作时刷新，agent 新建的项目不在 → **跟随失效** |
| 草稿实时刷新 | `handleDraftChanged` L1946：`payload.project !== project` 即 return | agent 的草稿全写进"看不见的新项目"→ **用户看不到任何编辑** |

另：全局事件流已携带 `map_*` 工具的 `tool_start`/`tool_end`（同 canvas 模式，2026-11-11-009 的链路），前端未利用——可复用同一模式做"编辑活动"指示。

## 1. 范围

### 1.1 本次要做

- **F1 新建项目画布自动切换**：`handleMapAction` 对 `action === "project_created"` 特判——刷新项目列表（`mapProjects()`）后 `setProject(新项目)`（切换后面板的 loadProject/loadDrafts effect 链自动生效）；App 侧既有绑定逻辑零改动（bridge 已透传 `map_action`）。
- **F2 地图项目编辑活动指示**：App 全局流跟踪 map 写类工具活动（`map_draft_layer / map_fixate_layer / map_edit / map_import / map_save_analysis / map_reset / map_analyze / map_project_create / map_export`；排除只读 `map_read / map_datasets / map_layer_info / map_clear_analysis / map_template`）→ `mapActivity[project] = { active, tool, threadId }`（project = 入参 project || 会话绑定项目）；Run 终态清理（同 canvas 模式）。地图模式浮动 pill 优先显示地图项目活动（"Agent 正在编辑地图项目《X》· 工具名"），其次创作画布活动（010 既有）。
- **F3 pill 点击行为**：地图项目活动 → 通过 bridge 发 `switch_project` 让面板切到活动项目（不退出地图）；创作画布活动 → 既有行为（退出地图打开画布）。
- **F4 会话项目跟随加固**：MapPanel "会话项目跟随" effect 在列表不含目标项目时触发一次列表刷新再跟随（兜底 bridge 之外的路径，如服务重启恢复会话）。

### 1.2 非目标

- 不改 server（`map_action{project_created}` 与 `map_draft_changed` 事件 004 已有）。
- 不动创作画布联动（009/010 既有行为保留：创作画布新建仍自动退出地图打开画布——两类画布事件不同、不冲突）。
- 不新增事件类型；不动工具白名单。

## 2. 设计

### 2.1 F1 项目切换（client/src/components/MapPanel.jsx）

`handleMapAction` 开头特判（在跨项目守卫**之前**）：

```jsx
// 新建项目画布（2026-11-11-012）：agent map_project_create 后自动切换到新项目。
// 必须在跨项目守卫之前——project_created 的 project 就是"别人"（新项目）。
if (action?.action === "project_created" && String(action.project || "")) {
  const next = String(action.project);
  mapProjects().then((r) => {
    const listed = (r.projects || []).map((item) => String(item.project || item.name || ""));
    setProjects(r.projects || []);
    if (listed.includes(next)) setProject(next);
  }).catch(() => {});
  return;
}
// 会话内切换请求（2026-11-11-012 F3）：活动 pill「查看」用。
if (action?.action === "switch_project" && String(action.project || "")) {
  changeProject(String(action.project));
  return;
}
```

依赖：`handleMapAction` 的 useCallback 依赖数组补 `changeProject`。

### 2.2 F2 活动跟踪（client/src/App.jsx 全局流 handlePayload）

- state：`const [mapActivity, setMapActivity] = useState({});`（project → { active, tool, threadId }）。
- 全局流 `tool_start`/`tool_end` 分支扩展：`name` 匹配地图写类名单时，`project = input.project || mapContexts[event.threadId]?.mapProject || "当前地图项目"`；写类名单常量 `MAP_WRITE_TOOLS`。
- Run 终态（`run_finished`/`agent_error`/`run_recovered`）按 threadId 清理 mapActivity（与 canvasActivity 同款）。
- `mapActiveCanvas` 派生改为 `mapActiveTarget`：优先返回 `{ kind: "map", project, tool }`，其次 `{ kind: "design", slug, title }`。

### 2.3 F3 pill（App.jsx + styles.css）

- pill 渲染复用 `.map-canvas-activity-pill`（类名不变，避免样式迁移）：
  - map 态文案：`Agent 正在编辑地图项目《X》· <工具 label>`；点击 → `mapBridgeRef.current?.onMapAction?.({ action: "switch_project", project })`（不退出地图）。
  - design 态：既有文案与行为不变。
- 无新动画（呼吸点复用 `oaw-agent-pulse`，宿主已登记）。

### 2.4 F4 跟随加固（MapPanel.jsx L552-557）

会话跟随 effect 中列表不含目标项目时：`mapProjects()` 刷新一次后再跟随（加 in-flight ref 防循环）。
