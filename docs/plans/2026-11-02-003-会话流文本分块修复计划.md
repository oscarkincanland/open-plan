## 1. 背景与目标

### 1.1 背景

用户在对话流中看到渲染错乱（截图）：

```
明白，做一个 demo 级精简版。我按景宁县新能源重卡充换电方向写，先读工作区素材拿真实数
┌ 操作 Office 文档 view 景宁任务/景宁… ─────────────────┐
据。
```

一句话被工具卡切成两截：前半句缺尾部两字，孤零零挂着一个「据。」。

### 1.2 目标

定位并修复「模型的一次连续输出被工具调用切断」这一类渲染错乱，并补上能真正抓住它的回归测试。

### 1.3 非目标 / 不做清单

- 不改服务端消息格式或 SSE 事件协议——服务端数据本来就是对的。
- 不改会话流的整体信息架构（折叠形态、字号档位、总结位置）。
- 不动工作区画布、Office 写作层、并发写锁等其它链路。

## 2. 影响文件与现状

### 2.1 根因（三层取证）

| 层次 | 结论 | 证据 |
|---|---|---|
| 服务端数据 | **正确** | 该条 assistant 消息 content 顺序为 `thinking` → `text("明白…拿真实数据。")` → `toolCall(officecli)`，47 字一字不差 |
| 事件流 | text 与 tool_call 交错 | 该会话 50 条 entries 里共 17 个 text 块、17 个 toolCall，二者交替出现 |
| 前端渲染 | **缺陷所在** | 打字机按 90 字/秒分帧揭示（`enqueueTextReveal` 的 `state.pending`），而 `tool_start` 事件**同步**把工具卡 push 进 blocks 尾部；SSE 里 `tool_start` 可能早于最后几个 text token 到达，工具卡就插进了句子中间 |

旧逻辑复现（与截图逐字一致）：

```
块0 text  "明白…拿真实数"     ← tool_start 到达前已落定
块1 tool  "officecli"         ← tool_start 同步插入
块2 text  "据。"              ← 后续 token 因尾部已是 tool，只能新开一块
```

### 2.2 附带发现：权威全文补齐的缺口定位错位

`enqueueTextReveal` 的 `authoritative` 分支用 `displayed.length`（整轮已显示文本的**累计长度**）
去裁剪 `text`（**单块**内容）。两者粒度不同，多块场景下会落到错误偏移，造成内容丢失或重复。

### 2.3 与本次合并的关系

**无关**。`appendTextBlock` 合并前后逐字相同，合并 diff 未触及
`enqueueTextReveal` / `displayedTextRef` / `fullText` 任何一行——属既有缺陷。

## 3. 分步修改计划

### Step 0：取证与隔离

**修改内容**
- 从真实会话 JSONL 与服务端 `/api/sessions` 接口双向核对，确认服务端数据无误、错乱只在渲染层。
- 用最小复现脚本验证「尾部是 text 才追加，否则新开」的旧逻辑必然产出 2 段。
- **隔离并发改动**：修复期间有另一条功能线（完成偏好 / 标签页标识 / 流配额）在同一工作区改动
  `server/task.mjs` 等文件，已用 `git stash` 隔离，避免混入本次提交。

**验收**：复现脚本产出形态与用户截图一致。

**回滚**：无需回滚（纯调查）。

### Step 1：抽出可测的纯函数

**修改内容**
- `client/src/components/流式文本队列.js` 新增：
  - `属于同一句话(previous, pending)`——判断待揭示文本是否为前一段 text 的同句延续
    （判据：前段未以终止标点收尾）。
  - `追加流式文本块(blocks, text)`——尾部是 text 就并入；尾部是工具卡时，
    若新文本与工具卡之前那段仍属同一句话就并回原句，否则新开一段。
  - `并回上一段文本块(blocks, text)`、`追加文本块(blocks, text)`。
  - `计算权威文本缺口(text, queued)`——缺口相对「已入队文本」定位。
  - `构建流式块序列(blocks, events)`——按组件真实时序建模事件→blocks 的编排。

**验收**：`node --check` 通过；纯函数可被测试直接 import。

**回滚**：还原该文件。

### Step 2：组件接线

**修改内容**
- `client/src/components/ChatPanel.jsx`：
  - 新增 `flushTextReveal(id)`——把打字机缓冲立即落定（工具边界让路用）。
  - 在 5 类插队点前调用：`tool_start`、`subagent_start`（含 planned/started）、
    `pipeline_started`、`ask_user`、`tool_approval_request`。
  - reveal 的追加逻辑由 `appendTextBlock` 改为 `追加流式文本块`（同句并回）。
  - `cancelTextReveal` 的保留分支同样改走 `追加流式文本块`。
  - `enqueueTextReveal` 的 `authoritative` 分支改用 `计算权威文本缺口`，
    缺口基准从「已揭示长度」改为「已入队文本」，累加改为赋值。
  - 移除已无调用者的本地 `appendTextBlock`。

**验收**：`npm run verify` 通过；新测试全绿。

**回滚**：还原该文件。

## 5. 风险与待确认决策

### 5.1 风险

| 风险 | 后果 | 缓解 |
|---|---|---|
| 「同一句话」用终止标点判断，模型句子恰好以逗号等收尾 | 该并的没并，仍会裂句 | 判据覆盖常见终止标点；若仍复现需按真实样本补判据 |
| 同句并回可能把模型真分段的两段误并 | 段落边界丢失 | 判据要求前段**未**以终止标点收尾；真分段输出通常以句号收尾 |
| 工作区存在并发改动 | 把别人的工作混进本次提交 | Step 0 已用 stash 隔离；提交前核对改动清单 |
