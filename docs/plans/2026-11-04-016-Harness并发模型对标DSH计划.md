# Harness 并发模型对标 DSH 计划

> 状态：已实施（2026-11-04）　依据：DSH Harness 机制总结、ZCode 并发机制调研、[ADR 0022](../决策记录/0022-Harness并发采用短锁与版本CAS.md)
> 目标：长任务不再被写锁整区阻塞；同工作区多会话互不影响；技能路由去硬编码。

## 1. 问题

1. `stageWrite/stageWriteWithRetry` 把目标锁持有到 Run 结束；`edit.access` 取锁不释放。长任务早期写过的文件会挡住其他会话整个 Run。
2. `bashWriteTargets` 对无法推导的命令回退锁工作区根，`node build.js`/`npm run build`/`bash -c` 让整个工作区串行。
3. 全局模型并发默认 2、officecli 1；同一标签页对话流 supersede 未带 thread，不同会话互相收流。
4. Skills 是“会话创建时 top-8 快照 + 复杂度阈值 + simple 禁止搜索”；技能根只扫应用仓库，不扫任务 workspace。

## 2. 对标结论

DSH 的做法：

- 会话日志/运行时按会话独立，跨会话没有全局工具队列；
- 文件层不做工作区锁，`write/edit` 按 realpath 短锁 + stat 版本 CAS；bash 明确不受版本守卫保护；
- Skills 目录按轮注入，模型按 description 判断，无复杂度门禁；
- worktree 是可选真隔离手段，默认不启用。

本项目保留 staging/发布模型，但把“锁”降为“写暂存/发布瞬间”，发布期用版本 CAS；冲突时写副本而不是覆盖或整轮失败。

## 3. 实施内容

### 3.1 文件层

- 新增 `server/文件版本.mjs`：`revisionOf`（dev/ino/size/mtimeNs/ctimeNs + 内容指纹，规避 Windows 同尺寸快速改写时间戳相同）、`sameRevision`、`conflictCopyPath`。
- `stageWrite/stageWriteWithRetry`：写完 staging 立即释放锁；entry 记录 `baseRevision/baseExisted`。
- `publishStagedRun`：短锁内比对当前 revision 与 base；变化时写 `name.conflict-<runId>` 副本，entry 标 `conflict`，发 `artifact_conflict`；其余文件继续发布。
- `materializeStagedReferences`：目标版本变化时跳过并发 `artifact_materialize_skipped`；取短锁避免检查与复制之间被插入。
- `agent.mjs`：read/edit.readFile 记录本轮 `readRevisions`；write/edit 前比对，发现读后被改抛 `FS_STALE_VERSION`；`OAW_FS_OBSERVATION=strict` 时要求覆盖前先读；移除 `edit.access` 长锁。
- `runs.mjs`：终态早退路径也释放 Run 锁。

### 3.2 bash / git

- 新增 `bashWritePlan`：能推导的目标照旧；无法推导时 `targets=[] + unscoped=true`，不再回退工作区根。
- git 写子命令锁 `.git`；会改工作树的子命令额外标 unscoped。
- `withBashWriteLocks` 对 unscoped 发 `write_scope_unknown`；`OAW_BASH_SCOPE=strict` 恢复旧回退。

### 3.3 会话并发

- `Pi运行时管理.mjs` 默认模型并发 6、Office 2，保留 `OAW_MAX_AGENT_RUNS`/`OAW_MAX_OFFICECLI` 覆盖。
- `流连接.mjs` 的 `/api/agent/stream` supersede 增加 thread 条件。
- `index.mjs` 持久事件使用 `entry.eventClientId`（原始 client），不再写 `client::thread` 复合键。

### 3.4 Skills

- `server/资源发现.mjs`：技能根增加 workspace 的 `.zcode/skills`、`.agents/skills`、`.pi/skills`、`.claude/skills`、`.oaw/skills`，优先级 workspace > project > user。
- 新增 `server/技能目录.mjs`：按 SKILL.md mtime/size 缓存扫描，支持目录 bundle 与平铺 `.md`。
- `_promptEntry` 每轮注入 `buildSkillCatalog`（独立 `skills` 上下文段，预算 10KB）；删除 top-8 快照与 simple/complex 文案。
- `resolveSkillsRouting` 收敛为 `preflight/off/catalog`；`resolveSkillDraftRouting` 只由项目设置决定，默认 `on`；`skill_draft` 仍只写 `.oaw/skill-drafts`。

## 4. 测试

新增：

- `test:version-cas`：revision/冲突副本/短锁/发布 CAS/物化跳过。
- `test:session-concurrency`：并发默认值、流 supersede thread、事件 client 归属、会话键。

更新：

- `test:parallel-write-lock`、`test:write-lock`、`test:bash-locks`、`test:phase1`、`test:phase7`：旧“锁到 Run 结束/回退工作区根/同文件 stage 冲突”断言改为新契约。
- `test:skill-injection`、`test:task-complexity`、`test:office-route`、`test:config-priority`：去掉固定 top-8/复杂度门禁，新增目录预算与 workspace 根断言。

## 5. 验证

- 受影响 `test:*` 全绿；`npm run verify` EXIT=0。
- 真实验收：同一 workspace、同 client 不同 thread 起 3 个任务，写不同目录 + 一个长 bash；另起任务写同一文件触发冲突副本；切换会话确认原任务继续。

## 6. 风险

- 冲突副本会多出文件，需在产物面板/终态摘要标注。
- bash 盲写同一文件仍 last-writer-wins；可用 `OAW_BASH_SCOPE=strict` 恢复强串行。
- 并发默认提高后 provider 可能限流；env 可降回 2/1。
