## 1. 结论先行

四件事都是**收敛**，不是加功能：

1. **去掉一层模型协议**：`complete_task` 让模型多跑一个收尾回合、多维护一套偏好与事件语义，收益低于成本。删除后，**模型最终答复就是结论**，Run 完成状态统一按终态推断（`inferred`）。
2. **输入区从 3 层压到 1 层**：现在「上下文 + 自动批准」悬在消息流上方（`.chat-topbar`），「图片 + 附件 + 地图 + 压缩」又单独一行（`.chat-toolbar`）。合并后：输入框上方只有「本轮目标」，下方只有一行工具条。
3. **Word 预览先修 bug 再减信息**：`已就绪`竖排是 `flex` 收缩导致的真实布局缺陷；在此之上把「已就绪 / Word·浏览器排版 / 专用预览工具栏 / 预览模式·共 N 页」四处重复语义收进一个 ⓘ。
4. **工作区入口只换壳**：把现有「工作区工具」下拉菜单换成卡片面板，每个卡片仍调用原来的 `openCanvasView(...)` / `setCanvasSideOpen(...)` / `taskCenterRef.open()`，**不新增页面、不改页面内部逻辑**。

## 3. 改造方案

### 3.1 complete_task：彻底删除，回到原生收尾

#### 3.1.1 删除原则

- **工具层**：不再定义、注册、白名单、提示。
- **偏好层**：`server/运行偏好.mjs` 只有这一个偏好，整文件删除；`/api/runtime-preferences` 一并删除（本机内部 API，无外部消费方）。
- **事件层**：`task_completed` / `completion_nudge` 不再发射，但**保留注册表条目**并标 `legacy: true`，保证 `.oaw/` 历史事件的回放、筛选与渲染不报错。
- **完成语义**：`resolveRunCompletion` 只走 `inferCompletion`，`source` 恒为 `inferred`；`applyObjectiveDowngrade` 保留（取消/失败/验收失败仍要下调）。
- **模型收尾**：提示词统一改为「直接给最终答复，不要调用收尾工具」；不再有补充回合。

## 6. 风险与回滚

| 风险 | 影响 | 处置 |
|---|---|---|
| 删除 `/api/runtime-preferences` | 本机外部脚本若调用会 404 | 仓库内无其他调用方；变更日志注明；如未来需要偏好，另建通用偏好模块 |
