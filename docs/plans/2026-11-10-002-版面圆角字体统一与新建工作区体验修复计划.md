## 1. 调研结论（三个问题的根因）

### 问题 1a：中间版面与预览版面没有圆角

- 现状：`.center-area`（[styles.css:480](file:///d:/Claude%20code文件/office-agent-web/client/src/styles.css#L480)）、`.chat`、`.app-preview-slot`（[styles.css:5994](file:///d:/Claude%20code文件/office-agent-web/client/src/styles.css#L5994)）、`.docview`（[styles.css:281](file:///d:/Claude%20code文件/office-agent-web/client/src/styles.css#L281)）全部是平铺直角面板，只靠 1px 边框分隔。
- 圆角令牌已存在（`--radius-xs/sm/md/lg/xl/pill`，[styles.css:88-94](file:///d:/Claude%20code文件/office-agent-web/client/src/styles.css#L88-L94)），DESIGN §5.7 有明确档位；但 styles.css 里仍有约 190 处硬编码 px 圆角（4px×71、3px×51、6px×41、8px×34、2px×15、5px×2 等）未走令牌。
- 可以做圆角适配；属于 DESIGN 视觉方向微调，需要本次确认。

### 问题 1b：预览里"文字+图标"展示形式不统一

同一份文件在不同位置用了两套图标语言：

| 位置 | 现状 | 证据 |
|---|---|---|
| 左侧文件树（SessionSidebar） | 扁平彩色 `文件类型图标`（已统一） | [SessionSidebar.jsx:26-30](file:///d:/Claude%20code文件/office-agent-web/client/src/components/SessionSidebar.jsx#L26-L30) |
| 预览页文件树（文件树抽屉） | 文件夹=线框 `Icon folder`，文件=扁平彩色图标，同棵树两种风格 | [文件树抽屉.jsx:137](file:///d:/Claude%20code文件/office-agent-web/client/src/components/文件树抽屉.jsx#L137) |
| 预览页签栏 + 底部文件名行（DocViewer） | 通用线框图标映射 `ICONS[ext]`，不是 `文件类型图标` | [DocViewer.jsx:1024,1040](file:///d:/Claude%20code文件/office-agent-web/client/src/components/DocViewer.jsx#L1024) |
| 产物卡片 / 画布文件树 | 已用扁平彩色图标 | DESIGN §5.8 |

即：**侧栏已是扁平彩色体系，预览区（页签、页脚文件名、画布文件树的文件夹）仍在线框体系**，视觉上"文字+图标"忽粗忽彩、忽线忽面。

### 问题 2：MD 渲染英文/数字与系统格式不统一

- 根因：全局字体栈把 `"OPPO Sans 4.0"` 放在最前（[styles.css:195](file:///d:/Claude%20code文件/office-agent-web/client/src/styles.css#L195)、`--font-emphasis` [styles.css:63](file:///d:/Claude%20code文件/office-agent-web/client/src/styles.css#L63)），而其 `@font-face` 的 `unicode-range` 第一段覆盖 `U+20-7E`（[oppo-sans/index.css:2-8](file:///d:/Claude%20code文件/office-agent-web/client/src/assets/fonts/oppo-sans/index.css#L2-L8)）——**全部 ASCII 英文字母、数字、半角标点都由 OPPO Sans 渲染**，与 Windows 系统字体（Segoe UI）字形不同。MD 正文、表格数字、聊天流全部受影响；不是 MD 链路单独的 bug。
- 等宽代码栈（`SF Mono/Fira Code/Cascadia Code/Menlo/Consolas`）与 KaTeX 不在本次范围。

### 问题 3：新建工作区流程繁琐 + "项目历史崩溃"

**崩溃根因（缺陷，已定位）**：[App.jsx:1639-1685](file:///d:/Claude%20code文件/office-agent-web/client/src/App.jsx#L1639-L1685) `handleWorkspaceChange` 在**调用服务端之前**就执行了 `setHistoryMessages(null)`、`setCurrentSessionId(null)`、`clearDocumentTabs()`；`catch` 分支只恢复 `currentDir` 和 `files`，**不恢复会话与历史**。因此只要切换失败——点了一个目录已删除的项目卡（当前项目列表里确有失效项目 `D:\oaw-canvas\office-workspace`，且 `C:\Users\jijec\.pi\agent\sessions` 被误登记为项目）、或输入了不存在的路径——聊天区历史就被清空，表现为"整个项目历史崩溃"。

**流程繁琐的根因（交互缺陷）**：

1. 新建项目表单只有"项目工作区绝对路径"文本框（[SettingsPanel.jsx:223](file:///d:/Claude%20code文件/office-agent-web/client/src/components/SettingsPanel.jsx#L223)），没有原生文件夹选择器；而工作区切换器里的"选择文件夹"又有（[SessionSidebar.jsx:597-621](file:///d:/Claude%20code文件/office-agent-web/client/src/components/SessionSidebar.jsx#L597-L621)）。两个入口、两套行为。
2. 表单路径默认=当前工作区（[SettingsPanel.jsx:96](file:///d:/Claude%20code文件/office-agent-web/client/src/components/SettingsPanel.jsx#L96)）。**不选新文件夹直接点创建**时，后端返回 `existing: true`（[项目管理.mjs:206](file:///d:/Claude%20code文件/office-agent-web/server/项目管理.mjs#L206)，已实测验证），前端随后 `onProjectSelect` → `closeExternalModules()` 静默关面板并切到现有项目：用户输入的项目名被丢弃、提示语来不及看到、界面无任何变化——"创建了个寂寞"。
3. "新建工作区"语义上还应支持"新建一个文件夹"（如 `D:\新项目2026`），当前只能先去资源管理器建目录再回来选，这是繁琐感的最大来源。

## 2. 修改方案

### 块 1：版面圆角适配（方案 A，待确认）

- 预览版面：`.app-preview-slot` 内的内容区（docview-body / mdview / preview-event-stream 等）加 `--radius-xl` 圆角 + 与栏壁的 8px 内边距，形成"卡片浮在栏里"的观感；栏壁背景用 `--body-bg`，卡片用 `--panel-bg`。
- 中间版面：聊天流容器外层同规格加 `--radius-xl` 圆角（对话列已居中，视觉负担小）。
- 同步把本次触碰的选择器里硬编码圆角改为对应令牌（只改触碰行，不做全文件清扫）。
- 同步更新 DESIGN §5.7（新增"主版面卡片化"条目 + 变更日志 `docs` 记录）。
- 不做：侧栏、顶栏、弹窗不纳入本次卡片化，避免大范围视觉回归。

### 块 2：预览区图标统一（无争议项）

- `文件类型图标.jsx` 增加扁平彩色 `folder` 变体（沿用 `--file-other`/专用令牌色底 + Tabler 文件夹字形），供目录使用。
- [文件树抽屉.jsx:137](file:///d:/Claude%20code文件/office-agent-web/client/src/components/文件树抽屉.jsx#L137)：目录改用 `文件类型图标`（isDir 走彩色 folder），与文件同一体系。
- [DocViewer.jsx:1024,1040](file:///d:/Claude%20code文件/office-agent-web/client/src/components/DocViewer.jsx#L1024)：页签图标与页脚文件名行改用 `文件类型图标`（size=12/14），删除本地 `ICONS` 映射。
- 同步 DESIGN §5.8 说明，并跑 `test:design-tokens`、`test:ui-guard`。

### 块 3：英文字体回归系统栈（方案 A，待确认）

- 把 body 与 `--font-emphasis` 字体栈调整为**系统 Latin 字体在前**：
  `"Segoe UI Variable Text", "Segoe UI", system-ui, "OPPO Sans 4.0", "Microsoft YaHei UI", "PingFang SC", "Hiragino Sans GB", sans-serif`
  → 英文/数字/半角标点由系统字体渲染（与系统一致），中文回落到 OPPO Sans（字体体验保留）。
- 生效范围是全局（聊天流、MD、侧栏、表格），从根上消除"MD 里英文数字与系统不一致"。
- 备选（不推荐）：只改 `.markdown-body`——会造成 app 内部英文数字两套字形，问题 1b 的不统一感会转移到这里。

### 块 4：新建工作区体验与崩溃修复

**4a 修复崩溃（缺陷修复，必须）**

- [App.jsx handleWorkspaceChange](file:///d:/Claude%20code文件/office-agent-web/client/src/App.jsx#L1639-L1685)：把 `setHistoryMessages(null)`、`setHistoryWindow(null)`、`setCurrentSessionId(null)`、`clearDocumentTabs()`、doc 中止逻辑**移入 switch 成功分支**；失败分支恢复原目录/文件清单的同时不再触碰会话状态，仅 `setWorkspaceSwitchError` 提示。失败时聊天区保持原会话原历史。
- 回归测试：新增用例（脚本内单测，仿 `test:ava-sessions` 风格）覆盖"切换失败 → 历史不清空、错误条出现"。

**4b 项目列表脏数据防护**

- `server/项目管理.mjs` `listProjects()`：对每个项目加 `rootMissing: !fs.existsSync(rootPath)` 标记（只读探测，不删数据）。
- 前端项目卡：`rootMissing` 的项目显示"目录缺失"角标，点击弹确认（"该目录已不存在，仍要打开吗？打开将尝试重新指向"），不再静默切换。
- 不做：不自动清理 projects.json 脏数据（删除用户数据需显式确认，走归档入口）。

**4c 新建项目/工作区流程简化（交互，待确认取舍）**

1. SettingsPanel 新建项目表单增加"选择文件夹"按钮（复用 `/api/workspace/pick` + 取消等待，取消时保持原值不报错）。
2. 创建时若 `existing: true`：不再静默切换关面板——表单内就地提示"该路径已有项目 X"，由用户点"切换"或"改名重建"。
3. "新建文件夹"支持：在选择器选中某目录后，若用户在表单里把路径改成不存在的子路径，提供"创建并使用该文件夹"按钮（后端新增一个受审批的 `POST /api/workspace/create`：仅允许在已存在父目录下 mkdir 一层，防路径穿越）。
4. 侧栏"项目"页签的"+"按钮行为改为：打开系统文件夹选择器 → 选完直接带着路径打开设置面板新建表单（少一步找入口）。
