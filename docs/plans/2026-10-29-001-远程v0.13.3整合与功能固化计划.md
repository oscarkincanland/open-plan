## 三、冲突点与解法（合并时只有 3 处需要动手）

| # | 位置 | 冲突 | 解法 |
|---|---|---|---|
| C1 | styles.css 令牌层 | 本地 qoderStyle opt-in 块 vs 远程设计一致性对基线层的修改 | **远程基线为准**；本地 opt-in 块仅在与远程基线无变量名冲突时保留，冲突变量以远程取值覆盖，`--oaw-gray-*` 别名机制沿用 |
| C2 | server/内置浏览器.mjs | feat `waitForCondition` vs 远程 `browserWaitForExpression` 双实现 | **执行期修订：两套共存**。两者接口不同类——远程是 key 级 + 超时抛错 + 布尔返回（G7 导出底座），feat 是 session 级 + 富结果对象（matched/elapsed/url/title）+ 不抛错（工具需要 matched:false 语义）；强行统一必须改远程签名，违背不碰远程原则。已加注释注明分工 |
| C3 | server/agent.mjs 2 个冲突块 | ① run_subagent 编排区：feat 幂等包装 vs 远程 tasks[] 并发重构；② customTools/tools 白名单 | ① 把 feat 的幂等包装**套在远程新结构外层**（内层用远程的 runOrchestration 等价物，不改远程逻辑一个字）；② 白名单取**并集**（远程新增 + feat 4 个浏览器工具名） |

自动合并成功、无需动手：task.mjs、事件注册表.mjs（并集已由 git 完成）、运行开关.mjs、编排器、两个测试脚本。

## 四、整合步骤（每步有验收，先固化后移植）

**Phase 0 — 备份与基线固化（远程为准）**
1. `git stash push -u -m "pre-v0.13.3-本地未提交备份"`（AGENT.MD 命令表 + maps 两文件 + geojson 一并入栈；montbell-price-monitor 移出仓库目录）
2. main 快进到 origin/main（v0.13.3）；`npm install`（lockfile 有变化）；`npm run verify` + CI 18 步全绿
3. 启动服务 + 无头 Edge 冒烟：首页/三模式/一次真实 run（用 minimax-cn）
   ✅ 验收：verify 全绿、冒烟 0 控制台错误 → **固化点 A（v0.13.3 功能基线）**

**Phase 1 — feat 分支能力移植（远程缺失项，一项一开关）**
1. 子代理幂等缓存 + 阻塞冒泡：按 C3 解法重做（在 v0.13.3 的 agent.mjs 上），开关 `OAW_SUBAGENT_IDEMPOTENT`/`OAW_SUBAGENT_BLOCKED_BUBBLE` 默认关；事件注册表补登 2 事件（含 schema）
2. 浏览器原子工具 ×4：按 C2 解法重做（复用远程 browserWaitForExpression），`OAW_BROWSER_ATOMIC` 族默认关；task.mjs 白名单追加（取并集后落位）
3. 每项移植后跑对应测试（子代理编排器/内置浏览器测试的新用例随迁）
   ✅ 验收：`node --check` + 两套测试全绿 + 默认关时行为与 Phase 0 逐字一致 → **固化点 B（能力补齐）**

**Phase 2 — 基线测试重校准**
1. tests/baseline 8 项逐项重跑：预期变化点 = officecli 路由取值、产物证据链字段、文件接口形状（Office P0-P2 可能改了 /api/files 或产物结构）
2. 变化项照实改断言并注明"v0.13.3 起"，怪异行为照旧记录
   ✅ 验收：基线测试全绿且注释与 v0.13.3 行为一致 → **固化点 C（守护网就位）**

**Phase 3 — 体验最优的收尾决策（逐项过，需要你拍板的单独列）**
1. 双实现清理确认：内置浏览器只剩远程等待原语 + 4 个原子工具；无死代码
2. Qoder 开关矩阵最终态：默认全关不变；是否把其中稳定项（如 P2-2 心跳）列入转正队列——**只列清单不实施**
