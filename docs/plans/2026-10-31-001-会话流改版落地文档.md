# 会话流改版落地文档（对话流前端重构）

> 状态：待评审　日期：2026-10-31　类型：前端重构计划（docs/plans）
> 视觉与交互基准：[会话流改版-真实回放-v3.html](../demos/会话流改版-真实回放-v3.html)（已确认稿，下称「确认稿」）
> 关联：R-A bash 兼容回退（server/shell 探测，另立任务）、R-C 输出策略结构化（server/agent.mjs 提示词，本计划 T6 仅引用其数据口径）
> 约束：遵守 `AGENTS.md`；不改 Pi SDK；不新增/改名 SSE 事件（纯前端消费既有事件与消息块）；不引入新依赖。

## 1. 背景与问题定位

本轮改造源于用户对会话流的五点反馈，逐条定位到代码根因：

| # | 用户反馈 | 代码根因（现状） |
|---|---|---|
| 1 | 总结/内容/思考弄混，折叠后边界不清 | `Message`（ChatPanel.jsx:5229）把 thinking/tool/subagent/pipeline/ask/approval/process_note 归入**多个** `<details class="message-process-fold">`（5383-5466），与正文 text 块交错；折叠头只有「执行过程/思考与工具过程」两个字，无时长、无条数 |
| 2 | 容易错位 | 流式期正文走 `flow-stream-text` 纯文本，流完换 `SafeMarkdown` 重排（高度跳变）；SSE 事件轨迹挂最后一个折叠区，与前面工具卡两套展示互相重复 |
| 3 | 字体不统一、层级靠颜色不靠字号 | `.thinking-text` 在 styles.css 950 / 1560 / 9838 三处重复定义；思考 10-12px 灰字、工具卡 11px、正文 12.5px 混排，无统一字号阶梯 |
| 4 | 工具后小结乱、思考长短不一 | 输出策略（server/agent.mjs:62 `buildOutputPolicyLines`）只约束"1-3 句短句、禁 Markdown"，无结构模板（R-C 配套解决，本计划只管渲染） |
| 5 | 结论只有一句话 | `complete_task.summary` 服务端允许 4000 字 Markdown（agent.mjs:2947），但前端事件行截 50 字（事件展示.js:268），完整 summary 只在无产物时进结果卡 fallback，基本不可见 |

参考形态：WorkBuddy「已完成 1m58s ›」整轮折叠 + ①②③结构化结论；zcode 过程流一行式工具条目。

## 2. 目标与非目标

**目标**
- G1 整轮折叠：一轮 Run 收起后只剩一行「已运行 x 分 x 秒 · 工具 N · 文件 N ›」，点击展开完整时间流；运行中显示实时秒数与当前动作。
- G2 时间流一行化：思考/工具/子代理各占一行（图标 + 动作词 + 对象摘要 + 耗时 + 状态点），点击平滑展开明细。
- G3 总结外置：运行框只装过程；框外依次为「本轮总结」（做了什么 → 结论大字 → 详细展开，含表格/代码块，渲染 `complete_task.summary` 全文）与「本轮产物」卡。
- G4 产物卡瘦身：只保留文件行（类型图标 + 名称/路径/大小/打开·定位·回滚），移除目标达成/文件变更/验证三格网格。
- G5 字体收敛：全会话流单一字体族，层级只靠字号+字重；清理重复 CSS 定义。
- G6 动效令牌化：全部动效走 `--dur-fast/base/slow + --ease-out`，只作用于 transform/opacity，支持减少动效降级。

**非目标（本轮不做）**
- 不改 SSE 事件契约、不改 `Run.events` 持久化结构、不改服务端。
- 不做小结/思考的模型端结构化（R-C 负责）；前端只保证"模型给什么就按什么结构渲染"。
- 不做跨 Run 聚合（一次只折叠一轮）；不做时间轴缩放/虚拟滚动（现有消息列表机制不变）。
- 不动 Chat/Review 模式差异渲染逻辑（本改造对三种模式同构生效）。

## 3. 确认稿规格（实施的唯一视觉/交互基准）

## 5. 目标架构

### 5.1 数据层：会话流投影（新模块 `client/src/会话流投影.js`）

职责：把 `blocks[]` 与 `runTrace.events[]` 归约为**有序时间线**，供 RunFold 渲染。实时流与历史回放共用（与 运行轨迹.js 同一原则）。

```js
/**
 * buildRunTimeline({ blocks, events, runTrace }) → TimelineItem[]
 * TimelineItem:
 *   { kind:"thinking", id, text, chars, durationMs }
 *   { kind:"text",     id, text, cap:"阶段结论" }          // 模型阶段小结，不可折叠
 *   { kind:"tool",     id, name, icon, verb, obj, state:"ok|err|run", durationMs, detail, toolCallId }
 *   { kind:"subagent", id, block }                          // 展开态渲染原 SubagentCard
 *   { kind:"pipeline", id, block }
 *   { kind:"ask"|"approval", id, block }                    // 交互块原样保留
 *   { kind:"sys",      id, text }                           // 系统提醒 / steer 播报
 */
```

归约规则：
1. 以 `blocks` 顺序为主轴（保持真实输出顺序，解决"错位"根因）；
2. tool 块按 `toolCallId` 与 `runTrace.tools` 合并：补 duration、state、output 明细（现 `visibleExecutionEvents` 的去重逻辑 ChatPanel.jsx:5350-5372 迁入此处）；
3. SSE 里有、blocks 里没有的工具调用（历史淘汰/重连丢失）按 `tool_end.at` 插入时间线（复用 运行轨迹.js `startMissing` 语义）；
4. `steer`(turn-progress/turn-budget) 与 `[系统提醒]` 归为 `sys` 行；
5. 排序只依赖既有顺序字段，**不新增时间排序**（避免时钟误差再次制造错位）。

### 5.2 组件层（新目录 `client/src/components/会话流/`，从 ChatPanel.jsx 拆出）

| 组件 | 文件 | Props 草案 | 职责 |
|---|---|---|---|
| `RunFold` | RunFold.jsx | `{ timeline, runTrace, live, finishing, durationMs, liveLabel, toolCount, fileCount, verification, defaultOpen, onToggle }` | 折叠头 + 时间流容器 + 收起/展开状态机 + 跟随滚动（迁移 ChatPanel.jsx:5474-5499 的 processOpenMap/follow 逻辑） |
| `TimelineRow` | TimelineRow.jsx | `{ item, expanded, onToggle, renderDetail }` | 一行条目壳：chevron + 图标 + 动词 + 对象 + 耗时 + 状态点 + 明细容器（grid-rows 动画） |
| `SummaryBlock` | SummaryBlock.jsx | `{ completion, durationMs, whatText, conclusionText, artifactsCount }` | 框外总结：做了什么 → 结论 → 详细展开（`SafeMarkdown` 渲染 `completion.summary` 全文；**移除事件展示.js:268 的 50 字截断对消息流的引用**，截断只保留在事件诊断视图） |
| `ArtifactCard` | ArtifactCard.jsx | `{ artifacts, onOpenFile, onLocateRun, onRollback }` | 产物卡：头行 + 文件行（复用 `产物类型.js` 图标与现有 回滚/定位 回调 `onOpenRunChanges`/`onRollbackRun`） |

放置：`Message` 中原 `renderMessageBlocks()` 处改为 `RunFold + SummaryBlock + ArtifactCard` 顺序渲染；`Message` 其余逻辑（版本切换、复制、重发）不动。

  - `.ac-card` `.ac-file-row` `.ac-badge` `.ac-actions`

### 5.4 动效规格

| 动效 | 实现 | 令牌 |

### 5.5 无障碍

- 折叠头与行头均为 `<button aria-expanded aria-controls>`（对齐现 ThinkingBlock 的按钮模式，弃用 `<details>` 以便动画）；
- 状态点/图标一律 `aria-hidden`，语义由文字（完成/失败/进行中）承载；
- 运行中头部 `role="status" aria-live="polite"`（秒数更新不打断读屏）；
- 键盘：Tab 顺序 = 折叠头 → 各行头 → 明细内交互元素；焦点环沿用全局 `:focus-visible`。

## 8. 边界与兼容

1. **历史回放（无 live 状态）**：`buildRunTimeline` 只吃 blocks + Run.events，同构归约；入场动画经 `.static` 关闭；老消息（无 Run 关联的纯问答）不出现 RunFold，维持现有气泡渲染。
2. **运行中 → 结束自动收起**：迁移现有 `processWasLiveRef` 语义（ChatPanel.jsx:5479-5488）到 RunFold；用户手动展开过的轮次在收起时不强制（保留用户偏好 map，key 从 `process-{blockIndex}` 改为 `run-{runId}`）。
3. **ask / approval 挂起**：这类交互块**始终展开**且不可被折叠隐藏（即使轮次收起，待审批条目在折叠头下方以独立卡浮出，沿用现 `pendingApproval` 定位机制）。
4. **错误/取消轮**：折叠头仍显示「已运行 x 秒」+ chips（验收状态按 runConclusion 真实值，如「验收失败」红色）；不显示「失败」大标题——与确认稿「不突出状态词」口径一致，真实语义由 chips 与总结承担。
5. **多文件产物**：产物卡多行；超 8 个折叠为「+N」摘要行（点击展开全部），防止长列表刷屏。
6. **并行 Run**：RunFold 以 `runId` 为 key；同一会话多条运行各自的折叠互不影响（现状 runSummaryById 已按 runId 分组，ChatPanel.jsx:4063）。
7. **流式正文**：流式期间时间流 text 行直接用现有 `readableProgressText`；流结束换 SafeMarkdown（现状行为保留，但重排发生在行内，不再影响折叠头高度）。
