# 对话运行终态与产物归属修复计划

> 状态：已实施（待用户验收）　日期：2026-10-28　分支：`feature/zcode-harness-align`
> 关联需求：R3 对话流与运行可信度、R5 会话管理

## 一、目标

1. 任务结束后不再追加文本、不再把界面拉回“运行中/收尾中”。
2. 本轮产物不再混入其他 Run / 会话的写入。
3. 同一会话多轮任务时，“本轮产物”默认跟随最新 Run；查看历史轮次有明确标识。
4. Office Word/PPT/Excel 的预览能力与限制在界面上说清楚，并提供必要的高保真回退。

## 二、分阶段

### Phase A：运行终态围栏

- [x] `server/runs.mjs`：终态 Run 的迟到事件只写 `lateEvents`，不再进入 Run 事件流/全局事件流。
- [x] `server/agent.mjs`：`emit` 在推送前检查 `isRunTerminal`，终态事件只审计。
- [x] `ChatPanel`：`finishedRunIdsRef` 终态围栏；`agent_end` 守卫；无终稿也收尾流式气泡。
- [x] 过程区在 `agent_end → run_finished` 之间显示“收尾中”。

### Phase B：产物归属精确化

- [x] `filterRunChanges`：具体路径存在时忽略 `.` 通配。
- [x] `finalizeFileChanges`：只有 `write-ledger` 自动可交付；目录前缀可归台账。
- [x] `withNormalizedAttribution`：不再把 `unattributed` 追溯升级。
- [x] mtime 兜底收紧到 `startedAt`；同工作区有其他 active Run 时禁用。
- [x] 产物面板把 `run-window/unattributed` 单列为“疑似变更”，不计入本轮产物；会话范围按路径去重。
- [x] “本轮”默认跟随最新 Run；钉住历史轮次时标题与提示明确。

### Phase C：预览与刷新收敛

- [x] `file_changed` 500ms 合并刷新。
- [x] 任务结束自动打开产物增加焦点/输入/其他文件守卫；被挡住时在工具菜单提示“本轮新产物”。
- [x] 产物面板刷新 350ms 合并，隐藏时跳过；只对含产物的 Run 查询验收。

### Phase D：Office 预览能力

- [x] Word 增加 OfficeCLI 高保真只读回退；简化编辑保存前强制警告。
- [x] Excel 网格标注“仅显示单元格值”，增加 OfficeCLI 高保真只读预览。
- [x] PPT 标注 Canvas 不播放动画/文本不可选。
- [x] 新增 `client/src/预览能力.js` 能力矩阵与 `test:office-preview`。

### Phase E：测试与文档

- [x] 新增 `test:run-attribution`：归属优先级、`run-window` 不可自动交付、终态围栏。
- [x] `test:startup` 增加终态围栏/范围/Office 源码契约。
- [x] 更新 `变更日志.md`、`DESIGN.md`、`REQUIREMENTS.md` 与实施记录。

## 三、验收口径

- 先发 `run_finished` 再注入 `token/assistant_final/agent_end`：消息文本、状态、busy 均不变。
- 同工作区两个并发 Run：各自产物不交叉；`run-window` 不计入本轮产物。
- 同会话连续两轮：第二轮“本轮产物”只显示第二轮；钉住历史时明确标识。
- 任务结束后 10 秒内无残留实时状态、无反复预览重载。
- Office：Word 可切高保真；Excel 明确值/格式限制；Word 保存有警告。

## 四、风险与回滚

| 风险 | 处理 |
|---|---|
| 收紧 mtime 兜底降低 bash/officecli 产物召回 | 保留“疑似变更”可见区；仅并行 Run 时禁用 |
| 终态围栏误丢审计事件 | 迟到事件写 `lateEvents`，可审计不进 UI |
| 自动打开守卫让用户错过新产物 | 工具菜单“本轮新产物”入口 + 文件树高亮 |
| OfficeCLI 高保真渲染开销 | 只在用户手动切换或浏览器渲染失败时调用 |
