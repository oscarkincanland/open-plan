- 影响：正常路径（网络/服务正常）下刷新很快，满足 1s；但**只要 style.json 的这一次 fetch 失败/超时/服务端尚未完成原子写**，token 已被消费且无轮询兜底 → 预览永久停在旧样式，直到下一次文件变更。即"1 秒内刷新"存在无法保证的失败路径（与 Lead 线索 b 一致）。
- 建议：`reloadStyleNow` 失败时不消费 token（或用 `reloadState` 计数 + 有限重试 2–3 次，间隔 200ms）；readOnly 模式下增加低频兜底（如可见期 10s 一次 hash 比对）。

#### FE-MAP-08 `map_action` 渲染重试 interval：无卸载清理、事件重叠时可能乱序显示

- 类别：状态竞态
- 证据：`MapPanel.jsx:1734-1764`
  ```js
  let attempts = 0;
  const render = () => {
    attempts += 1;
    const rendered = mapRef.current?.showAnalysis(action);
    if (rendered || attempts >= 12) { clearInterval(timer); syncTempLayers(); }
  };
  const timer = setInterval(render, 250);
  render();
  ```
  每个 `map_action` 事件创建一条独立 interval（最长 3s）；无 `useEffect` cleanup，组件卸载 / 项目切换后 interval 仍会运行（`mapRef.current` 变 null 时最多空转到 12 次）。连续两次分析（如 Agent 连续调 `map_analyze`）会产生两条 interval，后到的 action 先渲染、先到的 action 可能在后（若 style 未就绪）——同 id 时最终显示哪个取决于时序。
- 影响：偶发"地图显示的是上一轮分析结果"；卸载后多余 setState（React 18 不报错但浪费）。
- 建议：用 `useRef` 保存当前 render session id（每次 handleMapAction 递增），旧 session 的 interval 自行退出；`useEffect` 卸载时清理。

## 9. Lead 线索逐条核验

- **b) 只读预览不轮询 style、依赖 App file_changed → 存在 1s 承诺无法保证的路径 → 成立（P2，FE-MAP-07）**。正常路径很快（事件同帧递增 revision，`App.jsx:2132`）；失败路径为 `MapViewer.jsx:720-726` 先消费 reloadToken 再 `void reloadStyleNow()`，失败无重试且 readOnly 无轮询兜底（`:627-644`）。另 `styleHash` 弱（`:20`）导致轮询不可靠（FE-MAP-11）。
