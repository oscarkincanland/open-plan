| # | 结论 | 关键证据 |
|---|---|---|

## 3. 为什么"改完还会再坏"——四个结构性原因

### 3.1 形态没冻结就动代码（会话流为什么是第一返工区）

- 15 天内《会话流前端规范》从 2.0 升到 2.11（12 版）；
- 折叠形态变过 5 次（运行中不折叠 → 去掉内部滚动 → 改平铺 → 换位置 → 结论默认折叠 → v3 重做）；
- 阶段小结被移动过 5 轮（术语 → 空白 → 间距 → 对齐 → 压缩 → v3 归位）。

**病理**：每次都是"在旧形态上打补丁"，而不是先定"这一层到底应该长什么样（信息层级 + 谁能折叠谁不能）"，再一次性改。补丁之间互相覆盖，于是同一处反复。

### 3.2 双实现并存 + 开关只加不减

`ChatPanel.jsx` 同时存在：`renderTimelineItem`（新）、`renderMessageBlocks`（旧）、`ExecutionFlow`（更旧的事件流）、`SummaryBlock`（结论卡）、`RunSummary`（旧运行卡）。**5 条渲染通道并存**。

- 用户在中断后看到"老式 SSE 界面 + 箭头"，就是旧通道没被 v3 覆盖；
- 本次会话里我删 `SummaryBlock` 时，没意识到"最终答复是双通道"（隐藏文本块 + 结论卡），于是**部分轮次结论直接消失**。

### 3.3 "静态验证"冒充"运行时验证"

| 验证手段 | 能发现 | 发现不了 |
|---|---|---|
| `node --check` / `vite build` | 语法、导入、类型级错误 | 作用域运行时错误、hook 规则、渲染分支异常 |
| 文本断言型测试（226 个脚本） | 代码里"有没有这段字符串" | 组件能不能真的渲染出来 |
| `npm run verify`（只串 2 个脚本） | 服务端 API 结构 | 前端渲染 |
| CI 67 步（实际只跑 64 个脚本 ≈ 28% 测试） | 被串进去的部分 | 另外 72% |

**历史原话**（`变更日志.md:2146`）：
> "该 bug 说明合并冲突消解需要'运行时验证'而不只是'代码能编译'——`npm run verify`、49 步 CI 全绿都发现不了它（TDZ 只在特定分支执行时才抛）。"

**这条结论 11-02 就写下了，但 11-15 又原样复发**（见 §4）。说明"写下结论"不等于"建立机制"。

而项目里**已经有**能抓这类错误的脚本 `scripts/聊天界面冒烟检查.mjs`（`npm run smoke:chat`，用真实浏览器抓 `组件出错，请刷新页面` 与 pageerror），但它：
1. **不在 `npm run verify` 里**；
2. 默认调用时选中的会话消息数为 0（本次实测"消息条数: 0"）——**空会话不会渲染消息组件，等于没测**。

### 3.4 既有失败被长期容忍 → 门禁失真

- 40 处"既有失败"分布 22 个文件；`test:ui-guard` 红跨 4 份计划（11-09 → 11-11）仍照常提交；
- 提交说明里开始出现固定句式："XX 测试通过，`npm run verify` 的 API 冒烟因 kb.json 指向未挂载的移动硬盘阻塞（环境问题，与本次无关）"——**当"绿色"需要附带免责声明时，门禁已经失效**；
- 后果：新增回归与既有失败混在一起，**无法区分**（这正是 §7.1 提交门禁第 3 条要防的）。

## 5. 共性根因（跨历史与本次会话，5 条）

1. **没有"运行时契约"**：项目有 226 个测试脚本、230 个 `test:*`，但绝大多数是**文本断言**（"代码里有没有这句话"）。它们能防"改回去"，防不了"跑不起来"。
2. **渲染层多通道并存，且没有"通道清单"**：5 条渲染路径，改动时靠记忆判断改哪条——历史 9 次双实现类 bug、本次 2 次（结论丢失、旧 UI 复现）都是这个。
3. **交互形态靠目测迭代，没有几何/样式断言**：间距、折叠、对比度反复 8 轮以上；本次"颜色没变"也是因为没有断言计算样式。
4. **作用域/生命周期类错误没有护栏**：TDZ 历史 6 次 + 本次 2 次 ReferenceError + 1 次 hook 嵌套。这类错误编译器不报、单测不跑、只有渲染才炸。
5. **文档是"追认"不是"约束"**：计划与实现同提交、规范自相矛盾、ADR 只增不减（0 条被替代）——文档越写越多，约束力反而下降。

## 7. 可沉淀的经验与教训

### 7.1 五条"血泪"教训（每条都对应上面一个根因）

| # | 教训 | 反面教材 |
|---|---|---|
| L1 | **能编译 ≠ 能运行**。改任何渲染分支，必须跑一次"真实打开页面"的冒烟，且**必须是有消息的会话** | 本次 1/2 两个 ReferenceError；历史上 6 次 TDZ |
| L2 | **删通道前先列数据来源**。一条信息如果有多条渲染通道，删掉一条前要回答"另一条是否覆盖它" | 本次删除结论卡导致结论丢失 |
| L3 | **样式改动必须量证据**（`getComputedStyle` / `getBoundingClientRect`），不能看规则就宣布生效 | 本次颜色两处未生效、历史间距 8 轮 |
| L4 | **结构化代码禁止文本级补丁**（sed/正则替换）。JSX/hook 结构必须整体重写或精确锚点 | 本次 hook 嵌套导致 React #321 |
| L5 | **开关是"减法"不是"加法"**：加开关时就要列出"这个开关关闭时必须不生效的所有旁路" | 本次旧 ExecutionFlow / marquee 漏网 |

### 7.2 可直接照抄的检查清单（建议进 PR 模板）

```
[ ] 改了渲染分支？→ 打开一条有消息的会话，确认无「组件出错」
[ ] 改了折叠/滚动？→ 折叠前后锚点位移 ≤ 2px，且无长帧
[ ] 改了样式层级？→ 记录 getComputedStyle 实测值（颜色/字号）

[ ] 引用新变量？→ 确认声明在**同一组件作用域**（不是父组件的）

```
