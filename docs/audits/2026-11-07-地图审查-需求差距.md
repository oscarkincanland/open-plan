## 6. 需求歧义 / 自相矛盾 / 非目标越界

1. **A1 "Chat 只读"的作用域**：R10 需求与验收均以"地图 Agent 工具"为上下文（REQUIREMENTS:246-247,262），但验收句"Chat 只能只读查询/临时可视化；写图层需 Work + 审批"可被解释为包含地图 UI 手工操作。当前实现在 Agent 工具层严格执行、在 UI 层仅部分拦截（替换数据拦截、导入/样式/删除/转正不拦截），导致同一验收点无法给出一致结论。**建议澄清并二选一**：a) 验收限定"Agent 工具层"，UI 手工编辑视为用户显式操作（需在 PRD 注明）；b) 要求 UI 同样按模式禁用写入口并补测试。
2. **A1 "审批"边界**：`map_save_analysis` 声明 `needsApproval:true` 但无 ask 规则（后端 P1-1），与"写工具仅 Work + 审批"矛盾；同时用户手工转正走 REST，不经过审批策略。**审批是否覆盖"用户在 UI 上点保存"未定义**。
3. **A3 演示数据标注口径**：未定义标注载体（`provenance.demo` 字段 / "演示数据"文案徽标 / 文件名后缀 / 报告水印）。当前 demo-analysis 用 `source:"demo"` + 卡片文案、柬埔寨用 `status==="demo"`、新昌内置用 `bundled-*` 命名、M2 无标注。**建议定义统一字段 `provenance.demo=true` + UI 文案 + 导出文件/报告标注三件套**。
4. **A13 "1 秒内刷新"**：未定义触发条件（仅 agent 写正式文件？用户手工保存？）、测量点（SSE 事件到首帧？style 请求完成？）与降级策略（轮询 3 秒）。live H10 证明的是"收到 file_changed 后重新请求 style"，并非严格 1 秒 SLA。**建议改为"事件到达后一次刷新"或明确降级容差**。
5. **R10-11 "临时层…可转正的分析结果" vs DESIGN"临时层可转正"**：R10 限定"分析结果"，DESIGN §9.3:366 写"临时层…转正（弹窗填写名称与分组）"未限定；实现仅分析结果可转正。**属于范围歧义**，需统一。
6. **R10-18 "五项"只列四类**（见漂移 #7），且"默认开启"未说明关闭后入口是隐藏还是报错（GIS PRD 要求"隐藏入口而不是报错"，实现按 flag 条件渲染，基本符合）。
7. **单活动画布 vs 画布页签**：ADR 0018 规定"不提供多画布标签页"，但右侧工作区画布存在"地图预览"标签；R10-16 又要求预览标签。**当前实现用"地图预览 = 只读镜像，不参与活动画布"自洽**，建议在 ADR 0018 补一句避免误读为"多画布"。
8. **非目标越界风险**：GIS PRD 的"项目打包/模板/设置开关/复制与模板起点向导"扩展超出 R10 原文；若按 AGENTS §3 严格执行，应回写 PRD 后再实现，目前是"先实现/先声明、后未回写"。
