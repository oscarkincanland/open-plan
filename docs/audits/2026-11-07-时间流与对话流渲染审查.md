## 3. "有时候会自己去调整"：定位到 4 个机制

### 3.1 真 bug：跟底滚动被高频 token 饿死（已修）

```js
// 旧实现（ChatPanel.jsx）
useEffect(() => {
  if (scrollTimerRef.current) clearTimeout(scrollTimerRef.current);   // 每次都清
  scrollTimerRef.current = setTimeout(() => { …scrollTo(bottom)… }, 60);
  return () => { if (scrollTimerRef.current) clearTimeout(scrollTimerRef.current); };  // 再清一次
}, [messages]);
```

流式打字约每 16ms 改一次 `messages` → effect 每次都清掉并重建 60ms 定时器 → **定时器永远等不到触发**。表现就是"有时跟到底、有时停在中间不动"。修复：已排队则复用（`if (scrollTimerRef.current) return;`），定时器触发后自清，卸载时统一清理。

### 3.2 运行态 vs 终态的形态差异（设计如此，可改进）

- 运行中出现「已运行 xx」（`.tl-elapsed`，12px 独立行），终态由折叠头承担 → **条目高度在结算瞬间变化**（规范 §2.1 的既定行为）。
- 运行中时间流每新增一行播放入场动画 `tl-row-in`（`translateY(6px)`，`styles.css` `.tl-list.is-live > *`）→ 视觉上"内容在动"。

### 3.3 思考预览从跑马灯切静态（设计如此）

运行中最后一条思考的"对象"是滚动预览（`.tl-think-preview`，`max-width: 320px`），结算后变静态「内部推理」→ 行宽变化。

### 3.4 思考正文内部滚动（设计如此）

`.tl-thinking-text` 有 `max-height: 220px` + 内部滚动；展开长思考时滚轮作用在内层，不完全跟随外层，容易被感知为"页面自己在调整"。

> 3.2–3.4 均为规范既定形态，本次**未改动**（改动会影响运行态语义）。如果希望消除结算瞬间的高度跳变，建议做"用时行高度预留"，需产品确认后再动。

## 4. 附带发现：思考档位显示「默认」的真因

用户反馈"默认思考程度应该是高"。实机核查：

- `localStorage.oaw_thinking_level` 现在是 **`high`**（一次性迁移生效），
- 但工具栏显示「思考：默认」，因为**当前会话使用 `Claude Haiku 5.5`，该模型 `thinkingLevels = ["off"]`**——它根本不支持推理档位，界面按"当前模型可用档位"降级显示。
- 全库 86 个模型中 **84 个支持 `high`**；切到 DeepSeek / MiniMax 等模型即会显示「高」并在发送时下发 `effort=high`。

同时修掉一个会"吞掉用户偏好"的缺陷：旧代码在模型不支持时把降级结果**写回 localStorage**，从支持 high 的模型切到只支持 off 的模型再切回，用户的「高」会被永久改成「默认」。现在只对"有效档位"降级，偏好值保持不动。
