## 1. traffic-material 14 份逐份结论

### 1.1 总体评价

14 份模板结构统一（定位→骨架→格式规范→逐章要点→图表规范→案例出处→常见错误→自检清单），且有两个突出优点：

1. **实测依据充分**：字体/字号/边距/行距均标注来源案例（温州 TIR、金华十五五、宁波公交 PDF 实测等），`00_格式数据汇总` 与 `00_总览通用规范` 明确"执行口径以总览为准"，版本关系清楚。
2. **交叉引用一致**：04↔05（可研/预可互引）、02↔03（条文式与叙述式"二者择一"）、07↔12（交评四案例对比）、10↔12（评审配套引用）均核对无误；格式口径全库一致（公文档 3.7/3.5/2.8/2.6cm、报告档 2.5/2.5/3.2/3.2cm，00 总览与各详版无漂移）。
3. **数值自洽**：抽验 09 需求预测表（1500→4500 万吨、2024–2035 年均 10.5%）等算术正确；08/11 指标表口径一致。

### 1.3 问题清单

#### P0（影响产出质量，建议尽快修）

- **P0-1（03 结构缺陷）**，`templates/traffic-material/03_规划文本条文式模板.md`：
  - §3 编号断档：`3.1 页面与字体` 后直接 `3.3 编号规则`，**缺 3.2**；
  - §4「逐章写作要点」开头残断：`## 4` 标题后是孤句"写客流走廊变化、机动车增长…"（应属"第3条 交通发展趋势"一类标题被删）；**第一章总则的 8 条（第1–8条）完全没有逐条要点**，第二章前 3 条（发展趋势/城市发展/交通趋势）也只有这半句；
  - **§5 整节缺失**：章节从 `## 4` 直接跳到 `## 6 文本与说明书分离模板`（对照同族文件，§5 应为逐章要点续编或其他专项变体）。
  - 影响：agent 按此模板写条文式文本时，总则与趋势章会缺结构参考，且 §4 残句会污染产出。

#### P1（数字/引用复核，影响权威性）

- **P1-1（05 服务水平分级存疑）**：`05` §4.3 写"公路服务水平分四级（V/C ≤0.6 / 0.6–0.8 / 0.8–1.0 / >1.0）"，这是 JTG B01-**2003** 框架；而 04/05/06 的编制依据均引用 JTG B01-**2014**，2014 版对高速公路/一级公路服务水平采用**六级**划分。**待按现行标准复核后更新**（审查按存疑标注，未下最终结论）。
- **P1-2（05 通行能力内部矛盾）**：同节先列"双向四车道一级公路通行能力：20000–30000 pcu/d"，随后又写"远景年交通量超过 20000 pcu/d 应选六车道"——与自身区间矛盾，需统一口径。
- **P1-3（09 标准引用年份）**：`09` §一/1.2 引用 GB 50072-**2010**《冷库设计规范》——该标准已被 GB 50072-**2021**《冷库设计标准》替代；GB 50016-**2014**《建筑设计防火规范》的部分条款已被 GB 55037-**2022**《建筑防火通用规范》承接，建议补注；GB/T 21334 版本年份待复核。模板已有"引用时须核对现行有效期"的通则，但具体条目应直接更新为现行版本。

#### P2（维护性）

- **P2-1（06 遗留注记 + 缺自检清单）**：`06` §六末尾残留编辑期注记"（本节图表清单待与 5.2/5.3 必备清单合并，见后续结构整改；本次不改动结构）"；且 06 是 10 份文体详版中唯一没有"自检清单/报批前校核"章节的（其余均有）。
- **P2-2（12 的定位与提示词口径）**：12 是维护文档（蒸馏方法备忘 + 后续优先级），不是写作模板；`agent.mjs:1481` 与 `工作区初始化.mjs:28/54` 把它当"14 类模板"之一列出，agent 引用 `@模板[12_素材库深挖]` 得到的不是骨架而是 backlog。12 §五 P0 行"低空规划 OCR → 第十一套模板"的说法也与现状（已编到 11_PPT汇报）不符。
- **P2-3（无完整性校验）**：仓库没有针对 traffic-material 的完整性测试，03 的编号断档/整节缺失这类缺陷 CI 抓不住（本次审查靠人工通读发现）。建议加一个轻量脚本：校验标题编号连续、模板清单（14）与 agent 提示词文案一致。

## 2. OpenDesign 模板库（templates/opendesign）盘点

### 2.1 结构与体积

| 项 | 值 |
|---|---|

### 2.2 有用性判断（对照产品目标）

产品目标是"PPT 与 HTML 汇报材料"（创作画布模板库方案 1.1 节）。据此分四档：

1. **核心有用（贴合汇报目标）**：47 个 `html-ppt-*` 演示风格（32 款 zhangzara + 15 款专题：tech-sharing / pitch-deck / weekly-report / xhs-white-editorial 等）+ 2 个集合（html-ppt 内含 36 主题/31 单页版式/动画，guizang-ppt）——agent 提示词明确以此为风格参考生成 HTML PPT，合计仅 **3.0MB**。
2. **通用汇报周边（可留）**：dashboard/live-dashboard/kanban-board、docs-page/blog-post/meeting-notes/weekly-update/pm-spec/eng-runbook、magazine-poster/image-poster、digital-eguide/finance-report/team-okrs、simple-deck/kami-deck/open-design-landing-deck 等，约 25 个，合计 <1.5MB——做网页汇报/看板类作品时可用。
3. **弱相关（拍板项）**：web-prototype×4、wireframe×4、saas-landing/pricing-page/mobile-app 等 Web 产品原型类，约 12 个——交通规划工作台基本用不上，但留着成本很低。
4. **无关或异常（建议移除）**：
   - `open-design-landing`（22.4MB）：OpenDesign 上游项目**自己的落地页模板**，巨型资产；Icon.jsx 的品牌 SVG 已内联，无运行时引用；
   - 纯无关类：dating-web、clinical-case-report（临床病例）、dcf-valuation、x-research、audio-jingle（音频模板）、video-shortform、sprite-animation、webgl-experience、hyperframes、email-marketing、invoice（发票）、contact-widget、gamified-app、orbit-gmail/notion/linear、waitlist-page、last30days、tweaks 等；
   - 8 个无 example.html 的目录中，dangling 的（dcf-valuation/hyperframes/last30days/replit-deck/x-research）模板库 UI 根本展示不了，属"死目录"。

### 2.3 引用链与误导项

- `server/tpl.mjs:32`：UI「HTML PPT（OpenDesign）」分类的唯一扫描入口，只收录 example.html → UI 实际展示 106 张卡片。
- `server/agent.mjs:1480/1482`：提示词让 agent 用 example.html 作风格参考；**数字过期**（"157 个/64 款"，实际 114/106、html-ppt-* 47 款）；示例引用的 4 个模板名均存在，引用有效。
- `client/src/components/Icon.jsx:225`：仅注释提及 open-design-landing/assets/agents（SVG 路径来源说明），**图形已全部内联**，无文件级依赖。
- `templates/opendesign/AGENTS.md`：**上游项目文档残留**——描述的 `/api/design-templates` 注册表、`od.mode`、New-project 面板等机制在本项目不存在（本项目走 tpl.mjs），对本仓 agent 有误导性，应替换为本项目口径的 README。

## 5. 审查局限

- 14 份模板的**领域判断**（章节逻辑、句式规范）基于交通规划通行实践与模板自身标注的实测来源交叉核对；未持有原始案例文件（模板已声明"案例库不随仓库分发"），实测值无法二次验证。
- P1-1（服务水平分级）为"待复核"而非定论；建议修 05 时对照现行《公路工程技术标准》原文。
- opendesign 各 example.html 未逐一渲染验收（106 个）；本审查只验证了入口完整性（example.html 存在）与引用链，未验证每个模板的渲染质量。
- 未核查历史会话中 agent 实际引用过哪些 opendesign 模板（.oaw 运行数据不在本次范围），"是否真的有用"的结论基于产品目标与引用链，不是使用频率统计。
