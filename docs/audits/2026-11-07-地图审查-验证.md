### 2.2 环境受限项的等价复跑（可写临时副本）

**环境根因**（非仓库缺陷）：
- 命令沙箱运行在 **Low Mandatory Level**；工作区根目录有一条 `S-1-4-304231729-134653416 Allow Write/Delete（ContainerInherit,ObjectInherit）` 的沙箱 ACE，但既有子目录（`office-workspace`、`docs`…）没有该 ACE（不继承），因此 node/pwsh 在仓库子目录写文件一律 `EPERM`；在工作区根**新建**目录可写（继承 ACE）。
- **嵌套进程创建被拒**：node 内 `spawnSync/execFileSync/execSync` → `EPERM`（实测 `spawnSync cmd.exe EPERM`），因此任何依赖子进程的测试（gis-flags、amap-mcp）和 Playwright 浏览器启动在沙箱内不可能完成；pwsh 顶层启动 node 正常。
- localhost 网络可用（`GET http://127.0.0.1:3002/api/status` → 200），故 HTTP 契约可探测。

**处置**：把仓库（server/scripts/client/src/docs/office-workspace/package.json/node_modules 等）复制到工作区根下临时目录，`cwd=副本` 重跑写盘型脚本（`PROJECT_DIR` 随 `import.meta.url` 指向副本，写盘落在副本内，不触碰真实 workspace）。结果：

### 4.3 `persist:false` 在刷新/历史恢复时的行为（证据）

1. **不落盘**：`server/事件存储.mjs:8` 引入 `PERSISTED_TYPES`，`appendEvent` 用它判定是否写 `.oaw/events/事件流.jsonl`（`事件存储.mjs:27,221`）。`map_action` 不在 `PERSISTED_TYPES` → 不写盘。
2. **实测无落盘**：当前活动事件流 `.oaw/events/事件流.jsonl`（约 2.0MB）全文检索 `map_action` → **0 命中**，与登记一致。
3. **仍在内存通道历史**：`lifecycle:true` 且非 delta 事件 → 写入 SSE 通道历史，受 `MAX_MEMORY_EVENTS=20000` 限制；同一服务进程内重连/回放可再收到 `map_action`（前端无专门重放恢复代码，只有 ChatPanel 的系统提示与 lastMapVisual 状态）。
4. **刷新/重启影响**：
   - 页面刷新（服务未重启）→ 分析临时层是前端 MapLibre 运行时图层，刷新即丢；是否依赖通道回放重建未验证（live 未跑）。
   - 服务重启/历史会话恢复 → `事件流.jsonl` 无 `map_action`，无法回放；`entry.lastMapAnalysis` 仅内存（`agent.mjs:3523/3564/3577/3629`）丢失 → `map_save_analysis` 必走 `agent.mjs:3655-3656` 的"当前没有可保存的地图分析结果，请先生成热力图或等时圈"，即使会话中能看到此前的分析提示。
   - 结论：这是登记表声明的设计语义（"前端实时更新，不落盘"），但**用户侧的"可保存"窗口与刷新/重启强耦合**，建议产品侧确认是否需要在恢复时重建 `lastMapAnalysis` 或持久化分析快照。

### 4.4 `write_started` / `write_locked` 与地图写工具

| 工具 | write_started | write_locked | 写盘方式 |
|---|---|---|---|
| map_edit（agent.mjs:3187-3192） | 1 条（`maps/<name>/style.json`） | 1 条 | 直接 `atomicWriteFile` 写 style.json |
| map_import（agent.mjs:3254-3256） | N 条（逐文件） | 1 条（`maps/<name>`） | map.importLayer（临时目录+rename） |
| map_save_analysis（agent.mjs:3677-3679） | 4 条（geojson/-lines/style/config） | 1 条 | map.importLayer |
| 通用 stageWrite（写入协调.mjs:453-455） | 1 条 | 1 条（**同 data、恒成对**） | 暂存+发布，有版本 CAS |

- 顺序与语义：三者都是"先取锁 → 再发 write_started/write_locked"，与 `写入协调.mjs stageWriteLocked` 一致。
- 偏差：地图导入/保存是 **N:1**（多条 started、单条 locked），违反注册表备注"write_locked 与 write_started 恒成对"（`事件注册表.mjs:59`）。前端只用它们做 phase/label（`事件展示.js:75-77,185-186`），暂无功能影响 → **P3**。
- 关键差异：地图样式/分析图层写入是**手工补事件、绕过 stageWrite/publish 管线**（无版本 CAS、无 write_stale/artifact_conflict、无回滚）；`map_save_analysis` 还会对同一 Run 连续写 4 个文件。
- 与 `map_action` 无联动：保存成功走 `file_changed` + 前端 `loadProject/reloadStyle`；`map_action` 只在内存临时层链路使用。
