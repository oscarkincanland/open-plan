## 0. 结论摘要

地图模块是当前产品功能面最宽的模块之一：MapLibre 矢量瓦片、QGIS 风格图层树、属性表、测量绘制、工程化（schema v2 / 基线 / 回收站 / 操作日志 / 图层注册表）、会话地图绑定、项目文件树、初始页只读预览、Agent 地图工具链都有真实实现，不是"文档功能"。

但审查发现 **1 个 P0 级断点、约 10 组 P1 级问题**，集中在"Agent 协作编辑"与"安全/一致性"：

| 结论 | 数据 |
|---|---|
| 需求条目（R10 + 验收 + 硬约束 + DESIGN + v0.13.x 增量） | 60 条：满足 37 / 部分满足 19 / **未满足 4** |
| 后端与 Agent 协作编辑 | 35 条：**P0×1、P1×7**、P2×16、P3×11 |
| 前端交互 | 27 条：P0×0、**P1×4**、P2×11、P3×12 |
| 测试执行（非 live，含等价复跑） | 可判定 14/17 通过（82.4%）；**1 个真实红测**（HEAD 遗留断言过期）；3 个 live 场景未跑 |
| 最关键断点 | `map_save_analysis` 引用未定义变量 `name` → Work 模式"把分析结果保存为正式图层"**100% 抛 ReferenceError** |

### 0.1 立即需要处理的 7 件事（按优先级）

| # | 问题 | 后果 | 证据 |
|---|---|---|---|

### 0.2 一句话判断

> 地图的"展示与编辑"已经可用，"工程化底座"超出文档预期；但 **Agent 协作编辑的写入语义仍是"单写者、无事务、无审批闭环"**，核心约束（坐标、记录数、共享数据、锁定、模式边界）只在部分入口成立。当前版本不建议对外承诺"Agent 可靠协作编辑地图"，应先修 P0/P1 再谈交互打磨。

### 2.2 三条关键链路

**A. Agent 编辑正式层（同会话闭环）**

```
用户对话 "隐藏高速公路/改颜色/导入图层"
  → ChatPanel 提交 task（含 mapProject，ChatPanel.jsx:4060）
  → agent.mjs 工具 map_edit / map_import / map_save_analysis
  → requireToolApproval（审批策略）→ withPathWriteLock（写入协调）
  → 写 style.json / layers/*.geojson / map.config.json / tiles
  → write_started + write_locked + file_changed（SSE，仅当前会话通道）
  → App.handleFileChanged（App.jsx:2106-2134）→ mapPreviewRevision + mapBridgeRef.onFileChanged
  → MapPanel.handleFileChanged → loadProject + MapViewer.reloadStyle
  → MapViewer 另有 3 秒轮询 style.json 兜底（MapViewer.jsx:627-644）
```

结论：**同会话内基本闭环**；问题在失败回滚、并发、审批与跨会话同步，不在"改了看不到"。

**B. Agent 分析临时层（设计为不落盘）**

```
map_analyze（演示/数据源/空间分析）→ emit map_action（persist:false，事件注册表.mjs:168）
  → ChatPanel 消费（ChatPanel.jsx:3485-3504）→ onMapAction
  → MapPanel.handleMapAction（MapPanel.jsx:1733-1764）→ MapViewer.showAnalysis
  → 临时层只存在于 MapLibre 运行时；刷新/重启不恢复（PRD/R10 已承认"临时分析层不回放"）
  → style 重载后由 图层注册表.js / analysisPayloadsRef 重放
```

结论：符合"临时层不落盘"的设计取舍，但导致三个衍生问题：清单识别、单删复活、`map_save_analysis` 依赖 `entry.lastMapAnalysis` 内存态（重启后"无可保存结果"）。

**C. 用户手工编辑（REST 直写）**

```
MapPanel / LayerPanel / 属性对话框 → api.js → /api/map/style|config|import|layer|reset...
  → server/map.mjs saveStyle/writeStyle/importLayer...
```

结论：**完全绕过 Agent 的工具审批、写锁与 `operations.jsonl` 的部分记录**，与链路 A 形成两套写入事实源，是协作编辑丢更新/状态漂移的结构性原因。

### 2.3 协作编辑语义现状

- 写入是"最后写入者获胜"：`style.json` / `map.config.json` 无 revision 字段，无 CAS，无乐观锁。
- 两套写路径（Agent 工具 / REST）只在"同时真正写盘"时可能撞上目录写锁；REST 不加锁。
- 同项目可被多个会话同时绑定（服务端不限制），变更广播只发给当前 `entry` 的通道；其他会话/初始页预览依赖 3 秒轮询。
- 中断不检查 abort signal：同步瓦片构建/导入中断后仍可能继续落盘。

### 3.4 验收口径（13 条）中需重点关注的 7 条

- **A1 Chat 只读**：Agent 工具层满足；**地图 UI 手工写路径（导入/样式/删层/转正/项目生命周期）不按模式限制** → 部分满足，口径需澄清。

- **A7 锁定层被 Agent 写入拒绝**：`map_edit/map_import` 满足；`map_save_analysis`（修好 P0 后仍无锁定检查）、REST import/replace/delete、提示词允许的直写均可绕过 → 部分。
- **A9 拖动无黑边**：ResizeObserver 实现存在，无像素级验证 → 部分。

## 5. 前端交互专项结论

### 5.1 用户可见影响排序

1. **"保存为正式图层"失败**（P0 链路，来自 Agent/结果卡）——用户会看到"分析已生成"，但保存动作报错/无反应。
2. **临时层不可管理/清除不彻底/复活**——"清除全部"后地图仍留有 OD/等时圈；单删后一段时间又出现；真实数据源分析结果完全不在清单。
3. **图层导出 GeoJSON 失败**（404）。
4. **Chat 模式下仍能编辑地图**（导入/删层/改样式/转正），与"只读"心理模型冲突。
5. **覆盖/替换数据没有二次确认**，选错文件即覆盖（旧数据虽进 trash，但入口无提示）。
6. **预览热刷新失败路径**：同项目 style 变更后地图可能不刷新（`reloadToken` 先消费后失败不重试）；初始页小地图跨会话不实时。
7. **错误不可理解**：瓦片/字体/style 加载错误只进 console；地图空白时用户只看到"加载中/无反应"。

### 5.2 做得好的部分（避免误伤）

- 地图模式对话栏紧凑呈现、项目/视口状态行、临时层"未保存"提示与结果卡文案与 DESIGN 基本一致。
- 图层树三段式、锁定图标、属性对话框字段、文件树两页签/`@`、AI 画布向导、三级重置对话框均落地且有源码级测试。
- ResizeObserver + 防抖 `map.resize()`、`setStyle` 后相机/下钻/底图/临时层重放等细节处理较完整，说明作者对 MapLibre 的坑有经验。
- `图层注册表.js` 解决"样式重载后临时层丢失"，是正确方向；问题是清除路径没接上。

### 6.3 审批与模式边界事实

- 代码默认审批模式为 `ask`；当前工作区运行时 `.oaw/permissions.json` 为 `{"mode":"auto"}`，会把 ask 提升为 allow（显式 deny 仍保留）。**审查结论按默认 ask 给出；auto 只是把 P1-B/P1-D 放大。**
- 工具层 Chat/Work/Review 白名单正确：Chat 只有 5 个只读地图工具；Work 全量；Review 无地图工具。
- 但 REST 地图写接口没有模式/审批边界，前端 UI 也不按模式限制 → "Chat 只读"在产品层不成立。

### 6.4 一致性与失败语义

- 写盘原子性：`writeConfig/writeStyle` 用 `atomicWriteJson` + `.bak`；但 `map_edit` 直写 `atomicWriteFile`（无 `.bak`）、`importLayer` 直写 GeoJSON（非原子）、`archiveProject/saveMapSettings` 非原子。
- 语义错误：`map_reset(temp)` 返回 ok 但未清前端；`map_save_analysis` 审批先弹、随后抛错；`map_import` 报"已导入"但样式可能尚未重建完成。
- 中断：地图写工具不接收 abort signal，用户中断后仍可能完成写盘并产生终态后事件。

### 6.5 演示数据口径

- 演示分析（heatmap/isochrone/OD）有 `source:"demo"`/`stats.demo:true`，ChatPanel/MapPanel 会显示"演示数据"；但**图层名/保存后的正式图层/报告**不保留 demo 标记。
- M2 四项（流量带宽/OD 期望线/区域交换/路网结构）由 `scripts/生成M2数据.mjs` 模拟生成，接口返回无 demo 字段、可视面板无标注 → 与 R10-17/AGENTS §6 冲突。
- 演示分析存在两套实现：`server/map-analysis.mjs`（Agent + `/api/map/demo-analysis`）与 `server/地图演示.mjs`（`/api/map/visual?dataset=demo-analysis`）；同一"义乌 OD"统计不一致（9 条线/2880 vs 1 条线/180），前端可视面板同时调用两者。

### 6.6 安全

- `/api/map/data` 静态根暴露 `maps/`（Key 文件、operations、agent reports、`*.bak`）。
- 路径校验：多数工具用 `isInside`，但 REST `prepare`、报告图片、空间分析等用字符串前缀比较，同前缀兄弟目录可越界。
- 密钥：`GET /api/map/settings` 只返回布尔（好）；`writeStyle` 会脱敏 map 服务 Key；但直写/import 路径不走脱敏，`settings.local.json` 可被静态路由读取。
- 锁定层：工具层部分生效，但直写/REST/`map_save_analysis` 可绕过。

## 11. 最终建议（给项目负责人）

1. **先止血再扩面**：P0（保存分析）+ 静态目录泄露 + 导出 404 是三个"改一行/一个小改动就能验收"的点，建议本周先修。
2. **把"协作编辑"当作一个明确的工程质量课题**：锁、版本、事务、审批、跨会话通知、失败回滚是一套能力，不是一个工具一个工具补；建议先定"地图写入模型"ADR（单写者 vs 多会话、UI 是否审批、事务边界），再批量改造。
3. **为地图写一条行为级回归红线**：至少覆盖"保存分析成功、越界导入被拒、失败替换不丢层、并发不丢更新、临时层可清可转正、Chat 无写入口"六条；否则本次发现的 P0/P1 以后仍会复发。
4. **演示数据与用户数据分层**：M2/演示分析/示例图层进入独立 demo 项目或明确标注，不要写入默认项目的正式图层；跟踪文件中的运行时迁移不要在提交里混入。
5. **文档同步**：PRD/DESIGN 与 ADR 对"默认开关、入口可达性、测试脚本名、验收口径"的漂移已累积到会影响验收的程度，建议随 Sprint 1/2 一并回写。
