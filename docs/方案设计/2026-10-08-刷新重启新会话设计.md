# 刷新与服务重启后的新会话设计

## 任务定义

- **目标**：网页刷新或后端服务重启后，仍停留在当前选定的工作区，但进入该工作区根目录下的空白新会话。
- **约束**：不自动恢复旧会话、旧文档标签或旧子目录；不删除用户文件、历史会话、运行记录或产物；旧会话与产物仍可由用户从列表手动打开。
- **交付**：更新前端启动行为，并重新构建 `client/dist`。

## 当前问题

`client/src/persist-ui.js` 将工作区、已打开文档标签、激活标签、当前子目录、侧栏状态和最后会话写入 `oaw_ui_state_v1`。`client/src/App.jsx` 启动时会恢复已保存的文档、子目录和最后会话；初始 thread id 也从 `localStorage` 复用。恢复会触发旧会话加载和关联文件打开，目录中文件异常或体积过大时可能阻塞界面。

工作区切换本身已会清空标签、子目录和当前会话，并创建新会话；缺口主要在刷新恢复及页面保持打开时的服务重启。

## 方案比较

1. **仅刷新时重置**：改动最小，但页面未关闭、仅后端重启时仍会沿用旧的内存状态。
2. **刷新和服务重启都重置（采用）**：完整覆盖用户提出的两种情形；通过 `/api/status` 中的服务启动时间识别进程代际变化。
3. **启动时连工作区也重置**：状态最干净，但会丢失用户希望保留的当前目录上下文。

## 设计

### 网页启动

- 每次加载应用文档时生成并保存新的浏览器 thread id，不复用上次 thread id；后端 session id 清空且不从旧状态恢复。两者分别表示前端对话通道和 Pi 持久会话。
- 仅恢复所选工作区和侧栏展开状态；不恢复旧会话、文档标签、子目录或外部模块。
- 新会话视图显示当前工作区根目录的文件列表，清空历史消息、文档预览和当前会话标识。
- 启动后仍刷新当前工作区的会话及产物列表；历史会话和产物元数据保留，可由用户手动选择查看。
- 持久化界面状态时只保存工作区及侧栏状态，覆盖并清除旧状态中的标签、子目录和会话 id。

### 后端重启

- 前端启动时读取 `/api/status` 的 `service.startedAt` 作为服务代际基准，并以 5 秒间隔轮询。若首次请求失败或没有返回有效启动时间，界面继续保持新会话；第一次有效响应只建立基准，之后的时间变化才触发重置。
- 后续状态响应中的启动时间与基准不同且有效时，执行与网页启动相同的重置：保留当前工作区，生成新 thread id，清空当前会话和预览，回到工作区根目录，并刷新文件、会话和产物列表。
- 状态接口暂时失败或未返回有效启动时间时，不清空界面；后续轮询继续检查。
- 中断运行和旧会话记录不删除、不自动恢复；用户仍可从历史列表手动打开。

### 构建产物

- 完成实现后运行前端生产构建，更新被 Git 忽略的 `client/dist`，使后续页面加载取得新资源。
- 不重载当前浏览器标签；该标签已有正在进行的会话，保持其现有内存状态，用户下次刷新时加载新构建。
- 本需求中的构建产物指应用前端资源；不改写所选工作区中的规划文档或其他业务文件。

## 验收标准

1. 刷新页面后，保留所选工作区，文件视图回到根目录，不自动打开之前的文件，也不恢复旧会话。
2. 页面保持打开而后端重启后，检测到新的服务启动时间，并得到同样的新会话界面。
3. 手动选择历史会话或产物时，现有查看流程仍可使用；重置过程不删除其文件或记录。
4. 前端生产构建成功，`client/dist/index.html` 引用本次生成的资源。
5. 更新现有启动/恢复回归脚本中与自动恢复相冲突的断言；按当前任务约束不运行测试套件。

## 不在范围内

- 清理、迁移或删除历史会话、运行、产物及工作区文件。
- 改变手动选择历史会话后的恢复行为。
- 改造后端会话格式或运行恢复协议。
